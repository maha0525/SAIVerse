### キャッシュ維持と自律行動の分離: 2026-09-12 表示案を暫定採用、画面で調整

現行ソースを限定確認した。`frontend/src/components/SettingsModal.tsx:538` 以降にキャッシュ維持の専用設定（既定 ON / ON / OFF）と維持呼び出しの説明がある。`sea/session_lifecycle.py:1690` 以降の予約は `keep_cache_alive=False` を除外する。その後 `sea/runtime.py:1994` で `autonomy_enabled=False` なら維持呼び出しをやめる。つまり維持設定が ON でも自律 OFF に連動して止まる。実稼働や課金の実測はしていない。

`cache_lifecycle_control.md` §8.5 は保温を自律側に置く旧設計を述べている一方、現行 `run_cache_keepalive` は判断・Spell 実行・SAIMemory 保存をしない維持呼び出しとして定義されている。v0.3 自律凍結、アラームの既決方針から、保温まで自動的に同じ結論にはしない。

Astra の提案は、会話のためのキャッシュ維持を自律行動の ON/OFF から分け、維持のための API 呼び出しを説明した専用設定で利用者が選べる正常挙動。まはーはこの選択肢を持てる方向に賛成し、活動に含まれる維持と追加の維持費用を分かりやすく示すことを条件として挙げた。原文・限定した予約経路の確認・表示案は `owner_decisions.md` の末尾に記録した。

2026-09-12 に「活動に合わせる」（普段の会話・自律行動の呼び出しに伴う更新）と「待機中も維持する」（活動の間が空くと専用呼び出しを追加、追加分の API 費用あり）という表示案に、まはーがひとまず賛成。実際に表示した後で調整する。この項目を現在の判断待ちから外す。自律 ON なら常に維持専用呼び出しがゼロ、とは現行コードから保証できないので、そのような説明にしない。現状は既定 ON なので、独立させる場合、現在自律 OFF で維持が止まっている利用者に、既存値の読み替えだけで課金を再開させない移行方法も具体化する。
