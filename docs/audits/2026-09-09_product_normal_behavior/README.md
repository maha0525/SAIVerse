## これは何

前回の棚卸し (機能を 215 項目に並べた台帳) を、**利用者・ペルソナ・運用者が一つの目的を果たし、
結果を受け取るまで**を単位とした **32 本の流れ**へ組み替え、各流れの「本来どうあるべきか」を書いた初稿。

**これはまはーが承認した仕様ではない。** 根拠のある期待と調査担当の提案は分けてある。
215 項目すべてに対応先または扱いを付けた ([mapping.md](mapping.md) で検算済み、漏れ 0 件)。

## 32 本の流れ

**会話 (6)** 話しかけて返事を受け取る / 立て直す / 切れた会話を復旧する / 送る中身と量とモデルを決める / 道具を使ってもらう / ファイルを渡す
**記憶 (7)** 過去ログを取り込んで使う / 編纂して見て会話を続ける / 会話しながら自動で整理される / 探して呼び戻す / 間違いを直す / Memopedia を育てる / 持ち出す
**世界 (5)** 移動して認識して会話する / 世界を作り変える / 物を作り持ち使う / 設置物と定期観測 / 世界の出来事が自動で何かを起こす
**ペルソナと設定 (5)** 導入して会話を始める / 設定を変えて使う / 決まった時刻に働きかけてもらう / 費用を把握する / ペルソナを消す
**画面のない処理 (3)** 見ていない間に動く / 起動して再開する / 終了して失われていない
**導入・運用 (6)** 更新して使い続ける / モデルを選ぶ / アドオンを足す / 外部から使う / 壊れたときに復旧する / 配布物を使えると信じられる

## まはーの判断が要る議題 (8 件)

詳細と選択肢の違いは [decisions.md](decisions.md) 第 1 部。

1. **意図的に配線していない機能の理由を、どこにどう書くか** — まはー本人が立てた課題。前例が 2 つある。
2. **機構が使った数字を、利用者にどう申告するか** — 事故 2 件の共通形。突き合わせの出し先が未定。
3. **機構が書いたもの・消したもの・失ったものを、ペルソナと利用者にどう知らせるか** — 設計倫理の芯。
   現状ペルソナへ通知するのはコア記憶だけで、その区別がどの intent にも書かれていない。
4. **利用者が仕掛けたアラームは「自律」に含まれるか** — まはーが既に v0.4 の未決として記録済み。
   費用の出る 2 つの自動処理が同じ設定に逆の反応をしている。
5. **確認を出す相手がいないときの既定** — 三方向に割れている。動機は同じだが前提が違う。
6. **失う操作の作法** — ペルソナの削除だけ先に決めることを推す (失うものの重さが桁違い)。
7. **外部に何を開くか** — 「凍結」の定義に待ち受けの停止が含まれるか。Unity はまはーが対処の意向を表明済み。
8. **検証とリリースの形** — 明示的な未合意。今回は決めない。
