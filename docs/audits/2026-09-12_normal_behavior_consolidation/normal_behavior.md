## 不可逆な操作に共通する規範 (2026-09-13 まはー)

> ユーザー操作の結果はその影響範囲をユーザーの期待と合わせる。
> 不可逆な操作であるほどこの規範は厳しく守られるべきで、削除はその筆頭。

以下は担当による整理: 期待がはっきりしない不可逆な操作は、どちらかを勝手に選ばず、利用者本人に確かめる。追加回答の逐語原文は [remaining_decisions.md の決着5](remaining_decisions.md) にある。

**この規範が効くのは、利用者が自分の意思で操作して正常に完遂される処理。**
別の原則「止めるのではなく、記録し、明示し、選択してもらう」は**エラーやイレギュラーで機構が止めたくなる場面**の
規範なので、混ぜない (統合担当は一度混ぜて、`FLOW-29` の判断を誤った形で立てた。経緯は
[remaining_decisions.md](remaining_decisions.md) の決着 5)。

2026-09-10 のチャットログ削除の裁定 (関連するあらすじ等が残ることとその影響を利用者へ説明し、
追加で変えた方がよいものは提案して選んでもらう) は、この規範の一例。

**訊いてよいのは、利用者が消すかどうかを決めてよいものだけ。** 他人の記憶に関わるものは訊く対象に出さない — 訊いて「はい」と言われたら、記憶を書き換えることになるから。

| 消えるものの性質 | どうするか | 根拠 |
|---|---|---|
| 利用者が用意したもの (物の元のファイル、アドオンが保存したデータ、自分で録った素材) | **訊く** — 「これも削除しますか？」 | 2026-09-13 の規範 |
| 誰かの記憶へ写った共有の記録 (部屋で交わされた会話) | **残ることを伝える。訊く対象に出さない** | 2026-08-25 の裁定 — 一人でも記憶へ転記していたら消さない。消すと「聞いた覚えがあるのに記録が無い」状態になり、無言で消えるより悪い |
| ペルソナ本人の記憶の中身 (コア記憶、あらすじ、物を持っていたという覚え) | **そもそも巻き込まない。** 消したいなら本人の記憶を扱う専用の入口から | 記憶の改竄になる。あらすじには 2026-08-19 に明示の除外が入っている |

**どれがどの行に入るかは、操作ごとに一覧を作ってから決める。** 既に決まっている操作の形 (ペルソナは「休ませる」と「消す」の二本立て、など) を、訊く選択肢として作り直さない。

**世界から物が無くなったことは、記憶を書き換えて伝えるのではなく、世界の出来事として届く** — 部屋の様子の照合が「見当たらなくなったもの」として運ぶ。ペルソナの記憶に「持っていた」が残っていても、それは嘘になっていない。

**この規範を当てる流れ** — `FLOW-11` (記憶を消す) / `FLOW-13` (手帳の全削除) / `FLOW-15` (部屋・街を消す) /
`FLOW-16` (物を消す) / `FLOW-23` (ペルソナを消す) / `FLOW-29` (アドオンを消す) / `FLOW-31` (世界のデータベースを初期化する)。

### FLOW-01: ペルソナに話しかけて返事を受け取る

**正常な結果**

利用者が一度送った発言は、通信の再送や二度押しがあっても部屋の記録に一行だけ入る。同じ送信 ID の二度目は受理されず、二度目の課金も起きない。保存できなかった回は受理そのものが成立せず、「発言を保存できなかったため、応答処理を開始しませんでした。同じ内容を再送できます。」が出るので、利用者は受理された発言と未受理の発言を見分けられる。送信ボタンを押したこと自体は保存を約束しない。話しかけた部屋と、その発言および返事が記録される部屋は一致する。応答は、その部屋にいて派遣に出ていないペルソナへ順に求められる (ゲーム Region では Ruler が先頭)。ただし全員ぶんの返答が生成されることは約束しない — 途中の停止・失敗・派遣中の除外がある。返事が一つも生まれなかった回も無言で終わらず、応答できる相手が部屋にいなければ `no_responder`、いたが返事が出なければ `no_response` が返る。画面に本文が出たことと、その発言が世界に残ったことは別々に届く (`speak_persisted`)。ペルソナは、その発言を次の会話で前提にできる。

### FLOW-02: 思った返事が来なかったときに立て直す

**正常な結果**

止める・続きを出す・やり直す・取り消すのどれも、追加の推論は必ず利用者のボタンの後ろに置かれる。押していない課金が勝手に起きない。**停止ボタンが止めるのは、その部屋で走っている発言の全部** — 巻き添えになったぶんの記憶に「ユーザーの操作により中断された」と残ることも含めて、現在の形を正常とする。取り消せるかどうかはペルソナがもう読んだかで決まり、読まれた後は取り消せない (「聞いた覚えがあるのに記録が無い」状態を作らないため)。断られた理由は利用者に区別できる形で返る (`already_heard` / `not_found` / `wrong_role` / `unavailable` の 4 種に日本語の説明が付く)。既に返事が付いた発言をやり直しで二重に燃やさない — API と生成直前の 2 段で門番が引かれ、判定できないときは通さない側に倒れる。取り消しが「もう読まれた」で断られても、応答を得る唯一の手段である再送は残る。そして、返事が来ていないという事実と、それに対して打てる手 (再送・取り消し) は、ブラウザを閉じて開き直しても失われない。

### FLOW-31: 壊れたときに復旧する

**正常な結果** — 二つの場面が入っている。**壊れたとき** (機構が止めたくなる場面) は、壊れたことが利用者に届き、失わずに戻せる。直せないものを毎起動のバナーで出し続けるのではなく、利用者が「分かりました」と言える出口を置く。バックアップを約束するなら、戻し方も同じ場所で利用者に届く。**利用者が自分で世界のデータベースを初期化するとき** (自分の意思の不可逆な操作) は、消えるものと残るものを名指ししたうえで、期待が分かれるものについて「これも削除しますか？」と訊く (上の [不可逆な操作に共通する規範](#不可逆な操作に共通する規範-2026-09-13-まはー))。この二つを同じ物差しで測らない。
