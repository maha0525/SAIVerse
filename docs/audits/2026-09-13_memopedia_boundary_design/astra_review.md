# Astra レビュー — 方針は採用、実装前に取り込みの二点を補完する

2026-09-14 / 開始・確認時 HEAD `19ea2010` / `codex/product-normalization`。

## 判断

カテゴリ定義に一括操作の対象を持たせ、物理削除・export・import・差分通知に適用する方針を採用する。コア記憶と Chronicle を対象から外し、通常ページとテーマの操作を成立させる。検索にコア記憶が出ることは `concept_consolidation.md` の既存意図と一致するので変えない。

**ただし、この設計のまま実装へ渡す判定にはしない。** 取り込み中の失敗と、取り込んだ通常データを読み直せることの二点が未完成。元の依頼にある「失敗時の既存データ」「提供範囲の往復・読み手」の具体化であり、全体調査をやり直す話ではない。

既に壊れたコア記憶の救済は、予防とは別の変更に分ける。原因を塞ぐ変更と、失われた情報・番号の衝突を扱う修復では、変更対象と検証が異なるため。[救済の追跡先](../../issues/core_memory_import_recovery.md)に残し、正常化の対象からは外さない。本番での発生有無は未確認だが、救済の設計と合成データでの検証は本番調査を待たずにできる。

## 1. 置換の途中失敗で元のデータを失う経路が残る

`design.md` §6 は「取り込める行が1件以上あるか」を削除前に確認し、それ以外の失敗は件数で知らせる案。`verification.md` 行4には部分適用か巻き戻しかをユーザー判断とする記載が残り、READMEの「新しい質問ゼロ」と整合していなかった。

既存 exp4 は不正な型の行を混ぜた実験。追加で**型・カテゴリとも正常な2行**を渡し、2行目の INSERT を SQLite の一時トリガーで失敗させた。現行の実ルート関数は `success=true, imported_count=1` を返し、置換前の通常ページは消えた。この例は型の事前検査だけでは解けない。

**私の修正案は、置換を最後まで成立させてから確定し、保存失敗時には操作前の状態を保つこと。** 途中まで置き換わった結果を、利用者が選んだ完全な置換として扱わない。これは今回の操作に対する提案で、全機能を一律に停止させる規則ではない。

成立性の根拠と残作業:

- `Memopedia._atomic` は共有DBロックと `BEGIN IMMEDIATE`、例外時rollbackを既に持つ。`storage.create_page` も `commit=False` に対応する。
- **そのまま外側を包むだけでは足りない。** `storage.delete_page` と `_detach_chronicle_page` は内部でcommitし、importは行ごとの例外を捕まえて続行する。削除の再帰と保護行の退避まで含め、誰が確定するかを揃える必要がある。
- 入力全体の型・識別子・親子関係の検査、除外とエラーの区別、既存のトランザクションに参加する場合の責任を設計する。正常な旧形式からcore行を除外することは、保存エラーとは分ける。
- 新規保存だけでなく、削除途中・保護行の退避後にも失敗を入れ、ページと付随データ、core/Chronicleの読み取りが操作前と一致することを検証する。

## 2. 対象に含めた通常データの往復が閉じていない

`design.md` はthemeを操作対象に含める一方、§8でその往復の欠落を範囲外へ送り、検証文書もthemeの読み手を未確認にしている。役割表で対象を決めるだけでは、取り込んだページを使える保証にはならない。

追加実験では**通常ページ1枚・Fragment1件・テーマ1枚だけ**を用意し、無変更のexport/importルートを通した。core行は入力に含まない。

- APIは2件の取り込み成功を返した。
- Fragmentは持ち出し元1件、取り込み先0件。
- themeのmetadataが欠落し、取り込み先に `root_theme` が無かった。
- 取り込み後の `Memopedia.get_tree()` にテーマの表題が出なかった。

コア記憶を除外しても残る、今回提供する側の不成立である。少なくともテーマを正規の読み手から参照できる親子構造は必要。Fragment・themeのmetadata・短い参照について、現行画面と既存intentから約束している範囲を定め、何を運ぶか、運べないものをどう伝えるかを具体化する。汎用の全記憶バックアップやコア記憶の移植機能へ拡張しない。対象を狭く説明する案でも、利用者に黙って既存データを置換・喪失させないことが条件。

## 根拠の表現を訂正する

- ユーザーの原文は「操作の影響範囲を期待と合わせる」。FLOW-13の具体的な除外と三分類は、その規範を統合担当が適用した記述。採用する根拠にはなるが、本人の発言原文と同一視しない。「訊くのは利用者が用意したものに限る」という一般規則には広げない。
- 「修正で赤になる既存テストは無い」は未検証。検証文書が実測したのは変更前の3ファイル93件。修正後は本件の境界・既存の操作を検証して判定する。
- 残った表題 `コア記憶 c:N` は調査の手掛かりであり、正規のIDを復元できる保証ではない。本文が残ることと、由来・kind・confirmed・識別子が復旧できることを分ける。
- headの章の読み取り失敗は確認できているが、実発話停止・画面表示の実測ではない。既存の停止や据え置きの実装を、新たなユーザー承認として扱わない。
