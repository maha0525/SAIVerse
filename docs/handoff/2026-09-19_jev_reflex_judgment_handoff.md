## 3. 次の仕事: 反射判断の第 1 段の実装

**設計の正典は docs/intent/reflex_judgment.md (実装待ち・裁定全件確定)。
読んでから始めること。** 骨子: Jev で開けた「状況 + 型付き質問 → 確率」を、
モデル設定ファイル + モデルの役割の形に載せ、答える側 (公式 / OpenRouter /
localjev / 将来は軽量モデル) を役割へのモデル割り当てで選ぶ。

第 1 段の内容 (intent §6 の裁定どおり):

- 反射判断の共通層 (`saiverse/reflex_judgment.py` 案)。器 (締切・同時 4 本・
  伏せ字・全 qid 検証) は `saiverse/typesafe_client.py` から引き継ぐ。
- jev 互換の provider type (組み込み限定)。宛先 path・応答の方言・対応する型を
  設定ファイルの欄で宣言。**公式へのキーは宛先とペア** (既存の provider 照合の
  原則のまま)。
- モデルの役割「反射判断」を一元表 (`saiverse/model_defaults.py` の
  `MODEL_ROLES`) に追加 — 保存時検査・画面警告・プリセットが自動で効く。
- **ペルソナごとの「自動想起を強化する」スイッチ** (DB の AI テーブルに列追加 +
  ペルソナ設定画面のトグル、`AUTONOMY_ENABLED` と同じ形・既定 OFF)。
  env `SAIVERSE_AUTO_RECALL_JEV` と `TYPESAFE_API_KEY` 以外の Jev 実験 env は
  ここで廃止 (environment-vars.md も同時に直す)。
- 自動想起の載せ替え: `sea/auto_recall.py` の `is_jev_rerank_enabled()` を
  「ペルソナのスイッチ ON + 役割にモデル割り当てあり」へ。
- 同梱するモデル設定ファイル 3 つ: TypeSafe 公式 (`jev-latest`,
  `TYPESAFE_API_KEY`, $0.042/1M 入力) / OpenRouter (`typesafe/jev-latest`,
  path `/api/alpha/decisions`, OpenRouter の既存キー) / localjev (ローカル宛先,
  キー任意)。

**実装の落とし穴 (このセッションで確認済みの事実):**

- `run_auto_recall` は現在 persona_id (文字列) しか受けない — ペルソナの
  スイッチを読むには呼び出し側 (`sea/runtime_context.py`) から旗を渡すか、
  DB 参照の口を足す必要がある。呼び出しの形を変えるなら OFF 時の挙動不変の
  既存テスト (`tests/test_auto_recall.py`) に注意。
- DB 列の追加は `database/migrate.py` + コピーで試す (`--db`)。スキーマの
  参照文書は `gen_reference_docs.bat` で再生成して同じコミットに入れる。
- モデルの役割を足すときは `saiverse/persona_model_selection.py` の保存時検査、
  `manager/initialization.py` の画面警告、`api/routes/tutorial.py` のプリセット
  が同じ表を読んでいる (整合性検査での確認済み事実)。
- Gemini の構造化出力は additionalProperties 不可 — 第 2 段の変換層は配列
  `[{id, probability}]` で受ける (intent §3)。
- 実装はサブエージェント (model: opus) 委譲。ペルソナの記憶・費用に触るので
  レビューはフルの流れ (ローカル + 敵対、収束まで)。
