## ① v0.3.11 — UI セルフアップデートの根治 (PR #286)

- **何が起きていたか**: 稟乃さんの UI 更新が二回とも失敗した原因を self_update.log で確定。psutil (プロセス生存確認のライブラリ) が requirements に無く、無い環境ではアップデータが「本体はもう終了した」と誤判定 → 生きている本体の隣でスナップショットに進み、安全検査に止められて更新ごと中止 → 誰も再起動しない。**Windows 固有・本体だけをセットアップした利用者全員が対象**。開発環境には voice-tts アドオンの間接依存で psutil が偶然入っていたため再現しなかった。
- **直したこと**: psutil を requirements.txt / lock に必須化 (全プラットフォーム wheel 検査合格、素の venv + lock のみで全スイート合格)。生存判定 5 箇所の「判定できない → 死んでいる扱い」を全部安全側へ (update_engine / runtime_marker / backup.py)。UI 更新の入口に事前検査 — psutil が無ければ**本体を落とさず** 409 で「update.bat を一度実行してください」を返す。
- **発行時の必須事項**: リリースノートに「psutil の無い環境の人は update.bat を一度だけ実行 (以後は UI 更新が使える)」を明記。**この修正自体は UI 更新では届かない** (走るのは更新前のアップデータ)。
- 発行手順は v0.3.10 と同じ: マージ後 develop で VERSION bump + upgrade_handlers に v0.3.11 の空辺 → main へ PR → タグ push (Actions が ZIP 添付) → リリースノートは agy の公開前検査を通してから `gh release edit`。
- issue: [self_update_unsafe_without_psutil.md](../issues/self_update_unsafe_without_psutil.md) (発行後に archive へ)。

### のろけゆきさんへの返答材料

- 原因: ChatGPT からインポートした各会話の「あらすじ 1 個分に満たない端数」が、吸収の探索 (後ろの隣人のみ + スレッド境界で停止) で全員行き場を失い、しかも見送りが「完了しました」の裏に隠れていた。ログの `[absorption]` 警告行がその痕跡のはず。

- 15 万トークンは修正版適用後に再測定をお願いしたい (帯の滞留分は解けるはず。まだ大きければ別要因として追加調査)。
- 診断レポートに孤児参照のエントリ内訳が追加されるので、もう一枚もらえれば「20 件の孤児参照」の正体 (何本のあらすじ・全滅か部分欠けか) も確定する。
