### 2-4 実機検証 ④ — 三つの層が順に出た

1. **「続きの生成」がその場で出ない** (別の部屋へ移って戻ると出る)
   → 印を載せた完了イベントが、例外の下流にあって届いていなかった
2. **言いかけた本文がペルソナの記憶に残らない**
   → `memorize` も同じ理由で届かない。建物の記録には残るので、**世界には刻まれたのに
   本人だけが覚えていない**状態だった
3. **⚠️ 生成し終えた直後に停止すると、発言そのものが消える**
   → 下書き行が本文の入らないまま残る。§3 に詳しく

これらの後始末を `_settle_cancelled_utterance` として一本化した (`sea/runtime_llm.py`)。
確定・印・記憶・記録の四つをまとめて揃える。

### 2-5 中断の記録をどうするか (まはー裁定で決着)

- **途中まで喋ってから止められた回**: 本文を印つきで記憶へ + 中断の事実を建物の記録へ
  (`role: "host"` で平文、文面は「(ユーザーの操作により、ここで発言が中断されました)」まで)
- **一言も出ないうちに止められた回**: 何も書かない。`PulseController._record_interruption`
  を撤去した (707 セッション中 1 回しか通っていなかった)

押さえた制約 (→ memory: `project_system_notice_uses_user_role`):

- 本人の発言そのものには追記も変更もしない (ペルソナが模倣する)
- `metadata` の印はペルソナから知覚できない
- システムからの通告は `user` ロール + `<system>` タグ。ただし**それは取り込みが作る形**で、
  建物の記録へ書くときは `role: "host"` で平文

### 起票時の判断が誤っていた

この現象は同じ日の午前に issue へ起票済みだったが、そこにこう書いていた —
**「優先度 low、害はゴミが溜まることに限られる」「ユーザーの停止 → 確定は通る」**。両方とも誤り。

- 「画面にも記憶にも出ない」を無害の根拠にした。それは**消えた発言が見えない**というだけ
- 空の行が残ることを「ゴミ」と読んで、「本文が失われた」と読まなかった
- 「停止は確定が通る」は、ストリームの**途中で**止めた場合だけの話だった

### 既存の 32 件の扱い (まはー裁定)

**そのまま残す。** 現状害が出ておらず、誰も気づいていない。本文はどちらにせよ戻らない。

ただし**他のユーザーの環境にも同じデータがあるはず**なので、
**空の発言として読み込まれたり UI に出たりしないこと**を保つのが要点 (まはー)。
2026-08-26 に実装で確認した:

- **履歴 API**: `api/routes/chat.py:299-302` の `if msg.get("content")` で空を除外
- **取り込み**: `builtin_data/tools/get_building_messages.py:205-206` が空を `consumed` で飛ばす

⚠️ **どちらも判定しているのは `content` の空であって `_streaming_placeholder` フラグでは
ない。** placeholder は必ず content 空で作られるので現状は問題ないが、**フラグを見て
いるわけではない**ことは知っておくこと。

## §4 次のセッションへの申し送り — 私が三度繰り返した形

**コードが存在することを、それが動いていることの証拠にした。** 同じ形を一日に三度やった。

1. **「読み手が去ったら生成を止める」** — 停止イベントを立てて「止まる」とコミットに書いた。
   実際には走っている LLM には届かない仕組みだった。Codex の 3 巡目で判明
2. **「中断は記憶に記録される」** — コードを読んで「書かれる」と断定した。ユーザー発話が
   その経路を通らないことを確かめていなかった。まはーの «本当？» で判明。707 セッションの
   ログを数えたら 1 回しか通っていなかった
3. **「停止しても確定は通る」** — issue にそう書いた。ストリームの途中で止めた場合だけ
   だった。まはーが実機で踏んで判明

**判定式**: 「このコードは、この経路で**実際に実行される**か」を、ログか実測で確かめてから
書く。読めることは通ることの証明ではない。

もう一つ。**まはーの «本当？» «これはいいのでは？» «ちょっと気になる» が、三回とも本物の
欠陥を掘り当てている。** 引っかかりを述べられたら、自分の説明を守る前に測りに行くこと。
