## 0. 芯 — 提案の全部を5行で

1. **ペルソナの体験が長期記憶に入る道を、一本にする**: どの体験も「提示から退場する瞬間に、要約1本になって年表の列に合流する」。長期記憶への合流点はこの一つだけで、どの機構も独自の抜け道を持たない
2. **列に生ログは立たない**: 列の住人は要約だけ。どんなに小さい体験も要約されてから合流する
3. **出来事 (エピソード) はまはーの発言も含む両側の記録に直す**: 片側だけの出来事が、取り残しと例外規則の量産源だった
4. **列の中の規則は3つだけ残す**: 「同じ格同士 (10倍以内。ただし小さい要約は一段下の床 = 1,000字まで同格扱いで、隣の束ねに吸収される)」「まとめたら5倍以上に育つときだけ」「条件を満たしたら最短で閉じる」
5. これで治療・非常弁・恒等転写・転写という**4つの救済機構がまるごと消える**。規則が減るのは、来るはずのないものが来なくなり、残る小粒は正規の束ねが吸うから

## 1. 今の川 — どこが破れているか

体験の種類ごとに、生まれてから長期記憶 (Chronicle の列) に入るまでの現状:

```
【会話】
まはーの発言 ──(取込・エピソード帰属なし✗)──┐
エリスの発言 ──(帰属あり)──────────────┤
                                        ▼
                              提示の川 (メインライン)
                                        │ 膨らむと Metabolism
                                        ▼
                     退場: エピソード単位で1万字ぶんを畳む
                     ✗ 帰属のない発言が範囲から置き去りにされる
                                        ▼
                     編纂: 範囲まるごと要約1本に
                     ✗ 置き去りの端数(1,000字未満)は生ログのまま列へ =「豆粒」
                                        ▼
                              年表の列 (Chronicle)
                     ✗ 豆粒は比率10倍検査に永遠に落ちる → 救済機構「治療」
                     ✗ 治療は R1/R2 の二律背反で3巡直しても穴 (Codex)
                     ✗ 束ねは「伸ばせるだけ伸ばす」で一週間を1本に丸呑み

【作業セッション】
作業ログ ──(volatile: 提示に乗らない)──▶ 行き止まり (編纂対象外)
終了時にエリスが書く要約1本 ──▶ 提示の川に残る
                                        │ 退場のとき
                                        ▼
                     ✗ 除外タグで編纂拒否 → あらすじ化されずに消える
                     ✗ 受け皿のはずの「転写」機構は発火条件が成立せず全ペルソナで0件
                     = 作業の記憶が長期記憶に入る道が存在しない

【スケジュール起動・システム通知】
起動文 ──(帰属なし)──▶ 会話と同じ川 → ✗ 毎朝1個の豆粒
```

破れの共通根: **上流の傷2つ** (①まはーの発言・システム文に出来事の帰属がない ②作業の要約に合流点がない)。下流の複雑さ (治療の4条件・閉包・凍結、非常弁の5条件、恒等転写、転写) は、この傷から漏れてくるものを受けるために生えた**かさぶた**で、かさぶた同士がさらに矛盾している。

## 2. 提案の川 — 一本

```
【あらゆる体験】 会話 / 作業 / スケジュール / 自律

  生ログ (まはーの発言も含めて出来事に帰属) ──▶ 提示の川
                                                │
                          退場の瞬間 (体験の種類で瞬間は違ってよい):
                          ・会話 = Metabolism が畳むとき
                          ・作業 = セッションが閉じるとき
                                                │
                                                ▼
                          編纂: 退場する範囲を要約1本にする
                          (作業は post_session が書く要約がそのまま1本になる。
                           小さい範囲も要約する — 生ログのまま置かない)
                                                ▼
                          年表の列 = 要約だけが時系列に並ぶ一本の列
                                                │ 溜まったら (X 超過)
                                                ▼
                          束ね: 同じ格 (10倍以内、小さい要約は床=1,000字まで
                          同格扱い) の連続する並びを、まとめた結果が最大メンバー
                          の5倍以上に育つときだけ、条件を満たした最短の範囲で
                          1本の上位要約へ
                                                ▼
                          提示: head の年表枠。新しいほど細かく、
                          体験量に比例して粗く (現行のまま・健全)

  ※ 知覚イベント・システム通知は本提案の対象外 (知覚バッファ側の設計の管轄)。
    ただし「長期記憶に入れるなら、この川の合流点を通す」だけを契約として課す (§6)
```

**不変条件は4つ**:

1. **退場したものは必ず要約になっている** (現行の下限 — 維持)
2. **列に生ログは立たない** (新設 — これが治療と恒等転写を消す)
3. **提示は全期間を覆い、どの期間も黙って落ちない** (現行 — 維持)
4. **長期記憶への合流点は一つ** (新設 — どの機構も編纂を迂回する独自の長期化経路・独自の消滅経路を持たない。作業の要約が「除外タグで編纂拒否→黙って消える」は本条違反の実例)

## 3. 何が消えて、何が残るか

| 機構 | 今 | 提案後 | 理由 |
|---|---|---|---|
| 退場 (三水位・エピソード単位) | あり | **残す** (帰属の修理で置き去りが消える) | 健全。傷は入力側だった |
| 編纂 (範囲→要約1本) | あり | **残す** (簡素化: チャンク3種→実質1種) | 〃 |
| 恒等転写 (1,000字未満は生ログのまま) | あり | **消す** — 小さくても要約する | 列の純度 (不変条件2)。コストは1回数円未満 |
| 転写 (確定済み digest の置き写し) | あり (発火0件) | **消す** — 作業の要約はクローズ時に列へ直接合流 | 発火条件が構造的に成立しない死んだ機構 |
| 治療 (束ね不能ノードの救済・4条件+閉包+凍結) | あり (再設計中断中) | **消す** — 小粒の吸収は比率判定の床 (下記) が肩代わり | 短い作業・短い会話からは今後も小さい要約が正規に生まれる (例: `[1万, 200, 1万]` の 200)。放置すると比率10倍に落ちて列を永久に分断する (Sol 指摘)。だから救済専用機構ではなく、**束ねの規則に一句** — 比率判定でのみ質量を `max(実質量, 1,000)` と見る — を足し、小粒は隣の正規束ねに吸収されて消える。薄まることは治療の裁定 (2026-07-27) で織り込み済み |
| 非常弁 (最古の隣接2件を強制束ね・5条件) | あり | **消す** | 床により小粒が正規束ねで吸われるので、非常弁の想定客が消える。発火したのに打てない形はログ観測のみ残す |
| 束ね (比率10倍・5倍下限) | あり (最長貪欲) | **残す** (変更2点: ①5倍下限に届いた**最短**で閉じる ②比率判定に小粒の床 1,000字) | ①は丸呑みの防止。実測 (2026-07-28 ドライラン) で「最長」は59ノード/7.2万字を1本に丸呑み、「最短」は3本 (9千/2.7万/3.2万字) に割れた。②は治療の代替 (上記)。提案の条件での再ドライランは実装時に行う |
| 提示 (累積質量ルール+予算) | あり | **残す** (変更なし) | 実データ検証済み・健全 |
| session_digest ほか除外タグの編纂拒否 | あり (穴) | **作業の要約は合流に変更**。他タグは個別に「残す価値があるか」を再裁定 | 既知の欠けの本体 |

**消える概念・用語**: 治療 / 非常弁 / 恒等転写・恒等圧縮 / 転写 / 卒業 (→「5倍下限」と中身で呼ぶ) / 恒等転写の1,000字閾値。**数字のノブも減る**: U・比率10倍・5倍下限・X (提示予算から導出)・三水位、の5系統だけ。小粒の床は独立ノブにせず **U から導出 (U/10 = 1,000字)** — X と同じ「独立ノブを作らない」思想。

## 4. 上流の修理 2点 (この提案の前提)

### 4-1. 出来事を両側の記録にする

- まはーの発言・スケジュール起動文にも、取り込み時に「いま開いている出来事」の帰属を刻む (エリスの発言と同じ規則に揃えるだけ。issue 起票済み)
- これで退場の「エピソード単位で畳む」が、会話の**全員の発言**を一緒に運ぶようになり、置き去り (豆粒の量産源) が消える

### 4-2. 作業の要約に合流点を作る

- 作業セッションの要約が確定した瞬間 (post_session 判断が要約を書き、配送されて出来事に鍵が刻まれるとき)、その要約を**一次あらすじとして列に登録する** (質量 = 作業ログの実字数)。発火を待たず、編纂を経由しない — 退場時圧縮の原則の素直な適用 (作業ログの「退場の瞬間」はクローズ時だから)
- **冪等と部分失敗の契約** (Sol 指摘の採用): 登録は既存のダイジェスト配送 (outbox、at-least-once) に統合し、**ダイジェスト行の message id を一意キーにした冪等 insert** とする。memory.db 内の書き込み (ダイジェスト行 + あらすじ登録) は単一トランザクション。出来事への鍵 (digest_ref) とあらすじ登録の両方を確認できるまで配送を完了扱いにしない。停止・再配送で「登録漏れ」も「二重被覆」も出ないことを回帰で固定する
- 提示の川に残る要約行は今まで通り見えてよい。head の年表枠には「その行が提示から退場するまで出さない」— 提示中のあらすじを head から除外する機構は実装済み (圧縮区間の除外) なので、その仕組みに乗せる形 (対応付けの鍵は上と同じ message id)。配線の細部は実装時に確認

## 5. まはーが決める分岐

1. **§4-2 の形**: クローズ時に列へ直接登録 (推し) か、退場時の編纂で要約行を材料として拾う形 (変更が小さいが、「要約の要約」を1回挟む) か
2. **恒等転写の廃止** — 「小さくても要約する」に一本化してよいか
3. **束ねの止めどころ** — 5倍下限に届いた最短で閉じる、でよいか
3b. **小粒の床 (比率判定でのみ質量を U/10 = 1,000字に底上げ)** — ⚠️ これは今日いちど却下された「生ログの底上げ」の**復活ではない**。あのときの結論は「生ログは列に載るべきでない」で、本提案はそれに従い生ログを列から消す (分岐2)。その上で、**正規に生まれる小さい要約** (短い作業・短い会話) が列を分断する問題 (Sol 指摘) への答えとして、要約同士の吸収規則を1句置く。代替案は「小粒専用の吸収機構を残す」(= ミニ治療) だが、規則1句の方が薄い
4. **既存データの修復** (本番記憶の書き換え = まはー承認事項):
   - エリスの豆粒26個 → 隣の要約と合流させる一度きりの再編纂
   - air の取り残しダイジェスト6件 → 列への後追い登録
   - 既存メッセージへの出来事帰属のバックフィル → **やらない推し** (これからの分だけで川は健全化する。過去分の帰属は推測になるので、事実の捏造に近づく)
5. **治療の作業ツリー** (未コミットの再設計実装) → 破棄してよいか

## 6. この提案がやらないこと (正直な線引き)

- **Memopedia / コア記憶 / 自動想起には触れない** — 解釈層・想起側は健全 (実機検証済みの機構が多い)。今回の病巣は咀嚼層 (Chronicle) への合流だけ
- **知覚イベント (event_message) の長期記憶入りは設計しない** — 知覚バッファ側の設計 (experience_structure §7、「短期→長期の入口選別」issue) の管轄。ただし本提案は**支流の契約**だけ課す: 知覚のうち長期記憶に残すと決めたものは、この川の合流点 (編纂) を通す。独自の長期化経路や「除外タグ→黙って消える」経路を作らない (不変条件4)。Sol は「本提案内で知覚の分類まで設計せよ」と指摘したが、それは知覚バッファ intent の仕事で、ここで抱えると提案が再び肥大する — 契約だけ置いて委ねる
- **帰属タグ付けはベストエフォートのまま** — Sol は「帰属の強制契約・未帰属の隔離」を提案したが、採らない。理由: 本提案の世界では帰属の失敗の帰結が「小さい要約が1本増え、床の規則で後日吸収される」に**有界化**される。帰結が軽いのに入口を重くするのは複雑さの逆行
- **提示側 (質量ルール・予算) の変更なし**
- **エピソードの開閉の仕組み自体は変えない** — 帰属タグの付け方だけ直す

## 7. 検証の旅程 (実装時)

- 修理後の実データ dry: エリスで「豆粒の新規発生ゼロ」/ air で「作業要約が列に現れる」
- **救済機構の削除ゲート** (Sol 提案の採用): 治療・非常弁のコードを消すのは、全ペルソナの実データ dry で「束ねに一度も入れない凍結ノード」がゼロになってから。それまではコードを消さず呼ばれない状態で駐車
- 束ねの止めどころと床: 小質量の会話・作業・スケジュール要約を混在させた列の property test (将来必ず束ね可能になること) + 実データ dry で丸呑みが出ないこと
- §4-2 の配送: 各書き込み境界で停止・再配送しても登録漏れ/二重被覆が出ない回帰
- 提示: aifi/quon の「現行と完全一致」golden を維持 (健全データで挙動不変の証明)
- 実機: エリスの予算超過 WARNING が束ねの健全化で消えること

## 8. Sol 相談の記録 (2026-07-28 深夜)

観点「シンプル化が目標。4機構の削除の安全性・川の穴・前提失敗時の劣化を突け」で攻撃レビュー1巡 (no-ship、high 4件)。

- **採用**: ①小粒要約の列分断 (`[1万, 200, 1万]`) → 比率の床で解決 (§3, 分岐3b)。④直登録の冪等・部分失敗契約 (§4-2)。削除ゲートと property test (§7)
- **一部採用**: ②「知覚に道がない」→ 芯1の過大広告 (「例外なし」) を撤回し、支流の契約 + 不変条件4 に置換。知覚の分類設計そのものは知覚バッファ intent へ (§6)
- **不採用**: ③帰属の強制契約・未帰属の隔離 → 床により失敗の帰結が有界になるため過剰と判断 (§6)。理由ごと記録し、まはーの再裁定に開いておく
