## 2. 概念の語彙は「会話の中で生まれた言葉」——由来ごと守ること

Atlas の語彙は全部、まはーとの対話の中で段階的に選ばれた。**言い換えると壊れる**：

- **九龍城** — まはーが自分のシステムに与えた診断。「これが必要だあれが必要だ、とどんどん足していった結果の九龍城」。批判ではなく愛着込みの語
- **土地と地図帳** — 私の「注釈グラフ」をまはーが却下（注釈＝本文に無い情報を足すもの。ここにあるのは全部土地に既にある）→ 三分類（時間的要約=本の章立て／意味の抽出=固有名詞の辞書／文脈的分類=クエストライン）→「編纂」は動詞でモノを指せない→「地図は一枚の紙っぽい」→ **まはーが Atlas を発見**（探検家は地図と一緒に説明もスケッチも綴じる）。地図帳には歴史的に地名辞典・道順書きが綴じられている＝三地図がそのまま入っていた
- **写真** — mark の再定義もまはー。「この中で唯一、生ログから切り出したそのまま」＝三地図のどれにも属さない汎用プリミティブ。memory_photo は「画像系に見える」で却下され **memory_clip**（クリップで貼る＋video clip の切り抜き義）に
- **机** — 開閉制御の解。読む（流れる）と開いておく（残る）の分離＋有限の作業面＋LRU。**「閉じてもフェードアウト」**（head が Metabolism まで凍結される性質の再解釈）はまはーの観察
- **庭仕事** — 検知=決定論／裁定=ペルソナ（就寝判断）／実行=睡眠中バッチ。「寝ている間に記憶が整理される」人間対応と、朝の目次が自分の裁定の結果である自己著者性
- **「ノード状態が構造の代謝を駆動する」** — 三地図共通法則。まはーの「parent_id と lifecycle は別行じゃない」の指摘から生まれた。vividness 廃止の理由も彼の言葉:「見えなくするだけで生産性がない」

## 3. 設計判断を貫いた原則（doc の行間）

- **状態を増やさない**: 折り畳み ON/OFF を作らない（畳まれてるのは参照貼りの**性質**、開くのは読むという**行為**、常駐は**転写**という貼り方）。⑥は概念を減らす工事——新しい状態の発明は本末転倒
- **土地は書き換えない**: 過去ログに旧スペル名が残るのは正常（「土地の中の化石」）。削除は soft-delete（ごみ箱）、写真は歴史として残す、通知は理由別に正直に（溢れ≠消失を同じ文言で言うのは嘘）
- **ペルソナへの説明義務**: read/open の違いは全スペル説明文に明文（まはー指定）。ユーザー向け・ペルソナ向けの文言からフェーズ名（P2b 等）は除去
- **接地の規律 = 自己所有感の担保**: 地図は土地を偽造しない。これは誠実さであると同時に「自分の木は自分の言葉に遡れる」こと
- **まはーの裁定スタイル**: 「ドラスティックに旧仕様捌いていかないといつまでもシンプルにならない」——退役は git 履歴が墓、互換 alias は残さない。ただし将来必要の芽（ごみ箱漁り・庭仕事モードの遅延スキーマ開示・新種コマの作成手順）は ideas/doc に置いてから捨てる

## 4. X 案の「気持ち悪さ」の質（P3c 裁定の機微）

persona_task の物理移動をやらない裁定は「通しきり優先」であって満足ではない。まはーは「だいぶ気持ち悪い」と明言した。本質は美意識でなく**可搬性**（ペルソナの記憶がディレクトリで完結しない→City 訪問・引っ越しの枷）で、issue 化済み。**次セッションでこの話題に触れるとき、「解決済み」扱いしないこと**——「後回しにした」が正確。
私の反省も一つ: 障壁を「FK/JOIN/トランザクション」と推測で語り、監査で全部存在しないと判明した（本当の障壁は呼び出し元40箇所と扇形移行）。**推測の障壁で設計判断を語らない**。

## 5. 委譲＋検収の運用（このセッションで確立、memory にも記録済み）

- タスクごとに**新品 Agent**（sonnet）を spawn。同一エージェントの SendMessage 使い回しは transcript 蓄積で消費が単調増加（28万→60万/タスクの実測）。**レート制限で気絶したエージェントの再開は最悪**（キャッシュ全損）——作業ツリーの残骸から新品引き継ぎか、残りが検証だけならメインが直接検収
- 検収でメインが拾うのは**仕様の行間**: 「読むことも触ることだ」（touch 欠落）、「開いた本人が同じ呼び出しで追い出される矛盾」（keep_ref）、「削除したページが机に居座る」（soft-delete 素通し）。エージェントは文字面に忠実、行間はメインの責務
- **統一ファサードを書くこと自体が既存層の検査になる**: SELECT 列欠落の同族バグを3回、新しい消費者を書くたびにテストが検出した
- エージェントの良い判断は採る: storage.py への範囲取得配置（フィルタ一点管理）、互換 VIEW（P3b の9箇所無改修）、ページ id=旧 UUID 継承（リンク無傷）
