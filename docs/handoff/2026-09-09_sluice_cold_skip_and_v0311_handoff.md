## ② 稟乃さんの真相 (rate_diag で確定) とスルース被覆の穴

- 実体: 起動直後の読み戻しが v0.2 履歴 **212 万字**を窓に開き、非常畳みのスルースが
  それを一発で読もうとして OpenAI の 429 (TPM 超過)。**429 の文面 "Request too
  large" がコンテキスト超過判定の文字列に一致して誤分類され**、「直近の 1〜2 通を
  外して再試行」が夜通し回った (429 が 14,475 回、返事はゼロ)。費用は発生して
  いない見込み (429 は処理前拒否、残高無傷の報告と一致)。
- 設計: [intent sluice_coverage_gaps.md](../intent/sluice_coverage_gaps.md)。
  まはーの決定 (原文つき): 冷たいときのスルースは走らせない・通っていない範囲は
  記録して後から通せる・スルース以前の記憶に遡及義務なし・8/23 のパンマーカー
  頭打ちは撤回 (代替の制約 =「見える・直せる」)。
- 実装済み (第一段): 量の事前判定で飛ばし + `sluice_skipped_spans` へ記録
  (fail-closed) / 誤分類の文字列一覧と後退方式を機構ごと撤去 / 429 でペルソナ単位の
  小休止 (既定 600 秒) / 読み戻しは「あらすじの圧縮区間だけ丸ごと、生の未編纂は
  後ろから残す量まで」/ 後から通す採取ジョブ (API まで、入口 UI は第二段)。
- **採取ジョブの判断の主体は再設計を経ている** (最初の実装をまはーが「第三の主体の
  でっち上げ」と棄却): **機構モード** (機構の声で候補を拾い、候補テーブル止まり —
  本人の器に書かない。採用は第二段 UI) と **本人モード** (読み返している現在の
  本人。過程は discardable、本線にはダイジェスト一行 = user ロール + `<system>`) の
  二本立て。**過去の本人の再構成**はコア記憶に履歴が付いたら開く将来の扉。
- **手帳に二つの時刻**: `event_date` (できごとの日 — 機械刻印) + `origin` (由来:
  live / readback / mechanism)。提示・ソート・めくり・導出 3 件 (未消化判定・
  最後のできごとの日・内容重複) すべて できごとの日 の軸 — 過去の読み返しが現在の
  手帳を押し流さないため (まはー裁定)。v3 §13.6 改訂済み。
- 隔離検証: `tests/test_sluice_cold_isolation.py` 12 本 — 稟乃さんの形の縮尺再現で
  即応・記録・429 回帰・採取完走を固定 (修正を外すと全量が開く実証つき)。この
  検証が導出 3 件の取りこぼしを発見して即日修正した。
