## 到達してほしい具体案

1. **対象の一覧**: Memopedia の通常ページ・Fragmentとその参照、コア記憶、Chronicle、root等の機構の行が、画面・API・保存表・本人への提示のどこで区別されるかを示す。既存の一括操作の四つの入口 (書き出し・追加入力・置換入力・全削除) と差分通知を追う。同じ表に保存されていることを、同じ操作対象である根拠にしない。
2. **隔離での再現**: 合成の通常ページ・Fragment・コア記憶・Chronicleを同居させ、実APIの操作に相当する入口から現在の結果を確認する。DBの行が残ることに加え、各種の正規の読み取りとheadへの提示まで確認する。従来の層単体の実験をどこまで越えたか明記する。
3. **修正案**: 対象範囲の判定を誰が持ち、四つの入口と通知へどう一貫して適用するかを示す。画面だけ、全削除だけの修正で終えない。一方、コア記憶の汎用移植機能やペルソナの無効化へ拡張しない。
4. **旧ファイルと途中失敗**: 既存のexportにcore行が含まれる場合、何を取り込み何を利用者に告げるかを示す。入力不正・一部処理失敗・識別子衝突で、置換前のデータを消してから失敗する形にならないか確認する。既に壊れた記憶は、復旧可能な根拠と不可能な範囲を分ける。識別子・本人の言葉・失われた内容を推測で補わない。
5. **結果の確認**: 下の観測表を具体的な呼び出し・fixture・判定へ落とす。まだ作られていないテストを利用可能と書かない。UIの文言と実際の対象が一致し、保護の結果 Memopedia の操作自体が使えなくならないことも確認する。

| 利用者の操作 | 正常化後に確かめる結果 |
|---|---|
| Memopedia 全削除 | 対象のページ等だけが消え、コア記憶・Chronicle・それらの読み取りは変わらない。関連する参照の扱いは既存の目的へ照合する |
| 書き出しと再取り込み | 提供すると明示した範囲が往復し、対象外の記憶を不完全な形式で新設しない |
| 既存ページを置き換えて取り込み | 置換対象が説明と一致する。除外した記憶を先行削除しない |
| 不正な入力・途中の失敗 | 成功したように見せず、入力確認前に既存データを失わない。どこまで変わったかが判別できる |
| 操作後の次の提示 | コア記憶・Chronicleが正しく読める。別種の操作をMemopediaの変更として誤通知しない。既存の正当な通知は維持する |
