## 3. 後半（前提レベル設計議論）— ここが主役

§3-1 を入口に「そもそも作業セッションを分身（WORKER）でやるのが適切か」→「生ログを volatile で
捨てる原則自体が正しいか」と掘り進み、まはーの発散（前提の疑い）を大量に受けた。共通根 **3束**に
束なった。**全文は gaps doc。以下は地図。**

### 束A: 単位の世代交代（Pulse → できごと/コマ/日）→ 頂点に新概念「ライフ」
方向確定。階層 **ライフ → エピソード（できごと）→ パルス → ビート**。
- **A1**: **外部監査役**（ペルソナ外・そのできごと分のコンテキストだけ渡し目標整合を判定・低コスト）
  →ハルシネーション/インジェクション検出できごとに**危険マーク**、想起時に定型文付加。マーク無しは
  経験として読める→**作業セッションを WORKER でなく AUTONOMOUS アスペクトに**（§3-1 も同時解決）
- **A2**: できごと単位でメッセージを括り概要表示/生データは要求時に開く。Metabolism 時は進行中＋
  直近1つ＋ユーザー会話以外を畳む。**畳んだできごとを読むスペル＝`memory_read` と統合可**（Memory
  Atlas 合流）。「できごとは1ペルソナで閉じるか2ペルソナ共有か」→前者で進めるが、**会話は既に
  `episodes.py occurrence_id` で複数ペルソナ束ね済**（kind=conversation のみ）
- **A3/A4**: 予算＝コマ数＋ラウンド×係数 は**ライフに吸収**。ライフ＝開始終了時刻＋パルス予算で宣言
  （1日複数可・動的可・user/ペルソナ両方）。**モデル別モード**（Anthropic/OpenAI＝標準パルス均等必須
  ／Gemini＝自由）。均等時 **ライフ＝Session 一致**。ライフ中＝キャッシュ熱い→気軽に話しかけ OK を
  状態明示。**ライフビュー UI がこれを指す**

### 束B: 世界に向く last mile の断線 → 裁定済み
- **B1＋X1 統合UX**: Building でのエピソード発生を検知→チャットに大枠投下（「エアが机に向かって
  いるようです」）→クリックで中のパルス・ビートをリアルタイム→終了で概要（**＝Lv1 Chronicle**、
  エピソード終了次第 即生成・長尺でも一本）。同 Building 他ペルソナには冒頭通知のみ
- **B2**（Item Open 共有）→ **スコープアウト**（別件・別 issue） / **B3**（勝手移動・ペルソナ指定
  ジャンプ）→ **神モードUI 待ち** / **B4**（型→施設の休眠：resolve_facility 未配線＋施設タグ0を実機
  確認）→ **独立・早め着手**（A/B 主線外）

### 束C: Track の意味論の再整理（2026-07-13 浮上、第3の根）
- 問題: Track が「進行状態管理」から「今どの目的で動いているか の指し示し」に変質したのに、実装が
  古い意味論を引きずる。表面化症状＝[redundant_track_switch_notification](../issues/redundant_track_switch_notification_on_reactivation.md)
  （同一 Track 復帰で切替通知が氾濫。**まはー早め対応希望**）
- **C2 で現状の全遷移を洗い出した（実装確認済み）。核心2つ**:
  1. **コマ発火は Track を切り替えない**（`_handle_worker_slot`→`run_work_session` WORKER、activate なし）
  2. **時間で勝手に pending するのは wait_response 30分だけ・user_conversation Track 限定**（自律 Track は
     時間で勝手に pending しない）
- **含意**: redundant issue の芯は wait_response pause 一点。自律側は既にまはーの理想に近い。ギャップは
  逆側で **「時間割の行動を始める → その Track が running」の連動が無い**こと。→ 束A（ライフ）と束C が
  **コマ発火の一点で握手**する（コマ＝エピソード開始＝Track 切替タイミング）
