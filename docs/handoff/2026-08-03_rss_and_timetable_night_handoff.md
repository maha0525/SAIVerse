## 2. RSS フィードの実機検証手順 (メインツリー)

起動前提: `python main.py city_a` (通常起動。migration が feed 3 テーブルを自動作成する)。

1. **起動時取得**: 起動ログに `[feed]` の取得ログが出るか (起動時に一度 + 30 分ごと)。フィード施設が無い初回はスキップされるのが正常
2. **施設を作る**: グローバル設定 → 「フィード」タブ → 施設作成で Building とプリセット (技術ニューススタンド / ニューススタンド / 科学の掲示板) を選択。購読と健康状態が一覧に出ること
3. **手動取得**: 「今すぐ取得」→ 記事ビューアに当日の実在記事が並ぶこと (Zenn/GIGAZINE 等で照合)
4. **ペルソナへの配送**: フィード施設のある Building にペルソナを置き、次の取得サイクル後にそのペルソナへ話しかける → 会話コンテキストのプレビュー or 応答に「[フィード] 『◯◯』の新着記事」の知覚が入っていること (`SAIVERSE_FEED_FETCH_INTERVAL_SEC=60` で加速可)
5. **視覚情報**: ペルソナの visual context (施設の設置物欄) に feed_stand の購読タイトル・最新見出しが出ること
6. **購読追加 UX**: フィードタブでサイトの素の URL (例: `publickey1.jp`) を貼って自動発見が働くこと
7. **透明性**: 記事ビューアの内容とペルソナに届いた記事が一致すること
8. サーバー停止: 停止ログに feed worker の join が出て、例外なく閉じること (stop() の実走 join はテスト未検証の境界)

## 3. 時間割改修の実機検証手順 (worktree ブランチ)

**先に RSS を main 系へ取り込んでから、`feature/timetable-redesign` を rebase して統合する** (§4)。検証はその後:

0. **playbook 再取込 (必須)**: `python scripts/import_playbook.py --file builtin_data/playbooks/public/judgment_day_open.json` (T1 文面改稿+T2 の一文が DB に載る)
1. **カタログ**: 起動後、時間割系 UI のコマ種別が新 7 種 (調べる/絵を描く/日記を書く/随筆を書く/出かける/自室で過ごす/自由時間) になっていること。旧種別 (作る等) の過去データ表示が壊れていないこと
2. **習慣テンプレート**: ペルソナメニュー → 「習慣テンプレート」(ライフ設定の隣) でコマ行を作成・保存。翌朝の day_open で**テンプレの枠どおり**の時間割が組まれ、穴 (「朝に決める」) だけが埋められていること (一日新聞で確認)
3. **途中起動**: 午前のコマがあるテンプレのペルソナでサーバーを昼に起動 → 午前分が「流れた（サーバーが起動していなかったため）」記録になり午後から合流すること
4. **出かける**: 出かけるコマの実行で実際に公共施設へ移動し、軽い一手の独白が SAIMemory に残ること (充填的な長文になっていないか質を見る)
5. **コマ締め (経験値ノート)**: 作業コマ (調べる等) の完了後、`~/.saiverse/personas/<id>/memory.db` の root_theme 配下にテーマページが立ち fragment (経験値ノート) が書かれていること + purpose_tags に帰属タグ (層2)。メモリーモーダル「経験」タブで見えること
6. **経験の台帳**: メモリーモーダル「経験」タブ — 索引の統計バッジ、薄い棚の減光、ページの動的合成 (エア実データで「定義の切り株」が数字で見えるか)
7. **T3 文面レビュー**: 出かける/自室/自由時間の文面と T4 の締めプロンプト全文は、各エージェント報告 (このセッションのログ) と worktree の `saiverse/day_plan.py` / `saiverse/slot_close.py` に実物あり — まはーの目でトーン確認
