## 開いている設計問題 (まはーが 09-04 昼に提起、未裁定)

まはーの問い: 「残す量」は会話の行だけで数え、「整理を始める量」は送る合計 (会話 + 知覚ブロック) で数える。だから知覚が多いと、両方を満たせる状態が存在しない。どう対応するか。あわせて、会話だけで数えるなら既定の残す量 100,000 は多すぎるので既定値の見直しも。

詳細と私の案は `docs/issues/watermarks_unsatisfiable_when_perception_is_large.md` に置いた。要点だけ:

- 事実 1: いまの v0.3.7 は、この状況になると整理を何もしない。会話は残す量のぶん守られるが、送る合計は整理を始める量を超えたままになる (警告 1 回 + context-status に `perception_over_budget`)。
- 事実 2: 知覚ブロックは、会話を畳んでも一緒には消えない。消えるのは、その期間のあらすじが作られたとき。だから会話を残す量まで畳んだ後に残る知覚は、守っている直近の会話の期間に乗っているぶんで、会話を守るかぎり下ろせない。
- 私の案: 知覚の合計に上限を置き、超えたら古い知覚から提示に乗せない (台帳には残る)。水位の保存時に「整理を始める量 − 残す量 > 知覚の上限」を検査する。
- 既定値の叩き台: 最初に読み込む文字数 20,000 / 残す量 40,000 / 整理を始める量 120,000 (いまは 40,000 / 100,000 / 200,000。場所は `saiverse/model_configs.py` の `BUILTIN_METABOLISM_*_CHARS`)。数字はまはーの製品判断。
- 順番の提案: PR #280 はいまの形でマージし、上の規則と既定値は 0.3.8 でその上に載せる。
