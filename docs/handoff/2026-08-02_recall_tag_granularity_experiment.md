# 想起用タグの粒度実験 — メッセージ単位 vs あらすじ単位 (2026-08-02)

**目的**: 想起用タグを「メッセージ単位」で貼れるか、それとも「あらすじ(チャンク)単位」で足りるかを、机上論でなく実データ+本番同一条件で確かめる。まはーの事前予測は「メッセージ単位の処理は生のメッセージの記載内容に意識が吸われ、文脈の関係(これはスタックチャンのことだ)が載ってこないのでは」。

**帰結 (まはー裁定)**: **貼る単位はあらすじ(チャンク)、指し先は実体ページ ID、実装は entity_extractor 相乗り (B2 形式・同一コール)**。メッセージ単位の意味タグは二層目(よぎり)の将来再訪へ降格。

関連 intent: [`recall_tags_and_track_reduction.md`](../intent/persona_cognition/recall_tags_and_track_reduction.md) (§9 に本実験の帰結を反映)

---

## 1. 実験条件 (本番忠実性)

まはーの条件「普段の Chronicle バッチ処理で見てる情報を踏襲」に従い、**本番の関数をそのまま import して使用**:

- 会話整形 = `sai_memory.memory.entity_extractor._format_messages`
- 周辺文脈 = `sai_memory.arasuji.context.get_episode_context_for_timerange` (max_entries=10)
- 既存ページ一覧 = `entity_extractor._format_page_list`
- ベースプロンプト = `entity_extractor._build_extraction_prompt` (無改変)
- モデル = `gemini-3.5-flash-lite-paid` — エアの本番 Chronicle バッチが実際に解決するモデル (persona の MEMORY_WEAVE_MODEL 未設定 → env `MEMORY_WEAVE_MODEL`)。クライアント構築も本番の `build_memory_weave_client`
- データ = エア (air_city_a) の memory.db の**複製** (scratchpad 上、本番 DB には一切接続しない)。まはーの事前承認済み (複製データの LLM 送信・少額費用)

**対象チャンク**: Chronicle L1 エントリ `a9bb17b5` (2026-05-25、source 20 メッセージ)。スタックチャンのための身体性リサーチ (web_research Playbook 実行) のセッション。**表面に「スタックチャン」の語を含むのは 20 件中 5 件のみ** — 文脈関係のタグ付けが最も問われる混成材料。

## 2. 比較した 4 方式と結果

| 方式 | 出力単位 | 語彙 | 結果 |
|---|---|---|---|
| A | メッセージ | 自由 | **全滅**。リサーチ群 17 件に「web_research」を連打しスタックチャンのタグはゼロ。表面に語がある行 (#1, #3) すら拾わず。「ｽﾀｯｸﾁｬﾝ」(半角) の表記化けも発生 |
| A2 | メッセージ | 閉 (既存ページ一覧に限定) | **部分改善**。表面なし 15 件中 1 件 (#4) だけ文脈で捕捉、大半は素通り。表記は周辺文脈テキスト (Chronicle 記述が半角表記) に引きずられ半角のまま — 閉語彙の指示だけでは表記が固定できない |
| B | チャンク | 本番プロンプトそのまま | 新規用語 (DOVE / SuperTac / Proprio-MLLM) のみ抽出。スタックチャンには触れない — **本番の抽出は「新たに判明した知識」が仕事であり、「関与の記録」は仕事の範囲外**。既知エンティティへの関与はどこにも残らない |
| B2 | チャンク | 本番プロンプト + involved_entities 一項目 | **完捕**。スタックチャン (ページ一覧の正確な全角表記)・まはー・エア・SAIVerse・DOVEモデル・web_research・エアの存在哲学ページを列挙。出力 407 文字 |

## 3. 判定

1. **まはーの予測どおり、メッセージ単位の LLM タグ付けは表面に崩壊する** (視野にチャンク全文と「表面に無くても文脈で判定せよ」の明示指示があっても)。現行軽量モデルでは信頼性が出ない。
2. **チャンク単位の関与列挙 (B2) は安定して文脈関与を捕捉する**。一層目 (経験の台帳 = 対象について何をやってきたか) の材料はこれで足りる。
3. **同一コール相乗りが成立**: B2 は本番抽出プロンプトへの出力一項目追加のみ。入力は不変・追加コストは出力数百文字。
4. **タグは名前でなくページ ID で結ぶ**: 表記ゆれが 2 方式で実演された (自由語彙の半角化 / 閉語彙でも文脈テキストの表記に引きずられ)。生成後にタイトル照合で page_id へ解決する層を挟む。
5. 決定論の文脈刻印 (このメッセージはどのコマ・どの場所・どの記事の最中か = origin_track_id の一般化) は本実験の失敗と無関係 — LLM を使わないため、メッセージ単位のまま別枠で成立する。

## 4. 限界

チャンク 1 個・モデル 1 種 (ただし本番実機と同一)・各 1 回の試行。統計でなく失敗/成功の**型**の確認。ただし A の失敗も B2 の成功も事前に予測したメカニズム (表面への崩壊 / チャンク視野での関与判定) の通りに発現した。実装時の受け入れ検証は intent 側の検証ジャーニーで行う。
