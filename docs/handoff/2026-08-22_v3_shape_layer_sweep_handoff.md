## 2. 裁定を求める 5 件 (この文書の本体)

すべて `docs/issues/` にあり、選択肢と判断材料を本文に書いてある。ここには**争点の一文と私の見立て**だけを置く。

### (1) [手帳まわりの `commit` 引数がトランザクション所有を検査しない](../issues/archive/pocketbook_commit_flag_is_not_ownership_check.md)

**争点**: 罠は開いているが、現に踏んでいる経路は無い。閉じるか、放置か。

**⚠ 先に読むべき点**: レビューが提案した一行修正 (`if commit:` → `if commit and not conn.in_transaction:`) を**そのまま当てると直す前より悪くなる**。`commit` は commit と rollback の三箇所で所有の旗として使われており、commit 側だけ条件を足すと**失敗時に呼び出し元のトランザクションを巻き戻す**経路が残る。

**私の見立て**: 選択肢 D (所有の判定をヘルパか context manager に切り出す) が根に近い。`pocketbook.py` だけで同じ形が 10 箇所以上あり、判定を書き写していること自体が非対称の供給源になっている。ただし既定が `commit=True` である限り誤用は書けてしまうので、C (誤用を例外で落とす) と既定の反転をセットで検討する価値がある。**急ぎではない** — 現在の呼び出しは全て正しく `commit=False` を渡している。

### (2) [スルースが場面の記憶を先頭だけ見せて丸ごと書き換えさせていた](../issues/archive/sluice_truncated_scene_update.md)

**争点**: 壊れる経路は塞いだ (切り詰めて見せた項目への update を拒否)。残るのは「**本人に全文を見せるべきか**」の設計。

**私の見立て**: 判断材料が実データで取れる。**`scene` 種のコア記憶が実際に何本あり、どれくらいの長さか**を読み取り専用で数えれば、選択肢 A (全文を見せる) の可否が決まる。分量の問題が現実に無いなら A が素直で、切り詰めという概念自体が消える。数えずに B (見せるが書き換えさせない) を仕様に固定すると、本人が自分の記憶を直せない状態が残る。

### (3) [スルースの手帳メモだけ内容ベースの重複防止を持たない](../issues/archive/sluice_memo_duplicate_across_spans.md)

**争点**: コア記憶には「同一本文ならスキップ」があるのに、手帳のメモには無い。同じガードは持ち込めない。

**私の見立て**: コア記憶と手帳では「重複」の意味が違う。コア記憶は事実の記述なので同一本文＝重複だが、**手帳は日々の記録で「今日も小説を書いた」が二日続くのは事実**。選択肢 B (同じ日・同じアクティビティ・同じ本文だけ弾く) が意味論に合う。加えて C (既存の手帳メモをプロンプトに載せる) を入れると、プロンプトの「既にあるものは再度採らない」という指示が**初めて実行可能になる** — 現状は本人が確認する手段を持たないまま指示だけされている。B と C は排他ではない。

### (4) [504 継続が空応答のとき、二重保存された部分文に別コールの数字が乗る](../issues/archive/stamp_empty_continuation_double_save.md)

**争点**: 直す場所が二つあり、選ぶ場所で意味が変わる。

**私の見立て**: 症状を消すだけなら B (返す直前に三つ組を落とす) で束 5 の中に収まる。ただし**根は C (二重保存そのもの)** で、これは束 5 以前からある挙動。刻印の導入で初めて「数字の帰属」として見えるようになっただけ。C/D は生ログの保存設計に触るので v0.4 送りが妥当だと思うが、**B を入れるかどうかは今決められる**。頻度は低い (504 が起きて、かつ継続が空のときだけ)。

### (5) [会話ロックを持ったまま DB へ書き、単一の発火スレッドが止まる](../issues/archive/conversation_lock_held_across_db_write.md)

**争点**: 素朴に「書き込みをロックの外へ出す」と別の並びが開く。

**私の見立て**: 実害の観測が先。選択肢の前に「**沈黙タイマーの発火が集中する時間帯に、他ペルソナの予約がずれているか**」を実機で見れば、A (何もしない) の根拠が取れる。ずれが観測できないなら急がない。観測できたら B (書き込みを予約してロックの外で実行) だが、失敗時の扱いを決め直す必要がある。

## 3. 次の一手 (実装ではなく判断が要るもの)

### 3-1. Codex による掃討をかけるか

**私の見立て: 同じ観点で投げても実りが薄い。** ローカルで一巡した観点 (並行安全性・冪等・帰属・移行の耐性) は消化済みで、重複が多くなる。投げるなら**ローカルが構造的に見られなかった観点**を指定したい。

ローカルレビューの制約 (実測):
- **`Grep` と `Glob` が無い** (`--bare` モードに存在しない)。だから「リポジトリ全体でこの型の欠陥が他にもないか」は原理的に見られない
- 材料に入れたものしか見ない。**呼び出し元を辿る調査ができない**
- 一便あたり材料 1000〜2700 行が上限の目安 (出力上限の都合)

つまり Codex に投げる価値があるのは「**横断的な走査**」で、束ごとの縦の掘り下げではない。具体的には、今日見つけた 4 件の非対称と同じ型が形の層の他の場所に残っていないか、といった観点。

### 3-2. まはーの実機検証 (前便から未着手)

手順は[前便](2026-08-22_v3_shape_layer_complete_handoff.md)の「実機検証チェックリスト」がそのまま生きている。**起動前に `python scripts/import_all_playbooks.py` が必須**。

今日の修正で**見え方が変わる点**が二つある。

- **会話**: 沈黙の終わり際に話しかけたとき、応答中に「会話が終わりました」が出ないこと (今日の修正が効いていれば出ない)
- **起動時 migration**: `[v3機械写し]` のログに**まとめの行**が出るようになった (「対象 N 件中 M 件を写しました / 期限を読めず飛ばした X 件 / 書き込みに失敗して飛ばした Y 件」)。まはーの DB では対象 0 件なので、0 件のまとめが出るはず

## 4. 引き継ぐ知見 (次に同じ作業をする人へ)

### 4-1. 今日の欠陥の 4 件が同じ形だった

| 手当てを入れた側 | 隣で忘れられた側 |
|---|---|
| 会話の開始経路が応答の前にタイマーを張る | 継続経路は応答の後にしか張らない |
| 兄弟 2 関数がトランザクション所有を検査 | 同じモジュールの他の関数は検査しない |
| 取り置きの検査を INSERT と同じ tx へ入れた | 指し先のページがまだ在るかは検査しない |
| 帰属不明なのでトークン三つ組を落とす | 同じ理由の前駆刻印は落とさない |

**4 件すべて、コメントや docstring に判断の理由が明記されていた。** 考えていないから漏れたのではなく、考えた結果を隣まで運ばなかった。しかも束 5 では**既存テストがその非対称を「正しい振る舞い」として名前ごと固定**しており、欠陥がテストを素通りしていた。

横断的な走査をかけるなら、この型が最も歩留まりが良いと思う。

### 4-2. ローカルレビューの上限は三枚あり、別々に効く

| 壁 | 症状 | 対処 (適用済み) |
|---|---|---|
| argv の長さ (約 32KB) | 起動前に OS が弾く。事後診断は「窓超過」と表示するので timeout に見える | プロンプトを一時ファイル経由の標準入力へ |
| 入力窓 (`--ctx-size`) | `400 request (N tokens) exceeds...` | 24GB では **98304 が安全上限** (KV = 1 トークン約 49.3KB、固定分約 1223MB の実測から) |
| 出力トークン (既定 32000) | `response exceeded the ... output token maximum`。**思考も数える** | `CLAUDE_CODE_MAX_OUTPUT_TOKENS=49152` をラッパーで明示 |

**窓を広げても出力上限は動かない。** 同じ束で二度落とした。

**思考が長いときは推論設定より先に自分の指示を疑う。** 「一度に 150 行以内で読め」という窓が狭かった頃の節約指示が残っていて、材料に全文があるのにモデルへ Read を選ばせていた。指示を直したら Read 12 回以上が 0 回、15 ターンが 2 ターンになった。

### 4-3. 材料の渡し方

- **関係するファイルは全文で渡す。** 切ると足りない範囲をモデルが自分で読みに行き、節約したつもりより多く食う
- 束ごとに分け、観点を 4 つに絞る。1 束あたり 6〜17 分
- 「確かめられないことは推測で埋めず、**何を足せば結論が出るか**も書く」と指示すると、次の便で材料を足せる。束 3 はこれで前半の未解決 3 問が全部決着した
