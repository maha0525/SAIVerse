## ① 応答者ゼロ — 無言が消えたか (束 2 の本丸)

**やること**: 誰もいない建物へ移動して、何か話しかける。

**見るもの**:

- 発言の吹き出しは普通に出る
- そのあと 🚪 **「この場所には、応答できる相手がいません。」** が出る
- 説明文に「あなたの発言は記録に残っています。ただし、この場所には応答できる相手が
  いないので、やり直しても結果は変わりません。別の場所へ移るか、誰かが来るのを
  待ってください。」が続く
- 自分の発言の吹き出しに出るボタンは **「取り消す」だけ。「再送」は出ない**

**これが出なければ束 2 が効いていない。** 以前はここで何も出ずスピナーだけ消えていた。

**ログ**: `backend.log` に
`the utterance was accepted but nothing reached the user (building=..., responding_personas=0)`
が 1 行。

**8/26 に変えたところ**: 修正前はここで「発言は受け取りましたが、返事が生まれません
でした。」+「発言の『再送』から応答をもう一度求められます」が出ていた。誰もいない部屋で
再送しても結果は永久に変わらないので、**果たせない約束**をやめて別の文言に分けた。
「発言は受け取りましたが、返事が生まれませんでした。」の方は、**応答できる相手はいるのに
返事が生まれなかった**回のために残っている (この手順では狙って起こせない)。

## ② 再送ボタン — 出ないことの確認 (束 3)

**やること**: ① の自分の発言の吹き出しを、押さずに見る。

**見るもの**:

- **「再送」ボタンが無いこと** ← 8/26 に変えたところ
- 「取り消す」は出ていること

押しても結果の変わらない操作を勧めない、という形にした。**「再送が発言を二度載せないか」の
確認は ⑤ の後ろへ移した** — 誰もいない部屋では再送ボタン自体が出なくなったので、ここでは
踏めなくなったため。

---

## ③ 取り消す — 誰も読んでいない発言を手元へ返す (束 4)

**やること**: ① の自分の発言の **「取り消す」** を押す。

**見るもの**:

- 吹き出しが消え、**入力欄にその文が戻ってくる**
- 入力欄に書きかけがあれば、改行して継ぎ足される
- **押した瞬間に、①で出ていた案内も一緒に消える** ← 8/26 に足したところ

案内は履歴ではなく「いまの状態の表示」なので、**何か操作したら消える** (2026-08-26 まはー
裁定)。消える引き金は送信・再送・続きの生成・取り消しの四つで、**時間では消さない**
(読んでいない可能性があるため)。修正前は誰も消さなかったので、発言を取り消しても案内だけが
残り、その上に次の案内が積み上がっていた。

**次に、読まれた発言でも試す**: ペルソナのいる部屋で普通に会話してから、返事をもらった
自分の発言の「取り消す」を押す — と言いたいところだが、**返事が来た発言にはボタンが出ない**
(出るのは返事が来なかった発言だけ)。読まれた側の断り文句を見たい場合は言ってほしい、
出し方を用意する。

---

## ④ 続きの生成 — ここからペルソナが喋る

**やること**: ペルソナのいる部屋で話しかけ、**返事の生成中に「停止」ボタンを押す**。

**見るもの**:

- 途中まで出た発言がそのまま残る (消えない)
- **その発言が二つに増えていないこと** ← 🆕 8/26 の夜に直したところ。**ここが今日いちばん
  見てほしい**
- その吹き出しに **「続きの生成」** ボタンが出る ← 印 (`_interrupted`) が効いている証拠
- 押すと、**続きが新しい吹き出しとして生まれる**
- 続きが生まれたら「続きの生成」ボタンは消える

**なぜ二つに増えうるか**: 停止すると、途中まで出た文で下書き行を確定させて、その ID を
「無い」にしていた。ところが下流はその「無い」を**「下書き行を作れなかった」**と読んで、
履歴を失わないようにもう一度書き込む。片付け済みの回にもその救済が誤発火して、同じ本文が
二度入っていた。

**この経路には自動テストを付けられていない** (巨大な関数の内側にあって、LLM のストリーム
ごと偽物に差し替えないと到達できない)。**④ が唯一の確認手段。**

**2 つの吹き出しで並ぶのは仕様** (2026-08-26 まはー裁定 — 一つに繋げる案は採らない)。
中断があった事実が見た目にも残る形。**見て違和感があれば言ってほしい**、というのが
裁定と同時の申し送り。

## ⑤ 通信断 — 分からないと正直に言うか (出口 7)

**やること**: 話しかけた直後に、**バックエンドを止める** (ターミナルで Ctrl+C)。
あるいはブラウザの開発者ツールで Network を Offline にしてから送る。

**見るもの**:

- 発言が届いたことをサーバーから聞けていた場合 → 🔌「接続が途中で切れました。ここまでの
  内容は残っています。」+ **再送ボタン**
- 聞けていなかった場合 → **「発言が届いたかどうかは、この画面からは判断できません。
  同じ内容を送り直す前に、履歴に残っているかを確認してください。」**

後者が出れば出口 7 が効いている。**送り直しを勧めていない**のが要点で、勧めると二重発話に
なりうるため。

### ⑤-b 再送が発言を二度載せないか (② から移した確認)

**前者 (再送ボタンが出た) の場合だけ踏める。** バックエンドを起動し直してから、その発言の
**「再送」** を押す。

**見るもの**:

- **自分の発言が二つに増えないこと** ← ここが一番見てほしい。押しても送り直しではなく、
  応答だけを起こす形になっている
- 応答できる相手がいる部屋なら、返事が生まれる

再送ボタンが出ずに後者の文言だった場合は、この確認は踏めない。そのときは言ってほしい、
別の起こし方を用意する。

## ⑥ 見た目 — ライトとダークの両方

**やること**: ①〜④ で出たボタンを、**ライトモードとダークモードの両方**で見る。

**見るもの**: ボタンの枠と背景が地に沈んでいないか、ラベル (「続きの生成」「再送」「取り消す」)
が読めるか。この 3 つは通常の操作ボタンと違って**常時表示**にしてある — 気づいてもらえないと
機能が無いのと同じなので、そこも含めて見てほしい。

## 見つかったら教えてほしいこと

- ①で何も出ない → 束 2 が効いていない
- ①で「再送」ボタンが出てしまう → 果たせない約束の消し込みが効いていない
- ③で案内が消えない → 案内の寿命が効いていない
- ⑤-b で自分の発言が増える → 再送が送り直しになっている (一番まずい)
- **④で停止した発言が二つに増える → 8/26 夜の修正が効いていない**
- ④で「続きの生成」が出ない → 印が画面まで来ていない
- ④で 2 つの吹き出しが読みづらい → 表示統合の再相談。見た目の違和感として言ってほしい
