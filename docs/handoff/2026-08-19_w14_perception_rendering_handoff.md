# W14 知覚レンダリング 走行メモ (2026-08-19)

**状態**: 実装済み・実機検証待ち。正典 = [perception_buffer.md](../intent/perception_buffer.md) §10 (設計裁定 2026-08-18: 台帳正準・畳み判断は会話の退場に相乗り)。

## 何が変わったか (一言で)

システム通知・知覚は会話ログに event_message 行として書かれなくなった。消費 (Beat 頭の flush) は「消費バッチ」(一意 id + ペルソナが見た確定文面) を知覚台帳に記帳し、提示はコンテキスト組み立てが未付記バッチを時刻順マージする。Chronicle 編纂が期間の知覚を digest へ決定論転写して付記印を打ち、印が付いたバッチだけが提示から下りる。退場後もキーワード検索 (Memory タブ) で全文へ到達できる。

## レビューの経緯

Codex 敵対レビュー 8 巡で 30 件 (high 16 / medium 14) を消し込み。主要な設計改訂:

- 一巡: 消費のまとまりを秒精度時刻から再構成していた設計を撤回し、**消費バッチ** (確定レンダリング済みテキストの永続化 + 付記印) へ再設計。
- 三〜六巡: Chronicle 保護のもぐら叩き (入口検査の積み増し) を経て、**保護を境界 (memopedia storage の再帰削除本体) へ降ろして族が閉じた**。既存欠陥 2 件 (一括操作の chronicle 巻き込み・検索の chronicle 同居) もここで根治。
- 七巡: 旧二段 flush の中断状態の一度きり移行 (アップグレード時の二重提示防止)。
- 八巡: 配送冪等の DB 側強制 (UNIQUE)・Recall の決定性・移行走査の窓限定。

回帰 = tests/test_perception_rendering.py + test_perception_buffer.py の 89 件。フルスイート 4571 緑・ruff 全域通過。

## 実機検証の手順 (まはー向け)

1. **アップグレード移行**: バックエンド起動だけで走る (consumed_at 列の ALTER 時に一度きり)。起動ログに reconcile のエラーが出ないこと。
2. **知覚が届く**: 入退室 or コア記憶編集 → 対象ペルソナに話しかける → 応答のプロンプト (送信前プレビュー) に [システム通知] ブロックが載り、**メモリタブの生ログには新しい通知行が増えない**こと。
3. **プレビュー**: ContextPreviewModal の「知覚バッファ (未消費)」節が従来どおり出ること。
4. **フィード**: 出かけるコマでフィード施設到着 → 到着 Pulse で記事が読めること (2026-08-08 検証の再確認)。
5. **退場の畳み**: Metabolism 発火後、畳まれた期間の digest 末尾に「この期間に届いた通知・知覚の記録」の転写が付き、提示から同期間の通知ブロックが消えること。
6. **検索到達**: Memory タブの検索で「知覚」ソースを ON にし、畳まれた後の通知本文がヒットすること。
7. **Chronicle 操作**: Chronicle タブであらすじを 1 件削除 → 該当期間の通知が提示に再登場すること (次の編纂で再び畳まれる)。

## 受容済み残欠 (いずれも「消える方向には倒れない」設計)

1. legacy event_message 行はチャンク skip 等で転写機会を失うと従来どおり digest に入らず退場する (行は DB に残る)。
2. 編纂が付記印を打ってから退場適用までの短い間、バッチは提示から先に下りる (節目量子化の一部)。
3. Metabolism の水位勘定はマージブロックの文字数を数えない (発火が僅かに遅れる安全側)。
4. perception の saiverse:// URI は未登録 (検索ヒットの再訪導線は source_id のみ。kind 新設は別件)。
5. 再生成の失敗パスに ms 級の一時二重 (旧 entry 転写残 + 提示復帰) — 既存の swap 競合受容と同族。
6. ペルソナ向け recall (memory_recall_unified / auto_recall) の perception ソースは OFF (表示分岐の実装とセットで後続)。
7. chronicle ページの生成済み memopedia_embeddings 行は corpus 除外で無害化 (行の掃除は任意)。
8. recall 併合の件数調整は固定点方式で解決済みだが、振動時は 10 巡で打ち切り (実害なし)。
9. push_ledger_perception の UNIQUE 冪等は新規行から効く (移行前の旧行は前関所の順序保証の既存前提のまま)。
