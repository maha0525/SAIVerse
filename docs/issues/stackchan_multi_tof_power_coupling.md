# 複数 ToF (VL53L1X) を PaHub で使うと、片方の至近検出でもう片方が巻き込まれる (電源結合・ハード起因)

**状態**: ✅ 原因特定済み（**ハードウェア起因・SAIVerse ソフトの問題ではない**）。対策はハード側。
**記録日**: 2026-07-04
**キーワード**: VL53L1X, ToF, 距離センサー, PaHub, PaHUB2, TCA9548A, I2C MUX, 同一アドレス,
0x29, 複数センサー, 両方0, both zero, クロストーク, 電源結合, ground bounce, VCSEL continuity,
有効SPAD 崩壊, 崖検知
**関連**: `docs/intent/stackchan_unit_placement.md`（複数同アドレスユニットの配置設計）

## 一行サマリ

Stack-chan の Port A に PaHub (TCA9548A 系 I2C MUX) を挟んで **VL53L1X ToF を 2 個** 別 channel
に挿した構成で、**片方のセンサーを至近で覆う（or 至近に物が来る）と、もう片方のセンサーも
0mm / エラー (VCSEL continuity) を返す**。SAIVerse の channel 分離・測定直列化は正しく動いて
おり（遠距離では 2 個が別々の値を返す）、これは **2 センサーが共有する電源/GND を介した
電気的結合**（ハード）。ソフトでは解消できない。

## 症状

- 2 個の VL53L1X (どちらも I2C addr `0x29`) を PaHub の別 channel (例: ch3 / ch4) に接続。
- 遠くの物体は 2 個が独立した値を返す（分離できている）。
- ところが **片方に指を近づけて至近になる特定のタイミングで、両方が同時に 0mm もしくは
  status=1 (ハードウェアエラー / VCSEL continuity) になる**。
- 視野の重複では説明できない（徐々にではなく閾値で両方同時、かつ下記 D の通り光路を塞いでも
  電気的に繋がっていれば起きる）。

## 切り分け（実機コントロール実験 — ここが本質）

`get_tof_distance(target=..., detail=true)` で診断値（信号強度 / 環境光 / sigma / 有効SPAD）を
取りながら、変数を 1 つずつ変えて総当たりした結果:

| 条件 | 右センサーの結果 | 有効SPAD | 判定 |
|---|---|---|---|
| 両方接続・指なし | 74cm 正常 | ~194 | 基準 |
| 両方接続・**左に指** | **エラー(VCSEL continuity)** | ~194 | 巻き込まれる |
| **左ケーブル抜き**・指なし・右のみ | 74cm 正常 | ~199 | — |
| **左ケーブル抜き**・**左に指**・右のみ | **73.8cm 正常** | ~199 | 指単体では無害 |
| 左接続・指なし・右のみ | 50cm 正常 | ~193 | — |
| 左接続・**左に指**・右のみ | **6.7cm (最小レンジclip)** | **0.2** | 巻き込まれる |

決定的な 2 点:

1. **左ケーブルを抜くと、指を同じ位置に置いても右は完全に正常**（73.8cm）。
   → 結合は「左センサーが電気的に接続されていること」を必須とする。指（光学）単体では起きない。
2. **左接続＋左に指のとき、右の「有効SPAD」が ~193 → 0.2 に崩壊**し、最小レンジ clip (6.7cm)。
   → VL53L1X の DSS は入射信号が強すぎると SPAD を減らす。0.2 まで落ちるのは「桁違いに強い
   信号が来ている」判定。右の前には何も無いのに、右のフロントエンドが**実在しない超至近
   ターゲットを掴まされている** = 電気的に信号が注入されている。

さらに:
- 2 センサーの間に**不透明な仕切り（光路遮断）を入れても再現**した。
- そもそも**指で左を覆っている**ので、左から出た光が右へ回り込む光路自体が塞がっている。
  → 光学クロストークでは説明できない。**電気結合で確定**。
- 環境光は全条件 ~0 Mcps なので外光は無関係。

## 原因

PaHub (TCA9548A) が channel ごとに切り替える (isolate する) のは **SDA/SCL だけ**。**VCC と GND は
全 channel 共通**。片方のセンサーの SPAD が至近の物体で強烈に照らされると、そこで生じる大きな
過渡電流が共有電源/GND を通じてもう片方のセンサーのアナログフロントエンドを叩き、偽の至近
信号を注入する。= 電源/グラウンドのインテグリティ問題。

## SAIVerse ソフト側（正しく動作している・変更不要）

- per-channel select (`pahub.select_channel`) で対象 channel だけをバスに出す → 同一アドレス衝突は解消。
- vessel ごとの `pahub.get_hub_lock` で「select + 測定」を直列化 → 並列読みの channel 競合も解消。
- 実際、遠距離では 2 個が独立した値を返す（例: 236mm vs 518mm）。
- 詳細な結合原因の特定には `get_tof_distance(detail=true)` の診断値（特に**有効SPAD の崩壊**）が有効。

## 対策（ハードウェア・安い順）

1. **各センサー直近にデカップリングコンデンサ**（0.1µF + バルク 1〜10µF を VCC-GND 間、
   センサーのできるだけ近くに）。過渡電流を地元で吸わせる。まずこれ。
2. 効き足りなければ **給電を分離**：両センサーを PaHub のレール daisy-chain でなく、別々に
   太い線で（or 電源のしっかりしたハブ / 外部給電）。
3. さらに **GND を star 配線 / 太く**して共有インピーダンスを下げる。

デカップリングで過渡が吸われれば、片方が至近を検出しても有効SPAD 崩壊（193→0.2）が止まり、
もう片方は独立して測れるようになる想定。崖検知など複数 ToF を同時運用する用途では、実運用前に
ここを潰しておくこと。
