# LLM エラーで応答が死んだとき、ユーザー発言に「再送」ボタンが出ない

**発見**: 2026-08-31 (llama-server busy 判定の実機検証中。生成中のサーバーを手動停止 → チャットに「LLMでエラーが発生しました」カードが出たが、直前のユーザー発言に再送導線が出なかった — まはーの観察「これ系の中断で再送ボタン出ないのおかしい。抜け漏れかも」)
**状態**: 🔲 未解決 — 未調査 (観察の記録のみ)
**深刻度**: P3 — 回避は同じ内容をもう一度手で送るだけ。ただし「返事が来なかったら再送を出す」という導線の約束が破れている

## 事象

生成の途中で LLM 側が死ぬ (今回はサーバープロセスの停止) と、アシスタント側に「LLMでエラーが発生しました」のエラーカードが立つ。このときユーザーの発言には `needsRetry` (再送ボタン) が立たない。

## 当たりをつけた場所 (未検証)

`frontend/src/app/page.tsx` に再送の機構は実装済み:

- `needsRetry` = 「この発言に返事が来なかった」印。立っている間だけ再送ボタンが出る。
- 印を立てる `markRetryable` は列挙された出口 (「出口 3 / 7」のコメント) から呼ばれる。
- サーバー側の門番 `already_replied` は「この発言には既に応答がある」と判定すると再送を拒否する。

仮説は二つ (どちらか、または両方):

1. LLM エラーの経路が `markRetryable` の出口に入っていない (抜け漏れ)。
2. エラーカード自体が「応答があった」と数えられ、`already_replied` に化ける — エラー応答は返事に数えるべきでない、という設計判断が必要。

## 再現

llama.cpp 自動起動のモデルで会話 → 生成中に llama-server プロセスを手動停止 → エラーカードが立つ → ユーザー発言に再送ボタンが無いことを確認 (2026-08-31 実機)。
