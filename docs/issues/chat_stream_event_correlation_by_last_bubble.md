# チャット画面のストリーム表示は、イベントを「最後の生成中の吹き出し」で対応付けている

**ステータス: 未解決 (2026-09-21 に敵対レビューが指摘、既知の限界として記録)**

## 何が問題か

チャット画面は、本文の断片・思考・想起の折りたたみ・フォールバックの注記などの
イベントを、原則「一番最後にある生成中の吹き出し」へ流し込む。持ち主
(persona_id / pulse_id) の突き合わせは、取り消し (streaming_discard) と一部の
貼り付け (想起・注記 — 2026-09-21 に追加) にしかない。**同じ部屋で二人のペルソナが
本当に同時にストリーミングしたら、本文そのものが混ざる** — 注記や想起の貼り違いは
その氷山の一角にすぎない。

いまの世界では実害が出ない: v0.3 は自律の駆動が止まっており、ユーザー起点のターンと
グループの返答は部屋の中で逐次に流れる。つまり「同時に二つの生成中の吹き出し」は
現行の運転では発生しない前提で、画面はその前提に立っている。

## 直すなら

イベントとメッセージの対応付けを persona_id / pulse_id キーで持つ作り直し
(全マージ経路 — streaming_thinking / chunk / complete / discard / 想起 / 注記 — で
持ち主を照合し、不一致は破棄)。v0.4 で自律の駆動が入って同室並行が現実になる前に
やるのが正しいタイミング。

## 経緯

- 2026-09-21: 反射判断のフォールバック注記の敵対レビューで、貼り違い → 空の受け皿の
  誤結合 → 全経路の照合不足、と指摘が土台へ掘り下がった。注記と想起の貼り付けには
  持ち主の照合を入れ、食い違うときは表示を諦める形にしたが、土台 (本文の流し込みが
  持ち主を見ない) はこの束の範囲外として本 issue に切り出した。
