# 期限付きのシステムタスクは、済にする経路が来るまで空きティックを塞ぎ続ける

**ステータス**: 未解決 (潜在 — 今の書き手は期限付きのシステムタスクを作らない)
**起票**: 2026-10-12 (v0.4 段 3 の敵対レビュー 3 巡目の消し込みで確定した裁定の縁)

## 現物

段 3 の裁定 (2026-10-12): **期限の無いシステムタスクは、割り当てられたティックが
走りきったら機械が「済」にする。締め切りのある件は済にしない** (v3 §5「未完なら
台帳に残り続け、次の空きティックが自然に同じ件を引く」)。

この組み合わせで、「期限付きのシステムタスク」だけが宙に浮く — 機械は閉じず、
ペルソナが自分でタスクを閉じるスペルはまだ無い (段 4 の範囲) ので、期限が
過ぎた後も毎回の空きティックに割り当てられ続け、自由時間が塞がる。

## なぜ今は実害が無いか

システムタスクの書き手は 2 つ (自己定義の聞き取り `_offer_self_definition_task` /
判断の `judgment_finalize._add_event_task`) で、どちらも期限を付けない。

## 直すとき

段 4 (やることの実行と画面の仕上げ) で、ペルソナが自分でタスクを完了・取り下げる
経路を作るときに一緒に答えを出す。候補: 期限付きのシステムタスクも「期限が過ぎて
から一度割り当てたら機械が閉じる」/ そもそも期限付きのシステムタスクを書き手の
検証で禁止する。
