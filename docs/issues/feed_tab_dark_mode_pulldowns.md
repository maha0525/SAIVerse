# フィードタブが丸ごとダークモード非対応 (プルダウンは操作不能級)

**ステータス: 実装済み・検証待ち** (2026-08-08 起票。2026-09-02 に根因を特定して修正。実アプリでの確認が残る)

## 症状

グローバル設定 → フィードタブの**タブ全体**がダークモード未対応 (2026-08-08 スクリーンショットで確認):

- 「施設を追加」の各種プルダウン: 候補が何も見えず**選択操作そのものができない** (操作不能級。ダークモード利用者はライトモードへ切り替えないと施設を作れない)
- 購読カード: 白背景のまま文字色だけテーマに追従し、フィード名がほぼ白飛びで読めない
- 記事ビューアのパネル: 白地のままでテーマに馴染んでいない (読めはする)

後回し棚の中では優先度高め。

## 原因 (2026-09-02 特定)

**`--bg-primary` という、どこにも定義されていない CSS 変数を使っていた。**

`FeedManagementPanel.module.css` の 5 箇所が `background: var(--bg-primary, #ffffff)`
と書いていたが、`app/globals.css` が定義しているのは `--background` / `--bg-secondary`
/ `--bg-tertiary` / `--bg-hover` で、`--bg-primary` は存在しない。**存在しない変数は
フォールバック値に固定される**ので、テーマを切り替えても常に `#ffffff` のまま。
そこへ `color: inherit` (ダークでは明るい文字) が乗るため、白地に白文字になっていた。

症状 3 つの対応:

| 症状 | 該当箇所 |
|---|---|
| プルダウンが操作不能 | `.formRow select, .formRow input` |
| 購読カードの白飛び | `.subRow` / `.addSubRow input` |
| 記事ビューアが白地 | `.itemsBox` / `.candidateBox` |

「ダークモード対応を書き忘れた」のではなく、**書いたつもりの指定が変数名の
食い違いで無効になっていた**。ファイル末尾には `[data-theme="dark"]` の上書きが
6 つ書かれており (`.notice` / `.subRowWarn` / `.warnBadge` / `.subError` /
`.deleteBtn` / `.errorText`)、それらは正しく効いていた — 対応する意思はあった
のに、面の色だけが黙って無効化されていた。

## 直したこと

5 箇所の `var(--bg-primary, #ffffff)` を `var(--background, #ffffff)` へ変更。
ライトモードの見た目はほぼ変わらず (`#fdfdfd`)、ダークモードで `#0a0a0a` になる。

検証: 実際の `globals.css` の変数定義と `FeedManagementPanel.module.css` を
そのまま読み込んだ静的プレビューを作り、ライト / ダークを並べて確認した
(本番のバックエンドには接続していない)。購読カードのフィード名・プルダウン・
入力欄・記事ビューアのいずれもダークで正しく表示されることを目視で確認済み。

**残っているのは実アプリでの確認** — プルダウンを開いたときの候補リストは
ネイティブ UI で、`globals.css` の `color-scheme: dark` に従う。定義上は効くが、
静的プレビューでは開いた状態を確認していない。

## 同じ型の欠陥が他にもある (2026-09-02 発見、未対応)

「使っているが定義が無い CSS 変数」をフロントエンド全体で機械的に洗ったところ、
フィードタブ以外にも残っていた。いずれもフォールバック値に固定されるため、
テーマを切り替えても色が動かない。

| 変数 | 使用箇所 |
|---|---|
| `--bg-card` / `--border` / `--text` | `app/page.module.css` (847-870) / `components/ToolModeSelector.module.css` (48-49, 77, 142-143, 161) |
| `--card-bg` | `app/page.module.css:554` |
| `--danger` | `app/page.module.css:816` |
| `--success-color` | `components/PeopleModal.module.css:179` |

フォールバック値が両テーマで許容できる色なら実害は小さいので、**実際に見て
判断する**必要がある。今回は報告のあったフィードタブのみ対応した。

洗い方: `frontend/src` 配下の全 `.css` から `var(--x)` を集め、`.css` の宣言と
`.tsx` のインライン指定 (`'--x':`) の和集合に無いものを列挙する。
`--inv-scale` (CityMap.tsx が JS から入れる) と `--stackchan-X` (コメント中の
記法説明) は誤検出。

## 未点検 (起票時に「族で消す」として挙げた範囲)

フィードタブ以外は今回触っていない。ダークモードに切り替えて開く点検が要る:

- 習慣テンプレート編集モーダル (TimetableTemplateModal) のセレクト類
- ライフ設定モーダル (LifeSettingsModal)
- メモリーモーダル「経験」タブ

## 背景

フィード管理 UI は 2026-08-02〜03 の夜間実装 (サブエージェント分業のエージェント B 担当)。memory の恒常規則「新規 UI はダークモード対応を同時に書く (毎回漏れる)」(feedback_darkmode_checklist) の再演。

今回の根因を踏まえると、規則を守るだけでは足りない — **書いた指定が本当に効いて
いるか**は、変数名を打ち間違えた時点で誰にも気づかれない。上の機械的な洗い出しを
点検の道具として使える。
