# チャットの新着確認が、空の部屋へ移ったあとも前の部屋のメッセージ番号を使い続ける

**ステータス**: 未着手 (2026-10-09 調査済み、修正方針はまはーの判断待ち)
**発見**: 2026-10-09、サキの PR #376 を隔離環境の画面で検収している途中にメティスが気づいた

## 何が起きるか

チャット画面は 5 秒ごとに「この番号より新しいメッセージはあるか」をサーバーに問い合わせて、新着を画面に足している (`frontend/src/app/page.tsx` の新着確認)。この「番号」は、画面に並んでいる最後のメッセージから取って覚えておく。ただし、覚え直すのは画面にメッセージが 1 件以上あるときだけになっている。

そのため、メッセージが 1 件も無い部屋へ移ると、前の部屋の最後の番号を覚えたまま、新しい部屋について問い合わせることになる。サーバー (`api/routes/chat.py` の履歴 API) は、その番号が部屋の履歴に見つからないと「新着なし」の空の答えを返す。結果として、空の部屋を開いているあいだは、その部屋で誰かが入室したり発言したりしても画面に出てこない。ユーザー自身が発言するなどして履歴を読み直すまで、この状態が続く。

メッセージがある部屋どうしの切り替えでは起きない。読み込みが終わるまで新着確認が止まり、読み込み後に番号が覚え直されるため。

## 本番で実際に起きた記録 (読み取りのみで確認)

`~/.saiverse/user_data/logs/20261004_020830/backend.log`:

1. 03:04:57 まはーが Skyrim の部屋 (`skyrim_city_a`、その時点でメッセージ 0 件) を開いた。
2. 03:05:01 まはーがミラさんをその部屋へ呼んだ。ミラさんの入室の記録が部屋に書かれた。
3. 03:05:02〜03:11:37 画面は前の部屋の番号 `mira_city_a_room:777` で新着を問い合わせ続け、サーバーは 47 回「番号が見つからない」(WARNING) と空を返した。この間、履歴を読み直す問い合わせは無かった。
4. 03:11:42 まはーが発言した。返事のあとで履歴が読み直され、新着確認は `skyrim_city_a:4` から正しく続いた。

つまり、ミラさんの入室の記録は、約 6 分半のあいだ画面に出なかったと考えられる (画面の表示そのものは記録が無いので、問い合わせの内容とサーバーの答えからの推論)。

## 直し方の候補

覚えておく番号を「どの部屋の番号か」と組にして、表示中の部屋が変わったら捨てる。番号が無いときは、新着確認をやめるのではなく、その部屋の最新のページを問い合わせて、重複を除いて足す (今は番号が無いと新着確認そのものを飛ばしている)。セッションログの表示 (ゲームの Region) でも同じ番号を使っているので、そちらも同じ扱いにする。
