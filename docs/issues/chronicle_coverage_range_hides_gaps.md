# Issue: あらすじの被覆表示が「歯抜け」を表現できない

**ステータス**: 未着手 (2026-07-29 発見 / 2026-07-30 独立起票)
**優先度**: low — 表示層のみ。データは正しい
**関連**: `frontend/src/components/memory/ArasujiViewer.tsx` ・ [duplicate_message_ingestion_record](duplicate_message_ingestion_record.md)

## 何が起きているか

一次あらすじの被覆は「メッセージ番号の最小〜最大」の**連番レンジ**として表示される。そのため範囲内に**材料に入っていない発言** (取りこぼし・除外) があっても、見た目では区別がつかない。「10〜40 を覆う」と表示されているあらすじが、実際には 31 件中 12 件しか読んでいない、という状態がありうる。

## 直す方向 (未検討)

歯抜けの明示。件数表示 (「N 通」) をレンジに併記するのが最小の案。レンジと実件数が食い違えば歯抜けだと分かる。

## 経緯

2026-07-29、[arasuji_modal_500_limit_truncation](arasuji_modal_500_limit_truncation.md) (一覧 API の 500 件切り詰め) の調査中に気づき、当初はその issue の追記として書かれていた。2026-07-30 の二重起票の整理で、500 件切り詰めとは別の問題なので独立させた。

**訂正の記録 (2026-07-29 当日)**: 当初この項目には「豆粒が隣のあらすじに入っているように見えたのはこの表示のせい (まはーの誤認)」と書かれていたが、**誤りだった**。実際は生ログ側にメッセージの重複格納があり、豆粒と隣のあらすじは同一発言の別コピーをそれぞれ本当に持っていた — まはーの観察の方が正しかった (詳細は [duplicate_message_ingestion_record](duplicate_message_ingestion_record.md))。範囲表示が歯抜けを隠すこと自体は事実として残るので、本 issue は生きている。
