# 知覚の届く順が、起きた順とずれる (配達の経路が二本あるため)

**起票**: 2026-09-07 (まはーの実機所見 — v0.3.10 実機検証中)
**状態**: 未着手 (対処の方向は未設計。v0.3.10 候補)

## 現象

1. アイフィの部屋へ入った回の知覚で、**再会の想起がその移動の経路一行より上に出た** (まはーの実機、2026-09-07)。起きた順は「移動 → 想起」なのに、読む並びが逆で因果が変に見える。
2. 同族として、**入室通知の配達が数十秒遅れる** (実測 38 秒、2026-09-07 の実機検証時に観測。当時は issue 未起票のまま v0.3.10 候補に記載)。

## 原因

知覚バッファへの積み込みに、速さの違う二本の経路がある。

- **配達保証つきの経路 (outbox)**: 移動通知・入退室通知などの差分ラベルは、実行台帳の配達の列に積まれてから届く。失敗しても再配達される代わりに、届くまでに遅れが出る (38 秒の実測はこの遅れ)。
- **直接の経路**: 再会の想起 (`_inject_persona_recall_on_enter`) と部屋の様子は、検知したその場で直接バッファに入る。

知覚の並びは**届いた順**なので、同じ瞬間に起きた出来事でも「直接の経路のもの (想起) が先、配達の列を通ったもの (移動通知) が後」になり、起きた順と食い違う。

## 裁定 (2026-09-07 まはー)

致命的ではなく、issue 化して扱うのが適切 (想起だけ先に動かしても、配達の遅れが残る限り別の並び崩れが出る — 遅れそのものと一緒に設計する)。

## 対処の方向 (未裁定の候補)

1. **想起も同じ配達の列に載せる** — 同じ execution の outbox に積めば、並びが列の順で揃う。想起に配達保証が付く副次効果もある (Codex 2026-09-07 三巡目が求めていた恒久化と同じ向き)。
2. **配達の遅れ自体を詰める** — 38 秒の遅れの根 (配達の列の駆動間隔) を調べて縮める。並びの問題は残るが、ずれの窓が小さくなる。
3. **組成の消費時に並べ替える** — 回収 (reclaim) の仲間として「移動の経路一行は想起より前」の規則を足す。ただし例外処理の追加なので、供給側 (1 か 2) を先に検討する。
