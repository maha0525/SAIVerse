# Issue: スペルをバッククォートで囲むと不発になる

**ステータス**: 🔲 未着手 (低優先)
**優先度**: low
**作成日**: 2026-06-29
**関連**: `sea/runtime_llm.py:59` (`_SPELL_PATTERN = ^/spell\s+name='...'`), `builtin_data/playbooks/public/track_autonomous.json` (スペル例をバッククォートで囲んで提示している)

## 背景

ペルソナがスペルを発動する際、`` `/spell name='...' args={...}` `` のように **markdown のインラインコード (バッククォート) で囲んでしまい、スペルが不発のまま Pulse が終了する**事例がある。

## 原因 (確認済み)

`_SPELL_PATTERN` は行頭アンカー付き正規表現:

```python
_SPELL_PATTERN = re.compile(r"^/spell\s+name='([^']+)'\s+args=(.+)$", re.MULTILINE)
```

`re.MULTILINE` の `^` は行頭にマッチする。スペルがバッククォートで囲まれると、その行は `` ` `` で始まり `/spell` で始まらないため `^/spell` が一致せず、**パース対象から外れて不発**になる (fuzzy パターン `_SPELL_PATTERN_FUZZY` も同じく `^/spell` 始まり)。

**助長要因**: プロンプトのスペル例自体がバッククォートで囲まれている (例: `track_autonomous.json` の「タスクを追加: `/spell name='task_add' args={...}`」)。ペルソナはこの提示形式を忠実に真似て、実発動時にもバッククォートで囲んでいる可能性が高い。

## 直す方向 (案)

2 つは併用可能:
1. **パーサを寛容に**: 行頭/行末の バッククォート (`` ` `` / ```` ``` ```` フェンス) と前後空白を許容してから `^/spell` 判定する。`_parse_spell_lines` の前処理でストリップ、またはパターンに `` `? `` を織り込む。
2. **見本からバッククォートを外す**: プロンプト内のスペル例を inline code で囲まない (素のテキストで `/spell name='...' args={...}` と示す)。ペルソナが学習する形を正しくする。

1 はロバスト性、2 は根因への対処。両方入れるのが望ましい。
