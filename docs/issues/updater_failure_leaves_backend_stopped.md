# 更新・チャンネル切り替えの途中失敗後、旧版の SAIVerse が自動では再起動しない

**状態**: 未解決 (2026-09-25 起票。優先度 = 中 — 次の起動の自己回復が受け止めるため、無音で壊れたままにはならない)

## 何が起きるか

セルフアップデート (画面からの更新) と、アーリーアクセス版へのチャンネル切り替えは、どちらも「バックエンドを止める → 別プロセスの更新エンジンが作業する → 新しい版を起動する」の流れで動く。この途中 — 停止後にもう一度行う事前検査 (切り替えでは取得 (fetch) を含むため、ネットワークの瞬断でも失敗しうる)・ワールドの保存 (スナップショット)・コードの取得や切り替え・依存の更新 — のどこかで失敗すると、エンジンはコードを元へ巻き戻して (または無傷のまま) 終了するが、**元の版のバックエンドを起動し直す処理は無い**。SAIVerse は止まったままになり、ユーザーが自分で起動し直すまで画面は「再起動待ち」のまま。

## いまの受け止め (これがあるので優先度は中)

次にユーザーが `start.bat` / `start.sh` で起動すると、更新の仕上げの検査 (`.update_complete` の印) が「中途半端な更新」を検出して自動で更新をやり直す (v0.3.11 で導入済みの自己回復)。つまり実害は「一度手で起動し直す手間」で、壊れたままにはならない。

## 直すなら

更新エンジンの「バックエンド停止後の全工程」を一つの取り消し可能な単位として包み、どこで失敗しても (a) 必要な巻き戻しを行い、(b) 元の版のバックエンドを起動し直し、(c) 健全性を確認してから終了する形にする。あわせて、config あり (実運用形) でのスナップショット失敗・切り替え途中失敗・依存更新失敗の各テストを足す。2026-09-25 の敵対レビュー (アーリーアクセス実装の一巡目) の指摘 1・4 が該当。切り替え側は巻き戻し先のブランチの記録と、Windows で切り替えが半端に止まった場合の実地確認までは実装済みで、足りないのは「その後の再起動」。
