# アイテムの作成が失敗すると、保存済みのメディアファイルが孤児で残る

**起票**: 2026-09-12 (アイテム表示上限のレビュー三巡目で指摘、出自は従来からの形)
**状態**: 未解決 — 実害の頻度が低いため後回し

## 現象

文書・画像の作成は「本文/画像ファイルを保存 → DB にアイテムを登録」の順で進む。登録側が失敗する (DB 例外、または 2026-09-12 に入った置き場所の実在検査での拒否) と、保存済みのファイルがどのアイテムからも辿れないままディスクに残る。

- 文書 (document_create 経路) は 2026-09-12 に、置き場所の検査をファイル保存より前へ動かして、拒否での孤児は塞いだ。**DB 例外での孤児は従来どおり残る。**
- 画像 (image_generator → create_picture_item 経路) は、生成した画像を保存してから登録するので、登録失敗で画像ファイルが残る。生成には API 課金も伴う。

## 対応方針 (着手時に)

登録失敗時に保存済みファイルを削除する後始末を、作成経路の失敗処理に一体で入れる。頻度は低い (健全な世界では置き場所は常に実在し、DB 例外もまれ) ので、単独の掃除案件として扱う。
