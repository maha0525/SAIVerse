# 非ストリーミングの会話の器は、生成直後の割り込みで本文が記憶に書かれない

**状態**: 未解決 (2026-10-10 起票)

## 症状

非ストリーミングの会話 Pulse (speak=true) で、LLM の生成が終わった直後・スペルの周が始まる前にユーザーの割り込み (取消) が入ると、早期の吹き出しは建物の記録に出るのに、本人の記憶 (SAIMemory) には何も書かれない。本人は「言った」ことを次の文脈で思い出せない。

## 経緯

v0.4 段 2 の敵対レビュー 1 巡目 (2026-10-10) が、ティック (speak=false・記憶だけが行き先の器) で同じ形の消失を high で指摘した。ティック側は修正済み — `sea/runtime_llm.py` の `_keep_generated_body_before_first_round_stop` が、周の頭の取消評価で投げる前に本文を記憶へ保存する。

このとき speak=true のノードは意図して対象から外した: 会話の本文は建物の記録と記憶を対で持つ器で、記憶だけ書く修正は「本人は言ったと覚えているのに誰も聞いていない」の逆の食い違いを作りうる。ストリーミング経路は下書き行の保存 (`_save_draft_on_beat_death`) が守っているため、残る穴は**非ストリーミングの会話**だけ。

## 直し方の候補

吹き出しが既に建物に出ている以上、正しい向きは「記憶も書く」(ストリーミングの下書き確定と同じ着地)。`_keep_generated_body_before_first_round_stop` の speak=true 除外を、「建物の記録に既に出た本文は記憶も書く」へ精密化する形。早期の吹き出しが出る条件 (`_emit_bubble1_early`) と対にして設計すること。
