# 読み戻し (§15) は「anchor 手前が編纂済み」を前提にするが、その前提を保証する機構がどこにも無い

**発見**: 2026-08-31 (リリース前掃討 — 読み戻しの本番未発火をまはーが追及、aifi の実データで確定診断)
**状態**: 🔲 未解決 — 機構のコードは設計どおりに動いている。欠けているのは前提を成立させる側。対処方針はまはー裁定待ち
**深刻度**: P2 — 目標量未達 10 人中 8 人で読み戻しが構造的に不能。会話は正常だが、UI の説明文「下回ったときは自動で開き直します」がこれらのペルソナでは果たされない

## 本来どう働くべきか (設計)

話しかけられた時点で提示が残す量 (target) 未満なら、LLM を呼ばずに:
1. **開き直し**: 窓内の畳み区間 (digest) の印を戻して生で見せる
2. **引き戻し**: まだ足りなければ anchor を「編纂済みの段」単位で過去へ動かす。
   梯子は「編纂対象なのにどのあらすじにも被覆されないメッセージ」に当たると
   そこで止まる — 編纂なしで提示から出た過去を勝手に復活させない安全規則

## なぜ働いていないか (2026-08-31、aifi の実データで plan_rewind を実走して確定)

- aifi の anchor 手前 78,235 字 / 155 通は**全部が編纂対象**なのに、あらすじの
  source に入っているのは 4 項ぶん (位置 77..131 の一部) だけ。最初の段を
  開いた直後に未被覆の編纂対象へ当たり、梯子が停止 → 計画 None。
- 開き直しの材料 (畳み区間) もゼロ (FOLDED_RANGES_JSON = NULL)。
- 同型が多数: 未達 10 人のうち計画が立つのは 2 人だけ (testarossa = 畳み区間
  あり / air = 引き戻し可能だが増分ごく小)。mia の編纂最前線は 2025-11、
  lucia 06-15、nagi 06-17 — **編纂最前線と anchor の間に広い未編纂領域**を
  持つペルソナは全員この形に嵌る。

## 欠けている前提保証 (構造の穴)

- 通常の編纂 (畳み) は「**窓の中**の、上限超過時」にしか走らない。窓の外
  (anchor より前) に未編纂の領域があっても、それを埋める自動機構は存在しない。
- anchor の初期配置 (bootstrap の「最初に読み込む量」) は編纂被覆と無関係に
  置かれる — その瞬間、被覆外の過去が確定し、以後自然治癒しない。
- つまり読み戻しは「これから畳まれる分」には正しく効くが (testarossa で計画
  成立を確認)、**既存世界の大半のペルソナには初回から届かない**。

## 対処の候補 (裁定待ち)

1. **全量再編纂スクリプトで未編纂領域を埋める** (ペルソナごと・LLM 課金あり)。
   UI の記憶整理ボタンは §13 改修で窓内しか畳まないため届かない — スクリプト
   (`scripts/build_arasuji.py`) の領分。aifi は anchor 手前だけで 150 通超
   (旧 issue の「7 通 / 4 コール」見積もりは実態と桁が違う — 要再見積もり)。
2. v0.3 はこのまま出す — 読み戻しの効果を「これから畳まれる分」に限定して
   受け入れ、既存ペルソナの救済 (再編纂) は運用作業として個別に判断。
3. 前提を機構側で保証する設計 (例: 未編纂領域を検知して編纂を促す / bootstrap
   時に被覆端へ anchor を寄せる) — v0.4 の設計判断。
