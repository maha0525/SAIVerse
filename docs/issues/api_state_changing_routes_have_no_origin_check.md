# Issue: 状態を変える API に「どこから来た操作か」の確認が無い

**ステータス**: 🔲 未着手 (2026-08-16 起票)
**優先度**: medium (= 実際に踏むには条件が要るが、踏んだときの範囲が広い)
**作成日**: 2026-08-16
**関連**:
- `api/owner_auth.py` (持ち主確認の仕組み。LAN モードのときだけ有効)
- `main.py:614-617` (LAN モードのときだけ差し込んでいる箇所)
- `api/routes/system.py` (確認した範囲。他のルートも同条件と思われる)
- Codex adversarial-review (2026-08-16、退避 API のレビューで指摘)

## 何が起きうるか

SAIVerse のバックエンドは、まはーの PC の中で `127.0.0.1:8000` を開いて待っている。
**同じブラウザで開いている別のサイトのページからも、そこへ操作を送れる。**

ブラウザは「どのページから送られた操作か」を SAIVerse に伝えはするが、SAIVerse は
今それを見ていない。だから SAIVerse の画面から押したボタンと、まったく別のサイトの
ページが勝手に送ってきた操作を、**区別できない**。

具体的には、悪意のあるページを開いている間に、そのページが裏で次のような操作を
送れる (どれも画面のボタンと同じもの):

- 壊れた履歴ファイルを脇へ移す (`/api/system/legacy-log/{id}/archive`)
- 隔離された部屋をバックアップから復元する (`/api/system/quarantine/{id}/restore`)
- 隔離された部屋を空の履歴にリセットする (`/api/system/quarantine/{id}/reset`)

`system.py` で確認したのはこの 3 つだが、状態を変えるルートは他にもあるので、
**この API 全体の話**として扱うのが正しい。

## 読み取りはできない

ブラウザの別の仕組み (CORS) が効いていて、別のサイトのページは**送った操作の
返事を読めない**。だから「会話を盗み見られる」形にはならない。できるのは
「操作を起こさせる」ことだけ。

## 踏むのに要る条件

1. SAIVerse が動いている
2. 同じブラウザで、悪意のあるページを開く
3. そのページの作者が、SAIVerse のポート番号とルートを知っている

3 は隠し事にならない (SAIVerse は公開されているので、既定のポートもルートも読める)。
実質の条件は 1 と 2。

## いま持っている仕組みと、効いていない理由

`api/owner_auth.py` に持ち主確認 (`OwnerAuthMiddleware`) がある。合言葉つきの
セッションと、送り元のページの確認までやる。しかし `main.py` はこれを
**LAN モードのときだけ**差し込んでいる。まはーの普段の起動 (ローカル) では
入っていない。

つまり道具は既にあって、掛ける場所が足りていない。

## 手をつけるなら

1. **ローカル起動でも送り元を確認する** — 合言葉まで求めると普段の使い勝手が
   落ちるので、「どのページから来たか」の確認だけをローカルでも常に効かせる形。
   一番小さく済む。
2. **持ち主確認をローカルでも既定にする** — 起動のたびに合言葉のやりとりが要る。
   使い勝手と引き換えに堅い。
3. **何もしない** — 手元だけで動かす前提を明示して受け入れる。

私 (メティス) の見立ては 1。既にある仕組みの掛け場所を広げるだけで、まはーの
普段の操作は変わらない。

## なぜこの差分に入れなかったか

2026-08-16 の過去ログ取り込みの改修で `/api/system/legacy-log/{id}/archive` を
足したとき、Codex がこの点を指摘した。ただし新しい口だけ塞いでも、隣の
`/quarantine/*` が同じ状態のままでは意味がない。API 層全体の判断が要るので、
その差分には入れず issue として切り出した。
