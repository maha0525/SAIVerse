# Issue: conscious_log の cursor 取り込みの失敗が握り潰され、後から拾い直せない

**ステータス**: 🔲 未着手 (2026-08-16 まはー裁定で後回し)
**優先度**: low (= 実害は「本当に未読だった過去を読み飛ばす」まで下がっている)
**作成日**: 2026-08-16
**関連**:
- `docs/intent/building_memory_unified.md` の「過去ログ取り込みの自動化と検算」節
- `docs/handoff/2026-08-16_legacy_log_import_prevention_handoff.md` (Codex 1 巡目の F1)
- `saiverse/upgrade_handlers.py` `_v0_3_0_dev5_conscious_log_cursor_import`

## 何が起きるか

旧 `personas/<id>/conscious_log.json` の pulse cursor を DB へ移す処理
(`_v0_3_0_dev5_conscious_log_cursor_import`) は、例外を捕まえて握り潰し、そのまま
続行する。枠組みはハンドラが成功したものとして `LAST_KNOWN_VERSION` に
`0.3.0.dev5` を刻むので、**以後このハンドラは二度と走らない**。

失敗したことは、毎起動の検算にも現れない (検算が見ているのは building ログだけ)。
起動ログの ERROR 一行だけが痕跡になる。

## なぜ握り潰しているか (変えられない側の事情)

例外を上へ返すと枠組みは `False` を返し、`main.py` が `sys.exit(1)` する。
つまり **SAIVerse が起動しなくなる**。逃げ道は `SAIVERSE_SKIP_VERSION_CHECK=1`
(全アップグレードを飛ばす、危険) だけ。cursor が入らないという不具合を、世界に
入れないという不具合に変える形になるので、そのままでは採れない。

## 実害の現在地 (2026-08-16 時点)

読んだ位置の記録が無いときの既定を「起動時にひかえた末尾」へ変えた
(`_ingest_round`) ので、cursor が入らなかったペルソナは「未読なし」から始まる。

- **変更前**: cursor 行が無い → 0 (= 全部未読) → 部屋の全履歴を一度に転記。
  件数の上限が無く、そのまま有料の推論に載る。
- **変更後**: cursor 行が無い → 起動時の末尾 → たまっている履歴は読まない。
  失うのは「本当に未読だった過去」だけ。

つまり実害は「読み飛ばす」まで下がっている。取り込んだ過去ログ自体は seq が
0 未満なので、どの cursor 値でも既読側に入る (履歴が消えるわけではない)。

## 後から拾い直す道が無い

手動 CLI (`scripts/migrate_conscious_log_to_db.py`) は残っているが、
`migrate_persona_cursors(only_if_no_existing_rows=True)` の設計上、cursor 行が
既にある環境では何もしない。失敗した後は稼働の中で cursor 行ができるため、
**後から走らせても効かない**。まはーの「失敗したならもう取れる手段がない」
(2026-08-16) はこの通り。

## 手をつけるなら

まだ設計を決めていない。候補:

1. **検算に足す** — 「conscious_log.json に cursor があるのに、そのペルソナの
   cursor 行が DB に 1 行も無い」だけを見てバナーに出す。今の skip 条件と裏表なので
   誤検知が出ない。ただし直すのは人 (CLI が効かない以上、直す手段の用意が要る)。
2. **毎起動へ移す** — building ログの取り込みと同じく、バージョンのエッジから
   毎起動の処理へ移す。失敗は次の起動で自動的に再試行される。dev5 の City ハンドラは
   同じ理由で 2026-08-16 に no-op 化済み。
3. **何もしない** — 実害が「読み飛ばす」に下がっているので、リリース版ユーザーの
   実績が出るまで待つ。

2 が構造としては素直だが、cursor の remap は building ログが DB に入っている前提
なので、毎起動化するなら取り込みとの順序を明示する必要がある。
