# 習慣テンプレートが種別×場所の矛盾を書ける (自室で過ごす + 図書館)

**ステータス: 実装済み・レビュー/実機検証待ち** (2026-08-08 起票・同日実装 48edbf1。時間割実機検証の Step 2 でまはーが発見)

**実装 (2026-08-08)**: 保存検証 (`saiverse/timetable_template.py`) が stay_home 系×自室以外の facility を 422 で拒否。UI (TimetableTemplateModal) は該当種別選択時に場所セレクトを「自室」固定+送信時正規化 (修正前に保存された矛盾値も 422 を踏まない)。同族の点検 (出かけるの「空欄=穴」の意味表示・自由時間の場所欄) は未着手のまま残る。

## 症状

テンプレート編集 UI で種別「自室で過ごす」を選んだ状態でも、場所セレクトで自室以外を選んで保存できる。

## 実装の事実 (2026-08-08 調査)

- 保存検証 (`saiverse/timetable_template.py`) は「場所が行ける場所の集合 (candidate_buildings + own_room) に入っているか」だけを見る。**種別との整合検査は存在しない**。
- 実行時 (`saiverse/day_plan.py` コマ発火の (c) 段) は種別に関わらず先に `_apply_slot_move` で場所へ移動する。「自室で過ごす」+「図書館」の場合、ペルソナは図書館へ移動したうえで `_handle_stay_home_slot` が「自室で過ごす時間ですが、部屋に戻れず『図書館』で過ごしています」と正直に記録する。**捏造はしないが、矛盾した予定を実行が律儀に演じる**。

## 直し方 (未着手)

器の原則 (不正値は検証で弾くのでなく書ける口をなくす — feedback_design_from_user_mental_model): 

- UI: 種別=自室で過ごすの行は場所欄を「自室」固定 (セレクトを鎖す)。
- 保存側 (`save_template`): stay_home 系 execution_type の facility を own_room へ正規化 (UI を経ない書き込みにも効かせる)。

**同族の点検** (族で消す): 種別ごとの場所欄の意味論が UI に出ていない — 「出かける」で場所が空欄 (own_room) = 「当日、決定論で行き先が決まる穴」だが、編集画面にその説明がない。自由時間の場所欄の意味も同時に確認すること。カタログの execution_type ごとに「場所欄の意味と許される値」を一覧化して UI・保存検証の両方を揃える。

## 確認手段

- テンプレ編集 UI で矛盾の組み合わせが作れないこと
- 保存 API へ直接矛盾値を PUT しても正規化されること (`tests/test_timetable_template.py` に回帰追加)
