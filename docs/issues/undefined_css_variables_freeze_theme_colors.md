# 定義の無い CSS 変数が 6 種残っていて、その色はテーマ切り替えで動かない

**ステータス: 未解決** (2026-09-02 起票。フィードタブのダークモード修正の副産物。実害の有無は画面を見て判断が要る)
**優先度**: 未判定 (フォールバック値が両テーマで許容できる色なら実害は小さい)
**関連**: [feed_tab_dark_mode_pulldowns](archive/feed_tab_dark_mode_pulldowns.md) (同じ型で実害が出た先行例)

## 何が起きるか

CSS で `var(--x, 既定値)` と書いたとき、`--x` がどこにも定義されていないと**常に
既定値へ固定される**。エラーも警告も出ない。テーマを切り替えても色が動かない。

フィードタブはこれで丸ごとダークモード非対応になっていた。`--bg-primary` という
存在しない変数を 5 箇所で使っており、既定値の `#ffffff` に固定された面へ
`color: inherit` の明るい文字が乗って、**白地に白文字**になっていた。プルダウンの
候補が何も見えず、ダークモード利用者は施設を作れない状態だった。

**「ダークモード対応を書き忘れた」形ではないのが厄介なところ。** 同じファイルの
末尾には `[data-theme="dark"]` の上書きが 6 つ書かれていて、そちらは正しく効いて
いた。対応する意思はあったのに、面の色だけが変数名の食い違いで無効化されていた。
対応漏れとして探しても見つからない種類の欠陥。

## 残っているもの (2026-09-02 時点)

| 変数 | 使用箇所 |
|---|---|
| `--bg-card` / `--border` / `--text` | `app/page.module.css` (847-870) / `components/ToolModeSelector.module.css` (48-49, 77, 142-143, 161) |
| `--card-bg` | `app/page.module.css:554` |
| `--danger` | `app/page.module.css:816` |
| `--success-color` | `components/PeopleModal.module.css:179` |

定義済みの変数は `app/globals.css` の `:root` と `[data-theme="dark"]` にある
(`--background` / `--foreground` / `--primary` / `--primary-foreground` /
`--bg-secondary` / `--bg-tertiary` / `--bg-hover` / `--border-color` /
`--text-primary` / `--text-secondary` / `--accent-primary`)。

## どう判断するか

**既定値が両テーマで許容できる色なら実害は小さい。** 機械的に置き換えるのではなく、
ダークモードに切り替えて該当画面を実際に見てから決める。フィードタブのように
「読めない」なら直す、許容範囲なら変数を実在のものへ揃えるだけでもよい。

まはー方針 (2026-09-02): 出荷対象外なので急がない。**別セッションを立てて精査する。**

## 洗い方 (再現手順)

`frontend/src` 配下の全 `.css` から `var(--x)` を集め、`.css` の宣言
(`^\s*--x\s*:`) と `.tsx` のインライン指定 (`'--x':`) の和集合に無いものを列挙する。

誤検出に注意:

- `--inv-scale` — `CityMap.tsx:869` が JS から `['--inv-scale' as string]:` の形で
  設定している。`as string` が挟まるので素朴な正規表現では拾えない
- `--stackchan-X` — `addon-panels/.../theme.module.css` のコメント中にある命名規約の
  説明であって、実際の使用ではない

## なぜ起きるか (予防の手がかり)

memory の恒常規則「新規 UI はダークモード対応を同時に書く」を守っていても、
**書いた指定が本当に効いているかは変数名を打ち間違えた時点で誰にも気づかれない。**
規則を守るだけでは足りない種類の欠陥なので、上の機械的な洗い出しを点検の道具として
使うのが現実的。CI に入れるかどうかも含めて、精査セッションで判断する。
