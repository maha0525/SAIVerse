# 分裂した episode の digest が、同じ出来事を二回記述する

**ステータス**: 未解決 (2026-07-25 発見、`chronicle_eviction` の実装中に `alignment.py` を読んでいて気づいた)
**関連**: `sai_memory/arasuji/alignment.py` の `_segment_by_digest` ・ [`../intent/experience_structure.md`](../intent/experience_structure.md) §1 (同一事実の多重記述) ・ [`../intent/chronicle_eviction.md`](../intent/chronicle_eviction.md)
**まはー**: 「よく分からんので別セッションでまた訊く」(2026-07-25)。この doc はそのときの説明用に書いてある

---

## 何が起きるか

一つの episode の会話が、別の episode の会話に割られることがある。会話しながら作業セッションを回すと、こうなる。

```
[作業 A の前半] [会話 B] [作業 A の後半]
```

作業 A は閉じるときに自分の digest（あらすじ）を持つ。その digest は **A 全体**を語っている。

ところがこれを一次あらすじに載せるとき、`_segment_by_digest` は**最初の連続域だけ**に digest を渡す。二個目以降は「digest 無し」に降格して、普通の材料として扱う。同じ digest を二回転写しないための処置。

結果:

- **A の前半**を覆う一次あらすじに、**A 全体**を語った digest が載る
- **A の後半**は普通の材料として、隣と束ねられて別途要約される

だから **A の後半の出来事が二回記述される**。一回目は前半に載った「A 全体の digest」の中で、二回目は後半を含む別のあらすじの中で。

## なぜ問題か

`experience_structure.md` §1 が病巣として名指しした「同一事実の多重記述」そのもの。ペルソナの記憶に、同じ出来事が別の言葉で二回現れる。

加えて、**あらすじが覆っている範囲と、あらすじが語っている内容が食い違う**。前半だけを覆うノードが全体を語っている。これは撤回した借用案が Codex レビュー P1 で指摘された欠陥（「digest の被覆と source_ids が食い違う」）と同じ形。

## どれくらい起きるか

**実測していない。** 起きる条件は「digest を持つ episode が、別の episode のメッセージに割られていて、両方の断片が同じ編纂範囲に入る」。

作業セッションは閉じるときに digest を持つ。そして「会話中に作業セッションを回す」は設計上想定された形（`chronicle_eviction.md` §2 — 種類の違う episode は並行して開ける）。なので**稀ではないと見ている**が、これは推測。

## 直す方向（未検討）

思いつくだけ挙げる。どれも検討していない。

1. digest を**分割して**各断片に対応する部分だけを載せる — 分割の判断に LLM が要る
2. 断片が複数あるときは digest を使わず、全断片を**まとめて一つのあらすじ**にする — 間に挟まる別 episode を跨ぐので §4-5（偽の隣接）に触れる
3. 二個目以降の断片を、一個目のあらすじの**継承先**として繋ぐ — 記述の重複は残るが、関係は表現できる
4. そもそも episode の断片を別々に扱わず、episode 単位で編纂の順番を決める

## 触っていない理由

2026-07-25 のセッションでは `chronicle_eviction` の実装が主問題で、まはーの判断は「これ以上ことを大きくできない、まず運用できる形に実装を進める」。記録だけ残した。
