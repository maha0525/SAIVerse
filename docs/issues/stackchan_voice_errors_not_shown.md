# Issue: スタックチャンに声で話しかけて、ペルソナが返事をできなかったとき、何も伝わらない

**ステータス**: 🔲 未着手 (2026-09-11 まはー「今触ることではない」)
**優先度**: medium
**作成日**: 2026-09-11
**関連**: `expansion_data/saiverse-stackchan-addon/audio_input_relay.py` (`_drain_stream_sync`)、`manager/runtime.py` (`handle_user_input_stream`)、[stackchan_vessel.md](../intent/stackchan_vessel.md)、[persona_model_selection.md](../intent/persona_model_selection.md)

## 背景

Web のチャット画面では、ペルソナが返事をできなかったとき (API の利用制限、APIキーの失効、選んだモデルが SAIVerse に無い、など)、返事が出るはずの場所にエラーの文面が出る。

スタックチャンに声で話しかけたときは、アドオンがユーザーの声を SAIVerse に渡したあと、SAIVerse から返ってくる知らせ (返事の途中経過とエラー) を全部読み捨てている (`_drain_stream_sync` は受け取ったものを何もせずに捨てる)。ペルソナの返事の声は、発話のたびに音声をスタックチャンへ送る別の経路 (`speak_hook.py` の `on_persona_speak`) で届く。エラーはその経路に乗らない。そのため返事ができなかったとき、スタックチャンは黙ったままになり、ユーザーには理由が分からない。

この件は、2026-09-11 に「選んだモデルが SAIVerse に無いとき、代わりのモデルで動かさない」設計 ([persona_model_selection.md](../intent/persona_model_selection.md)) を詰めている途中で見つかった。その設計ではモデルが無いペルソナは話せなくなるので、スタックチャンに声で話しかけても黙ったままになる。ただし黙ったままになるのはモデルの件に限らず、今もすべての種類のエラーで起きている。

いま、スタックチャンに声で話しかけた人に理由が伝わる場所は、Web のページを開いたときに出る警告だけになっている (モデルが無い件の場合)。

## 守ること

- スタックチャン本体で知らせるとしても、ペルソナの声で「話せません」のように言わせない。ペルソナが言っていない言葉を、SAIVerse がペルソナの名義で作ることになる。
- 表情 (`set_avatar`) はペルソナの顔なので、エラーの知らせには使わない方がよい (メティスの意見、まはー未確認)。

## 解決案候補

- (メティス案) 返事ができなかったとき、アドオンが LED を決まった光り方 (たとえば赤の点滅) にして、「何かあったのでページを見て」の合図にする。理由の文面は、Web のページを開いたときの警告が伝える。LED はペルソナもスペル (`set_led` など) で使えるので、ペルソナが使わない光り方を一つ、SAIVerse の知らせ用に取っておく形になる。
- stackchan_vessel.md にある stackchan-mcp の道具の一覧には、画面に文字を出す手段と、効果音を鳴らす手段が見当たらなかった。ファームウェア側で足せるかは調べていない。
