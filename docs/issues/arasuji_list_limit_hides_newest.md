# あらすじ一覧が 500 件上限で「最新側」を切り落とす

**ステータス**: 未解決 (2026-07-29 発見)

## 症状

UI のあらすじ一覧 (Memory 設定 → ArasujiViewer) が、エントリ総数が 500 件を超えると**最新の一次あらすじを一切表示しなくなる**。削除・再生成を行っても見える範囲の顔ぶれが変わらず、「操作が反映されていない」ように見える (実測: エリス 510 件時、直前に生成された一次あらすじ 8 件が既定一覧に 1 件も現れない)。

## 何が起きているか

`GET /api/people/{id}/arasuji` (level 指定なし) は

```sql
ORDER BY level DESC, start_time ASC LIMIT 500
```

で返す — 上位レベル → 各レベル内は**古い順**。500 件で切ると、並びの最後尾 = **レベル1 の最新側**が真っ先に落ちる。新しい記憶ほど見えない窓になっている。`?level=1` 指定の経路 (`get_entries_by_level`) には上限が無く、そちらでは全件見える。

## 実害

- 記憶の操作 (削除・再生成・編纂) の結果を UI で確認できない。今回、実際に「削除が行われていないのでは」という誤認を生んだ。
- 実運用のエントリ数は増える一方 (エリス 510、増加中) なので、放置すると常時この状態になる。

## 修正の方向 (案)

1. **新しい順 (start_time DESC) + ページング** — 「最近の記憶から遡って見る」が一覧の自然な用途。レベル混在の既定ビューも新しい順に。
2. 少なくとも `LIMIT` を切るなら「最古側」を落とす (最新を必ず見せる)。

## 発見の経緯

2026-07-29、エリスの記憶修復 (歪み世代 101 件削除 → 新方式で 8 件再生成) の直後、UI 一覧が削除前と同じ顔ぶれのままに見えた。API 応答の突き合わせで、変更が全て 500 件上限の外側 (並びの尻尾) で起きていたことを確認。

## 関連: 被覆の範囲表示が歯抜けを表現できない (2026-07-29 追記、同日訂正)

一次あらすじの被覆は「メッセージ番号の最小〜最大」の連番レンジで表示されるため、範囲内に**材料に入っていない発言** (取りこぼし・除外) があっても見分けられない。修正時は歯抜けの明示 (件数表示「N通」の併記等) を併せて検討。

**訂正 (同日)**: 当初ここに「豆粒が隣のあらすじに入っているように見えたのはこの表示のせい (誤認)」と書いたが、**誤りだった**。実際は生ログ側にメッセージの重複格納があり、豆粒と隣のあらすじは同一発言の別コピーをそれぞれ本当に持っていた (ユーザーの観察が正しかった)。詳細は `docs/issues/duplicate_message_ingestion_record.md`。範囲表示が歯抜けを隠すこと自体は事実として残る。
