# ワールドエディタからペルソナを保存すると、一部のモデル欄の個別設定が黙って消える

**ステータス: 解決済み (2026-09-20 発見、同日修正 — 受け側 (manager/admin.py の
update_ai) がモデル欄の既定を「送られてこなかった = 触らない」の印 (UNSET) にし、
印の解決を錠と refresh の後で行う形。回帰テストは tests/test_admin_ai_edit_contract.py
の test_omitted_model_fields_keep_their_stored_values ほか 3 本)**

## 症状

ワールドエディタ (`PUT /api/world/ais/{id}`) でペルソナを保存すると、その画面が
扱っていないモデル欄 — Memory Weave・画像/音声/動画の要約・反射判断のペルソナ個別
設定 — が **NULL (世界の既定に従う) に戻る**。名前や説明だけ直したつもりでも、
そのペルソナに設定してあった個別モデルが黙って外れる。

## 原因 (裏取り済み、2026-09-20 時点の行位置)

- `api/routes/world.py` の保存リクエスト (`AIUpdate`, 140 行) は `default_model` と
  `lightweight_model` しか持たず、`manager.update_ai(...)` (494 行) にもその 2 つしか
  渡さない。
- 受け側 `manager/admin.py` の `update_ai` は、モデル欄を **無条件に代入する**
  (`ai.MEMORY_WEAVE_MODEL = memory_weave_model or None` など)。渡されなかった欄は
  引数の既定 None → NULL 代入になる。
- ペルソナ設定画面 (`api/routes/people/config.py` の PATCH) は「リクエストに無い欄は
  現在値を詰め直してから `update_ai` を呼ぶ」作りなので無事。穴はワールドエディタの
  入口だけ。

## 影響範囲

MEMORY_WEAVE_MODEL / VISION_MODEL / AUDIO_MODEL / VIDEO_MODEL (以前からこの挙動) と、
2026-09-20 の反射判断 第 2 段で入った REFLEX_JUDGMENT_MODEL (既存の族の形に揃えて
実装したため同じ挙動)。標準・軽量モデルはワールドエディタも送っているので消えない。

## 採った直し方

最終形は**受け側の印**: `update_ai` のモデル欄の既定を None から「送られてこなかった」
の印 (`manager/admin.py` の `UNSET` — Building の更新が同じ問題を解いたときの印を流用)
に変え、印の欄は錠と refresh の後で現在値に解決する (= 触らない)。None と空文字は
これまでどおり「個別設定を外す」。ペルソナ設定の PATCH も、リクエストに無い欄を
現在値で詰め直すのをやめて印を渡す形に揃えた。

途中で一度、入口 (world.py) が現在値を詰めて渡す形を採ったが、敵対レビュー 2 巡目に
「読んでから書くまでの間に別の画面の保存が挟まると、その保存を古い値で巻き戻す」
(競合の窓) と指摘されて受け側の印へ差し替えた。入口の詰め直しは、単独の保存では
正しく見えて競合で壊れる — 「触らない」を保証できるのは、錠を持っている受け側だけ。

## 経緯

- 2026-09-20: 反射判断 第 2 段 (ペルソナ個別の反射判断モデル列の追加) の実装中に、
  実装サブエージェントが「ワールドエディタ経由の保存はこの欄を NULL に戻す。既存の
  Memory Weave 等が前から同じ挙動で、その族の形に揃えた」と報告。検収で
  `api/routes/world.py` と `manager/admin.py` を読んで裏取りした。いったん「族ごと
  直すのは別件」と issue 送りにしたが、同日の敵対レビュー 1 巡目が「新設の列に対する
  新規のデータ損失」として high で挙げ、入口で現在値を詰める形なら族ごと小さく直せる
  ため、この束で修正した (Memory Weave・画像/音声/動画の要約も同時に直っている)。
