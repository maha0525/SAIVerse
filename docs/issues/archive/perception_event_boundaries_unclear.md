# 知覚バッファの出来事の区切りが見えない

**起票**: 2026-09-07 (まはーの実機所見 ③)
**状態**: 完了 (2026-09-07) — まはーの実機確認済み。入室・経路 (大図書館込みの畳み)・様子がそれぞれ自分の頭を持つ形で出力され、「さっきの件は解決」の裁定

## 現象

未消費の知覚が複数の出来事にまたがって溜まると、消費時に一枚へ畳まれた文面の中で、どこからどこまでが一つの出来事なのか読み分けられない。まはーの実例 (アイフィの往復ダンプ) では、前の部屋の「役割・指示」と次の部屋の「様子 (前回見たときからの変化)」が見出しの並びだけで隣接し、並列の項目にしか見えなかった。回収 (§11) と指示の一本化の後も、経路一行と「エリス が入室しました」が一枚の `[システム通知]` の下に空行だけで並び、切れ目が読めない形は残った (2026-09-07 実機ダンプ)。

## 裁定 (2026-09-07、まはー「それでやっちゃおう」)

**区切り線は導入しない。一出来事一ラベルにする** — `format_perception_message` (sai_memory/perception_buffer.py) の「連続する world_state を一枚の `[システム通知]` にまとめる」畳みを退役し、world_state の出来事ごとに `[システム通知]` を付ける。

- **理由 1 (畳みの存在理由の消滅)**: 合流は「通知の乱発を防ぐ」ための 2026-07-09 の対策だが、乱発の供給源 (移動通知の堆積) は回収 (room_state_packages.md §11-2 — 往復を経路一行に畳む) が殺した。例外処理は上流の傷が塞がれたら機構ごと消す。
- **理由 2 (区切り線の衝突)**: `---` はドキュメント本文に現れ、部屋の様子の描画自身も節の区切りに使っている。中身の文字列で区切る限り衝突は原理的に消えない。行頭ラベル + 直後に出来事文の形は実質衝突しない。新しい記法もゼロ (「[システム通知]」「[フィード]」「# 「…」の様子」の既存語彙で全塊の頭が揃う)。
- **代案の却下**: 区切り線の記号替え (太線等) も同じ衝突を持つ。数トークンの節約にしかならない別案より、この形で十分 (まはー裁定)。

### 前方一致との整合 (裁定済みの前提への適合)

「区切りの印は積むときに持たせる — 提示時に後から足すと提示済みブロックの描画が変わって前方一致が割れる」(起票時の前提)。本裁定は適合する: `format_perception_message` は**消費の瞬間**に一回だけ走り、文面は消費バッチの `rendered_text` として確定・永続化される (提示は再構成しない)。畳みの退役が影響するのはこれから消費される新しいバッチだけで、提示済みの過去バッチは保存済みの文面のまま変わらない。

### 確定後の出力例

```
[システム通知]
この間に現在地が移動しました: 「アイフィの部屋」 → 「まはーの部屋」 → 「アイフィの部屋」

[システム通知]
エリス が入室しました

# 「アイフィの部屋」の様子 (前回見たときからの変化)
……
```
