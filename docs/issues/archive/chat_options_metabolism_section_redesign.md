**状態**: ✅ **完了 (2026-09-01 実機検証三点合格)** — ①水位バーとプレビューの整合 (まはー確認 8/31) ②トグル消滅後の通常動作 (数日間の全会話が証拠) ③モデル編集→表示反映: 専用欄に metabolism_high_chars=150000 を保存 → チャットオプションの上限表示が 150,000 字に追従 (まはー実機 9/1)。派生発見: 追加設定 JSON に書いた水位キーが黙って消える UI 欠陥は別 issue ([model_editor_drops_watermark_keys_from_json](model_editor_drops_watermark_keys_from_json.md))。(2026-07-30 起票・同日実装完了。Codex 8 巡 → approve、指摘 12 件消し込み)

## 背景

§15 読み戻しの実機検証後、まはーがチャットオプションの「データ送信量の管理」セクションに 4 点のツッコミを入れた:

1. 履歴の新陳代謝は OFF にできて大丈夫なのか
2. 各水位が「（自動）」としか出ず、結局何文字なのか分からない
3. 今のコンテキストが何文字なのか見えず、水位との位置関係が掴めない
4. 低水位の説明文が古い (現設計では eviction に使われていない)

調査で判明した事実:

- **OFF 経路は生きているが半端**: 全発火点が `metabolism_enabled` で門をしており、OFF なら anchor を使わず低水位分だけ読む従来スライディングウィンドウに落ちる。ただし head のあらすじ枠は OFF でも出続け、畳み記録による「あらすじと生ログの二重提示防止」の調整は OFF では働かない。加えてウィンドウ始点固定が消えるため毎ターン prefix キャッシュ作り直し。**今の SAIVerse で OFF を選ぶ利点がほぼ無い。**
- **「（自動）」の原因**: この画面はグローバルのモデル設定からしか既定値を引けない。実際の会話モデルは「チャットUI上書き > ペルソナ DEFAULT_MODEL > …」で決まるため、グローバル未設定だと既定値が null になり素の（自動）だけ残る。
- **水位グローバル上書きのスコープずれ**: 上書きは manager の揮発属性 (全ペルソナ・全モデルに波及) なのに、置き場所は会話ごとの画面で、そうと分かる表示がない。
- **低水位の現役の仕事は一つだけ**: eviction では未使用 (「残す量 = 目標」が保護を兼ねる、`sea/eviction_plan.py` の Watermarks docstring に明記)。唯一の現役は「anchor が無いときの初期読み込み量」(`_minimal_load_chars`)。

## 決定 (2026-07-30 まはー裁定)

1. **新陳代謝 ON/OFF トグルと OFF 経路 (従来スライディングウィンドウ) を撤去し、常時 ON にする。**
   「ちょっと大胆にでも保守する経路減らしていかないと持たない」。半端に進化が止まった旧経路を養い続けない。
   モデル定義で水位を null にした場合の「Metabolism を持たない」経路は残る (これが唯一のオプトアウトで、モデルの属性として定義される)。
2. **水位のグローバル上書きを廃止し、水位はモデル定義一本に集約する。**
   水位をいじる実在の需要は「モデルの都合」(短いコンテキストのローカルモデル等) だけで、その受け皿はモデル定義として既にある。「この子だけ調整したい」需要は現時点で想像上のもの — 実例が出たらペルソナ設定側に足す。
   検討過程: ペルソナごと上書き案は「同じ画面にグローバル設定 (モデル選択) とペルソナ限定設定が同居してややこしい」で棄却。
3. **チャットオプションの当該セクションは読み取り専用の状態表示に作り直す。**
   キャッシュタイマーの persona switcher に相乗りし、選択ペルソナの「実効モデルの水位 + 現在の提示コンテキスト文字数 + 水位バー」を表示する。読み取り専用なら「誰に効くか」問題自体が消える。
   文字数は §15 の read-only 計画を再利用し、**読み戻し後の値** を出す (コンテキストプレビューと一致させる — プレビューが嘘にならないの原則)。
4. **低水位の説明を実態に合わせて刷新する** (「そのまま残す直近の文字数」は目標水位の説明であり誤り)。

## 実装記録 (2026-07-30)

追加実装 (工事範囲からの発展):

- **モデル編集 UI に水位 3 欄を追加** (`ModelEditorModal.tsx`) — モデル保存 API は既に `metabolism_*_chars` を受けていた (書き込み口は最初から正しい場所にあった) が UI 入力欄が無かった。欄は「空欄 = 標準既定 / none = 使わない / 数字 = 指定」の三値で、キーを専用欄が単独所有 (JSON との二重所有は空欄で null が復活する欠陥になる)。
- **モデル保存 API に水位順序の実効値検証** (`_validate_metabolism_watermarks`) — キー無しは組み込み既定へ解決して 低 ≤ 目標 ≤ 高 を検査 (入力同士の比較だけでは「high=5万だけ指定 → 実効 target=10万 > high」が保存できる)。
- **POST /api/config/model の直列化 + client_id ごとの世代ガード** — abort されたモデル変更の遅延書き込みが新しい選択を上書きしない。世代台帳は最終利用時刻付き・安全期間 600 秒超だけ刈る。
- `preview_refilled_history` に `raise_on_error` — context-status は strict で呼び、内部失敗を「適用なし (正常)」と区別して `measurement_failed` で返す。

Codex レビュー 8 巡の主要指摘 (全て修正済み): 水位 null モデルが anchor 経路に入る (唯一のオプトアウトが機能していない — `metabolism_active` 門を新設) / 水位解決の例外で履歴ゼロのサイレント障害 / 状態表示の障害偽装・staleness / モデル編集の三値二重所有 / モデル切替の追い越し (サーバー直列化・世代ガード・遅延 resync の適用直前検査まで 4 巡)。
