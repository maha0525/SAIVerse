# 部屋の様子の差分が、描画済みの文字列の解析で組まれている (v0.3.9 出荷停止)

**ステータス**: 🔲 未解決 (設計中 — 性質の洗い出しまで完了。設計はまはーとの議論から)
**深刻度**: 高 — v0.3.9 の発行を止めた欠陥。[PR #282](https://github.com/maha0525/SAIVerse/pull/282) は draft へ落とした
**発端**: 2026-09-06、まはーのリリース前確認
**関連**: [persona_recall_perception_unbounded.md](persona_recall_perception_unbounded.md) (v0.3.9 主案件 — 差分機構はその 1 件) / [room_state_single_source_of_truth.md](room_state_single_source_of_truth.md) (一元化 — 同じ主題、設計を一緒に行う候補) / [perception_buffer.md §10.8](../intent/perception_buffer.md)

## 何が起きたか

リリース前確認で、差分の「## 見当たらなくなったもの」に、閉じた (または消えた) ドキュメントアイテムの**本文の段落**が箇条書きで列挙された。アイテム名と ID は出ていない。実例 (まはーの実機):

```
## 見当たらなくなったもの
- このドキュメントは、様々な名画の要素をアイフィ（…）に調和させ、…アイデア・覚え書きです。
- ## 1. 巨匠たちから吸収するエッセンスと…
```

「さっき」の段階で読んだ説明文・本文を、消えた報告のためにもう一度積んでいる — 絶対に重複にしかならない情報で、しかも肝心の「何が消えたか」(名前と ID) が無い。

## 三つの原因

1. **直接原因**: `render_room_diff` の分割 (`_split_blocks`) が「空行 = アイテムの境目」と仮定していた。開いたドキュメントの本文は空行を含むので、本文の段落が一つずつ独立した「アイテム」に化ける。見出し行の対応づけでアイテム本体は「変わったもの」側へ行き、対を持たない段落たちが「見当たらなくなった」側に段落頭だけ晒される。
2. **判断の失敗**: 描画済みの**一枚の文字列**を差分の入力に選んだこと。描画側 (`get_visual_context`) はアイテムを一個ずつ組み立てているのに、一枚に繋いで構造を捨て、受け取る側が文字列から構造を推測し直す設計にした。Open/Close を概念として設計で扱わず、状態の遷移を「文字列が変わったか」に落とした。
3. **通した工程**: テストが合成の行儀のよいデータ (一行説明のアイテム) だけを食べ、本物の描画 (開いたドキュメント・思い出付きの画像) を一度も食べなかった。レビュー 6 巡も同じ合成前提の上で回った。

## まはー裁定 (2026-09-06)

- 知覚関連の処理を文字列そのものの処理でやってはいけない。中身は文字列だとしても、**一個一個はパッケージングして扱う**。
- **設計の前に、知覚に現れる物の性質を全部洗う** (Open/Close を含む)。洗い終わるまで設計をしてはいけない。
- v0.3.9 はこの状態では出荷できない。

## 洗い出し: 知覚に現れる物の性質 (2026-09-06 実施)

### 知覚バッファに積まれる種類 (本 issue の対象は 1 だけ)

1. **surroundings** — 部屋の様子 (本件。`push_room_state` → 入室時のみ、`saiverse/dynamic_state.py`)
2. **world_state** — 出来事の通知 (入退室・スペル付与・予定など)
3. **persona_recall** — 再会の想起
4. **core_memory_correction** — コア記憶の訂正
5. **feed** — フィード記事

### 部屋の様子 (surroundings) に現れる物

描画は `builtin_data/tools/get_visual_context.py` (`for_perception=True`)。順に:

- **他ペルソナの外見** — 同一性はペルソナ ID。`[名前の外見]` + 外見画像 (メディア添付)。入退室で増減。
- **ユーザー** — 同一性はユーザー ID。名前と ID の行のみ。入退室で増減。誰もいなければ節ごと出ない。
- **内装画像** — 建物に一つ。`[内装]` + 画像 (メディア添付)。変更はまれ。
- **建物のシステムプロンプト** — 建物に一つ。`[システムプロンプト]` + 自由文 (**複数行・空行を含みうる**)。設定変更で変わる。
- **アイテム** — 同一性は `item:N` (安定 short_id)。型は Object / Image / Document / Bag / Audio / Video + 不明型。
  - 共通の姿: 見出し行 `[item:N] [型] 名前` + 作成日時 + 説明。
  - **`is_open` (Object と不明型には無い)**: **ユーザーが右サイドバーで切り替える「AI コンテキストに含める / 除外」のトグル** (`docs/user-guide/items-and-files.md`)。書き手は UI の一本だけ (`api/routes/info.py:583` → `toggle_item_open_state`)。**ペルソナ側のツールからは変えられない**。新規作成は既定 open (生まれた瞬間から見える)。
    - Document: open = 本文 (最大 8,000 字) を ``` 囲いで全掲 / closed = 説明のみ。
    - Image・Audio・Video: open = `saiverse://` URI + メディア添付 + 説明 / closed = 説明のみ。
    - Bag: open = 中身を入れ子で列挙 (各 160 字に切った説明、入れ子 Bag は再帰、子も自分の `item:N` を持つ) / closed = 説明のみ。
  - **Image だけの追加挙動「あの時の思い出」**: 作成時刻がそのペルソナの文脈窓の最古より古いとき、作成時刻周辺のログ最大 10 件が描画に差し込まれる (`_fetch_item_memory_recall`)。**ペルソナ依存かつ時間依存 — 世界が全く変わらなくても、ペルソナの記憶の整理が進むだけで同じ部屋の描画が変わる。**
  - 出現・消滅: 作成 (ユーザーのアップロード / ペルソナのツール) / `item_move` (別の建物へ・Bag の中へ・ペルソナが拾う) / 削除。**「部屋から見えなくなる」原因は多義** — 特にインベントリは知覚に描かれないので、誰かが拾った物は部屋の眺めからは消える。
  - 内容の変化: 名前・説明・本文の編集 (UI の ItemModal、ペルソナのツール)。
- **設置物 (Fixture)** — 同一性は FIXTURE_ID。名前・種別・説明 + Observer の観測値 / フィードスタンドの購読タイトルと新着見出し (feed_manager が定期更新)。**移動しないが中身は定期的に変わる。**
  - 補足: `docs/concepts/item.md` は Fixture を「設計のみ・未実装」と書いているが、描画・観測値・フィードスタンドは動いている — doc の古さ。別途直す。

### 積まれる瞬間と既存の境界

- 部屋の様子が積まれるのは**入室時のみ** (`saiverse/dynamic_state.py`)。起動直後・ブートストラップでは積まれない ([一元化 issue](room_state_single_source_of_truth.md) の成立条件 2 と同じ穴)。
- Chronicle 無効のペルソナは毎回全文 (`allow_diff=False`)。
- **メディアの扱いは境界ではなく欠陥だった** (2026-09-06 まはーが「怪しい」と嗅ぎ当て、検算で確定): 差分は中身が何であれ無条件でメディアを空にする (`build_room_state_push`)。(a) 差分が新しい画像・音声・動画を連れてくる回 (新登場、Close→Open) は、本文が `saiverse://` 込みでアイテムを名乗るのに実体が添付されない — ペルソナは「見える」と書かれた物を見られない。(b) 移管・開き直しは文章だけを書き戻し、メディアには一切触れない — 土台のメディアが下りた後は、全文が画像を名乗るのに実体なしが恒常化する。この「差分にメディアは載せない」は設計された契約ではなく、実装時に docstring へ一行書いて流した簡略化だった。

## 設計で答えるべき問い (設計局面で扱う。ここでは列挙まで)

1. **Open→Close の描き方**: 閉じる = ユーザーが「コンテキストから外す」操作。本文や説明の再掲はその操作の裏切りになる。「閉じられた」という事実の一行が正しいはず。逆向き (Close→Open) は新しく見せる操作なので全文が正しい。
2. **「あの時の思い出」を包みの同一性に含めるか**: 含めると、世界が変わっていないのに「アイテムが変わった」と誤検知して全文再掲する。外すなら「包みの中身」の定義から思い出を分離する必要がある。
3. **「変わったものは全文」の粒度**: ドキュメント本文の一字の編集 = 8,000 字の再掲でよいか。
4. **消え方の多義**: 移動・収納・拾得・削除・close を描き分けるか、「見えなくなった」で束ねるか。
5. **一元化との関係**: [room_state_single_source_of_truth.md](room_state_single_source_of_truth.md) (head の Visual Context 退役、部屋の様子は知覚だけが運ぶ) と同じ主題。一緒に設計するか、包み化を先行させるか。
6. **旧形式との互換**: 既存の文字列 snapshot は構造照合できない。一度だけ全文を積み直して、以後は構造付きで運ぶ形が単純。
7. **メディアは包みの属性にする**: 上記の欠陥 (a)(b) の帰結。包みが「新しく見せる」回はそのメディアも一緒に運び、開き直しで包みが全文へ戻るならメディアも戻る。バッチ全体の付属品として扱う今の形では、差分と復元の両方で実体が落ちる。一元化 issue の「画像埋め込み上限との整合」もここに合流する。
