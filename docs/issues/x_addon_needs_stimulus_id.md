# X アドオンのポーリングが刺激の ID を付けずに封筒を作るため、v0.4 では X の通知がペルソナに届かない

**状態**: 未解決 (2026-10-09 起票、v0.4 実装計画の段 1-3 の後始末)。**v0.4 を本番相当で動かす前に対応する**
**対象**: X アドオン (`expansion_data/saiverse-x-addon`、本体リポジトリの外。修正はアドオン側)
**関連**: [on_event_judgment_has_no_idempotency_key.md](on_event_judgment_has_no_idempotency_key.md) (刺激の ID の義務化の決定と実装) / [v0.4 実装計画](../intent/autonomous_behavior_v04_plan.md) §4 の決定 6

## 何が起きるか

v0.4 の段 1-3 で、現象の封筒 (`phenomena/triggers.py` の `TriggerEvent`) の `stimulus_id` は既定値の無い必須の欄になった (キーワード専用)。供給源が自分の永続 ID から作る義務で、受け取り口では代理採番しない。

X アドオンのポーリング (`integrations/polling.py` の `poll_persona`) は、`TriggerEvent(type=..., data=...)` を `stimulus_id` 無しで作っている。2026-10-09 にメインの作業ツリーの `expansion_data` にあるアドオンを読んだ限りでは、次の順で X の通知が失われる (実行して確かめたのではなく、コードを読んだ結果):

1. 封筒を作る瞬間に、必須の引数が無いので TypeError になる。
2. アドオン自身の `poll` が例外を拾い、`[XPolling] poll_persona failed` を ERROR で残して、そのペルソナの封筒を出さずに次へ進む。
3. ただしその時点で、メンションの取得 (`detect_mentions`) は既に since のカーソルを進めており、エラーの無い回は `touch_last_polled` も済んでいる。次のポーリングは同じメンションを取り直さないので、**届かなかったメンションは失われる** (フォロワーとエンゲージメントの差分のスナップショットも同じ形で進む)。

本体側の歯止め (`IntegrationManager` が `stimulus_id` の空の封筒を ERROR で落とす) まで届く前に、アドオンの中で落ちる。どちらで落ちても X の通知はペルソナに届かない。

本体のコードで封筒を作っているのは `saiverse/saiverse_manager.py` の `_emit_trigger` だけで、呼び手 (サーバーの起動・停止、ユーザーとペルソナの移動) はどれも内部の一回きりの出来事として uuid4 で ID を作っている。メインの作業ツリーの `expansion_data` にあるアドオン 8 つのうち、封筒を作っているのは X アドオンだけだった (2026-10-09 時点)。

## 直し方 (アドオン側)

`stimulus_id` を X の永続 ID から作って封筒に入れる。契約は `TriggerEvent` の docstring と `BaseIntegration.poll` の docstring にある — 同じ出来事をもう一度返してしまったとき (カーソルが進まなかった・再試行した等) に同じ ID になること。poll のたびの uuid4 と本文のハッシュは使わない。メンション一件なら `x:mention:<tweet_id>` の形。

**決める必要があること — 束ねた封筒の ID**: いまのポーリングは、一回のポーリングでペルソナごとに封筒を一つだけ作り、その中にメンション (複数)・新しいフォロワー・エンゲージメントの差分・いいね / リツイートした人・取得エラーを束ねている。一つの封筒に一つの ID を付ける契約なので、次のどれかを選ぶ:

- 封筒を出来事ごと (メンション一件ごと等) に分ける。ID はそのまま X の ID から作れるが、ペルソナに届く通知の回数と、その都度の判断 (on_event) の回数が増える。
- 束ねたまま、束に入っている出来事の X の ID の集合から決定的に ID を作る (例: 種類ごとに ID を並べたものから作る)。同じ束をもう一度返したときに同じ ID になる。本文のハッシュではないので契約には反しないが、束の中身が一件でも違えば別の刺激として数えられる。
- 取得エラーだけを知らせる封筒は、再送という概念の無い内部の出来事として、封筒を作った時点の uuid4 でよい (契約の「内部の一回きりの出来事」)。

あわせて、封筒が作れなかったときにカーソルを進めてしまう並び (上の 3) は、ID の対応とは別に、アドオン側で見直す価値がある。

## 確認手段

隔離環境 (`docs/test_environment.md`) で X アドオンを有効にし、テスト用のアカウントへのメンションで、`[IntegrationManager] 'x_polling' returned 1 events` の行と、ペルソナへのイベントの到着 (`inject_persona_event`) がログに出ることを見る。同じメンションを含む封筒を二度出させたときに、二度目が受領の照合 (`stimulus_receipt`) で弾かれることも見る。
