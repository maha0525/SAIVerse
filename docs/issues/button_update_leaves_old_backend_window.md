# 画面の「Update」ボタンで更新すると、更新の前のバックエンドのウィンドウが空のまま残る

**状態**: 未着手 (2026-10-02 発見。同日まはー裁定「別にほんとに暇な時の対応で良い」— 急がない。ほかの作業が止まっているときの穴埋めに回す)
**深刻度**: P3 — 更新そのものは成功する。利用者の画面に、何も動いていない「SAIVerse Backend」のウィンドウが一つ残り、新しいバックエンドのウィンドウと並ぶので、どれが動いているものか分かりにくい

## 何が起きるか (2026-10-02、v0.3.19 から v0.3.20 へのボタンからの更新を通して確認)

1. start.bat は、バックエンドを「SAIVerse Backend」という題のウィンドウで起動する (`cmd /k "title SAIVerse Backend && ... python main.py city_a"`)。
2. 画面の「Update」ボタンを押すと、バックエンドは自分で終了する。`cmd /k` は中のプログラムが終わってもウィンドウを閉じない作りなので、「SAIVerse Backend」のウィンドウは入力待ちの状態で残る。
3. 更新プログラムは、新しいバックエンドを新しいウィンドウで起動する。画面のサーバーのほうは、古い「SAIVerse Frontend」のウィンドウを更新プログラムが閉じてから、新しいウィンドウで起動する。
4. その結果、更新のあとの画面には、古い「SAIVerse Backend」(空)・新しいバックエンド・新しい「SAIVerse Frontend」の三つのウィンドウが並ぶ。

古いウィンドウは閉じても害は無い。ただ、利用者には「閉じてよいウィンドウ」と「閉じると SAIVerse が止まるウィンドウ」の見分けがつかない。新しいバックエンドのウィンドウには、「SAIVerse Backend」という題も付いていない (python を直接起動しているため)。

## 決めること

- 更新プログラムが、古い「SAIVerse Backend」のウィンドウも閉じるか (画面のサーバーのウィンドウは、すでに閉じている)。
- 新しいバックエンドのウィンドウに、「SAIVerse Backend」の題を付けるか。
