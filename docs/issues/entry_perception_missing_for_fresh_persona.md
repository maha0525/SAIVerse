# 一度も会話していないペルソナで、最初の移動の知覚が丸ごと欠ける

**起票**: 2026-09-07 (まはーの実機所見)
**状態**: 調査待ち (読み取り専用の事実採取から — 設計より先に事実)

## 現象

テスト用ペルソナのテリス (テスト・エリス) で「テリスの部屋 → まはーの部屋 → テリスの部屋」と往復したところ、知覚バッファに**「テリスの部屋 → まはーの部屋」の区間の情報だけ入っていなかった**。まはーの部屋にいる段階で確認しても入っていなかった。アイフィ (会話歴のあるペルソナ) の同型の往復では全区間が入る。

まはーの仮説: 一度も会話したことがないテスト用ペルソナなので、そもそも「テリスの部屋にいた」という情報が最初に書き込まれていなかったのではないか。

## 調査の仮説 (2026-09-07 メティス — どれも未確認)

1. **SAIMemory 未 ready 経路**: 会話歴の無いペルソナは SAIMemory が未初期化で、`push_perception` / `push_room_state` は `self._ready` が偽だと**黙って捨てる** (`saiverse_memory/adapter.py`)。最初の移動の時点で未 ready なら、様子の直接 push が消える。outbox 経由の通知も、配達時の adapter が未 ready なら同じ穴がありうる (配達失敗として再試行に残るのか、捨てるのかは未確認)。
2. **outbox の配送見送り**: 移動の配送中に積まれた通知は再入検知で次の flush 回しになる ([room_state_packages.md](../intent/room_state_packages.md) §11-3)。一度も Pulse が無いペルソナは Beat 関所も来ないので、配送されないまま溜まっている可能性 — ただしこれなら「消えた」ではなく「遅れて出る」はずで、二度目の移動の flush が先送り分を配るはずなので、単独では説明が足りない。
3. Section snapshot の初期化: 初回はセクションの「前回 snapshot」自体が無く、diff (移動通知) が組めない経路。

## 次の一手

`scripts/inspect_world.py` とセッションログ (`backend.log`) で、テリスの移動時刻の push / outbox / ready 状態を読み取り専用で採る。§11 の flush 配り直しが入ると症状が変わる可能性があるため、採取は §11 実装後の再現テストとセットで行うのが効率的。
