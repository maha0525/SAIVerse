# プロバイダタブのキー設定で、Gemini の無料枠のキーを入力する欄が出ない

**状態**: 検証待ち (2026-10-01 にまはーが実機確認で発見し、同日に直した。隔離環境の画面での確認は済み。残るのは、まはーの PR 確認と実機確認)
**深刻度**: P2 — Gemini を無料枠だけで使う利用者は、プロバイダタブからキーを入れられない (環境設定の画面か初回チュートリアルからは入れられる)

## 症状 (2026-10-01、まはーの実機)

Gemini は無料枠のキーと有料枠のキーをそれぞれ設定できる形なのに、プロバイダタブの「キー設定」ボタンを押すと、有料枠のキーの欄しか出ない。

## 原因 (コードを読んで確認)

「キー設定」のパネルは、プロバイダ定義の `api_key_env` (キーを読む環境変数の名前) を一つだけ見て、入力欄を一つ作る。

Gemini のプロバイダ定義 (`builtin_data/providers/gemini.json`) は、キーの変数を二つ持っている。

- `api_key_env`: `GEMINI_API_KEY` (有料枠)
- `api_key_env_alternates`: `GEMINI_FREE_API_KEY` (無料枠)

二つ目の `api_key_env_alternates` (代わりに使えるキーの変数の一覧) は、プロバイダ一覧を画面へ返す API (`api/routes/providers.py`) が返していない。画面 (`frontend/src/components/settings/ProviderManagementPanel.tsx`) も `api_key_env` しか読まない。だから無料枠の欄が出ない。

## 同じ原因で起きている隣の症状 (コードを読んで確認、実機では未確認)

プロバイダ一覧の「KEY OK / キー未設定」のバッジも、`api_key_env` の変数だけを見て決めている。Gemini を無料枠のキーだけで使っている利用者には、Gemini が動いているのに「キー未設定」と表示されるはずである。

## 直し方の案

- プロバイダ一覧の API が、キーの変数を全部 (主の変数と、代わりの変数) 返す。それぞれが設定済みかどうかも返す。
- 「キー設定」のパネルは、変数ごとに入力欄を一つずつ出す。Gemini なら、有料枠 (`GEMINI_API_KEY`) と無料枠 (`GEMINI_FREE_API_KEY`) の二つの欄が並ぶ。取得方法ガイドへのリンクも変数ごとに出す (無料枠のガイドへの対応は画面側に既にある)。
- バッジは、どれか一つでも設定されていれば「KEY OK」にする。

直した後の見え方: Gemini の行で「キー設定」を押すと欄が二つ出て、無料枠だけを入れて保存すると、バッジが「KEY OK」に変わる。キーの変数が一つだけのプロバイダは、今までと同じ見え方のまま。

## 直したこと (2026-10-01)

上の案のとおりに直した。設計の記録は [model_provider_management.md](../intent/model_provider_management.md) §12 の 2026-10-01 追補にある。

- 隣の症状 (無料枠のキーだけだと「キー未設定」と出る) も同じ変更で直った。隔離環境で、無料枠だけにダミーの値を保存するとバッジが「KEY OK」に変わることを確かめた。
- あわせて調べたこと: 同梱の Gemini を画面から編集して作られる上書き定義にも、無料枠の変数は引き継がれる (落ちない)。テストで固定した。

## 経緯

- 2026-10-01: まはーが実機確認で発見。原因を特定して起票し、まはーの GO を受けて、本体とは別の作業ツリー (ブランチ `feature/provider-key-alternates`) で直した。台帳から押し出した旧文面: 「実機確認で、Gemini は有料枠のキーの欄しか出ず、無料枠のキーを設定できないことが分かった。原因は特定済みで、キーの変数を二つ持つプロバイダの二つ目を画面が知らないこと。直し方は issue に書いてある。次 = まはーの GO を受けて直し、隔離環境の画面で確かめる。」(誰待ち: まはー (GO) → 私 (修正))

- 2026-10-01 (レビュー): ローカルのレビューモデルに差分を一巡させ、指摘 5 件の裏を取った。
  - 採用 1 件: 「有料枠」「無料枠」の名前は、欄が二つ以上あるプロバイダにだけ出す。欄が一つのプロバイダ (利用者が自作して `GEMINI_API_KEY` を読ませたものなど) に「有料枠」だけが出るのを避けるため。
  - 裏取りで解消 2 件: 「バッジの基準と、実際に返事を作るときのキーの読み方が食い違わないか」は、`saiverse/gemini_clients.py` が無料枠と有料枠の両方の変数を読むことを確かめて解消。「テストの後始末がモデル定義を読み直していないのでは」は、`reload_providers_and_models` がプロバイダとモデルの両方を読み直すことを確かめて解消。
  - 採らなかった 2 件: 「片方を保存している最中に、もう片方で Enter を押すと何も起きない」は、二重送信を防ぐ既存の作りどおりで、押した側の入力は消えずに残るので、そのままにした。「主の変数が無く代わりの変数だけを持つ定義だと欄が出ない」は、同梱の定義に該当が無く、モデルが使えるかの判定も同じ規則 (主の変数が無ければ代わりの変数も見ない) なので、揃ったままにした。
