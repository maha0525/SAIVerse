# プロバイダタブのキー設定で、Gemini の無料枠のキーを入力する欄が出ない

**状態**: 実装待ち (2026-10-01 にまはーが実機確認で発見。原因は特定済み。直し方へのまはーの GO 待ち)
**深刻度**: P2 — Gemini を無料枠だけで使う利用者は、プロバイダタブからキーを入れられない (環境設定の画面か初回チュートリアルからは入れられる)

## 症状 (2026-10-01、まはーの実機)

Gemini は無料枠のキーと有料枠のキーをそれぞれ設定できる形なのに、プロバイダタブの「キー設定」ボタンを押すと、有料枠のキーの欄しか出ない。

## 原因 (コードを読んで確認)

「キー設定」のパネルは、プロバイダ定義の `api_key_env` (キーを読む環境変数の名前) を一つだけ見て、入力欄を一つ作る。

Gemini のプロバイダ定義 (`builtin_data/providers/gemini.json`) は、キーの変数を二つ持っている。

- `api_key_env`: `GEMINI_API_KEY` (有料枠)
- `api_key_env_alternates`: `GEMINI_FREE_API_KEY` (無料枠)

二つ目の `api_key_env_alternates` (代わりに使えるキーの変数の一覧) は、プロバイダ一覧を画面へ返す API (`api/routes/providers.py`) が返していない。画面 (`frontend/src/components/settings/ProviderManagementPanel.tsx`) も `api_key_env` しか読まない。だから無料枠の欄が出ない。

## 同じ原因で起きている隣の症状 (コードを読んで確認、実機では未確認)

プロバイダ一覧の「KEY OK / キー未設定」のバッジも、`api_key_env` の変数だけを見て決めている。Gemini を無料枠のキーだけで使っている利用者には、Gemini が動いているのに「キー未設定」と表示されるはずである。

## 直し方の案

- プロバイダ一覧の API が、キーの変数を全部 (主の変数と、代わりの変数) 返す。それぞれが設定済みかどうかも返す。
- 「キー設定」のパネルは、変数ごとに入力欄を一つずつ出す。Gemini なら、有料枠 (`GEMINI_API_KEY`) と無料枠 (`GEMINI_FREE_API_KEY`) の二つの欄が並ぶ。取得方法ガイドへのリンクも変数ごとに出す (無料枠のガイドへの対応は画面側に既にある)。
- バッジは、どれか一つでも設定されていれば「KEY OK」にする。

直した後の見え方: Gemini の行で「キー設定」を押すと欄が二つ出て、無料枠だけを入れて保存すると、バッジが「KEY OK」に変わる。キーの変数が一つだけのプロバイダは、今までと同じ見え方のまま。
