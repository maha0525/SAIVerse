# Issue: 編纂は残す量まで「削る」だけで「戻す」がない (水位を上げても既存ペルソナに効かない)

**ステータス**: 🟣 検証待ち (実装完了 2026-07-30、Codex 敵対レビュー 7 巡で approve。正典 = [`arasuji_levels.md`](../intent/arasuji_levels.md) §15)
**優先度**: high (アップデート移行で「生ログほぼ無し」のペルソナが発生するため medium から引き上げ)
**作成日**: 2026-07-30
**関連**: [`arasuji_levels.md`](../intent/arasuji_levels.md) §9 (予算の値) / §13 (編纂入口の一本化) / §14 (冷えたウィンドウの保守) / **§15 (本件の正典)**、[`metabolism.md`](../concepts/metabolism.md)

## 背景

2026-07-30、水位の既定を **上限 12万 → 20万字・残す量 6万 → 10万字** へ引き上げた (まはー裁定)。ところが既存ペルソナには効かない — アンカー (提示ウィンドウの始点) は既に前進していて、水位を上げても提示は遡らない。

さらに (まはー指摘、同日): **アップデート移行の欠陥**でもある。旧設定で運用されたペルソナは新バージョン開始時点でほぼ全メッセージ編纂済み = 生ログがほぼ無い状態で会話が始まる。編纂済みのものが生ログ領域へ戻る経路が無いのは大問題。

## 設計 (確定、詳細は intent §15)

編纂を **「残す量へ揃える」双方向の操作**にする。多ければ削る、少なければ畳んだところを開き直す。

- **機構 4「読み戻し」**: 会話開始時 (§14-3 非常畳みと対称の関門)、提示が残す量を下回っていたら ①窓内の圧縮区間を新しい方から「生で見せる」印 (`presented_raw`) に切替 ②足りなければ一次あらすじの `source_ids` から圧縮区間の記録を合成して anchor を引き戻す (専用書き込み経路、CAS 付き)。
- 記録は消さず印一つ → head のあらすじ枠との二重表示は起きない。再畳みは印戻しだけ (**往復とも LLM ゼロ**)。
- 引き戻しの梯子はあらすじの段だけ (Chronicle 無効ペルソナの忘却済みログを掘り起こさない)。
- 天井は残す量。モデルごとのばらつきは容認。手動巻き戻しボタンは作らない。

## 設計時の裁定記録 (2026-07-30、まはー)

1. 発火点 = **応答前** (会話開始時)。アップデート組が新バージョン最初の会話から厚い生ログで話せる。
2. モデルごとのばらつき (A では戻して B では畳んだまま) = **容認**。

## 次アクション

実機検証 (まはー): 水位引き上げ済みの既存ペルソナに話しかけて、①応答前に生ログが残す量まで開き直されること (`[metabolism] window refill` ログ)、②head のあらすじ枠と提示の二重表示が無いこと、③会話を続けて上限超過したとき印戻し (`refolded ... LLM-free`) が編纂なしで畳むこと。
