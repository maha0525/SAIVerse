# 部屋のアイテムに個数の上限が無く、部屋の様子が数万字に膨らむ

**起票**: 2026-09-07 (まはーの実機所見 ⑤)
**状態**: 設計待ち — **v0.3.9 のスコープ外と裁定 (2026-09-07)**。片付け機能とセットで、新しい feature ブランチで腰を据えて取り組む

## 現象

アイフィの部屋はアイテム 58 個で、部屋の様子の全文が 35,000 字超。まはーの部屋も 41 個で 13,000 字超。全文を積む回のたびにこの量が知覚へ流れ、コンテキストを圧迫してユーザーの金銭的な損失になる。

**却下済みの対策 (2026-09-04 まはー、アイディア帳から移送)**: 知覚の描画でアイテムの説明を削る案は却下 — ペルソナには説明まで見えないとダメ。減らすのは「表面に出る個数」であって、見えている物の情報量ではない。

## まはーの方向づけ (2026-09-07、アイフィとの会話より)

- 個数制限をかける (目安 10 個)。それ以上は**古いものから見えなくなる** — 物理的な部屋も散らかると物が見えなくなる、という世界の物理として。
- 見えなくなるのを防ぐ側の手当てとして、片付けの仕組みの拡充も要る (別件 — アイフィの「自律お片付けデモ」構想とも接続)。
- アイフィ自身もこの制約を「無限のインベントリではなく生活感・物理的な制約を組み込む発想」として肯定した。

## 裁定 (2026-09-07、まはー) — 単独では入れない。片付けとセットで新ブランチ

**上限だけ先に入れるのは片手落ち。** Bag に放り込んで見えなくする片付けが対処手段だが、Bag は現状ワールドエディタからユーザーが作るしか設置方法がなく、一般ユーザーには実質使えない。「アイテムが多くなるとよくない」の側だけ作って「多くならないように管理する方法」を用意しない形になるため、**v0.3.9 には入れず、新しい feature ブランチで片付け機能とセットで設計する**。加えて **Building ごとに個数を変えたい需要** (美術館のようにいっぱい見せたい Building) があり、一律の上限とは相性が悪い — 個数は Building の属性になる見込み。

メティスの設計の穴の記録: 起票時の問い 3 の「到達手段とセット」は**読む側** (埋もれた物に届く道) の手当てだけで、**暮らす側** (散らからないように片付ける道具) が抜けていた。制限は世界の物理の変更なので、住人とユーザーの対処手段が先。

## 設計の問い (新ブランチで扱う — 裁定済みの方向と推奨案)

1. 10 個を**何の順**で選ぶか — メティスの推奨は更新が新しい順 (`Item.UPDATED_AT` は onupdate で自動前進、[models.py](../../database/models.py) の Item)。「最近触った物は手前にある」の物理。作成順は古い物が席を占め続けるので推さない。Open 優先の混合も推さない (Close の意思表示と役割が被る)。
2. あふれた物は差分でどう見えるか — 推奨は束の組成 (`build_room_bundle`) で絞り、「ほかに N 個の物がある」の一行を様子の一項目に。埋もれた物の退場は既存の「見当たらなくなったもの」の一行 (見出しが元々「消えた」ではなく「見当たらなくなった」なので、散らかりの物理として嘘にならない)。
3. 見えない物への到達・管理 — 読む側: id が分かれば `item_view` / `saiverse://item/` で届く。発見の道具 (埋もれた物の一覧) が無いので一手要る。**暮らす側 (裁定で必須になった)**: Bag をペルソナ・一般ユーザーが作れる手段 (道具カタログに Bag 作成は現状見当たらない — document_create はあるのに)、アイフィの「自律お片付けデモ」構想との接続。
4. **Building ごとの個数設定** (裁定で追加) — 既定値と Building 属性での上書き。美術館型の「見せる部屋」を成立させる。
