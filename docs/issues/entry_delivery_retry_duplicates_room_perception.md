# 入室の配送の再試行・遅延が、部屋の知覚を重複・混入させうる

**ステータス**: 🔲 未解決 (起票のみ — 既存の配送機構の性質。v0.3.9 の再設計で悪化はせず、むしろ軽減・自己修復がついた)
**深刻度**: 中〜低 — 発火条件は「入室処理の後段 (フィード配送・head イベント) の失敗による再配送」と「連続移動をまたぐ遅延配送」
**発見**: 2026-09-06、部屋の様子のパッケージ再設計の Codex レビュー六巡目。**再設計が作った穴ではない** — 移動の配送 (outbox) が入室処理を丸ごと再試行する構造は以前からで、部屋の様子の push には昔から重複を防ぐ鍵が無い
**関連**: [on_event_judgment_has_no_idempotency_key.md](on_event_judgment_has_no_idempotency_key.md) (刺激の永続 ID — 同じ族。冪等キーの設計はあちらの裁定に合流するのが自然) / [room_state_packages.md](../intent/room_state_packages.md)

## 二つの形

1. **再試行の重複**: 入室処理は部屋の様子を知覚へ push した後、フィードの入室配送や head イベントを行う。後段が失敗すると配送機構は入室処理全体を失敗扱いにして再試行するが、部屋の push に冪等キーが無いので、再試行のたびに同じ部屋の知覚が積まれる。
2. **遅延の混入**: 配送の荷物は移動時点の行き先を凍結している。A→B の配送が失敗したまま B→C が確定した後に B の再配送が成功すると、C にいるペルソナの知覚へ B の部屋が積まれる。

## v0.3.9 の再設計での変化 (悪化ではなく軽減)

- 再試行の重複は、旧実装では**毎回全文** (1 万字級) だったのが、差分化により Chronicle 有効ペルソナでは「変わっていません」一行の重複まで軽くなった (Chronicle 無効は従来どおり全文)。
- 遅延の混入は、新設の Pulse 頭の照合 (滞在中の検知) が**次の Pulse で自動的に矯正する** — 現在地の束と台帳の最新が食い違えば、正しい部屋の差分/全文が積み直される。旧実装にはこの自己修復が無かった。

## 修正の方向 (着手時に設計)

- 配送の実行 ID を部屋の push の記帳へ渡して重複を排除する (冪等キー — 刺激の永続 ID の設計と揃える)。
- 遅延側は、配送時に正典の現在地と荷物の行き先を突き合わせ、古い入室イベントでは行き先固有の push を行わない。
- どちらも「刺激の永続 ID」issue の裁定 (ID の発行元・冪等の窓) が出てから、その語彙で実装するのが二度手間を防ぐ。
