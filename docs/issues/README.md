# Issues — 未解決の課題 / 後回し事項

このディレクトリは「いまは手をつけないが、忘れずに残しておきたい課題」を記録する場所。
GitHub Issues とは別軸でローカルに完結する課題管理。

## 住み分け

| ディレクトリ | 役割 |
|---|---|
| [`docs/intent/`](../intent/) | 「なぜこう作ったか」「守るべき不変条件」の記録 |
| `docs/issues/` (ここ) | 「未解決の課題」「後回しにした事項」「既知の不具合」 |
| `docs/issues/archive/` | 解決済み issue の保管庫 (履歴は残すが現役 issue とは混ぜない) |

## ファイル命名

トピックベースのファイル名 (例: `no_spell_mode.md`, `phase4_meta_judgment_recovery.md`)。日付プレフィックスは付けない。

## ファイル構成 (テンプレート)

```markdown
# Issue: <タイトル>

**ステータス**: 🔲 未着手 / 🟡 進行中 / ⚠️ 保留 / ✅ 解決済み
**優先度**: low / medium / high
**作成日**: YYYY-MM-DD
**関連**: <intent doc / コミット / コード参照>

## 背景

<なぜこれが課題か>

## 解決案候補

<取りうる選択肢>

## 関連リソース

<コード参照、過去の議論、関連 issue 等>

## ログ

- YYYY-MM-DD: 状況更新
```

## 運用ルール

- **作成**: 後回しにした課題が出たら即書く。詳細を網羅しなくていい、後で自分が読み返して思い出せる粒度で十分
- **更新**: 状況が変わったら「ログ」セクションに追記
- **解決**: ステータスを `✅` にしてから [`archive/`](archive/) に移動。`ls docs/issues/` で残作業だけが見える状態を維持
- **再発**: archive 内の issue が再発したら、archive から戻すか、新規 issue として作る (どちらでも可、文脈で判断)
- **このインデックスは更新不要** — `ls docs/issues/` で十分。手動 index は古くなる
