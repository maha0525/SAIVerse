# 長い導入で、カタログの進捗の小窓が「完了」を受け取れずに回り続ける

**起票**: 2026-10-06 (voice-tts の画面確認で、まはーが実際に踏んだ)
**状態**: 未解決。voice-tts を公開のカタログに載せる前に直す ([voice_tts_catalog_listing.md](voice_tts_catalog_listing.md) の作業に追加)
**関連**: [addon_catalog_management.md](../intent/addon_catalog_management.md) の「導入時の質問と、アドオン専用の Python 環境」

## 何が起きたか

2026-10-06 0 時すぎ、まはーが voice-tts 0.6.0 への更新をカタログから実行した (エンジン三つ全部を選択。ダウンロードは合計で数 GB、約 30 分)。バックエンドは全 step を完了し、アドオンの切り替え・専用環境・答えの保存まで仕上がった (backend.log と `~/.saiverse/addon_install/saiverse-voice-tts/` で確認) のに、ブラウザの進捗の小窓 (AddonInstallProgressDialog) は「更新中」のまま回り続け、完了の表示にならなかった。風呂から戻ったまはーが発見。小窓を手で閉じれば実害は無い。

## 推定の原因 (未検証)

進捗はサーバーからブラウザへ流しっぱなしの接続 (SSE) で届く。30 分級の処理の間にこの接続が切れると (ブラウザのタブが裏に回ったときの節電、接続の時間切れなど)、小窓は切断にも完了にも反応せず、回る表示のまま残ると推定している。どの時点で切れたか (uvicorn のアクセスログの SSE リクエストの終わり方) は未確認。

## 直し方の候補

- 小窓が SSE の切断を検知したら、進行中の操作の有無をポーリングで確かめて表示を立て直す (バックエンドには per-addon の Lock と pending の記録があるので、「まだ走っているか」「終わったか」は問い合わせで分かる)。
- あわせて、切断されても処理自体は続いていて壊れないことを文言で伝える。

## 確かめ方

隔離した環境で、重い step (数分かかる pip など) の途中で SSE の接続を落とし (開発者ツールで切断)、小窓が自力で完了へ到達することを見る。
