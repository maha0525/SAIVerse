# Issue: 時刻の境を二か所とも保存できなかった起動から、保存できた再起動までに届いた真似た文は、自動で変換されうる

**ステータス**: ⚠️ 保留 (受け入れた残余)
**優先度**: low
**作成日**: 2026-10-29
**関連**: docs/intent/system_notice_delivery.md「時刻の境」の「境を守れない場合」、database/system_notice_migration.py (`resolve_cutover`・`_leave_cutover_attempt`)

## 背景

システム通知の移行は、この環境で新しい形式に切り替わった時刻 (境) を `cutover.json` と本体 DB の `execution_ledger` に残し、境より後に作られた行はどの規則に当たっても自動では変換しない。改修の後にユーザーが送った「規則の形を真似た文」を、後の起動で勝手にシステム通知へ変えないための柵である。

新しい版を初めて動かした起動で、この二か所の両方に書けなかったときは、その起動の時刻がどこにも残らない。その起動では移行は何も変換せず、画面に「境を決められない」警告を出す。保存先が直った後の再起動で境が決まると、境はその再起動の時刻になるので、二つの起動のあいだに届いた発言は境より前として扱われ、規則の形を真似た文があれば自動で変換されうる。

2026-10-29、まはーの判断で受け入れた。本体 DB に書けない状態では SAIVerse そのものがほぼ動かないこと、警告で所有者が気づけること、塞ぐには「保存できない状態を見つけたら起動を止める・再起動させる」といった、この穴一つに対して大きすぎる仕組みが要ることが理由。Codex の敵対レビュー 6 巡目の指摘。

## 解決案候補

- 書き込みのできない状態を検知したら、SAIVerse 全体で発言の受け付けを止める (または再起動を促す) 仕組みを入れる。データベースに書けない状態は、この移行に限らず全体の問題なので、入れるなら全体の設計として扱う。
