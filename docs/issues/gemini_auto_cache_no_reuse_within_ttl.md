# Issue: Gemini 自動キャッシュの保持秒数を 1 以上にしても、そのキャッシュは再利用されない

**ステータス**: 🔲 未着手（未解決 — `docs/issues/` 直下にある）
**優先度**: medium（設定が「効いているのに得しない」ため、ユーザーが損をする）
**作成日**: 2026-09-01
**関連**: `llm_clients/gemini.py`（`_auto_cache_wrap`）、`llm_clients/gemini_cache.py`（`GeminiCacheController.ensure`）、`api/routes/config.py`（`/api/config/gemini-auto-cache`）

## 何が起きているか

グローバル設定（環境タブ）の「Gemini 自動キャッシュ（実験的）」に、応答後の保持秒数 N を足した。

- N = 0（既定）: 応答が終わったらキャッシュを削除する。これは自動キャッシュ導入時からの挙動で、期待どおり入力トークンがキャッシュ価格になる。
- N ≥ 1: TTL を N 秒にして作成し、手動削除をやめて Gemini 側の失効に任せる。

ところが **N ≥ 1 にしても、残したキャッシュが次の呼び出しで使われることはない**。つまりユーザーは N 秒ぶんのキャッシュ保存料金を払うだけで、見返りが何もない。

## なぜ再利用されないか

自動キャッシュがキャッシュに焼いているのは「システム指示 + 直近 1 件を除いた会話全部」（`contents[:-1]`）で、送信するのは最新の 1 件だけという作りになっている。会話が 1 ターン進むごとに、キャッシュに焼かれる範囲は末尾に 2 件（ユーザー発言とペルソナの返答）伸びる。

`GeminiCacheController.ensure` はキャッシュの中身が前回と完全に一致したときだけ再利用する。ターンごとに中身が伸びる以上、一致することはない。だから毎回まっさらな作成になり、前回残したキャッシュは誰にも使われないまま TTL で消える。

## どう直すか（案）

キャッシュ済みの前置きが今回送りたい内容の先頭と一致していれば、そのキャッシュを `cached_content` に指定して、はみ出した差分だけを送る、という前置き一致の再利用を入れる。実装の要点は次の三つ。

1. 生きているキャッシュについて「何をどこまで焼いたか」を覚えておく（今は中身のハッシュ 1 個しか持っていない）。
2. 今回の内容の先頭が、覚えている範囲と一致するかを調べる。
3. 一致したら、キャッシュ + 差分だけを送る。一致しなければ従来どおり作り直す。

なお前置きが一致していても、キャッシュの残り寿命が短ければ生成の途中で失効しうる。残り寿命が閾値を切っていたら作り直す、という判断も要る。

## 暫定の扱い

再利用が入るまでは、保持秒数は 0 のままが正しい。UI と `docs/reference/environment-vars.md` に、1 以上は現状お得にならない旨を書いてある。
