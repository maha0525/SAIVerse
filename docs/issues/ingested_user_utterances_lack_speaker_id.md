# 取り込んだユーザー発言に発言者の ID が無く、複数ユーザーで区別できない

**起票**: 2026-09-06 (再会想起の門の修正レビューで Codex とローカルレビューが同着で指摘)
**状態**: 未着手 — 現行の SAIVerse は実質一ユーザー世界なので実害に届かない。複数ユーザーを本気で扱う日の前提工事

## 現象

建物ログからペルソナの履歴へ取り込まれたユーザー発言は `metadata.with = ["user"]` (literal) で、**どのユーザーの発言かの ID を持たない** (書き手: `builtin_data/tools/get_building_messages.py`)。このため、ユーザーを相手にする判定 (今回は再会想起の門 `should_recall_persona`) は「直近にユーザーの発言がある」までしか分からず、ユーザー A の発言がユーザー B の再会想起を抑止する形が構造的に残る。

## 裁定済みの倒し方 (2026-09-06 修正時)

門の側は「取り違えの向きが想起を抑える側 (= 知覚の堆積を防ぐ側) に倒れる」ことをコメントに明記して literal 照合を採用した。誤りの向きが安全側なので、一ユーザー世界では問題にならない。

## 根治の方向

門で捏ねても解決しない — **書き手側 (取り込み) が発言者の実ユーザー ID を `with` に刻む**のが供給源の修正。既存履歴は ID 無しのまま残るので、読み手は両形 (ID あり / literal のみ) を受ける移行期間が要る。着手は複数ユーザー対応が現実の要件になったとき。
