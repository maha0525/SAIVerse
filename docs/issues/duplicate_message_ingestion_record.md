# ユーザー発言の二重取り込みの記録 (2026-07-16〜18、エリス)

**ステータス**: 記録 (発生は過去に閉じている。原因調査は任意 / 他ペルソナの検査は air・aifi 修復時に実施)

## 事実 (2026-07-29 実測、エリス memory.db)

- 全 9,528 通のうち、**同一スレッド・同一発言者・同一内容・同一秒**のメッセージが 2 行ずつ存在するものが **6 組**。全てユーザー発言。
- 発生日は **7/16 (1 組) と 7/18 (5 組)** に集中。7/19 以降の発生はゼロ — 進行中のバグではなく、この 2 日間に閉じた事象。
- 原因は未特定 (当時の送信経路の二重書き込みと推定)。再発していないため深掘りは任意。

## 6 組の行き先と現況 (2026-07-29 特定完了)

生ログ一覧の並びは「時刻順、同時刻は登録順」なので、UI で同じ発言が 2 行並んだとき**下 (後) の行が後から重複登録されたコピー**。全 6 組でこの規則が成り立つことを rowid で確認済み。

- **4 組**: 両方のコピーが**同じ**旧世代あらすじの材料に編纂された。あらすじ本文は自然で、同じ出来事が二重に語られてはいない。
  - 7/17 01:04:51「PC全然発送されない……」 → entry `d57cd1ff` (余剰 = rowid 19312)
  - 7/18 21:48:27「ふたつ気になることがあるなぁ」 / 21:57:47「よしよし、考えてみよう」 / 22:11:20「まだちょっともやもやする」 → entry `8e942b6d` (余剰 = rowid 19390 / 19391 / 19392)
  - 片方を削除しても安全なことをコード全経路で確認済み (下記「材料の一部削除の安全性」)。どちらを消しても同じだが、規則の統一として「下の行」を消すのがよい。
- **2 組** (7/18 21:04:24「うわーっエリス、時間だ！」 / 21:15:03「不正解！？」): コピーが編纂バッチの境界をまたぎ、先のコピー (rowid 19367 / 19371) だけが正規あらすじ `d4fb6d7e` に編纂され、**後のコピー (rowid 19388 = `75de7f31…` / rowid 19389 = `f37970fe…`) が取り残されて豆粒 2 件 (`b48abdf8` / `85e8d1fc`、7/29 02:44 作成) になった**。
  - ⚠️ 豆粒 2 件は本記録の旧版で「UI から削除して解消」と書いていたが、実施前の誤記だった (実測で訂正)。
  - 消すべきは「後のコピーの生ログ行」と「豆粒エントリ」の**両方**。豆粒だけ消すと生ログ行が未編纂に戻り、次の記憶整理でまた豆粒が生える。順序は生ログ→豆粒が安全。
  - **処置の実績 (2026-07-29)**: ①余剰の生ログ 2 行 = ユーザーが UI から削除済み。②「不正解」豆粒が生成していた Memopedia 欠片 5 件 + 欠片埋め込み 5 行 + 豆粒 2 件の arasuji_embeddings 2 行 = 単一 tx で削除済み (トランザクション内検算つき。UI のエントリ削除は欠片・埋め込みに触れないため DB 直接。ページ概要の更新は edit_history 実測でゼロ = 差し戻し不要)。「うわーっ」豆粒の欠片はゼロだった。③豆粒エントリ本体 2 件 = ユーザーの UI 削除待ち (UI 経路は畳み記録の道連れ無効化を含むため、そちらで消すのが正)。

## 材料の一部削除の安全性 (2026-07-29 コード確認)

編纂済みあらすじの source_ids に「削除済みメッセージの id」が残っても壊れない:

- **詳細表示** (`api/routes/people/arasuji.py` の `/arasuji/{entry_id}/messages`): 引けなかった id は黙って飛ばす (`if msg:`)。
- **編纂・穴検知** (`sai_memory/arasuji/bands.py` `_mark_uncompiled_gaps`): 実在する messages 行だけを見るので、削除された行が「未編纂の穴」として再編纂を誘発することはない。
- **境界の端点引き** (`_edge_source_rowid`): 消えた id は単に照合されず、秒の閉区間へ保守側フォールバック。
- **被覆の逆算** (`backfill_coverage`): 欠損 source は「引けた分だけ」で集計する設計 (docstring 明記)。
- **束ね時の生ログ再読** (`_load_messages_by_ids`): `WHERE id IN` なので欠けた分は落ちるだけ。そもそも batch 産の一次あらすじの束ねは本文 (要約テキスト) を使い、生ログは読み直さない。
- **埋め込み**: UI の削除 (`adapter.delete_message`) は message_embeddings も一緒に消す。孤児は出ない。

source_count / message_count の数字は作成時のまま残る (表示上の飾りで、判定には使われない)。

## 教訓 (air / aifi の修復手順に反映済み)

恒等転写の豆粒を「唯一の記憶の欠片だから残す」と判定する前に、**必ず双子検査をする** — 同一内容の重複行が既に他のあらすじに編纂されていれば、豆粒は余剰コピーの残骸であり削除が正しい。エリスではこの検査を怠り、いったん「残す」と誤って提案した (ユーザーの「同じメッセージがもう入っている」という観察が正しかった)。
