# リリース発行の関所の残り: 本物のアップグレードの鎖の検算

**状態**: 未解決 (2026-09-25 起票。着手時期 = 最初のアーリーアクセス版 (v0.4 EA) の発行準備。それまでは実害の出る経路が無い)

## 背景

アーリーアクセス版の配布 ([intent](../intent/early_access_release.md)) で、リリースの自動発行 (タグ push → GitHub Actions) に三つの関所を入れた: タグの版名を Python の版名規格で解析してプレリリースの印を決める / タグと VERSION ファイルの不一致は発行を拒否する / タグが正しいブランチ (正式版 = main、プレ版 = early-access) の上に無ければ発行を拒否する (二巡目レビューの指摘で当初「初回 EA まで先送り」としていたブランチ検査は、非 main ブランチが現存する以上いま入れるべきと判断を改め、同日に実装済み)。残る一点を初回 EA 発行の準備までに入れる。

## 残り: 本物の鎖に対する検算テスト

いまの鎖の検算テスト (`tests/test_upgrade_prerelease_chain.py`) は**合成のハンドラ列**で選定の仕組みを検算している — 本物の rc の辺がまだ存在しないため。これは「正式版が、配った全 EA 版の辺を持ち続ける」という発行規律 (intent §3-5) を自動では守らない。初回 EA 発行の準備で:

1. 発行済みの版名 (安定版と EA 版) の一覧をリポジトリ内に正典化する。
2. その一覧の各版を起点に、実物のハンドラ登録から現行版まで隙間なく・二重なく辺が選ばれることを検査するテストに差し替える。
3. これを発行前の必須手順 (intent §3-5-3 の関所) にする。
