# アラーム・起床就寝の時刻 (TIME_OF_DAY) が書き込み口で検査されず、非ゼロ埋めの時刻が判定を狂わせうる

**発見**: 2026-10-09 (v0.4 段 1 のローカル LLM レビュー指摘 6 の裏取り)
**状態**: 未解決 (段 1 の退行ではなく元からの穴。直す場所は段 3 の管理画面と REST の書き込み口)

## 何が起きるか

スケジュール行の時刻 `TIME_OF_DAY` は "HH:MM" (ゼロ埋め 2 桁) を前提に、起床・就寝の窓やライフの判定で**文字列比較**される。ところが REST の書き込み口 (`api/routes/people/schedule.py` の作成 :128 と更新 :250) は形式を検査せずに保存する — `"7:00"` が入ると `"7:00" > "17:00"` のような誤った並びになり、起床時刻の選択・深夜跨ぎの判定・営業日の解決がずれる。

`scheduled_datetime` (単発の予約) は strptime で検査されているのに、`time_of_day` だけ素通しという非対称。ペルソナのスペル (schedule_add) の経路も同じ。

## 直し方 (段 3 の管理画面の便で)

書き込み口 (REST の作成・更新、schedule_add) で `day_plan.is_valid_hhmm` 相当の検査をかけ、不正な形式は 400 / エラー文で拒否する。既存の不正な行が無いかは、直すときに一度だけ点検する。
