# ペルソナに自分の持ち物と外見が届いていない (2026-09-06 からの退行)

**状態**: 検証待ち (2026-09-25 発見・同日実装。develop へのマージ後に、まはーがアイフィで実機確認する)
**発見**: まはーが「アイフィ (aifi_city_a) はインベントリにアイテムを三つ持っているが、本人から見えているか」と問い、調査で退行を確認した。

## 何が起きているか

2026-09-06 のコミット 8bfbcd96 (部屋の様子をパッケージの束で運ぶ再設計) 以降、どのペルソナの文脈にも次の二つが載っていない。

1. **自分のインベントリの一覧** (アイテム名・`item:N` の参照・開いている写真アイテムの画像など)。
2. **自分の外見の画像** (`[あなた自身（名前）の外見]` と画像添付)。

ログでの確認 (読み取り専用):

- 2026-09-05 の `llm_io.log` には、`### あなた自身（アイフィ）のインベントリ内` の見出しと、その下のアイテム (ラピスラズリのペンダントなど) が載っていた。`（…）の外見]` の行も 5 回出ていた。
- 2026-09-23 と 2026-09-24 の `llm_io.log` には、誰のインベントリの一覧も、誰の外見の行も一度も出ていない。

あわせて、**インベントリの増減の差分通知も消えている**。9/6 に削除された `BuildingItemsSection` が、部屋のアイテムとインベントリの両方の差分 (追加・削除・名前変更・移動) を末尾通知にしていた。部屋のアイテムの差分は「部屋の様子」(知覚) に移ったが、インベントリの差分の移り先は無かった。

## なぜ起きたか (三つの原因)

1. **直接の原因**: 持ち物と外見は、head の中の一通の独立した user メッセージ (旧 `VisualContextSection`、画像添付つき) だけが運んでいた。9/6 の再設計で、部屋の描画を head から知覚 (tail) へ一本化したときに、このメッセージを組み立てる部分ごと削除した。知覚側の「部屋の様子」は、設計の当初から「持ち物は部屋の性質ではなく、移動しても変わらない」として持ち物と自分の外見を載せない作りで、その前提は「head が運んでいる」ことだった。head から外した時点で、どちらからも運ばれなくなった。
2. **判断の失敗**: 旧メッセージを廃止するとき、「部屋の様子は知覚が運ぶから重複」という部屋の観点だけで判断し、**廃止するメッセージが運んでいた中身を全部数え上げて、それぞれの新しい運び手を確かめる**ことをしなかった。持ち物と外見は部屋の話ではないので、部屋の観点の確認から漏れた。
3. **それを通した条件**: 「ペルソナの文脈に最終的に何が載っているべきか」を検査するテストが無かった。各部品のテストは緑のまま、組み上がった文脈から持ち物が消えても何も落ちなかった。9/6 当日の検収も部屋の様子の文面だけを読んでいて、組み上がった head 全体を読んでいなかった。

**再発防止**: 組み上がった文脈 (実際に LLM へ渡るメッセージ列) に対して「ペルソナが自分について知っているべき事実が載っているか」を確かめる境界テストを置く。持ち物と外見に加えて、既存の必須の事実 (コア記憶、スペル一覧など) も同じテストで見る。これは、登録されているのに一度も描画されていなかった章 (`autonomy_modes` など、cached_head_architecture.md §2 の「2 つの関所」の件) や、作業セッションが履歴ゼロで走っていた件 (2026-07-23) と同じ形の欠落も捕まえる。

## 直し方 (まはー裁定 2026-09-25)

**持ち物と自分の外見を、head の中の独立したメッセージとして戻す。** システムプロンプトには入れない — 画像を添付できるのは独立したメッセージだけだから。途中の小さな変化は、他の章と同じく末尾のシステム通知として届け、head を組み直すときに本体へ取り込む。

### 仕様

- head pipeline に新しい Section を一つ足す。一つのメッセージが「自分の外見」と「インベントリ」の両方を持つ。
- **置き場**: `_compose_messages` で、システムプロンプトのメッセージと Memory Weave のメッセージの**後ろ**に、独立した `role: "user"` のメッセージとして置く (9/6 以前の旧ビジュアルコンテキストと同じ位置)。画像は旧実装と同じく `metadata.media` (`path` / `mime_type` / `type`) で添付する。メッセージを識別するマーカーを metadata に付ける。
- **本文の形** (出力例、アイフィの場合):

  ```
  <system>
  # あなた自身
  以下は、あなた自身の外見と、あなたが持っているアイテムです。持ち物は移動してもあなたと一緒にあります。

  ## 外見
  [あなた自身（アイフィ）の外見]
  saiverse://persona/aifi_city_a/image

  ## インベントリ
  [item:291] [Image] ラピスラズリとイタリアガラスのペンダント（まはーからの贈り物）
  (Open)
  作成日時: 2026-05-09 04:06
  saiverse://item/291/image
  …(アイテムの説明)

  [item:…] …
  </system>
  ```

  アイテム 1 件の描き方は、部屋のアイテムと同じ `_render_item_entry` をそのまま使う (同じ物が二つの見え方をしないように)。インベントリが空なら「インベントリにアイテムはありません。」と書く。外見の画像が設定されていないペルソナは「## 外見」の節ごと省く。「現在」「リアルタイム」のような、head が凍結されることと矛盾する言葉は書かない。
- **撮り直しの時機**: 他の Section と同じ (Metabolism・anchor TTL 切れなど)。移動では撮り直さない。
- **差分通知**: head を撮り直すまでの間の変化は、`diff_to_notifications` で末尾通知にする。対象は、インベントリへのアイテムの追加・インベントリからの削除 (手放した・置いた・消えた)・名前の変更、それと外見の画像の変更。追加されたアイテムと変わった外見には、描画と同じ画像を `NotificationLabel.media` で添付する。通知の文例:
  - 「インベントリにアイテム「X」(item:N) が加わりました」
  - 「インベントリからアイテム「X」(item:N) がなくなりました」
  - 「インベントリのアイテム「X」(item:N) の名前が「Y」に変わりました」
  - 「あなたの外見の画像が変わりました」(新しい画像を添付)
  - 「あなたの外見の画像が外されました」(外見の設定が外されたとき。文だけ)
- **読み失敗の扱い**: インベントリと外見の DB の読みが失敗した回は、capture が例外として上げ、pipeline が前の値を据え置く。凍結される head に「持ち物なし」「外見なし」を焼かないため。画像ファイルが無いのは読み失敗ではなく「外見が無い」状態として扱う (一時的な失敗ではないので、例外にすると外見もインベントリも永久に撮り直せなくなる)。
- **既存の head への反映**: 既に保存されている head には新しい Section が無い。`ensure_snapshot` の欠損補完 (`recapture_missing`) で次の Pulse から足されることと、そのときに通知の既読基準 (B) が初期化され、初回に全アイテムを「加わりました」と通知しないことを確かめる (cached_head_architecture.md C8)。
- 新しい Section は `required` にしない (失敗したら degrade して head から欠けるだけ。人格の同一性を担う Section ではない)。

## 検証

- 単体: Section の capture / render / diff、`_compose_messages` の置き場と画像添付。
- 境界: 実際の `prepare_context` の出力 (LLM に渡るメッセージ列) に、合成ペルソナのインベントリのアイテム名と外見の行・画像が載ること。上の「再発防止」のテスト。
- 隔離環境 (隔離した `SAIVERSE_HOME` + 合成ペルソナ) で組み上がった文脈を書き出し、メインが読者として読む。本番のペルソナには触らない。
- 実機確認は develop にマージしたあと、まはーがアイフィで行う。

## 経緯

- 2026-09-25: まはーの問いから調査し、9/5 と 9/23 以降のログを比べて退行を確定した。置き場について、私が最初に「head の章として戻す」と書いたのを、まはーが「システムプロンプトに入れると画像添付が機能しない。独立したメッセージとして置くべき」と正した。旧実装も独立した user メッセージだったことをコードで確かめ、その形で戻すことにした。
- 2026-09-25 (レビュー): ローカルレビューの指摘から、外見の DB 読み失敗が「外見なし」に化ける穴を塞いだ。Codex の敵対レビューの指摘から、外見が外されたときの通知を足した (DB 読み失敗が上がるようになったので、空を「外された」と言えるようになった)。採らなかった指摘: 画像ファイルが無いときに例外にする案 (永続的な状態なので、例外にすると撮り直しが永久に止まる) と、同じパスの画像の差し替えを内容で検知する案 (アップロードは毎回別の名前で保存されるので起きない)。通知の配送の仕組み全体に向けた指摘 3 件 (並行時の二重登録、既読基準の保存失敗の無視、台帳なし経路の部分失敗での再送) は、今回の変更より前からある性質で、全部の差分通知に共通するので、この PR では扱わない。
