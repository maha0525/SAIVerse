# Issue: 短期記憶 → 長期記憶の選別（システム通知を入口で止める）

**ステータス**: 🔲 未着手
**優先度**: medium
**作成日**: 2026-05-29
**関連**: `docs/overview/landscape.md` §6、`docs/intent/session.md`、Chronicle 生成（`sea/runtime.py` の Metabolism 経路）

## 背景

俯瞰地図 (`docs/overview/landscape.md`) を作る過程で、**Session = 短期記憶** という整理が明確化された。短期記憶（Session）に流入する情報は複数ある:

- SAIMemory（長期記憶）のチャットログ末尾
- head
- 現 Pulse 内の各 Beat（Spell 結果込み）
- Building の未読メッセージ
- **システム通知**（入室・退室・アイテム増減などの状態変化）

問題は、**短期記憶に入る情報がすべて長期記憶に残るべきとは限らない**こと。特に **システム通知** は「その場で分かればいい」情報であり、長期記憶（Chronicle / messages）にメッセージとして残す意義が薄い。

現状は **Chronicle 生成時にシステム通知メッセージを除外** している。しかしこれは「一度長期記憶側に入れてから、圧縮時に除外する」形であり、二度手間かつ整理が綺麗でない。

## 解決案候補

- **入口で選別する**: システム通知は短期記憶（Session）には載せるが、**そもそも長期記憶（SAIMemory の messages）側に渡さない**ようにする。これにより Chronicle 生成時の除外ロジックが不要になる
- システム通知の「短期記憶のみ / 長期記憶にも残す」の判定基準を定義（種別ごと？ 重要度フラグ？）
- 影響範囲調査: システム通知メッセージの生成箇所、`log_message` の tag、Chronicle 生成時の除外ロジック（現状どこで除外しているか）
