# Windows で画面の「Update」ボタンから更新すると、画面側の部品の入れ替えで必ず失敗する

**発見**: 2026-09-30 (Discord の kotori さんの報告。v0.3.16 と v0.3.18 への更新で二回続けて発生)
**状態**: 🔲 未解決 (実装済み・検証待ち)
**深刻度**: P1 — Windows で start.bat から起動している全ユーザーで、ボタンからの更新が毎回失敗する。失敗したあとは SAIVerse が止まったまま戻らず、次に起動すると画面のビルドが通らない

## 何が起きるか (時間順)

1. 画面の「Update」ボタンを押すと、バックエンドが止まり、更新プログラム (`scripts/update_engine.py`) が別のプロセスとして動き始める。
2. 画面を配っているサーバー (start.bat が「SAIVerse Frontend」の窓で立てた `next start`) は止まらない。更新プログラムには、このサーバーが動いているかを調べる処理が無い。
3. 動いている画面のサーバーは、`frontend/node_modules/@next/swc-win32-x64-msvc/next-swc.win32-x64-msvc.node` を開いたまま使い続けている (2026-09-30、まはーの手元で動いている `next start` のプロセスが読み込んでいる部品の一覧で確認)。
4. 更新プログラムは `npm ci` を実行する。`npm ci` は `frontend/node_modules` を丸ごと消してから入れ直す。Windows では、別のプロセスが開いたまま使っているファイルは消せないので、`npm ci` は EPERM で失敗する。そのとき、使われている一つのファイルだけが残り、他の部品は全部消える (2026-09-30、検証用に作った小さな npm のプロジェクトに同じ部品を置き、別のプロセスで読み込んだまま `npm ci` を実行して再現)。`next` もここで消える。
5. 更新プログラムはコードを元の版へ戻し、もう一度 `npm ci` を実行する。画面のサーバーはまだ動いているので、これも同じ理由で失敗する。そして元の版を起動し直す処理が無いので、SAIVerse は止まったままになり、画面の「Updating」の表示が回り続ける ([updater_failure_leaves_backend_stopped.md](updater_failure_leaves_backend_stopped.md) と同じ欠陥)。
6. ユーザーが PC を再起動すると、ファイルを使っていたプロセスが無くなる。start.bat は起動前に「更新が途中で止まっていないか」を調べるが、そこで確かめているのは `frontend/node_modules` のフォルダが在るかどうかだけ。ほぼ空のフォルダを「完了」と判定して先へ進むので、`npm run build` が「'next' は、内部コマンドまたは外部コマンド……として認識されていません」で失敗する。

まはーの手元の `self_update.log` にも、ボタンからの更新が最後まで通った記録は一件も無い (記録は全部、SAIVerse を止めてからの手動更新)。

## 直し方 (2026-09-30 まはーと合意: 両方やる)

1. **本筋 — 更新の途中で画面のサーバーも止め、部品を入れ直してから立ち上げ直す。** バックエンドが止まったあと、この SAIVerse フォルダの `frontend` で動いている画面のサーバーを探して止める。`npm ci` の後、本番モードで動いていたなら画面をビルドし直し、バックエンドと同じように立ち上げ直す。途中で失敗して元の版へ戻したときも、元の版のバックエンドと画面を立ち上げ直す。
2. **保険 — 起動時の確認を「必要な部品が全部入っているか」まで厳しくする。** `frontend/package.json` が必要とする部品が `node_modules` に一つずつ入っているかを確かめる。一つでも欠けていれば「更新が途中」と判定し、start.bat / start.sh が自動で更新を仕上げる。

## 移行上の注意 (リリースノートに必須)

ボタンを押したときに動く更新プログラムは、**更新する前の版**のもの。だから、この修正を含む版へボタンで上げようとすると、古い更新プログラムが同じ場所で失敗する。**この修正を含む版へは、Windows では SAIVerse を全部閉じてから update.bat で更新してもらう**必要がある。リリースノートにこの一文を載せる。

## 経緯

- 2026-09-30: kotori さんの報告から原因を特定。kotori さんには、SAIVerse の窓を全部閉じてから update.bat をダブルクリックする手順を案内した。
- 2026-09-30: 直し方 1・2 を実装。作業用フォルダで start.bat と同じ形の画面の窓を立て、更新プログラムの関数でそれを見つけて止めた (本体の画面のサーバーは対象に入らないことも同時に確認)。部品を使っていたプロセスが消えたあと `npm ci` は通り、ビルドと、新しい見える窓での立ち上げ直しまで通った。`next` を抜いた `node_modules` で起動時の確認が「更新が途中」と判定することも確かめた。ボタンを押してからバックエンドと画面が立ち上がり直すまでの一続きは、本物の更新元が要るので未確認。ローカルレビューの指摘から、起動時の確認で `devDependencies` を数えない形に改めた (`NODE_ENV=production` の `npm ci` が入れないため、数えると起動のたびに更新をやり直し続ける)。
- 2026-10-01: PR #339 が develop にマージ済みだったので、台帳の行を「発行後にボタンから更新して確かめる」へ進めた。台帳から押し出した旧文面: 「修正はブランチにあり、画面のサーバーを止めて部品を入れ直し、立ち上げ直すところまでは本物のプロセスで確かめた。次 = まはーが PR を確認し、リリース後にボタンから一度更新して、元どおり立ち上がるかを見る。」(誰待ち: まはー (PR の確認))
