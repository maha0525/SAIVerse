# Issue: 未読の発言の取り下げと、記憶への転記が競合すると、取り下げた発言が記憶に残る

**ステータス**: 🔲 未着手
**優先度**: low
**作成日**: 2026-10-29
**関連**: builtin_data/tools/get_building_messages.py (`_append_and_mark`)、database/building_messages.py (`withdraw_building_message`)、docs/intent/system_notice_delivery.md「確認待ちの行の確定」

## 背景

建物の履歴から記憶への転記は、ラウンドの頭で建物の履歴を読んだ写しで動く。所有者がまだペルソナに読まれていない発言を取り下げた (`withdraw_building_message`) とき、その取り下げが転記の「建物の行の読み直し」より後で、記憶への追記より前に割り込むと、取り下げた発言が記憶に追記される。

システム通知の追補 (2026-10-29) の作業で、読み直しで建物の行が見つからないときは追記しない形にした (読み直しより前に取り下げが終わっていれば塞がる)。読み直しから追記までの間の割り込みは残っている。この競合はその作業より前から取り下げ機能にあったもので、Codex の敵対レビュー 4 巡目 (2026-10-29) が指摘した。

## 解決案候補

- 取り下げと転記が同じ排他 (記憶 DB の錠、または本体 DB の行の状態の比較つき更新) を通る形にする。
- 転記が記憶へ追記した後に、建物の行がまだあるかを確かめ、無ければ追記した行を消す (後始末の形)。

## 関連リソース

- 転記の停止規律と照会の順序は builtin_data/tools/get_building_messages.py の `_append_and_mark` の docstring にある。
