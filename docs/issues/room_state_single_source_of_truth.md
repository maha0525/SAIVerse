## 残っている二重の経路 (head 照合では消えない)

1. head は前の部屋 (例: まはーの部屋) を見せている状態で、エリスの部屋へ移動する。
2. 入室時、head は別の部屋を見せているので照合相手にならず、エリスの部屋が**全文**で知覚に積まれる (正しい動作 — このときは二重ではない)。
3. その後 TTL 切れ (20 分) か Metabolism で head が再構築され、head にもエリスの部屋の全文が入る。
4. **この瞬間から head と知覚バッチが同じ部屋の全文を二枚見せる。** 知覚バッチは確定済みで後から縮められない (縮める形は §10.8 の移管の土台と正面衝突する)。

バージョン移行とは無関係に、「初訪問 (または久しぶりの部屋) + head の再構築」の組で恒常的に起きる。

## 構造の診断

**部屋の様子の置き場が二つある** (head の Visual Context / 知覚バッチ) こと自体が供給源。2026-09-05 の一連の欠陥 (head との全文重複・送る head と判定用 head のずれ・head 本文と知覚記法の二重読み) はすべてここから湧いた。head 照合 (§10.8.1) はその例外処理であり、供給源を閉じれば族ごと消える。

## 提案 (2026-09-05 まはー)

head の Visual Context (部屋の様子の描画) を退役し、**部屋の様子は知覚 (tail) だけが運ぶ**。v0.3.9 で tail 側の管理 (差分・移管・依存の連なり・合計上限・省略の印) が綿密になったので、受け皿は育っている。成立条件は二つ:

1. **「今いる部屋の様子」を絶対に提示窓の外に出さない** — 編纂や省略で窓外に出そうなとき、そのメッセージだけ tail 最上部 (窓の最古端) で食い止める。実装の当たり: 編纂と省略の対象から「今いる部屋のバッチ」を除外し、畳みで期間が窓外へ出る回だけ、どうせ割れるその瞬間に相乗りして置き直す (新しいキャッシュの壊れ時点を作らない)。
2. **初めて喋るときに、その部屋の様子が知覚に入っている保証** — 入室 push は既にあるので、足すのは起動直後・ブートストラップ (入室イベントなしで会話が始まる) の一点。

## 評価 (メティス、2026-09-05 — 賛成)

1. 二重の族が構造ごと消える (上記の診断)。
2. head 照合の機構 (§10.8.1: head 土台の差分・model ごとの開き直し・pin の受け渡し) を丸ごと退役できる — 「例外処理が本体を覆い始めたら供給源を塞いで機構ごと消す」(CLAUDE.md 把握可能性) の適用。
3. **キャッシュはむしろ改善**: いまは head 再構築のたびに部屋の様子ぶんの前方一致が割れる。tail に追記して動かさない方が優しい。
4. 成立条件は v0.3.9 で育てた機構の自然な延長で作れる。

## 設計で詰める点

- **画像 (media) の運び方**: head の Visual Context は部屋の画像実体を運んでいた。tail 一元での media の置き場と画像埋め込み上限との整合。
- 初回保証の正確な置き場 (起動時 push か、最初の組成での不足検知か)。
- 移行: head の構成変更なので全ペルソナのキャッシュが一回割れる (一回きりの移行コスト)。旧 snapshot との互換。
- ツールとしての `get_visual_context` (スペル・head 以外の利用) は残る — 退役は head のセクションだけ。
- 「割れ時点の統一」(会話の畳みと知覚の省略の相乗り案、まはー考え中) と同じ主題なので、一緒に設計すると収まりが良い。
