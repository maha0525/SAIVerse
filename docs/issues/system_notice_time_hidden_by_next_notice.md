# システム通知 (移動ログ) の時刻が、次の通知の箱に覆われて読めない

**ステータス: 未解決 (修正済み・検証待ち)** — 2026-09-21 起票。v0.3.13 を使っているユーザーからの報告。

## 症状 (報告者の観察)

移動ログ (🚶 User Action の灰色の箱) が連続して並ぶと、各ログの下に出るはずの時刻が、
次のログの箱に上半分から全部まで隠れて読めない。ブラウザを拡大しても隙間ごと広がるだけで
隠れたまま。連続の最後の 1 件だけは、次が普通の発言なので見える。

## 調べて分かったこと

### 報告者の見立ては、ある条件の下でだけ成立する

報告者は「`.systemNotice` の上下のマイナスの余白で通知どうしが約 0.7rem 重なり、
`.note-box` の `opacity: 0.85` のせいで後のログの箱が前のログの時刻の上に描かれる」と
書いていた。**この仕組み自体は正しい。** ただし成立するのは、通知が並ぶ親
(`.chatArea`) の隙間が効いていない環境に限る。

`.chatArea` は縦並びで `gap: 1rem` (16px) を持っており、その中で `.systemNotice` が
上下に -0.35rem (合わせて -11.2px) 食い込んでいた。差し引き **4.8px 空く** ので、
隙間が効く環境では重ならない。報告者が手元で切り出した HTML には親のこの隙間が
無かったため、マイナスの余白だけが残って重なったのだと思われる。

### 再現できなかった

開発機 (Windows, Chromium 系, 隔離環境) で移動ログを 6 件連続で並べて実測したところ:

- 通知どうしの間隔は 4.8px で、重なっていない。
- 時刻の上・中・下の 3 点で最前面にあるのは時刻自身で、何も被っていない。
- ダークとライトの両方、広い画面と狭い画面 (375px) の両方で同じ。

v0.3.13 と develop で `page.module.css` と `globals.css` に差分は無いので、
報告者が動かしているのは実測したのと同じコードである。**どの環境差が親の隙間を
無効にしているかは特定できていない** (縦並びの `gap` を持たない古いブラウザなら
説明がつくが、確認していない)。報告者のブラウザとバージョンが分かれば確定できる。

### それでも直す理由 — 失敗の仕方が「黙って消える」だった

親の 16px の隙間から 11.2px を食って 4.8px を残す作りは、その予算がずれた瞬間に
**時刻が黙って読めなくなる**。レイアウトが窮屈に見えるだけなら気づけるが、情報が
消えるので気づけない。実際に親の隙間を 0 にして測ると -11.2px の重なりになり、
時刻の下 2/3 が次の箱に覆われて、報告どおりの見え方になった。

同じ書き方が `.continuedBubble` (同じペルソナの続きの吹き出しを `margin-top: -0.7rem`
で引き上げる) にも残っていた。こちらも隙間が消えれば前の吹き出しの文字を覆う。

## 直したこと (`frontend/src/app/page.module.css`)

行間を「親の隙間を子がマイナスで削り返す」形から、**隣り合う二行のあいだに置く正の余白**へ
置き換えた。負の値が一つも無くなるので、親の隙間がどうであれ重なりようがない。

- `.chatArea` の `gap` を 0 にし、`.chatArea > * + *` 系の規則で行間を決めるようにした。
- `.systemNotice` の `margin: -0.35rem 0` と `.continuedBubble` の `margin-top: -0.7rem` を撤去した。

見た目の間隔は従来と同じになるよう合わせてある (実測で確認):

|  | 変更前 | 変更後 |
|---|---|---|
| 通常の発言どうし | 16.0px | 16.0px |
| 通常の発言と通知のあいだ | 10.4px | 10.4px |
| 通知どうし | 4.8px | 4.8px |
| 同じペルソナの続きの吹き出し | 4.8px | 4.8px |

## 検証 (2026-09-21、Claude が隔離環境で実施)

`test_fixtures/` の隔離環境 (バックエンド 18000 / フロント 18010、合成ペルソナ、自律 OFF、
本番の `~/.saiverse` には未接触) で、ユーザーを二部屋のあいだで 6 回行き来させて移動ログを
連続させた。

- 変更後、`.chatArea` の配下に負の余白を持つ要素は一つも無い。
- 上の表の 4 つの間隔がすべて変更前と一致した。
- 時刻は 3 点とも最前面のままで、画面でも読める。
- 「親の隙間が効かない環境」の模擬 (隙間を 0 にする) で、変更前は -11.2px の重なりと
  時刻の被覆が出たが、変更後は間隔が保たれ時刻も被覆されない。

**まはーの実機と、報告者の環境での確認が残っている。** 報告者の環境でも直っているかは、
原因の環境差が特定できていない以上、報告者の確認をもって初めて言える。

## 三つの原因 (CLAUDE.md「After a failure we caused」)

1. **技術的な原因**: 行間を、親が配る隙間と子が返すマイナスの余白の差で作っていた。
   差が 4.8px しかなく、予算がずれると重なる。
2. **判断の失敗**: 「隙間を詰める」を実装するとき、詰めた結果の余裕がいくらになるか、
   その余裕が足りないと何が起きるかを見ていない。窮屈になるだけだと思っていたが、
   実際には行の一番下にある時刻が消える作りだった。
3. **仕組みの条件**: 行間は数値で書かれているだけで、どこにも「重なってはいけない」が
   表明されていない。負の余白はレビューでも機械検査でも咎められないので、危うさが
   誰の目にも留まらなかった。

## 歯止め

負の余白を無くしたこと自体が歯止めになっている (正の値だけでは重なりが作れない)。
`.chatArea` のコメントに理由を残したので、次に詰めたくなった人が同じ形に戻しにくい。
ただし **他のコンテナで同じ形が新しく書かれることは止められていない** — それを機械で
止めるなら、負の margin を禁止する lint 規則のような別の仕掛けが要る。いまは無い。
