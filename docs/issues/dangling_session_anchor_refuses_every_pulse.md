# 起点が記憶に無い発言を指していると、そのペルソナは話しかけるたびに見送られ続ける

**状態**: 実装中 (2026-09-29 着手)
**起票**: 2026-09-29 (Discord の利用者 kotori さんの報告。v0.2 系から v0.3.16 へ一気に上げたあと、ペルソナ紬さんに話しかけるたびに「記憶の窓を用意できなかったため、この応答を見送りました。次に話しかけると再試行します。」が出て、一言も返らない)
**関連**: `sea/session_lifecycle.py` `resolve_metabolism_anchor` / `get_presented_window` / `_assert_anchor_message_exists`、`database/migrate.py` `_backfill_session_anchors`、前例 [window_floor_unmet_on_v02_memory_db.md](window_floor_unmet_on_v02_memory_db.md)

## 症状

診断ツール (floor_diag) の出力で確定した事実:

- 19:33 の起動で、更新の記録が「0.0.0 → 0.3.16」(v0.2 系からの直行) になっている。
- 20:13 以降、紬さん (`紬_city_a`) への話しかけ 8 回がすべて見送られた。同じ時間帯に、もう一人のイオさんは普通に会話できている。
- 見送りの理由はすべて同じ一行:
  `RuntimeError: anchor cde81e67-1574-406f-a241-ad85fbf7d4d4 is missing from messages (persona=紬_city_a model=claude-sonnet-4-5)`

## 原因

1. 起点 (session_anchor 行の ANCHOR_MESSAGE_ID) は「会話の窓がどの発言から始まるか」の印で、世界の DB (`saiverse.db`) にある。発言そのものはペルソナごとの `memory.db` にある。二つは別のファイルなので、起点が指す発言が記憶から消えても、起点は自動では直らない。
2. 返事の前の最終防衛ライン (`ensure_window_floor`) は窓を厳格に読み、起点の発言が記憶に無いと例外にする (`_assert_anchor_message_exists`)。例外は「床が確立できない」として見送りになる。
3. 起点が書き直されるのは返事が成功したあとだけなので、一度こうなると返事は二度と成功せず、起点も二度と直らない。見送りのメッセージの「次に話しかけると再試行します」は、この場合は果たされない約束になっている。
4. 紬さんの起点は v0.2 時代に記録されたものと推定する (v0.3 が起点を書くのは返事の成功後だけで、診断ファイルの範囲で紬さんの返事は一度も成功していない)。v0.2 の `AI.METABOLISM_ANCHORS` は `_backfill_session_anchors` で中身を確かめずに session_anchor へ写される。その発言がなぜ記憶から消えたかは、診断ファイルからは分からない。

起点が壊れる経路は v0.2 からの持ち込みに限らない。記憶の画面から発言やスレッドを消しても、削除処理は起点を直さない (`SAIMemoryAdapter.delete_message` / `delete_thread`)。

三つの原因の整理 (CLAUDE.md「After a failure we caused」):

- **近因**: 起点が実在しない発言を指したとき、厳格な読みが例外にし、それを直す経路が無い。
- **判断の失敗**: 最終防衛ラインを厳格にしたとき、「読めなかった」と「帳簿そのものが壊れている」を同じ扱いにした。前者は一時的で再試行に意味があるが、後者は何度試しても同じで、再試行の約束が成り立たない。
- **通した条件**: 起点の帳簿と発言が別ファイルにあり、「起点は実在する発言を指す」という約束を守る持ち主が決まっていなかった。

## 修正の方針 (2026-09-29 まはー GO)

起点を使う入口 (`resolve_metabolism_anchor`) で、起点が指す発言が記憶に実在するかを確かめる。実在しないと**確かに分かった**起点は「無かったこと」にする — その行を消し、そのモデルで初めて話すときと同じ道 (編纂の最前線 / 他モデルの起点の借用 / 最小ロード) で窓を始める。WARNING を残す。

- 起点を使う入口の一か所で確かめるので、v0.2 からの持ち込み・発言やスレッドの削除・その他どの経緯で壊れた起点も同じように拾える。v0.2 から写すとき (`_backfill_session_anchors`) にも確かめる案は採らない (まはーへの初回説明から変更)。写す側で確かめるには世界の DB の移行処理から各ペルソナの記憶ファイルを開いて回る必要があり、使う側の確認と役割が重なるため。
- 確かめる照会そのものが失敗したときは、消さない (厳格な読みでは例外のまま、既定の読みでは起点をそのまま使う)。「無い」と分かったときだけ消す。
- 起点を書き換えるのは本番の読み (`persist_advance=True`) のときだけ。プレビューの読みは同じ結果を返すが行は触らない。

## 検証

- 回帰テスト: 起点が実在しない発言を指す行 → 解決が「行なし」と同じ結果を返し、行が消え、WARNING が出る / プレビューでは消えない / 照会の失敗では消えない / 他モデルから借りる起点も同じ扱い / 別スレッドにある実在の発言は消さない / 最終防衛ラインが "unmet" にならない。
- 隔離環境で、実在しない発言を指す起点を持つ合成ペルソナに話しかけ、見送られずに返事が返ることと、起点の行が作り直されることを確かめる。

## 経緯
