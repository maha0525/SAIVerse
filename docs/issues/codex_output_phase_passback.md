# Issue: Codex の返答の分け方 (phase) を、次の呼び出しへ送り返す

**ステータス**: 🟠 実装中 (2026-10-19 まはー GO)

## 何が起きうるか

Codex (GPT-5.3-Codex 以降) は 1 回の返答を、途中の独り言 (`phase: "commentary"`) と
最終回答 (`phase: "final_answer"`) の複数のメッセージに分けて返す。SAIVerse は
それを `_iter_chunks` で全部つないで 1 つの発言にし、`phase` を捨てて保存している。
次の呼び出しでは、過去の自分の発言が「区切りの無い 1 つのメッセージ」として
`_build_input` から送られる。

その結果、モデルは過去の自分の発言の形をまねて、1 つの独り言の中に独り言と
最終回答をまとめて書き、さらに最終回答として同じ文をもう一度書くことがありうる。
SAIVerse はそれを全部つなぐので、利用者には本文が丸ごと二回続いて見え、独り言と
最終回答の両方に書かれた Spell 行は二回実行される。

2026-10-03〜16 の an nin さんの報告 (本文の全文重複、同じ `document_edit` が
1 発言に 4 回) はこの形で説明がつく。ただし an nin さんの環境での原因は未確定
([codex_stream_diagnostics.md](codex_stream_diagnostics.md))。まはーの環境の
正常な返答 3 回 (2026-10-19) では、独り言 1〜2 個 + 最終回答 1 個に分かれて
届いており、重複は無かった。起こりうる原因として、確定を待たずに手当てする
(2026-10-19 まはー裁定)。

OpenAI の公式リファレンスも、gpt-5.3-codex 以降では assistant メッセージの
`phase` を残して送り返すよう求めている (落とすと性能が落ちる)。

## 手当て (二つとも入れる)

1. **分け方を保存して送り返す**: Codex のクライアントが、返答ごとに
   メッセージ単位の本文と `phase` の並び (`output_phases`) を報告する。SEA は
   思考の記録 (`reasoning_details`) と同じ道で、それを保存する発言の
   `metadata` に載せる。`_build_input` は、`metadata.output_phases` をつないだ
   本文が送る発言の本文と完全に一致するときだけ、発言を `phase` 付きの複数の
   メッセージに分けて送る。一致しない発言 (古い発言・編集された発言・途中で
   止まった発言など) は今まで通り 1 つのメッセージで送る。
2. **Codex のモデル設定のシステムプロンプトに、表示と実行の規則を書く**
   (文面はまはーの起草):
   「この環境では応答の各phaseは並んでひとつのメッセージとしてユーザーに
   表示される。commentaryとfinal_answerに表示上の区別はない。Spell機能は
   commentary内でも有効である。commentaryにスペルを書いた場合、その場では
   実行が留保されfinal_answer後に実行される。二重実行を避けるため、
   commentaryに書いたのと同じスペルをfinal_answerに再度書いてはいけない。」

## 守ること

- **本文は変えない**: 表示・保存・Spell 実行に渡す本文は今まで通り全メッセージを
  つないだもの。重複の除去もしない (正当な繰り返しを消さないため)。
- **送る内容の過去部分を書き換えない**: 分けて送るのは `output_phases` を持つ
  新しい発言だけ。古い発言の送り方は変わらないので、キャッシュが一斉に外れない。
- **一致しなければ黙って今まで通り**: 分け方の対応がつかないときは `output_phases`
  を付けない / 使わない。壊れるとしても今の挙動に戻るだけにする。
- **Spell の周**: 保存される本文は「最初の Spell 行より前の文 + Spell 行
  (正規化済み) + 最後の Spell 行より後ろの文」に組み直される。各部分が元のどの
  メッセージに属していたかを、元の本文の中の位置で対応づけて `output_phases` を
  作る。同じ周の次の呼び出しへ渡す発言 (`_round_message_for_next_call`) にも載せる。
- Codex 以外のクライアントは何も変わらない (`consume_output_phases` は既定で None)。

## 確認の旅程

- 単体: `_iter_chunks` の報告 (独り言 + 最終回答、`phase` 欠落、delta 無し done のみ)、
  Spell の周の対応づけ (Spell 行が独り言だけ / 最終回答だけ / 両方 / 間に文がある)、
  `_build_input` の分割と不一致時の後退。
- 隔離環境: 合成ペルソナと偽の Codex 応答で 2 往復させ、2 回目に実際に送られる
  入力で、1 回目の発言が `phase` 付きで分かれていることを読んで確かめる
  (保存 → 履歴の組み立て → `_build_input` の境界を跨ぐ)。
- 実 API: Codex バックエンドが assistant メッセージの `phase` を受け付けるかは、
  まはーの承認を得た隔離環境の 1 往復でだけ確かめる。
