# 抽出の「空振り」はモデルの揺らぎで起き、起きても検知できない

**発見**: 2026-08-29 (v0.3 実機検証中。エリスの Chronicle に Fragment が付かない件の調査で判明)
**状態**: 未解決 (v0.4 向けの品質案件 — 門は塞がない)
**深刻度**: P3 — 機構は設計通りに動いており、失われる知識も将来の会話で再登場すれば拾われる

## 症状

Chronicle 編纂時の知識抽出 (`sai_memory/memory/entity_extractor.py`) が、
抽出すべき新知識が実在するチャンクに対して `entities: []` を返すことがある。
空リストは「抽出するものが無かった」という**正常な成功**なので、失敗の付箋
(`entity_extraction_backlog`) には載らず、拾い直し機構の対象外。知識は静かに落ちる。

## 実測 (2026-08-29、エリス実データでの A/B 実験)

- 対象: 当日編纂されたチャンク eb31a4b6 (〜8/19、21 メッセージ)。Elyth の新キャラ
  「ミュゼ」「ザリ・ロブステル」の初登場を含み、抽出すべき新知識が実在した。
- 本番の抽出呼び出し (gemini-3.5-flash-lite) は `entities: []` を返した (llm_io.log で確認)。
- 同じ材料・同じプロンプト・同じクライアント工場で 6 回再実行したところ、
  **6 回全部が 2〜4 件の entities を返した** (二人のキャラを毎回抽出)。
  本番の空は再現せず、出力の揺らぎの尾を引いた可能性が最有力。
- 対照: 中身が薄いチャンク 4a5cafae (〜8/17、甘え・朝の挨拶のみ) は 2/2 で空 —
  こちらは恒久的属性フィルタ (5/28〜) の仕様通りの空で、正常。
- 併せて棄却したもの: B2 欄 (involved_entities、8/21 相乗り) が entities を
  書きづらくしている説 — B2 ありでも 3/3 で非空。

## なぜ検知できないか

「知識があるのに空」と「本当に何も無い空」は、応答の形が同一 (`entities: []`)。
区別には内容の再判定が要り、それ自体が二回目の LLM 判断になる。

## 対処の候補 (裁定待ち)

1. 抽出モデルの格上げ、または thinking 引き上げ (揺らぎの尾を細くする)。
2. 「会話メッセージが N 件以上あるのに空」の回だけ一度だけ再試行する
   (空同士なら確定空。コストは薄い期間には発生しない)。
3. 受容 — 落ちた知識は将来の再登場で拾われることに賭ける (現状)。
