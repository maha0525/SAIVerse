# 部屋のアイテムの開閉 (Open/Close) を同室のペルソナで共有してよいか

**状態**: 未着手 (2026-07-13 にまはーが自律行動 v2 の設計から切り離した論点。2026-10-09 に v2 の課題ハブを閉じるとき、v2 の撤去と無関係に生き残る項目としてここへ切り出した)
**出どころ**: [autonomous_v2_post_live_gaps.md](archive/autonomous_v2_post_live_gaps.md) の B2
**関連**: [room_item_display_cap.md](../intent/room_item_display_cap.md) (部屋の様子の量の上限 — 量の側はこちらで手当て済み)

## 何が起きているか (2026-07-13 時点の観察)

自律行動で作られたドキュメントのアイテムが、すべて Open (開いた状態) で作られる。すぐ見えること自体は良い。

## まはーが疑った前提

- ずっと開きっぱなしだと、部屋の様子 (Visual context) を圧迫する。
- Building の中に複数のペルソナがいるとき、**開いた状態を全員で共有してしまうのは妥当か**。Memopedia のページでは「開く・閉じる」と「読む」の概念が整理されたのと同じように、アイテムの開く・閉じる・読むも一度整理すべき。
- 「変化したときに中身を見せれば十分」と思っていたが、移動などで一度にまとめて処理したときに全部が見えるのはどうか、という懸念もある。

## 2026-07-13 の裁定 (まはー)

自律行動 v2 の設計とは関わりが薄いところに課題が多いので、本設計からスコープアウトし、別の issue で扱う。

## その後に変わったこと

- 部屋の様子の量は、部屋のアイテムの個数の上限 ([room_item_display_cap.md](../intent/room_item_display_cap.md)、2026-09-13 実機合格) で抑えられた。圧迫の懸念のうち量の側はこちらで手当て済み。
- 開いた状態を同室のペルソナで共有することの是非と、開く・閉じる・読むの整理は手付かず。

## 次の一手

まだ決まっていない。着手するときは、いまの開閉の実装 (誰の操作で、どこに保存され、誰の部屋の様子に出るか) を読んでから、まはーと「開いた状態は誰のものか」を決める。
