# Issue: キャッシュ保管料の返金が、前払いした時点ではなく返金する時点の料金設定で計算される

**ステータス**: ⚠️ 保留 (既知の不具合として記録。直す予定は今のところ無い)
**優先度**: low
**作成日**: 2026-10-12
**関連**: [`docs/intent/cache_lifecycle_control.md`](../intent/cache_lifecycle_control.md) の「日付別料金と保管費の見積もり」、PR #384 (日付による料金切替) の Codex 敵対レビュー、`saiverse/usage_tracker.py` の `record_cache_storage_refund`、`llm_clients/gemini_cache.py` の `_refund_continuous_storage`

## 背景

Gemini の継続キャッシュの保管料は、作った時点で寿命 (TTL) の全部を前払いとして記録し、
寿命より早く消したときは、使わなかった残りの時間の分を負の金額で返金として記録する。

返金の金額は、返金するその時点で読み込まれているモデルの料金設定から計算している。
前払いしたときの単価や金額は、キャッシュごとには覚えていない。そのため、キャッシュを
作ってから消すまでの間 (寿命は最長 20 分) に、そのモデルの料金設定を書き換えると、
返金が前払いより多くなり、前払いと返金の合計が負になりうる。通貨の欄も返金時点の
設定から取るので、その間に通貨を書き換えると、前払いと別の通貨で返金が記録される。

Codex の再現: 1M tokens・寿命 300 秒のキャッシュを、割引期間が終わる 60 秒前に作って
前払いは $0.075。その後に期間の設定を消して、10 秒後に削除すると返金は $0.0806 になった。

料金設定を書き換えない限り、前払いと返金は同じ料金表 (期間による切り替えも含む) から
計算されるので、返金は前払いの中に収まる。起きる条件は「キャッシュの寿命の間に誰かが
料金設定を手で書き換える」ことだけなので、実害はほぼ無いと判断して直していない。
この性質は PR #384 より前 (継続キャッシュの返金が入った時点) からある。

## 解決案候補

- 前払いしたときの料金の区切りと単価・通貨・金額を、キャッシュごとに覚えておき、
  返金はそこから未使用の区間について計算する。返金の合計が前払い額を超えないように
  上限をかける。
