# 接続テストの上流エラー本文が資格情報を反射し得る

**状態**: 検証待ち（隔離回帰まで完了。コードレビュー・実機確認待ち）
**発見**: 2026-10-03、[PR #350 再レビュー](https://github.com/maha0525/SAIVerse/pull/350#issuecomment-5966385486) の範囲外として分離
**関連設計**: [モデル＆プロバイダ管理](../intent/model_provider_management.md)

## 修正前の条件と影響

`api/routes/providers.py` の `_run_connection_test` は、上流の非 200 応答に対して `HTTP {resp.status_code}: {resp.text[:200]}` を `ConnectionTestResponse.error` に返す。上流が受け取った資格情報を応答本文の先頭 200 文字内に反射した場合、その値が SAIVerse の接続テスト API 応答に載る。

長さ制限は秘匿化ではない。表示や応答のコピー先へ資格情報が広がるおそれがある。ただし実際の漏えい事故を確認した記録ではなく、条件付きのコード上の経路である。接続先の信頼検査と、返ってきた本文を安全に表示する責務も別であり、前者を迂回する必要はない。

## 対象経路

- 保存済み provider の `POST /api/providers/{provider_id}/test`
- 作成・編集フォームの `POST /api/providers/test`

両方が共通の `_run_connection_test` を使う。不正な provider 定義の診断から値を除く #350 の修正とは別の経路で、同 PR で解消したとは扱わない。

## 発見時の隔離再現案（当時は未実行）

1. 一時 HOME / SAIVERSE_HOME と synthetic provider を使い、HTTP transport を fake にする。
2. fake が非 200 と、先頭 200 文字内にダミーの機密マーカーを含む本文を返すようにする。本物の資格情報は使わない。
3. 接続テストの API 応答 `error` に同じマーカーが残ることを調べる。外部サーバーへ資格情報を送らず、応答例にも実値を載せない。

## 発見時の検討事項

上流本文をそのまま返さず、利用者に必要な HTTP ステータスと安全な説明をどう残すかを決める。本文の一部を表示する案なら、資格情報・未知の機密情報を安全に扱える境界を先に定義する。受け入れ条件は、反射する fake 応答でも API / UI にダミーマーカーが出ないことと、通常の失敗原因を判断できること。

## 修正内容（2026-10-03）

保存済み provider / 作成・編集フォームの共通関数で、HTTP コードと固定の説明だけを返す形にした。401（認証）、403（権限）、429（利用制限）、5xx（プロバイダ側の障害）を区別し、その他は URL・プロトコルの設定確認を促す。上流本文・reason phrase は読まず、既知の API キーだけを伏せる方式にも頼らない。

同じ関数の接続・通信・予期しない例外、JSON 解析ログ、送信前の設定拒否、未対応 protocol の表示も見直し、任意の値や例外本文・traceback を転載しない固定文にした。成功時のモデル一覧と、200 の JSON が読めなくても疎通成功を返す既存挙動は維持する。接続先・資格情報の送信可否の検査は変更していない。

**範囲の限界**: 保護するのは接続テストの API 応答と、その実装が出す診断ログ。httpx の通常 INFO アクセスログなど、HTTP ライブラリが別途出す URL の記録まで秘匿化する変更ではない。並行処理に影響する全体 logger の一時的な抑制は行わない。API の成功応答に載るモデル ID は従来どおりプロバイダのデータであり、任意の成功データを秘密かどうか判定するものでもない。

## 隔離検証

`tests/test_provider_connection_test_errors.py` は一時 HOME / SAIVERSE_HOME、合成 provider、httpx の fake transport を使い、保存済み / フォーム両方の API を通す。

- 修正前コードで fake が返したダミー資格情報・未知の機密マーカー・URL が応答へ反射し、回帰テストが失敗することを確認した。
- 修正後は OpenAI / Ollama 互換の 301/400/401/403/404/429/500/502/503、接続失敗・タイムアウト・通信・予期しない例外、JSON 解析失敗、モデル一覧の型不正でも、API 診断と自前ログへマーカーや例外本文が出ない。
- 成功時のモデル一覧、200 で不正な JSON を受けた場合の既存挙動、送信前の不正 URL 拒否も確認する。送信先の信頼判定は実処理を通し、DNS だけを合成回答にする。
- 本物の資格情報・外部通信・LLM・本番ペルソナは使用しない。実ブラウザ表示と実プロバイダでの確認は未実施。
