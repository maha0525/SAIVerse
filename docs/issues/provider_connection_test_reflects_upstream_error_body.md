# 接続テストの上流エラー本文が資格情報を反射し得る

**状態**: 未着手
**発見**: 2026-10-03、[PR #350 再レビュー](https://github.com/maha0525/SAIVerse/pull/350#issuecomment-5966385486) の範囲外として分離
**関連設計**: [モデル＆プロバイダ管理](../intent/model_provider_management.md)

## 条件と影響

`api/routes/providers.py` の `_run_connection_test` は、上流の非 200 応答に対して `HTTP {resp.status_code}: {resp.text[:200]}` を `ConnectionTestResponse.error` に返す。上流が受け取った資格情報を応答本文の先頭 200 文字内に反射した場合、その値が SAIVerse の接続テスト API 応答に載る。

長さ制限は秘匿化ではない。表示や応答のコピー先へ資格情報が広がるおそれがある。ただし実際の漏えい事故を確認した記録ではなく、条件付きのコード上の経路である。接続先の信頼検査と、返ってきた本文を安全に表示する責務も別であり、前者を迂回する必要はない。

## 対象経路

- 保存済み provider の `POST /api/providers/{provider_id}/test`
- 作成・編集フォームの `POST /api/providers/test`

両方が共通の `_run_connection_test` を使う。不正な provider 定義の診断から値を除く #350 の修正とは別の経路で、同 PR で解消したとは扱わない。

## 隔離再現の概要 (未実行)

1. 一時 HOME / SAIVERSE_HOME と synthetic provider を使い、HTTP transport を fake にする。
2. fake が非 200 と、先頭 200 文字内にダミーの機密マーカーを含む本文を返すようにする。本物の資格情報は使わない。
3. 接続テストの API 応答 `error` に同じマーカーが残ることを調べる。外部サーバーへ資格情報を送らず、応答例にも実値を載せない。

## 修正前に決めること

上流本文をそのまま返さず、利用者に必要な HTTP ステータスと安全な説明をどう残すかを決める。本文の一部を表示する案なら、資格情報・未知の機密情報を安全に扱える境界を先に定義する。受け入れ条件は、反射する fake 応答でも API / UI にダミーマーカーが出ないことと、通常の失敗原因を判断できること。

本記録はコード読解のみ。実装修正・追加回帰・実機検証は未着手のため、進行中台帳には載せない。
