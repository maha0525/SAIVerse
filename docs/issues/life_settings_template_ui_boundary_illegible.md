# ライフ設定と習慣テンプレートの縄張りが UI で見えない (食い合って見える)

**ステータス: 未解決・設計論点** (2026-08-08 起票。時間割実機検証の Step 2 でまはーが発見)

## 症状 (まはーの体験)

ペルソナメニューに「ライフ設定」(起床・就寝・予算) と「習慣テンプレート」(コマの並び) が兄弟モーダルとして並び、どちらも「一日の形」を決める画面に見える。実際に触ると両者がガッツリ食い合っているように感じられる。

## 設計上の縄張り (intent の言い分)

- **ライフ = 一日の窓の持ち主** (起床・就寝・予算。PersonaSchedule / life.md)
- **テンプレ = 窓の中のコマの骨格** (穴あきのコマ並び。timetable_redesign §5.1)

重複ではなく層の関係として設計されている。

## 問題の芯

二つは裏で強く結合している — テンプレのコマ並びの順序基準は「起床時刻を一日の起点とした流れ順」(`_template_order_key`、当日確定ライフ > PersonaSchedule) で解釈されるため、**ライフ側で起床時刻を変えるとテンプレの並びの解釈が変わる**。しかし UI は互いの情報を一切表示しない別モーダルで、この結合が不可視。

まはーが「食い合っている」と見えた時点で、把握可能性の設計制約 (CLAUDE.md) に照らしてこの見せ方は不合格。設計の言い分が正しくても、層が層に見えなければ器の負け。

## 検討の方向 (まはーと議論して決める)

1. テンプレ編集画面にライフの窓 (起床・就寝) を枠線・背景として描き、コマがその中に置かれる関係を可視化する
2. ライフ設定とテンプレを「生活リズム」一画面に統合する (窓の設定とコマの骨格を同じタイムライン上で編集)
3. 最低限: 両モーダルに相互参照 (「起床・就寝はライフ設定で」「コマの並びは習慣テンプレートで」) と、起床時刻変更がテンプレの解釈に効くことの明示

隣接: アイディア帳「スケジュール UI の日常語化」「起床・就寝をペルソナ自身が設定できるように」— 統合するならこれらと同じ改修面。
