# ツールが失敗した回は、画面の実行履歴とノード単位の記録に残らない

**状態**: 未着手 (2026-09-11 起票)
**起票**: 2026-09-11 (Unity Gateway の削除の Codex レビュー二巡目の指摘。削除とは別件として記録した)
**関連**: `sea/runtime_engine.py` の `lg_tool_node`、`sea/runtime_nodes.py` の `lg_tool_call_node`、[Unity Gateway の削除](unity_gateway_removal.md)

## 何が起きているか

playbook のツールのノードが成功した回と失敗した回で、残る記録が違う。

- **成功した回**: ノード単位の記録 (`log_sea_trace`、`sea_trace.log` に出る) に一行が残る。playbook の名前が `meta_` / `sub_` で始まらなければ、画面の実行履歴に使う一覧 (`state["_activity_trace"]`) に一件が足され、画面へ `status: "completed"` の出来事 (`event_callback` の `type: "activity"`) も送られる。
- **失敗した回** (ツールが例外を出した回と、呼ぶツールが見つからない回): `state["last"]`、出力先の変数、PulseContext、次の LLM への通知には「Tool error」が書かれ、`backend.log` に例外のログが出る。けれど、ノード単位の記録にも、画面の実行履歴の一覧にも何も残らず、画面への出来事も送られない。

どちらの経路 (`tool` ノードの `lg_tool_node` と、関数呼び出しの `lg_tool_call_node`) も同じ形だった (2026-09-11 にコードを読んで確認)。

## 困ること

- 画面の実行履歴を見ても、失敗したツールのノードは表示されない。成功したノードだけが並ぶので、失敗が起きたことに気づきにくい。
- `sea_trace.log` でノードの流れを追っても、失敗したノードが抜けて見える。原因は `backend.log` の例外のログを別に探さないと分からない。

## 決める必要があること

直すには、失敗した回を画面にどう見せるかを先に決める必要がある。

- 画面の実行履歴に、失敗したノードを `status: "error"` のような状態つきで出すか。
- フロントエンドが `completed` 以外の状態を受け取ったときにどう表示するかは、まだ確かめていない。

## 経緯

- 2026-09-11: Unity Gateway の削除で、呼ぶツールが見つからない回を「None という結果の成功」ではなく失敗として記録するように直した。その結果、見つからない回も上の「失敗した回」の記録の形になった (直す前は、中身が None の成功として実行履歴に残っていた)。同じ変更の Codex レビュー二巡目がこの記録の差を指摘した。画面の見え方の仕様が要るので、削除の PR では直さずにこの issue に記録した。
