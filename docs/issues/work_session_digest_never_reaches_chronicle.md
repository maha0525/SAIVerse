# 作業セッションの記憶が Chronicle に入る道が無い (転写の発火条件が構造的に成立しない)

**発見**: 2026-07-28 (あらすじ処理の総点検中。air/aifi の実データで裏付け)
**状態**: 未解決 (原因特定済み・修正方針は設計判断が要る)
**種別**: バグ (W4 改修内の二規則の矛盾)
**関連**: [2026-07-28 あらすじ処理の書き起こし](../handoff/2026-07-28_arasuji_pipeline_audit.md) §7-10、[user メッセージのエピソード無帰属](user_messages_missing_episode_attribution.md)、`docs/intent/experience_structure.md` §4-4

## 症状

作業セッション終了時にペルソナが書く要約 (session_digest 行) が、**長期記憶 (Chronicle) に入る道を持たない**。

- 恒等転写 (`digest_origin='episode'` — 確定済みの要約をあらすじの席に置き写す機構) は、**全ペルソナで発火 0 件** (2026-07-28 実測)。前提となる「digest 確定済みの closed 出来事」は air 31 件 + aifi 2 件が実在し、air は新世代の編纂 (batch 7件) も通っているのに 0
- 旧世代 (W4 以前) は要約行を普通の材料として編纂していた (air で 12 件が旧世代あらすじに現存)。W4 でこの経路は除外規則により閉じられた
- air で 6 件の要約行が、既に Chronicle 被覆の最新端より古いのにどのあらすじにも覆われていない (漏れの疑い。アンカー位置との厳密な突き合わせは未実施)

## 原因 (特定済み)

置き写しの発動条件は「**編纂の材料の中で、その出来事に帰属するメッセージに出会うこと**」(`sai_memory/arasuji/alignment.py` の `_segment_by_digest` — メッセージの `origin_episode` が digest index に載っていれば転写チャンクを立てる)。

ところが、作業セッションの出来事に帰属するメッセージは編纂の材料に一つも届かない:

1. **作業中の実行ログ**: `scope='volatile'` / `line_role='sub_line'` — メインラインに乗らず、編纂対象からも除外
2. **要約行そのもの**: `session_digest` タグが `CHRONICLE_EXCLUDED_TAGS` (`sai_memory/memory/storage.py:1894`) に入っており、材料から抜かれる
3. **user 発言**: 別 issue の穴で、どの出来事にも帰属していない

引き金になれる名札付きメッセージがゼロ件のため、判定自体が一度も発生しない。

**除外規則 (2) と置き写し機構は同じ W4 改修で一緒に入った。** 除外の目的は §4-4「同一レベルの再圧縮禁止」(要約を再要約して劣化させない) だが、実装が「要約を材料から消す」になり、再圧縮だけでなく**置き写しの引き金ごと**消した。目的 (再圧縮させない) と手段 (視界から消す) の取り違え。二つの規則を突き合わせる検算が設計時に無かった。

## 影響

- 作業セッションでペルソナが何をしたかの記憶が、提示から古くなって退場した時点で長期記憶から消える。自律稼働 (v2) を本格化するほど、失われる体験が増える
- 退場の適用側は「編纂対象を含まない畳み範囲は吸収のみで退場させる」ため、要約行は**あらすじ化されずに黙って提示から出る** (書き起こし §2-4 の既知の欠けと同根)

## 修正方針の候補 (設計判断が要る)

1. **要約行を転写の正規材料にする** (本筋と思われる): `session_digest` を「LLM 束ねに混ぜてはいけないが、転写の引き金・材料にはなる」扱いに変える。除外の目的 (再圧縮禁止) は「転写で置く」ことで満たされる — 消すのではなく写す。要約行が `origin_episode` を持っているかの確認が必要 (持っていなければ配送 handler で刻む)
2. 代替: 置き写しの発動をメッセージ遭遇でなく **digest index (出来事の時間範囲) 起点**に変える。ただし編纂の入力契約が変わるので影響範囲が広い
3. **取り残された既存の要約行** (air 6 件ほか) の後追い回収をどうするか — 修正後の編纂が自然に拾える形か、一度きりの修復が要るか
4. 本 issue は対症でなく、[書き起こし §7-10] の「体験→記憶の川の全体像を正典化する」再設計の一部として扱う選択肢もある (まはー裁定待ち)

## 再現・検証 (読み取り専用)

- 転写ゼロの確認: 各ペルソナの memory.db で `SELECT json_extract(metadata,'$.digest_origin'), COUNT(*) FROM memopedia_pages WHERE category='chronicle' GROUP BY 1` — `episode` が無い
- 前提の実在: world DB (saiverse.db) で `SELECT PERSONA_ID, COUNT(*) FROM episodes WHERE STATUS='closed' AND DIGEST_REF LIKE 'message:%' GROUP BY 1`
- 取り残し: air の memory.db で session_digest タグの行のうち、どの level-1 あらすじの source_ids にも入っておらず、Chronicle 被覆の最新端より古いもの
