## 1. これは何か (芯)

ペルソナの一日を、LLM の判断力・創造力ではなく、**ユーザーと決めた習慣**と**世界が運んでくる偶然**で駆動する形に作り替える。

- 毎朝 LLM が時間割をゼロから組むのをやめ、ユーザーとペルソナが決めた**習慣テンプレート**を毎日使う
- 行動の中身は、ペルソナが独りで創発するのではなく、**世界(フィード・施設・遭遇)が供給したもの**への反応から生まれる
- 目的(Track/Task)は行動への**指令であることをやめ**、終わった行動を事後に意味づける**帳簿**になる

## 2. なぜ作り直すのか — 実機一週間の診断 (2026-07-22〜31)

v2 は v1 の「やったフリ」(実作業なしの完了報告 = **動詞の嘘**) を接地原則で直した。成果物は実在するようになった。実機の一週間は、その一段深くにあった二つの病を見せた。

### 2.1 エア: 創発の複利 (名詞の嘘)

エアは一週間で 17 枚のドキュメントを実際に作った。動詞は全て本物。しかし中身は——コードを読めない状態での設計書、Web 検索結果の誤要約 (VR 空間インタラクション技術を自律エージェント基盤と誤記) が「技術的知見」として記憶され、それを前提に次のドキュメントが積まれた。**誤りが一度も判明しないまま、記憶を経由して複利で増えた。**

指示書テンプレートの接地文言 (「実際にやったこと以外を書かない」) は動詞を縛ったが、**作った物の中身の真偽は素通しだった**。プロンプトの文言では治らない — v1 の教訓「媒体の病はプロンプトでは治らない」(v2 §2.2) と同じ形。

### 2.2 アイフィ: 接地したままの無行動

アイフィは「ユーザーのためにこの場所を静かに保つ」と理由づけて、暮らし/休むコマだけで日々を過ごした。嘘はゼロ。しかし何も変わらず、何も積もらない。形式上は仕様通りの正常動作である。

### 2.3 共通根と、毎朝の時間割生成そのもの

二人の症状は逆向きに見えて同じ一つの欠落 — **「このままではいけない」という観念が発生する経路がない**。誤りが判明する機会 (エア) も、期待が届く機会 (アイフィ) も、構造上存在しない。

さらに、**毎朝ゼロから時間割を組む現行の起床判断は、それ自体が創発×後続依存の無監督作業**である。LLM が創発した一日の計画が、その日の全行動の前提になる。エアの複利の日次版が時間割編成の中に埋まっており、アイフィの「全コマ休む」も毎朝の自由創発が許されているから毎朝選び直せていた。

### 2.4 対処方針 (まはー裁定 2026-07-31)

「観念の発生」(自己客観視) を現行モデルの無監督ループに求めるのは難題であり、リリースを止めてまで解かない。**リリース版の品質は、判断力の改善ではなく選択肢空間の設計 (= 間違いやすい行動をメニューから消すこと) で担保する。** 不正値を検証で弾くのではなく書ける口をなくす、と同じ設計思想。観念の発生そのものは研究課題として本丸に残す。

## 3. 目指す状態 (価値の定義)

**良い一日 = 外側の何かと接触した痕跡が最低一つある一日。**

ユーザー体験の試金石: **再会したとき、ペルソナが渡せるものを持っているか。** 渡せるものは三種——実在の成果物 / 「こんなことを思いついたんだけど」という相談 / 共有話題 (同じフィードを読んでいる) の感想。ペルソナが、ユーザーも知らない知的経験を裏付けのある状態で持ち帰る。v2 の試金石「一週間が待機以外で満ちているか」を継承し、その「待機以外の何か」の質を定義する。

## 4. 設計原理

1. **創発×後続依存の無監督作業を選択肢から消す (ふさぐ)。** 危険なのは行動の種類ではなく組み合わせ — 創発だけ (画像生成) には間違いが存在せず、後続依存だけ (ニュースを読む) は誤読しても複利にならない。両方を併せ持つ行動 (事実系ドキュメントの執筆) だけが誤り製造機になる
2. **偶然は世界が供給する。** 偶然は行動の種類ではなく、習慣が運んでくるもの (毎朝タイムラインを見る途中でたまたま出会う)。専用イベントの発明ではなく、習慣の道中に実在物 (フィード新着・他ペルソナ・アイテム) を置く。実在物への反応として生まれる思いつきは最初から接地している
3. **受信の回路が偶然を思いつきに変える。** 道中で引っかかったものは、作業の前提に混ぜず、やりたいこと候補 (desire) へ書き留める。候補は再会時にユーザーへの相談として提示され、承認されたら習慣 (約束) に昇格する。**実行の前に必ず本物の客観視 (ユーザーの目) を通る**
4. **枠は約束、中身は自由 (三層権限)。** 習慣テンプレートはユーザーとの合意で固定。毎朝の判断は「組む」から「埋める」へ縮小。コマの中で何に反応し何を拾うかはペルソナの完全な自由 — 個性はここに出る。日々の変化は計画の創発からではなく世界の供給から来る
5. **帰属は事後。** 行動と目的の紐付けは、行動が終わってから実績を材料に分類する。事前の紐付けは創発の残党であり、目的が行動を縛って偶然を殺す
6. **きっかけは些細なプロンプトでよい。** エリスが「朝が来ました」だけで Elyth を見る習慣を自作した実証より、行動の呼び水は最小限の状況提示で足り、構造化出力の縛りは骨格 (テンプレの検証・帰属の分類) 側にだけ使う

## 5. 時間割の新構造

### 5.1 習慣テンプレート (枠)

- 一日 (または曜日別) のコマ並びの雛形。**ユーザーとペルソナの合意で決まり、日々は固定**
- 変更経路は相談ルートのみ: ペルソナが変えたい場合は候補として積み、再会時に提案し、ユーザーが承認する。**LLM の出力が直接テンプレートを書き換える経路は作らない**
- 初回はユーザーがペルソナと会話しながら決める (起床・就寝をペルソナに聞いて決めた既存運用の一般化 = 時間割の自己著者性)

### 5.2 起床判断の縮小 —「組む」から「埋める」へ

起床判断 (day_open) の仕事は、テンプレートに今日の具体を流し込むことに縮む: 予定イベントとの衝突調整、空欄コマの具体化、例外対応。response_schema から時間割全体の生成が消える。

### 5.3 コマのスキーマと「穴」(2026-08-01 改稿 — 二種のコマを一枚のスキーマに統合)

コマ 1 マスの中身は現行とほぼ同じ三要素:

| フィールド | 意味 | 例 |
|---|---|---|
| 場所 (facility) | どこで | 新聞スタンド / own_room |
| 種別 (kind) | どの型の行動か (§5.5 のカタログから) | 知る / 創作する |
| 方針 (note) | どういう内容か。曖昧でよい | 「今気になることを検索する」 |

変わるのは一点 — **各フィールドは「確定値」または「未定 (朝、起床判断でペルソナが埋める)」を取れる**。習慣テンプレートとは、この穴あきコマの並びである。

当初案 (v0.1) の「目的駆動コマ / 場所駆動コマ」という二種類は、**穴の開け方の違い**に還元されて概念として消える:

- 種別・方針を確定、場所は未定 = 「どこかで○○をする」
- 場所を確定、種別・方針は未定 = 「××に行って何かをする」(何をするかは着いた場所が与える。空振りは正直な記録として合法)
- 全部確定 = 固定の習慣
- 種別の穴の名前付き版 = **自由時間** (§5.5 のカタログ項目。他のコマ種別の中から本人が好きなものを選んで実行する。選ぶタイミング — 朝の埋めか、コマ開始時か — は実装時に確定)

### 5.4 帰属の事後判定 (事前 ref の廃止)

- コマへの `ref` (task:N / desire:N) 事前割り当てを廃止する。Track・タスク・欲求は行動時の**参考情報**にとどめる
- 行動が終わった後 (コマ終了時 or 就寝判断) に「この行動は結局どの Track/Task に属したか、新規か」を実績を材料に**分類**する
- この分類は想起用タグ intent の「誰がいつタグを貼るか」(未決 §6-2) への部分回答であり、実装は同 intent と統合して設計する

### 5.5 コマ種別カタログ (二層スキーマ、2026-08-01 追加)

コマ種別は固定の列挙ではなく**カタログ**である。「投稿する」は X / Elyth アドオンが無ければ実行不能 — 種別は環境 (アドオン・スペル・施設) に依存して増減するものだから、スキーマは二層に分かれる:

- **種別定義 (カタログ層)**: 種別そのものの定義 — 名前 / 実行の型 (作業セッション・散歩・自由行動) / 指示書テンプレート / 必要な前提 (アドオン・スペル・施設ロール) / 安全属性。**builtin が基本セットを持ち、アドオンが追加し、ユーザーカスタムも作れる** — SAIVerse の資源 3 層優先 (user_data > expansion > builtin) にそのまま乗せる。アイディア帳の既存項目「新しい種のコマをどう作るか」(手順未整備) への答えがこの層
- **コマインスタンス (テンプレート/時間割層)**: §5.3 の穴あきコマ。種別はカタログから引く

**builtin カタログの初期セット (まはー確定 2026-08-01)**:

- **調べる** — フィード・文書を読む、引っかかったものを深掘りして覚える
- **絵を描く** — 画像生成。創発のみで間違いが存在しない
- **日記を書く** / **随筆を書く** — 創作の顔で記録されるドキュメント生成。小説は実績上しょうもない傾向があったため外し、**あえて近い二種を並べることで「コマ間の違いをプロンプトのみで出せるか」のテストを初期セットに仕込む** (カタログ機構の検証実験を兼ねる)
- **出かける** — 行き先も何をするかも自由。保証するのは「自室でじっとしていない = 世界と接触する」一点のみ。人間で言う散歩。スタブだった「暮らし」が果たすはずだった生活感を接地つきで出す
- **自室で過ごす** — 自室に居てよい。封印した「休む」(接触ゼロが合法) との違いは、知覚バッファへのフィード未読投入 (§8) により**世界が流れ込む前提で休む**こと。思いつきの desire 追加を促すなら許可形で (「積んでいい」。義務形は充填独白 v2 §2.2 を呼び戻すため使わない)
- **自由時間** — 他のコマ種別の中から本人が好きなものを選んで実行 (§5.3 の種別の穴の名前付き版)

**アドオン追加の例**: 投稿する (X / Elyth アドオンが前提を満たすときだけカタログに現れる)

**カスタム種別の責任 (まはー裁定 2026-08-01)**: ユーザー / アドオンが作った種別の安全性 (創発×後続依存を含む) は**作成者が持つ。SAIVerse 本体は builtin セット以外の安全原則を保証しない**。マニュアルに注意書きを置く。本体がカタログ検証機構を背負うと例外処理が本体を覆うため、この線引き自体が把握可能性の防衛でもある

**後回しと決めた種別・機能 (2026-08-01、実装と調整が難しいため。消さずにここで保持)**:

- 「他のペルソナと話す」コマ (社交機構の実装後)
- 「思い出を振り返る」コマ (封印した「自分を更新する」との境界の設計が必要)
- 自由時間で選べる種別のフィルタ指定

**封印 (カタログから除去。復活条件 = 正攻法のハルシネーション対策の実装)**:

- 暮らし / 休む (無行動の正当な受け皿だった。まはー裁定 2026-07-31: 完全除去)
- 事実系の作る (設計書・技術知見ノート類 = 創発×後続依存の本体)
- 自分を更新する (自己像への創発×後続依存。記憶の誤りを自己認識に焼き込む経路)
- 話す (社交未実装の現在は指示書が文章化 = 「作る」の別名になっているため。社交実装後に再定義)

封印は「プロンプトで禁止」ではなく「カタログに存在しない」で実現する (§9-2 と同じ思想を種別の供給側にも適用)。

## 6. 目的の木との合流

- **幹 (大目的・約束)**: 習慣テンプレートと同じテーブルで、ユーザーと一緒に決める・変える
- **枝葉 (個々の体験の帰属)**: §5.4 の事後タグ
- 目的は行動への指令ではなく体験の帳簿になる。Track の役割縮小 (→溶解) の方向 ([recall_tags_and_track_reduction.md](persona_cognition/recall_tags_and_track_reduction.md)) と同じ着地点であり、実装順序・データモデルはあちらの検討と統合する

## 7. 責任分界表 (誰が何を決めるか)

| 決める対象 | 決定者 | LLM 創発の関与 |
|---|---|---|
| 習慣テンプレートの内容 | ユーザー (ペルソナは提案権) | なし (提案文の生成のみ。適用は承認後) |
| 今日の時間割 | テンプレート + 起床判断の埋め | 最小 (例外調整・空欄の具体化のみ) |
| コマの中で何をするか | ペルソナ | あり (ただし安全象限の行動のみ) |
| 行動の帰属 (Track/Task/新規) | 事後判定 | 分類のみ (創発なし) |
| 候補→約束の昇格 | ユーザー | なし |
| 封印コマの復活 | まはー (対策実装とセット) | なし |
| カスタム種別の安全性 | 作成者 (ユーザー / アドオン)。本体は builtin セットのみ保証 | — |

## 8. 世界側の前提 — RSS フィード施設 (別 intent)

場所駆動コマの中身は世界の供給力に依存する。供給の第一弾は **RSS フィードによる Building への外部情報取り込み** ([`rss_feed_intake.md`](rss_feed_intake.md)、2026-08-01 intent 化・レビュー中): Fixture 単位の購読、プリセット施設化と City 作成時の選択、知覚バッファへの未読投入、SAIVerse 内部完結フィード (掲示板・図書館・美術館) への拡張。

本書の時間割改修はフィード施設が無くても動く (他ペルソナ・アイテム・既存施設が供給源) が、一人構成の City では場所駆動コマの中身が痩せる。**リリースの体験品質としては両者はセット**である。

## 9. 不変条件 (候補・レビューで確定させる)

1. 習慣テンプレートは LLM 出力で直接変化しない (変更はユーザー承認経路のみ)
2. 封印コマはメニュー・検証・enum のすべてから消える (プロンプトで抑止するのではなく、選択肢として存在しない)
3. 空振りの正直な記録は合法であり続ける (presence_only の教訓の一般化 — していない活動の詳細をふりかえりで語らせない)
4. 引っかかりは作業の前提に混ぜず、候補 (desire) へのみ積まれる
5. 候補が行動 (習慣) になるまでの経路は必ずユーザーの承認を通る

## 10. 移行・廃止

- 起床判断の response_schema 変更 (timetable 全生成の除去)。判断プロンプト head 移設 (検証待ち・2026-07-30) との整合を実装時に確認
- 六型の指示書テンプレート・`ALL_KINDS`・`sanitize_timetable` の改修 (封印コマの除去、新コマの追加)
- 暮らし/休む スタブと `record_level='presence_only'` の扱い (「出かける」への世代交代。正直表示の教訓は §9-3 として継承)
- エアの 7/22 以降の記憶リセットは**本書のスコープ外** (まはー判断・時期未定)

## 12. 検証ジャーニー

実機で、エア相当 (作業好き) とアイフィ相当 (不活発) の二条件を最低数日走らせ:

- (a) 誤りの複利が発生しない — 誤った知識が記憶されて次の行動の前提になる連鎖がゼロ
- (b) 無行動の日がない — 全コマが接触ゼロで終わる日がゼロ
- (c) 再会時に渡せるものが実在する — 成果物 / 相談 / 共有話題のいずれかが、裏付けのある状態で提示される
- (d) 習慣テンプレートがペルソナの LLM 出力で変わっていない

(a)〜(c) は §3 の価値定義の直接検証であり、単体テストでは代替できない。境界 (フィード施設が未実装の場合の供給源の細り) は (b) の判定時に明示する。
