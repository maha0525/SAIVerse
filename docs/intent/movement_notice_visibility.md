# 入退室ログの表示設定

**ステータス**: 検証待ち (2026-10-05、隔離環境で検証済み。実ブラウザ・実機の確認は未実施)

## 目的と範囲

部屋の会話を読むユーザーが、繰り返される入退室の知らせを画面から隠せるようにする。
ペルソナには移動の事実が今までどおり届き、過去の会話・出来事の記録も残る。
運用者は再起動後も設定を引き継ぎ、部屋ごとの例外を決められる。

移動は OccupancyManager が構造化した `metadata.event` と表示文を作り、
`building_messages` に保存する。履歴 API は記録を UI 向けに整形し、チャットは
履歴・差分取得・ゲームの合成ログを描画する。変更するのは、この最後の表示判断と
設定の保存だけである。移動の実行、履歴の書き込み、知覚の配送、個人記憶への取り込み、
LLM のコンテキストには設定を渡さない。

## 決まったこと

- グローバル設定: 「表示」「非表示」。既定は「表示」。`user_settings` に保存する。
- Building 設定: 「グローバル設定に合わせる」「表示」「非表示」。未設定は継承。
  `building.SHOW_MOVEMENT_NOTICES` の NULL / true / false で表す。
- Building の明示値が優先される。全体の値を変えても、明示値は書き換えない。
- 対象はユーザーと AI の入室・退室通知。`host` / `system` の記録の
  `metadata.event.type = occupancy` かつ `action = enter | leave` で識別する。
  普通の発言に同じ文言があっても隠さない。アイテム取得・警告等の別の通知も残す。
- 本文の言い回し、HTML の見た目、送信者名だけを根拠に隠さない。
  構造化情報を持たず識別できない古い記録は表示を保つ。
- API は非表示の記録も返す。画面が描画を抑えるだけなので、ID・並び順・
  ページ送り・既読や差分取得の基準は変えない。再表示すれば読み込み済みの通知は戻る。
- 過去の記録と、新着の履歴差分に同じ判定を使う。複数部屋を合成したログでは、
  各通知が記録された Building の設定を使う。
- 保存成功後は表示へ反映する。他のクライアントで保存した変更にも再取得で追随する。
  遅い応答や部屋の切り替えで、古い設定・別の部屋の設定を新しい選択へ上書きしない。
  全体の保存中は閉じ直した画面でも次の保存を待たせ、保存応答はその操作が変更した値だけ反映する。
  Building 設定も、同じ部屋への保存が終わるまで再表示時の読込と次の保存を待たせる。
- 非表示の新着通知だけでは会話画面を最下部へスクロールしない。
  通知だけのページでも「以前のメッセージを読み込む」で過去の会話へ進める。
- 設定の追加は既存 DB の自動差分マイグレーションに載せる。過去の通知を削除・改変しない。

## 検証する境界

合成した隔離 DB で旧スキーマからの移行、保存・再読込、未指定と NULL の差、
全体と部屋の全組合せを検べる。実際の入退室イベントを保存して履歴 API へ読み戻し、
構造化情報と記録が保たれること、同じ文言の通常会話と別種の通知が分類されないことを検べる。
フロントでは実コードの描画・設定処理をハーネスで通し、履歴、新着、部屋切替、
再変更・失敗・遅延応答を検べる。実ブラウザの見た目と本番ペルソナへの配送はこの隔離検査の
代わりに実行しない。未検証の境界は PR に明記する。
