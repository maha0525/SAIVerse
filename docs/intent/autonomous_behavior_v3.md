## 1. 芯 (一言で)

**ペルソナの一日は、事前に決めた「やること」の台帳と、一定間隔で打たれる標準モデルの Pulse (Beat) で運営される。** 一日の縁 (起床・就寝) から LLM の義務判断が消え、判断は実行の場 (Beat と会話) に寄る。キャッシュの保温は Beat の営みそのものが行い、keep-alive 専用の温め直しは最後の保険に退く。

## 2. 前提となる歴史認識 (なぜこの形か)

- **v1 の最大の病理は「何をやるかの規定が無いまま、実行だけが走り続けた」こと。** タスクは、やることが具体的に決まっていればスペルループ一回で普通に終わる。30 秒駆動は不要だった。Track は決める器として曖昧で、一回きりの案件が常設の走路になり、尽きたら新規 Track の創発まで強いていた。
- **v2 の成功は「実行の前に、やることを決める瞬間を置いた」こと。** この芯は変えない。変えるのは決め方 — 毎朝 LLM が時間割を編成する形 (それ自体が創発×後続依存の無監督作業 = v2.5 の診断) をやめ、決定を各々の自然な時点へ分散する。
- **Gemini は自発的にツールへ手が伸びない** (まはー観察 2026-08-12、memory: project_gemini_no_spontaneous_tool_use)。保証が要る行動は、自発に頼らず、スキーマ強制か決定論の配線に載せる。

## 3. 要件 (Wave 2 冒頭で確定、2026-08-12)

1. ユーザーに届く声は標準モデル
2. ライフ中は会話がいつでも温かい — 「話しかけやすい」表示と課金の実態が一致する
3. 作業して暮らした記憶が長期記憶に残る
4. 直前のユーザー会話を**生ログで**覚えている — 自律行動の記録が提示コンテキストを埋め尽くさない (人格の連続性の要請、最重量)
5. 会話の至上性: 即応・往復中の無割り込み・声の混入なし。待ちの備えがその窓の自律予定を全滅させない
6. 席の数と規則は把握できる複雑さに収まる
7. 軽量モデルは、任された仕事の範囲を超える変化を起こさない

## 4. やることの型 — 四類型 + きっかけ

やること (行動の予定) は、やるタイミングの性質で型が分かれる。**型を enum で持たず、時間属性から導出する** (不正な組み合わせを書ける口ごと無くす):

| 型 | 時間属性 | 例 | 表現の器 |
|---|---|---|---|
| アラーム型 | 定時 (その時刻でなければ意味が無い) | 朝の起こしメール・定時連絡 | アラーム (既存の定時スケジュール)。中身は事前に完全確定 (指示書 / Playbook) |
| ルーチン型 | だいたいの位置。**当面「ライフ始め」「ライフ終わり」の二種のみ** (朝/昼の帯は持たない — 途中起床への頑健さを優先) | 朝のフィード確認・夜の日記 | 繰り返しの定義 |
| 締め切り型 | 期限 (いつやってもよいが、それまでに) | ユーザーの依頼・帰宅前に仕上げたいもの | 台帳の一件。失くせないので機械が持つ |
| プール型 | 無し (空き時間に) | 気になることの検索・画像生成の練習 | **システムの表現を持たない** — レパートリー (減らない品書き) + 本人の手帳・記憶 |
| きっかけ型 | 出来事が起きたとき | ユーザーの発話 (最強・常に最優先)・フィード新着・来訪 | 駆動側 (会話機構・判断点) が受ける |

**v1/v2 の失敗の言い直し**: v1 は四類型全部を Track に入れ、v2 は全部を時刻付きのコマに入れた。アラームだけが先に独立し (2026-08-09 裁定「テンプレートと統合しない」)、それは正しかった — 残りも各々の時間属性のまま持つ。

### 4.1 システムが構造として持つ台帳は三つだけ

1. **繰り返しの定義** (アラーム型・ルーチン型): ユーザー合意物。**LLM の出力で直接変わらない — 変更経路はユーザーだけ** (相談は機構ではなく、ただの会話。ペルソナが会話で提案し、ユーザーが UI 等で変える)
2. **締め切りのある一件** (締め切り型): 約束と依頼。期限を持ち、失くすことが許されないから機械が見張る
3. **レパートリー** (減らない品書き): ペルソナ固有の「できる・好きな活動」一覧 (track_retirement の関心の行き先)

**欲求とタスクの区別は廃止** — どちらも「やること」で、差は時間属性 (期限の有無) と**相手の有無** (約束は勝手に消えない・自分のものは薄れたら消してよい) だけ。**減衰機構は持たない** — 選ばれないものはただ選ばれない。見せ方の制限で溢れを防ぎ、消すのは本人の明示かユーザーの掃除。

### 4.2 やること一件が持つ情報

中身 (実行の瞬間に再発明が要らない具体さ) / 時間属性 (定時 or 期限 or 無し) / 繰り返すか / 出自 (どの会話・経験・誰の依頼から) / 相手の有無 / 状態 (ある・やり終えた〔成果物参照〕・取り下げた)。

### 4.3 手帳 — プール型の中身の住処

「気になっていること」は台帳の行ではなく、**本人の手帳** (Memopedia/document のページ) に本人の文章として住む。システムは中身を読まない。机 (memory_open) に開きっぱなしにして、空き Beat が想起なしで見る。書き込みの保証は §6 の採取が担う (自発の書き込みには頼らない — Gemini 前提)。

## 5. Beat — 一日の運転

- **ライフ中、標準モデルの Pulse (Beat) が「最後の標準呼び出しから T 分」で打たれる。** T はユーザー設定。均等モード (Anthropic/OpenAI) は物理から T ≦ 50 分。自由モード (Gemini) は任意。事前予測配置は採らない — 予測で省ける無駄は存在しない (間隔を広げる制御はキャッシュ的に禁止・詰める制御は転がし方式でも可能、まはー裁定 2026-08-12)
- **予算 (回数) 設定は T (間隔) 設定に置き換える。** 一日の手数はライフの長さと T から機械的に決まる
- **Beat が受け取るのは確定情報** (「この Beat は挿絵の続き」) であって、問い (「何をしたいか」) ではない — v1 の病因 2 を踏まない
- **割り付け**: アラームは定時に発火 (Beat の格子に丸めない)。ルーチンはライフ始め/終わりの Beat に機械で割当。空き Beat は**締め切り優先** (決定論の引き当て) → 無ければプール (手帳とレパートリーを見て本人が選ぶ — 末端の決定で複利に乗らない、v2.5「コマの中の自由」の継承)
- **継続**: 締め切り型が未完なら台帳に残り続け、次の空き Beat が自然に同じ件を引く。「続き」という概念・編集操作は存在しない
- **会話との関係**: アラームは会話中でも鳴る (電話が鳴れば目は逸れる)。**空の Beat は会話中は走らない** — 保温は会話自身がしており、待ちも 30 分 < T で切れない。会話終了後、最後の標準呼び出しから T 分で再開
- **重い下請け**: run_playbook を**投げっぱなし**で発注し (身体移動スペルと同型の非同期)、報告は次の Beat が読む。発注時に「報告を受けて何をするか」まで決めておく。渡すもの (Playbook・スペル・ループ上限) は発注者が仕事ごとに選ぶ (要件 7 の実現。静的な可否表は持たない — 権限の縛りが欲しくなったらそれはユーザーの権限設定であり、SAIVerse 本体は決めない)
- **締め切りの見張り**: Beat のプロンプトに「期限が近い / 過ぎている」を通知として出すだけ。Beat を足す等の増強は将来の拡張

## 6. 一日の縁 — 判断点の再編

- **起床: 機械の帳簿処理のみ** (ライフ確定・今日のアラーム/ルーチンの割り付け)。LLM の義務なし。時間割の編成・穴埋め・欲求の昇格・減衰は全部消える
- **就寝: 機械の帳簿処理のみ** (ライフ終了・keep-alive 停止・編纂の節目)。ふりかえりの独白・明日へのメモ・欲求の裁定・帰属付けは全部消える
- **朝晩の情緒は義務から習慣へ**: 朝の独白・夜の日記はルーチン型として本人が持てる (持たない人格も合法)。夜の日記用に「やり残し・約束の確認」を含む漏れ検知プリセット (Playbook / 指示書) を builtin で用意する
- **残る判断点は「外から何かが届いた直後」だけ**: 会話終了 (約束の捕獲 — スキーマで必ず「約束はあったか」を問い、締め切り型の追加・更新をここで確保する) と イベント到着
- **記憶整理 (編纂候補・命名候補のレビュー) は就寝判断から退去** — 自律行動しないペルソナの記憶が二級になる構造的欠陥のため、置き場は記憶側の機構で別途設計 (gate §9 に仕分け行を追加)

## 7. エピソードの解体 (episode.md v1.4 の上書き)

**エピソードという専用の記録行 (テーブル) は持たない。** v1.4 の行が持っていた情報は全て他所に既にある:

| v1.4 のエピソードが持っていたもの | 行き先 |
|---|---|
| どの件の実行か | メッセージへの記録 (書き込み時の目的参照) — 割り付けられた Beat は機械で書ける |
| 始まり・終わりの実在イベント | **遷移の一行** (機構名義のシステムメッセージとしてログに実在) — v1.4 の芯「始まりと終わりが実在する」はこの形で生存 |
| 完了・成果物 | 台帳の一件の状態欄 |
| できごと UI の一行 | 表示時にログから導出 (会話・自由時間と同じ扱いに統一)。自由時間の中身は実行スペル・Playbook から表示 (v1 ライフビューの手法の再利用) |
| 読み返し (episode_read) | 目的参照 + 期間でログを引く |
| チャンクの切れ目の目印 | 遷移の一行 |

**自由時間 (空き Beat) と会話はもともと記録行を持たない** — 意味づけは §6 の関所タグが運ぶ。実装上、表示や検索のための導出結果の置き場が欲しくなったら、それは概念ではなくキャッシュとして足す。

### 7.1 記憶と想起の完成形

- **書き込み時 (機械)**: 参加者 / 目的参照 (割り付けのある Beat・会話終了判断の捕獲分)
- **退場の関所 (Metabolism・gold_panning の席に相乗り)**: 提示から出る直前の範囲を見ながら、構造化出力の一手で ①コア記憶候補の採取 (既存) ②**手帳への採取** (「やりたい・もっと知りたいと思ったことは? 無ければ空」— 空が一級で正常。義務形にしない) ③**想起用タグの付与** (自由時間・逸れた分の意味づけ)
- **不変条件: 提示から出るものは、あらすじ・タグ・採取を済ませてからしか出ない。** タグが要るのは想起でしか届かなくなる素材だけであり、提示に見えている間の未付与は実害ゼロ — だから退場の関所が唯一かつ十分な付与点
- session_digest・恒等転写機構は対象ごと消滅 (セッションが無い。Beat がメインラインに書く本人の言葉がそのまま編纂の材料)

## 10. 一日の姿 (検証済みウォークスルー、2026-08-12)

07:00 アラーム (モーニングメール) → 07:50 ルーチン (フィード確認 — 引っかかりを書き漏らす) → 08:40 空き Beat = 締め切り優先 (挿絵、Playbook 投げっぱなし発注) → 09:30 報告を見て継続 → 10:40 ユーザー会話 (空き Beat はスキップ) → 12:20 会話終了判断 (「水曜までに」の約束を捕獲、期限更新) → 午後 締め切り完遂 (成果物参照つき完了) → プール (手帳と品書きから選ぶ) → 15:40 Metabolism (朝の範囲の退場 — あらすじ + タグ + **朝の書き漏らしが手帳に入る**) → 22:10 ルーチン (日記) → 01:00 機械の就寝処理。標準呼び出し 15〜20 回/日 ≒ 均等モードの保温必要数、keep-alive ゼロ。
