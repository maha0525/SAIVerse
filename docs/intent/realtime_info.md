# リアルタイム情報 — 現在時刻・前回発言時刻の項目別トグル

**ステータス: 完了 (v0.3.17 で発行。実機確認はまはーが実装時に済ませている — 2026-10-01 まはー。報告者への案内も済み)**

関連: `sea/runtime.py` (`_build_realtime_context`) / `sea/runtime_context.py` (注入位置) / `sea/runtime_llm.py` (`_execute_realtime_spells`) / `database/models.py` (AI テーブル) / `frontend/src/components/SettingsModal.tsx`

## これは何

ペルソナが返答や自律行動を作るとき、LLM へ送る文脈の末尾近くに「リアルタイム情報」という短いメッセージが差し込まれる。中身は「現在時刻」「あなたの前回発言」の時刻の行と、リアルタイムスペル (設定画面での名前は「事前実行スペル」— ペルソナや建物に紐づけて毎回自動で実行されるスペル) の実行結果。この文書は、その中身をペルソナごとに選べるようにする設計と、守るべき不変条件を記録する。

## 世界への約束

- ユーザーはペルソナごとに、「現在日時」と「前回発言日時」を見せるかどうかを別々に選べる。時刻を気にしすぎるペルソナからは時刻だけを外し、時間経過の感覚が欲しいペルソナには前回発言の時刻を渡す、という調整が一体ではなく項目単位でできる。
- リアルタイムスペルの結果は、時刻の設定と無関係に必ずペルソナへ届く。時刻の項目をどう選んでも、スペルの結果がペルソナへ届く経路は塞がらない。スペルを止める正規の手段は、時刻の設定ではなくペルソナ設定の「スペル」の無効化 (`SPELL_ENABLED`、[spell_disabled_mode](spell_disabled_mode.md)) — そちらは意図どおりリアルタイムスペルも止める。
- 見せるものが何も無いときは、リアルタイム情報のメッセージ自体を送らない。空の枠をペルソナに見せない。

## 全体像 — 作る側・運ぶ側・読む側

1. **作る側**: `sea/runtime.py` の `_build_realtime_context` が、履歴とペルソナ設定から時刻の行を組み立てる。
2. **運ぶ側**: `sea/runtime_context.py` が、組み上がったメッセージを、キャッシュが効く履歴の後ろ・文脈の末尾近くへ挿す (正確には「リアルタイム情報ではない最後の user ロールのメッセージ」の前。自動想起の差し込みが後から間に入ることがあり、ユーザー発言との厳密な隣接は保証していない — 現状の実装どおり)。リアルタイムスペルの結果は `sea/runtime_llm.py` の `_execute_realtime_spells` が同じメッセージへ追記する — メッセージが無ければ自前で作る (この予備の経路が「スペルは設定で塞がらない」の実装上の担保)。
3. **読む側**: ペルソナの LLM 呼び出し。このメッセージは履歴に保存されず、ターンごとに消えて作り直されるので、プロンプトキャッシュの前方一致は中身に関係なく元からここで割れる。項目が増えても減っても割れる位置は変わらず、これより前の履歴のキャッシュには影響しない。

## 設計 (2026-09-28 確定)

### 設定の形

AI テーブルの `REALTIME_INFO_ENABLED` (全体トグル) を廃止し、2 列に分ける:

| 列 | 意味 | 既定値 |
|---|---|---|
| `REALTIME_CURRENT_TIME_ENABLED` | 「現在時刻」の行を見せる | True (ON) |
| `REALTIME_LAST_UTTERANCE_ENABLED` | 「あなたの前回発言」の行を見せる | False (OFF) |

ペルソナ設定 UI の「リアルタイム情報」欄は、チェック 2 個 (現在日時 / 前回発言日時) になる。

### 既定値と引き継ぎ

- **既存ペルソナ**: 旧列の値を「現在日時」へ引き継ぎ、「前回発言日時」は OFF。旧列が ON だった子は「現在日時 ON + 前回発言日時 OFF」、OFF だった子は両方 OFF。**リリースの瞬間、全ペルソナに届く文面は 1 バイトも変わらない** — 不具合修正の副作用で全員の見え方が変わることを防ぎ、前回発言日時は欲しい人が明示的に ON にする。
- **新規ペルソナ**: 既存と同じ「現在日時 ON + 前回発言日時 OFF」。規則を一本にする。
- リリースノートで「前回発言日時は設定で ON にできるようになった」と案内する (報告者への回答を兼ねる)。

### 時刻の読み取りの修正

前回発言時刻の読み取りは、`created_at` / `timestamp` の値が数値 (epoch 秒) / `datetime` / ISO 形式文字列のどれでも読めるようにする。数値は UTC の epoch 秒として読み、表示時にペルソナのタイムゾーンへ変換する (現行の変換処理をそのまま通る)。二つのキーは独立に試す (`created_at` が読めない値でも `timestamp` を諦めない)。数字だけ 8 桁の文字列は epoch 秒ではなく基本形式の ISO 日付 ("20260928") として読む — 8 桁の epoch 秒は 1970 年の時刻で現実に存在しない。0 / NULL / 空文字は「時刻が記録されていない」であって読めない値ではないので、ログ無しで飛ばす (epoch 0 = 1970 年を前回発言として見せない)。

仮想クロック (一日シミュレータ) が有効な間は、前回発言の行を出さない。履歴の時刻は実時刻で、仮想の現在時刻と並べるとペルソナの世界像が実時計に引っ張られる — 現在時刻側で 2026-07-05 に実証済みの型 (`_build_realtime_context` 内のコメント参照) を、前回発言の行で再演させない。

### 不変条件

1. **リアルタイムスペルの結果は、ユーザーが時刻の設定をどう選んでも必ず届く。** 時刻の 2 項目が両方 OFF でも、スペル結果があればリアルタイム情報のメッセージは作られて届く。
2. **リアルタイム情報のメッセージは、キャッシュが効く履歴の後ろ (文脈の末尾近く) に置き、履歴には保存しない。** 毎ターン中身が変わる情報なので、キャッシュが効く範囲に置いてはならない。項目の増減もこのメッセージの中で閉じる。
3. **出すものが何も無ければ、メッセージ自体を送らない。**
4. **読めない時刻は黙って捨てない。** 形式が想定外だったら DEBUG ログに残す (今回の不具合が 1 バージョン以上気づかれなかったのは、失敗がログに一行も残らなかったため)。

### マイグレーション

列の追加 2 + 削除 1 + 値の引き継ぎが必要になる。`database/migrate.py` は、列の追加だけで済む差分なら生きた DB へ直接適用する (コード中の呼び名は「追加系」) が、列の削除を含む差分はテーブルを作り直す「全書換」で処理する — 今回は後者に載る。`ACTIVITY_STATE` → `AUTONOMY_ENABLED` の変換 (2026-07-14) と同じ型: 全書換がデータをコピーし終えた後で、旧 DB の `REALTIME_INFO_ENABLED` を読んで新列へ写す変換関数を置く。旧列を、全書換より前に列を落とす「既知の廃止列」の一覧 (`apply_known_column_drops`) へ**入れてはならない** — データのコピーより先に値が消えると引き継げない。

## 検証の道筋

- 単体テスト: epoch 秒の `created_at` で前回発言の行が出る / トグル 4 組合せそれぞれの出力 / 両方 OFF + スペルあり = スペル結果だけのメッセージ / 両方 OFF + スペル無し = メッセージ無し / 旧列からの値の引き継ぎ (ON→現在のみ ON、OFF→両方 OFF) / 仮想クロック有効時に前回発言の行が出ない。
- 「リリースの瞬間に文面が変わらない」の前提の検算: 履歴を供給する経路の時刻が実際に epoch 秒であること (万一 ISO 形式の時刻を持つ経路が残っていれば、その行は今も表示されており、既定 OFF で消えてしまう)。
- 実出力の検収: 隔離環境で、実際に組み上がったリアルタイム情報の文面を組合せごとに私 (メティス) が読者として読む。
- 実機: まはーの環境で設定画面のチェック 2 個の表示・保存と、コンテキストプレビューでの行の増減を確認する。
