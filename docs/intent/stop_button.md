# 停止ボタン — 止められる処理が走っている間は必ず出て、押せば必ず止まる

ステータス: 実装中 (2026-11-09 起草・同日まはー GO)

## この文書が守る約束

利用者 an nin さんの報告 (2026-11-09) が起点。X 連携の「X新規フォロワー確認」が固まり、停止を押した後に話しかけても「返事の準備をしています」のまま返事が来ず、再起動するまで戻らなかった。原因はアドオンの不具合 (X 連携 0.3.1 で修正) だったが、本体の側にも、ツールが一つ戻らないだけでペルソナが再起動まで止まる弱さがあった。調べると、停止ボタンには次の三つの穴があった。

- 停止ボタンは「この画面から発言を送って、その返事を待っている間」しか出ない (`frontend/src/app/page.tsx` の `loadingStatus`)。リロード・ペルソナの自律の行動・別のタブからの送信では、止められる処理が走っていても出ない。
- 停止を押すと、サーバー側では「ユーザーが今いる建物」のペルソナを止める (`cancel_active_generation`)。いる場所と違う建物を見ているときは、見ていない建物が止まる。また、新しい発言に割り込まれて裏で走り続けている古い処理には届かない。
- 止める合図は、ツールが戻ってくるまで確認されない。ツールが固まると合図は永久に効かず、その処理が Beat ロック (`sea/beat_gate.py`、ペルソナの処理を一つずつ順に走らせる鍵) を握ったままになる。

ここから、SAIVerse が保障することを四つ決める (2026-11-09 まはー GO)。

1. **表示している建物に、止められる処理が走っているペルソナがいる間は、停止ボタンが必ず出る。** リロードした後も、ペルソナが自分で動いているときも、別のタブから話しかけたときも出る。判断の材料は画面側の状態ではなく、サーバー側の記録とする。
2. **停止ボタンを押すと、表示している建物のペルソナの処理がすべて止まる。** 新しい発言に割り込まれて裏で走り続けている古い処理も含む。
3. **停止の合図が来たら、ツールが戻ってこなくても待つのをやめて抜ける。** 抜けたペルソナは Beat ロックを手放すので、次の返事に進める。
4. **新しい発言による割り込みは、今までどおりツールの完了を待つ。** 2026-07-16 の決定 (`beat_execution_context.md` §3.4 — 課金と生成がもう進んでいるので、割り込みは途中で止めずに完了を待って効かせる) を守る。たとえば画像生成の途中に話しかけても、画像は受け取ってから次に進む。待つのをやめて抜けるのは、停止ボタンが押されたときと SAIVerse の終了処理のときだけ。

## 画面の振る舞い

停止ボタンの出方は二通りある。

- **この画面から送った発言の返事を待っているとき**: 今までどおり、送信ボタンの位置に停止ボタンが出る (送信はできない)。
- **それ以外の処理が走っているとき** (リロード後・自律の行動・別のタブからの送信): 送信ボタンの隣に停止ボタンが並ぶ。送信ボタンを消さないのは、自律の行動の間も話しかけられる今の挙動を変えないため。

ブラウザからは、表示している建物について「止められる処理が走っているペルソナがいるか」を数秒おきにサーバーへ問い合わせる。

## 抜けたときに何が残るか

ツール自体は止められない (Python のスレッドは外から止められない)。待つのをやめた後も、ツールは裏で動き続けることがあり、後で戻ってきた結果は捨てる。外部への送信や課金がどこまで進んだかは、SAIVerse にも分からない。

ペルソナへの知らせは、既存の約束 (`reply_stop_exit.md` §通告の内容 ②) に乗る: 「発言の後に唱えたスペルは、実行が終わる前に中断されました。結果は届いておらず、どこまで実行されたかは不明です」。新しい知らせの文は作らない。

## 置き場所

- **待つのをやめる判定は、ツールを待つ場所に置く。** ツールを呼んで待つ場所は 4 か所ある — スペル (`sea/runtime_llm.py` の `_run_spell_tool_async`)、Playbook の中で LLM を呼ぶ手順 (LLM ノード) が、その場でツールを呼ぶところ (`_execute_handy_tool_inline`)、Playbook の中でツールを呼ぶ手順 (TOOL ノード。`sea/runtime_engine.py` と `sea/runtime_nodes.py`)。4 か所すべてで同じ関数を使ってツールを待つようにし、止める合図の確認と、合図の種類 (停止ボタン `user_stop` か終了処理 `server_shutdown` か) に応じて抜けるかどうかの判定は、その関数の中でだけ行う。
- **「いま走っている処理」の記録は、ペルソナの処理を受け付けて順に走らせる `PulseController` (`sea/pulse_controller.py`) に持たせる。** 処理を始めるときに記録し、終わったときに消す。新しい発言に割り込まれた古い処理も、本当に終わるまで記録に残す。停止ボタンが押されたときと、ブラウザから問い合わせがあったときは、この記録だけを参照する。

## 引き受けること・残ること

- **メタ判断 (ペルソナの次の行動を、会話の返事とは別の枠で決める判断。`_current_meta` に記録される) は対象外。** メタ判断は割り込まれない設計で、停止ボタンを押しても今まで止めていなかった。停止ボタンも、メタ判断が走っていることを理由には出さない。
- **作業セッション (ペルソナが会話とは別に作業を続ける仕組み。`sea/work_session.py`) は `PulseController` の外で走るので、この記録に載らない。** 作業セッションの中でツールが固まった場合は、この修正では止められない。
- 裏で動き続けるツールのスレッドは、プロセスの終了を妨げないようにする (daemon スレッド)。

## 確かめ方

- ツールを待つ関数の試験: 停止ボタンの合図で抜ける、新しい発言の割り込みでは抜けない、正常に戻ったツールの結果はそのまま返る。
- 本番と切り離した環境 (別フォルダの `SAIVERSE_HOME` + テスト用のペルソナ + 偽の LLM) で、わざと固まるツールをスペルとして唱えさせ、ブラウザで次を確かめる: 停止ボタンが出る → リロードしても出ている → 押すとペルソナが抜け、ペルソナの記録に②の知らせが入る → 次に話しかけると返事が来る。

## 経緯

- 2026-11-09: an nin さんの報告から調査。アドオン側は X 連携 0.3.1 で修正・配布。本体の弱さについて、まはーが「停止ボタンだけで抜ける」を選び (新しい発言でも抜ける案は、正常に時間のかかるツールの結果を捨てるので不採用)、続けて「リロードで停止ボタンが消えるのでは」と指摘した。コードで確かめたとおりだったので、ボタンをサーバーの記録で出す形を足して GO をもらった。
