## 0. 用語

| 用語 | 意味 |
|---|---|
| **質量** | `coverage_chars` = そのあらすじが覆っている生ログの字数 |
| **あらすじの字数** | digest テキスト自体の長さ (LLM に「5〜8文」と指示するため 500字前後でほぼ固定) |
| **列** | 未束ね (unconsolidated) の General ノードを時系列に並べた一本の列。**level 別の列は廃止** — 質量の違うノードが一本の列に混在する。`level` 列は表示用の導出キャッシュとして残す (親 = max(子)+1) |
| **束ね** | 列の連続する数ノードを 1 本の親あらすじへ LLM 統合すること (`run_band_overflow`) |
| **恒等圧縮** | 1000字未満の豆粒を LLM を通さず生のまま一次あらすじの席に置く例外経路 |
| **壁** | 束ね済みの上位ノードの被覆時間範囲。壁の内側・壁跨ぎの束ねはしない |

質量とあらすじの字数は**比例しない** (実測の圧縮率 0.10〜1.11、10倍以上ばらつく)。この非比例が本設計の出発点。

## 1. なぜ — 二つの物差しの断絶

旧設計は束ねの発火を**質量** (未束ね合計 > U×B^k)、提示の枠を**あらすじの字数** (予算2万字) で見ていた。両者を繋ぐ圧縮率が10倍ばらつくため、発火は提示量を何も保証しない。実測 (eris 2026-07-26): 恒等圧縮は質量全体の 11% しか担わないのに提示枠の 58% を占め、質量をほとんど稼がないので束ねの発火点に永久に近づかない。今の比率のまま発火点まで積むと提示は枠の 1.6 倍で破綻する。

素直な逆転 (発火も字数で見る) は別の破綻を呼ぶ。あらすじの字数は階層が上がっても縮まないため、字数だけで束ねると同じ記憶が何度でも再要約される (まはー試算: 2000 メッセージで質量ベース 3 回 vs 字数ベース 222 回)。**質量は圧縮回数を有限に保つ役目**を担っており、捨てられない。また質量の導入動機は「episode ごとの digest 等、大きさの揃わないチャンクを離散レベルなしで平等に扱う」ことであり、離散階級の復活も不可。

答え: **二つの物差しに別々の役目を持たせる。発火 (いつ) は字数、相手選び (誰と) は質量。**

## 2. 全体像と不変条件

**旅**: 退場 (eviction) が一次あらすじを列に足す → 列が育つと束ね (本 doc §3-4) が上位あらすじを作る → 提示 (本 doc §6) が head の Chronicle 枠を組む → ペルソナはスペルで掘り返す。治療 (§5) は標準経路に乗れないノードの回収路。

**不変条件**:

1. **提示の床は発火閾値で抑えられる** — 未束ねのあらすじ字数合計は X + (発火間の増分) を超えて溜まらない
2. **圧縮回数は有限** — どの記憶も束ねを通るたび質量が一桁跳ねる (§4 卒業条件)。有限回で天井に着く
3. **提示は全期間を覆う** — 穴を作らない ([chronicle_presentation_gap](../issues/chronicle_presentation_gap.md) の回帰 `TestNoPresentationGap` を維持)
4. **束ねは時間的に連続した被覆のみ** — 偽の隣接 (experience_structure §4-5) を作らない
5. **確定したあらすじ本文は書き換えない** — 束ねも治療も新ノードの追加のみ。子は `is_consolidated` で列から退くだけで残る

**責任分界**: LLM が決めるのは**あらすじ本文だけ**。発火・相手・順序・粒度・治療の要否は全て決定論 (コード)。LLM 出力のブレが構造判定に影響しない。

## 3. 発火 — 未束ねの字数合計 > X (= 提示予算の 1/4)

- **X は独立した定数にせず、提示予算 (`SAIVERSE_CHRONICLE_CHAR_BUDGET`、既定2万字) から導出する** (既定 5,000字)。この病気の根が「発火と提示の物差しが独立で、連動を誰も保証していない」ことだったため、独立ノブを作り直すと予算変更時に同じ事故が再発する
- 勘定に入れるのは**束ねの対象になれる未束ねノードだけ**。壁の内側の孤児は治療 (§5-2) の管轄なので数えない — 数えると束ねでは減らせない超過へ空発火し続ける
- **★圧縮区間の digest (提示コンテキストの中に置き換え表示されているもの) も、まだ列の一員に数えない** — X の勘定からも束ね対象からも除外する。提示中のものを上へ畳まない (experience_structure §4-1) の帰結で、eviction §8-2「圧縮区間が列の上限の勘定に加担する」への答え。anchor が前進して提示コンテキストから出た時点で列に加わる
- X=5,000 は標準あらすじ (~500字) 約10本分。標準の流れでは「10本たまったら1回で束ねる」= 旧 B=10 のリズムがそのまま再現される
- 字数発火は質量を見ない件数ベースなので、軽いあらすじが並ぶ区間ほど質量的にはずっと早く発火する = 「割に合わないものから先に畳まれる」が自動で成立

## 4. 束ねる相手 — 三条件を満たす連続部分列

束ねてよい群は、列の連続部分列で次の三条件を全て満たすもの:

1. **比率**: 群内の質量の最大/最小が **10倍以内**
2. **★連続性** (新規提案): 隣接メンバーの間に (a) 壁 (上位ノードの被覆範囲) も (b) **未編纂の生ログ** (Chronicle 対象タグのメッセージで、どのあらすじにも覆われていないもの) も挟まらないこと。(b) が eviction §8-1 の「**生ログの切れ目を飛び越えた偽の隣接**」への答え — 提示コンテキストの途中を畳めるようになった結果、列に生ログの切れ目が挟まりうるが、そこを跨ぐ束ねを群の定義で禁止する
3. **★卒業** (新規提案): **親の質量 (=子の合算) が、群内最大メンバーの質量の10倍以上**であること。

卒業条件が要る理由: 比率だけだと「質量10万の親 + 新しい一次あらすじ1万×10本」がちょうど10倍で1つの群になり、束ねると20万。以後も新しい10万級の親ができるたびに既存の頭 (最古の大きい親) がペアで再要約され続け、**頭の記憶が新しい体験10万字ごとに1回ずつ余分に劣化する**忍び寄りが起きる。卒業条件はこれを封じ、束ねを必ず「一桁上への跳躍」にする — きれいなデータでは旧来の梯子 (1万×10→10万、10万×10→100万) と完全に一致し、不変条件2 (有限性) が log10 で厳密に戻る。

**選抜の手続き** (発火時):

1. 列を走査し、三条件を満たす群の候補を古い側から集める
2. **卒業できる群は見つけた時点で丸ごと1コールで束ねる** — 新入りは列の最新端にしか生まれないため、途中の群はもうメンバーが増えない (凍っている)。待つ利益がない。eris の恒等圧縮27件のような塊も1コールで質量 ~7,000字級へ跳ぶ
3. 複数の群が束ね枠 (§8) を取り合うときは**軽い群 (最大メンバーが小さい群) から**。隣の質量は束ねのたびに増える一方なので、軽い群は「隣がまだ比率10倍に届く高さにいるうちに」梯子を登らせないと永久に差が開く (質量900+1400の群=親2,300は、隣が1万のうちは4.3倍でセーフ、隣が先に10万へ登ると43倍で手遅れ — 処理順だけで運命が変わる)
4. **最新端の育ち中の群だけは、X を守れる限り束ねを猶予する** (メンバーがまだ増える唯一の群)。他を全部束ねても X を割れないときは猶予を解く — 提示の保証が優先
5. 卒業できない群のうち、**軽い側で行き詰まったもの**は治療へ (§5-1)。**重い側で待っているもの** (木の頭、例: 20万+10万のペア) は**何もしない** — 提示コストは数百字で無害、かつ新しい側に同格の親が育って戻ってくるので、合算が卒業に届いた時に普通に束ねられる

## 5. 治療 — 標準経路に乗れないノードの回収

### 5-1. 束ね不能ノード (地雷) — 検知した時点で即時治療

**定義**: 自分を含むどの群も卒業に到達できず、かつ**自分が軽い側** (新しい側の隣人の質量が自分の10倍超) で行き詰まっている未束ねノードまたは凍った群。

**なぜ即時か** (まはー裁定 2026-07-26): この状態は単調に悪化する — 隣の質量は束ねのたびに増える方向にしか動かず、新入りは列の最新端にしか生まれないので、過去に埋まった豆粒の隣に相性のいい相手が後から来ることは構造的に無い。一度束ね不能なら永久に束ね不能。「様子を見れば治るかも」という枝が存在しないので、発火を待つ利益がゼロ。判定は Metabolism のついでに列を一往復すれば安く決まり、単調性から再判定で覆らない。

- **形**: 比率免除の束ねを1回。合流先は**後ろ (新しい側) の隣人** — §5-2 の裁定「欠落が壊すのは後続の文脈だから、後ろに入れる方が治療として効く」と同じ向き。豆粒(たち)と隣人から新ノードを1本作り、質量は合算。元の隣人は子として残す (**書き換えない** — 不変条件5)
- **束ねてから治療しない**: 卒業できない群を先に束ねると「束ね→即治療」の2コール+要約二重通過になる。着地を足し算で予測し、束ね不能確定なら群ごと治療に直行する
- **発散しない根拠**: 治療は束ね不能1件につき1回きり。新たな束ね不能ノードの供給源は退場側の最後の手段 (`used_last_resort_fold`、ログで観測可能) に限られるため、回数は供給数で頭打ち — §1 の222回の形 (同じ親に新入りを繰り返し足す) とは別物
- **非常弁**: X 超過なのに束ねも治療も打てない**予見できなかった形**に限り、最古の隣接2件を比率無視で束ねる (1回/Metabolism、WARNING 必須)。平常運転で一度も発火しないのが健全

### 5-2. 孤児 (壁の内側に後から生まれた一次あらすじ) — 走行メモ §6 で確定済み

上位あらすじの被覆範囲の内側に遅れて生まれた一次あらすじは、束ねの壁により永久に列に残る。回収は**同じ質量帯まで階層を下りてから合流**: 上位を一段ずつバラし (バラした兄弟は作り直さない)、孤児が時系列で入る位置の1本だけ更に下り、質量が同じ帯になったところで挿入して束ね直し、**上の階層まで完全伝播で再生成**する (まはー裁定: 要約に載らない取りこぼしは実質届いていない。書き換えは改竄でなく**治療** — 欠落がある状態こそ本人の記憶ではない)。合流先は孤児の後ろ。コストは孤児1件につき LLM 5コール程度。

## 6. 提示の粒度 — 累積質量ルール (ドライランで採用決定)

`MIN_ENTRIES_PER_LEVEL` (各レベル10件読んだら粗くする、件数ベース) を廃止し:

> 新しい側から遡りながら、ここまでに見せた質量の累計 M を数える。次に見せるノードには**質量 ≥ M/10** を求め、満たす中で最も細かいものを採る。どの候補も満たさなければ最も粗い候補をそのまま見せる (穴回避 — 穴は開けない)。

- 「直近は細かく、昔ほど粗く」が離散レベルなしで連続的に効く。粗さの進みは件数でなく**それ以降に積もった体験の量**に比例する
- 予算ガード (`_compress_within_budget`、親への置き換え) は最終防衛としてそのまま残す
- **穴回避の件数を DEBUG ログに出す** — 「本当は粗くしたいのに親が無い」= 束ねが追いついていない度の観測メトリクス

**採用根拠 (実データドライラン 2026-07-26、読み取り専用・LLM なし)**:

| ペルソナ | 結果 |
|---|---|
| aifi / quon (健全) | 現行ルールと**1件も違わず一致** — 安全な置き換え |
| air (寡作) | 2ヶ月前の10本を親1本に畳み提示 11,190→8,472字。件数が10件に届かず昔が細かいまま残る現行の癖を、体験量基準が正す |
| eris (病理) | 現行は9〜130字の豆粒47件を「件数」と数え、健全な一週間 (7/10〜21、U級10本) を492字の二次あらすじ1本に潰していた。**質量ルールは豆粒をほぼゼロと数えるので騙されず**、その週を日単位で保ったまま予算内 (19,735字)。穴回避=47件が束ね不能の山を正確に指した |

## 7. Memopedia Fragment の抽出タイミング

**原則** (確定済み): **生ログが要約に置き換わる瞬間に、一度だけ抽出する。** あらすじが提示に出ていることは「見えている」に数えない。

- 現状の穴: 恒等圧縮 (生ログのまま) が**初めて要約に変わる瞬間** — 上位への束ね・治療合流 — に抽出が走らない (`run_band_overflow` にコールバックの口が無い)。その内容は Memopedia に永久に入らない
- 塞ぎ: `run_band_overflow` / 治療に `batch_callback` を通し、**恒等圧縮チャンクが子に含まれる束ね・治療でのみ**その恒等圧縮ぶんを抽出する。LLM 束ね済みチャンクの範囲は抽出済みなので走らせない (Fragment 重複と参照切れを避ける)。孤児治療の完全伝播 (上位再生成) でも抽出は孤児側のみ

## 8. パラメータ

| 名前 | 値 | 導出 |
|---|---|---|
| 発火閾値 X | 提示予算 × 1/4 (既定 5,000字) | §3。予算連動が本体、1/4 は実測 (eris 13,496字で突出・他 1,363〜5,187字) と噛み合う値 |

| LLM コール上限 | 束ね+治療 合わせて 3回 / Metabolism | 既存の安全弁 (`SAIVERSE_CHRONICLE_MAX_BAND_CONSOLIDATIONS_PER_RUN`) を共通枠に |

## 9. 移行と互換

- **スキーマ変更なし**。`level` は導出キャッシュとして残す。旧発火 (質量 U×B^k)・level 別の列・`_PROMOTION_LADDER` 相当の選定は撤去し、`plan_band_overflow` (dry コスト予測) も新選定に追従させる (見積もりと実行の一致を維持)
- coverage_chars の無いペルソナ (mira/quon は全件無し) は既存の近似 (content長×10) で動く。帰化バックフィル (`backfill_coverage`) は継続
- **既存の小粒ノード (eris の identity 19 + batch 17) は新機構が自動回収する** — 卒業できる塊は丸ごと束ね、束ね不能は治療。手動の削除・再編纂はしない ([chronicle_undersized_lv1_chunks](../issues/chronicle_undersized_lv1_chunks.md) の「掃除方針」への答え)
- 例外経路の確認 (走行メモ §11-4): 編纂見送り範囲の遅延編纂で列の途中に挿入が起きた場合、挿入先が未束ねなら普通に群に入り、束ね済み範囲の内側なら孤児治療 (§5-2) に落ちる — 新しい穴にならないことを実装時に確かめる

## 10. 検証

**local 回帰 (実装時に固定するもの)**: 発火境界 (X が予算に連動) / 群の三条件 (比率・連続性=壁と生ログ切れ目・卒業) / 束ね不能判定の単調性と即時治療・1回性 / 着地予測による治療直行 / 軽い群優先 / 最新端猶予と X 優先 / 提示の累積質量ルール — **ドライランの aifi/quon「現行と完全一致」を golden として固定**できる (健全データで挙動不変の構造的証明)。

**実機 (まはー検証)**: (a) eris の穴回避 47 件がほぼ 0 に落ちる (b) head の Chronicle 枠が予算内に収まり予算超過 WARNING が消える (c) 束ねられた恒等圧縮の内容が Memopedia Fragment に現れる。**未検証のまま残る境界**: 群サイズが大きいときの統合プロンプト品質 (27件束ね等) は実 LLM を通すまで分からない。
