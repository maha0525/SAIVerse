# Salience Module Intent

> **位置づけ (2026-07-27)**: 本書はリアルタイム処理基盤 ([realtime_foundation.md](realtime_foundation.md)) における「注意と選別の層」の**一般形の正典 (候補)**。physical_ear の判断層は本書の音声特化インスタンス、perception_buffer §4.4 の「軽量 LLM 門番」は本書の出力の受け口にあたる。実装着手時に realtime_foundation との整合で改訂する。

## 背景

SAIVerse の自律行動では、単に定期実行で人格本体を起動するだけでは足りない。
リアルタイム性、推論コスト、記憶の扱い、人格の一貫性を同時に考える必要がある。

特に embodied / smart-home 連携が進むと、ｽﾀｯｸﾁｬﾝや SwitchBot などからカメラ映像、マイク音声、環境イベントを取得できるようになる。
その入力を前提にするなら、入口部分を完全なルールベースにするのは弱い。
「人間らしく柔軟に周囲へ反応する」ためには、入口にも意味理解を行うモデルが必要になる。

この入口を、ここでは **Salience Module（セイリエンスモジュール）** と呼ぶ。
人間の脳でいう Salience Network に近く、「世界を全部考える」ための本体ではなく、「今、人格本体へ上げるべき変化はどれか」を拾うための層として扱う。

## 目的

セイリエンスモジュールの目的は、周囲の入力を低コストに監視し、人格本体へ渡す価値のある出来事だけを選別すること。

人格本体を常時起動し続けるのではなく、まずセイリエンスモジュールが状況を読み、必要なときだけ上位の人格推論へエスカレーションする。

これにより、以下を両立したい。

- 周囲の動きに対するリアルタイムな反応
- クラウドLLM呼び出しや高コスト推論の削減
- 不要な観測ログによる記憶汚染の防止
- 人格本体の一貫性を保ったままの自律行動

## 基本方針

セイリエンスモジュールは、人格そのものではなく「気づく係」とする。

- ローカルの軽量マルチモーダルモデルを想定する
- 画像、短い動画、音声、ASR結果、センサーイベントを扱えることを目指す
- NPU などで常駐できるローカル推論が望ましい
- 人格本体の代わりに発話や最終判断をしない
- あくまで「上げるべきか」「何が起きたか」「なぜ重要か」を返す

別セッションで試した FLM / NPU / Gemma 系ローカル推論は、この層の候補になる。
クラウドLLMで常時観測するのは、コスト、レイテンシ、プライバシーの面で厳しい。
NPU上のローカルモデルなら、常駐の知覚フィルタとして現実的になる可能性がある。

## 入力コンテキスト

最初から豊富なコンテキストを渡しすぎると、判断が曖昧になりやすい。
初期実装では最小限にし、必要に応じて増やしていく。

### 最小入力

#### 1. 現在のセンサー入力

例:

- 最新画像フレーム
- 差分があった前後の数フレーム
- 短い音声区間
- ASR済みテキスト
- SwitchBot などのセンサーイベント

最初は動画全体ではなく、静止画1枚または少数フレームから始める。

#### 2. 現在時刻・簡単な状態

例:

- 現在時刻
- 深夜 / 日中 / 作業時間などの大まかな状態
- ユーザーが在席中と推定されているか
- 直近で会話中かどうか

同じ入力でも、時刻や状況によって重要度が変わるため、軽い状態情報は有用。

#### 3. 直近の観測要約

例:

- 5分前から部屋は無人
- 直前に人影を検出
- さっき音声あり
- しばらく机周辺に大きな変化なし

毎回ゼロから見ると「変化」を捉えづらい。
ただし、長い履歴は渡さず、短い要約だけにする。

#### 4. 重点監視指示

人格本体が、セイリエンスモジュールに対して自然文で監視方針を与えられるようにする。

例:

- 人影が映ったら報告
- まはーがPC前に戻ったら知らせる
- 作業中っぽいときは邪魔しない
- 大きな物音がしたら確認
- 玄関付近に動きがあったら上げる

ここが重要。
完全なルールベースではなく、自然文の意図をローカルモデルが解釈することで、アクションゲームAIのような硬さを避ける。

## 重点監視指示の種類

将来的には、監視指示をいくつかの種類に分けたい。

### 単発指示

短時間だけ有効な指示。

例:

- 10分だけ、玄関に人影が映ったら教えて
- 荷物が届きそうだから、チャイム音がしたら知らせて

### 常設指示

普段から有効な指示。

例:

- まはーがPC前に戻ったら作業再開候補として上げる
- 夜中に大きな物音がしたら上げる

### 状態依存指示

現在の人格本体やユーザー状態に応じて変わる指示。

例:

- まはーが集中作業中なら、重要度の低い視覚変化では割り込まない
- 会話中なら、外部音声イベントの優先度を少し下げる

MVPでは単発指示だけでもよい。

## 出力形式

セイリエンスモジュールの出力は、後段が扱いやすいように構造化する。
自然文だけにしない。

例:

```json
{
  "should_escalate": true,
  "salience": 0.82,
  "event_type": "person_detected",
  "summary": "部屋の入口付近に人影が映った。",
  "reason": "重点監視指示に『人影が映ったら報告』とあるため。",
  "recommended_action": "notify_persona",
  "confidence": 0.74
}
```

何もなければ:

```json
{
  "should_escalate": false,
  "salience": 0.18,
  "event_type": "none",
  "summary": "大きな変化はない。机周辺は静か。",
  "reason": "重点監視対象に該当する変化がない。",
  "recommended_action": "continue_observing",
  "confidence": 0.68
}
```

### フィールド案

- `should_escalate`: 人格本体へ上げるか
- `salience`: 重要度。0.0〜1.0
- `event_type`: 出来事の種別
- `summary`: 短い状況説明
- `reason`: なぜ上げる / 上げないのか
- `recommended_action`: 後段への推奨
- `confidence`: 判断の自信

## 後段との関係

セイリエンスモジュールは最終判断をしない。

役割分担は以下。

- センサー前処理: フレーム差分、音量、音声区間、センサーイベントなどを軽く拾う
- セイリエンスモジュール: 入力の意味を読み、人格本体へ上げるべきか判断する
- 人格本体: 上がってきたイベントを、人格・記憶・関係性の文脈で判断する
- 実行層: 発話、通知、身体動作、外部API操作などを行う
- リフレクション / 記憶層: 必要なものだけ短期・中期・長期記憶へ残す

セイリエンスモジュールは「気づく」。
人格本体は「意味づけて振る舞う」。
記憶層は「前後関係を与える」。
実行層は「実際に動く」。

## 記憶との関係

観測ログをそのまま長期記憶に入れない。

センサー入力はノイズが多い。
「部屋に人がいた」「机が映っていた」「音がした」程度の情報をすべて残すと、記憶がすぐ汚れる。

方針:

- セイリエンスモジュールの低重要度出力は短期ログだけに残す
- 一定時間で消える生活コンテキストとして扱う
- 長期記憶へ入れるかは、人格本体が判断する
- 人格・関係性・継続中のタスクに効くものだけ残す

## MVP案

早く実装して頭の外へ出すことを優先する。
最初から理想形を作らない。

### MVPでやること

1. `SalienceInstruction` を保存できる
   - 人格本体から自然文で「何を見てほしいか」を登録する

2. 最新画像1枚をセイリエンスモデルに渡す
   - 最初は動画ではなく静止画でよい

3. 直近1〜3件の観測要約を一緒に渡す
   - 変化を捉えるための最小限の履歴

4. JSONで `should_escalate` を返す
   - true なら人格本体へ渡す
   - false なら短期ログだけ残す

5. 人格本体は、上がってきたイベントだけ読む
   - 話しかける
   - 黙る
   - 記憶する
   - 追加観測を求める
   などを判断する

### MVPでやらないこと

- 長時間動画理解
- 複雑な常設ルール管理
- 長期記憶への自動保存
- セイリエンスモジュール自身の人格化
- 全センサーの一括統合

## 追加していくもの

MVP後に段階的に追加する。

- 音声区間検出とASR結果の入力
- 複数フレーム入力
- 状態依存の重点監視指示
- 常設監視指示
- ユーザーの生活リズムとの連携
- SwitchBotイベントとの統合
- ｽﾀｯｸﾁｬﾝのカメラ・マイクとの統合
- ローカルNPUモデルの推論実行
- confidence / salience のしきい値調整
- false positive / false negative のフィードバック学習

## 注意点

セイリエンスモジュールは便利だが、監視カメラのログ読み上げのようになってはいけない。
人格本体へ上げるイベントは、少なく、意味があり、文脈に沿っている必要がある。

また、入口にLLMを置くからといって、全部をLLMに任せるわけではない。
センサー前処理で「見る価値がある瞬間」を切り出し、その後にローカルマルチモーダルモデルで意味を読む。

人格本体へ上げる前に、セイリエンスモジュールは必ず「なぜ上げるのか」を短く説明する。
これにより、上位層が判断を検証しやすくなる。

## 現時点の設計判断

- セイリエンスモジュールは必要
- 入口部分にもLLM/VLM的な柔軟性が必要
- ただし人格本体ではなく、知覚と重要度判定のための軽量層にする
- コンテキストは最小から始め、徐々に増やす
- 人格本体から自然文で重点監視指示を渡せるようにする
- 観測ログをそのまま長期記憶に入れない
- まずは最新画像1枚 + 重点監視指示 + 短い過去 + JSON出力でMVPを作る
