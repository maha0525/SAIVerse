# モデルを選ぶ欄の作り直し

**ステータス**: 検証待ち — 実装済みで、メティスがテスト用の環境の画面で 4 つの画面を操作して確かめた (2026-11-13)。まはーの本番の画面での確認待ち
**関連**: [model_provider_management.md](model_provider_management.md) / [persona_model_selection.md](persona_model_selection.md)
**コード**: `saiverse/model_picker.py` (並べ方を決める一か所)、`api/routes/config.py` (`GET /api/config/models`)、`builtin_data/providers/*.json` (`current_models`)、`frontend/src/components/common/ModelPicker.tsx`、モデルを選ぶ欄を持つ画面 (`ChatOptions.tsx` / `SettingsModal.tsx` / `GlobalSettingsModal.tsx` / `settings/WorldEditor.tsx`)

## 一言で

モデルを選ぶ欄を、どの画面でも同じ見た目・同じ並びにする。選ぶ人はまずプロバイダを選び、次にそのプロバイダのモデルの中から選ぶ。プロバイダごとに「最初から出すモデル」を私たちが決めておき、それ以外は「他のモデル」に畳む。

## 何に困っていたか

- 標準で入っているモデルは 140 個を超える。日常的に使うのは数個なのに、選ぶたびに全部が一列に並び、スクロールして探すことになる。
- 古い世代のモデルも、最新のモデルと同じ扱いで並んでいる。
- Gemini は同じモデルが有料と無料で 2 行ずつ並ぶ。
- モデルを選ぶ欄が画面ごとに別々に作られていて、見た目も、並び方も、「使えるモデルだけ出す」の判定も違う (チャットオプション・ペルソナ設定・グローバル設定の「モデルロール設定」(会話用・軽量用など、役割ごとに使うモデルを決める画面)・ワールドエディタ)。
- お気に入りは助けにならない。面倒なのはお気に入りに入れる前、全部の中から目当てを見つける場面だから。お気に入りを全画面で共有すると、用途の違うモデルが混ざって膨らむ。

## 決まったこと (2026-11-12〜13、まはーとの相談)

1. **プロバイダを先に選ぶ。** 欄を開くとプロバイダのボタンが並び、押したプロバイダのモデルだけが下に出る。開いた直後は、いま選ばれているモデルのプロバイダが押された状態になる。使えるモデルが 1 つも無いプロバイダのボタンは出さない。
2. **Gemini は有料と無料を別のボタンにする。** モデル定義の `prefer_paid` (有料の鍵を使うかどうかの印) で分ける。モデル定義もプロバイダ定義も作り直さない。
3. **プロバイダごとに「最初から出すモデル」のリストを持つ。** プロバイダ定義の `current_models` に、モデル定義のファイル名 (拡張子なし) を並べる。新しい世代を足すたびに私たちが手で更新する。名前や料金からの自動判定はしない (Gemini の Argon / Carbon、GPT の Sol / Terra のように、名前から世代や新しさが分からないため)。
4. **リストに無い標準のモデルは「他のモデル」に畳む。** 「他のモデル」を開けば全部出る。消しはしない。
5. **リストの順番が、表示の順番になる。** 「他のモデル」の中は名前の順。
6. **利用者が自分で追加したモデルは、リストに無くても最初から出す。** 畳むのは標準で入っているモデルだけ。
7. **リストを持たないプロバイダは、全部を最初から出す。** 利用者が自分で作ったプロバイダがこれに当たる。
8. **利用者が自分で作ったプロバイダと、手元で動かすサーバー用の標準プロバイダ (Ollama / LM Studio / llama.cpp) は、1 つのボタンにまとめる。** ボタンの中では、プロバイダの名前を見出しにして分ける。1 つ 1 つをボタンにすると、手元のサーバーをいくつも登録している人ではボタンが 10 個以上増えるため。
   利用者が標準のプロバイダの設定を画面から編集しても (たとえば OpenRouter の接続先を変える)、そのプロバイダのモデルは元のボタンに残り、最初から出すモデルも標準のリストのとおりのままにする。
   反射判断専用のプロバイダ (型付きの質問に確率で答えるだけで、文章を書けないモデルのプロバイダ。6 つあり、モデルは 1 つずつ) も、同じやり方で「反射判断専用」という 1 つのボタンにまとめる。このボタンは反射判断のモデルを選ぶ欄にだけ出て、そこでは先頭に並ぶ。
   利用者が自分で作ったプロバイダと手元のサーバー用のプロバイダをまとめるボタンの名前は「カスタム」(2026-11-13 に「ローカル・カスタム」から短くした)。
9. **いま選ばれているモデルは、畳まれる側のものでも、開いた直後に見える。** 開いた直後はそのモデルのプロバイダが押された状態になり、畳まれる側のモデルなら「他のモデル」も開いた状態で始まる。古いモデルを使い続けている人が、自分の設定を見失わないようにする。
10. **お気に入りはチャットオプションだけのもの** (いままでどおり)。チャットオプションでは、お気に入りが「お気に入り」の見出しの下にまとまって出る。各行の星を押して、その場でお気に入りに入れたり外したりできる。ほかの画面にお気に入りは出さない。
11. **どの画面も同じ一覧 (`GET /api/config/models`) を使う。** API キーが無くて使えないモデルは、どの画面でも出さない。定義が壊れているモデルは、いままでどおり選べない状態で見せる。
12. **並べ方を決めるのはサーバーの一か所** (`saiverse/model_picker.py`)。画面の側では受け取った順番のまま表示し、画面ごとの並べ替えはしない。
13. **欄を開いたときの並びは、上から「選ばない」の選択肢 (「（デフォルト）」など) → 「お気に入り」の見出しとお気に入りのモデル → 「プロバイダ」の見出しとボタンの列 → 押されているプロバイダのモデル → 「他のモデル」。** プロバイダのボタンの名前は短くする: Meta (Muse) は「Meta」、PLaMo (Preferred Networks) は「PLaMo」、Sarashina (SB Intuitions) は「Sarashina」(どれもドメイン名に使われている名前で、モデルが増えても変わりにくいため)。

## 守ること

- リストに書いた名前は、実在するモデル定義でなければならない。打ち間違いや消し忘れがあれば、自動テストでエラーになって気づけるようにする。
- リストは「最初に見せるかどうか」だけを決める。リストに無いモデルも、選べば今までどおり使える。ペルソナやグローバル設定に保存済みのモデルには何も起きない。
- 画面を作り直しても、いま各画面に出ている情報は減らさない (チャットオプションの料金と 1 日の回数上限の表示、定義が壊れているモデルの「無効」の表示、保存済みのモデルが一覧に無いときの表示、「標準の設定を使う」の選択肢)。

## やらないこと

- 名前で絞り込む検索欄。プロバイダを先に選べば、残るのは数個なので要らないと見ている。足りなければ後で足す。
- OpenRouter の「他のモデル」を開発元ごとの見出しで分けること。最初から出す 7 つで足りるかを先に使って確かめる。
- チュートリアルのモデルの選び方。チュートリアルはプリセットを選ぶ画面で、モデルを 1 つずつ選ぶ欄ではない。

## 検証

- テスト用の環境 (別フォルダにした `SAIVERSE_HOME`) で画面を開き、チャットオプション・ペルソナ設定・モデルロール設定・ワールドエディタの 4 画面で、プロバイダを選ぶ → モデルを選ぶ → 保存される、を私が操作して確かめる。ライトとダークの両方、スマホ幅でも見る。
- 本番の画面での確認は、マージの前にまはーが行う。

## 経緯

- 2026-11-12: まはーが 3 つの画面のスクリーンショットを見せて「選択肢が多すぎてスクロールに手間取る」「全部体裁が違う」と相談。私の最初の案 (お気に入りを全画面で共有して最初はそれだけ見せる) は、「面倒なのはお気に入りに入れる前」「全画面で共有するとお気に入りが膨らむ」で退けられた。Claude・Codex・Antigravity・DeepSeekHarness の選択画面を見比べ、決まった型は無いと確認。プロバイダを先に選ぶ・古いモデルを畳む・Gemini を有料と無料に分ける、の 3 つがまはーから出た。
- 2026-11-13: 畳むかどうかを名前から機械的に決める案は、まはーが「機械的な分類は不可能」と退け、プロバイダごとに手で持つリストに決まった。同じ日に、OpenRouter の最新 5 モデルの追加と GPT-5.6 系の 272k への修正を先に入れた。
- 2026-11-13 (PR #476 のマージ後): まはーが本番の画面を見て、体裁の直しを 4 つ出した。「（デフォルト）」がプロバイダの列の直前にあって何のデフォルトか分からないので一番上へ。プロバイダの名前が長いものを短く。開いていきなりお気に入りの列が出るのが面食らうので「お気に入り」の見出しを付ける。プロバイダの列にも「プロバイダ」の見出しを付ける。あわせて、いま選ばれているモデルを一番上に出すのをやめた (お気に入りでないモデルが「お気に入り」の見出しの下に出てしまうため。選ばれているモデルは、そのプロバイダが押された状態で開くことで見える)。「ローカル・カスタム」の中にモデルが多く並ぶ件は、多ければ利用者が自分で整理できるので、この形のままにした。
