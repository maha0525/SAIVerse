## 1. 要点 (数行で)

SAIVerse は毎ターン、最新の発言の近くに「リアルタイム情報」(現在時刻・リアルタイムスペルの結果) と「自動想起」(ふと浮かんだ記憶) を差し込み、次のターンには消している。消える物が末尾近くにあると、キャッシュとして保持されている前回の送信の範囲と、今回の送信の先頭が一致しなくなる。

キャッシュの境目をこちらから指定できるモデル (Claude の cache_control、Gemini の継続キャッシュ) なら、消える物の手前を境目にすれば済む。指定できないモデル (Gemini 4 Argon の暗黙キャッシュ) では、消える物そのものを無くすしかない。

そこで、**モデル設定で ON にしたモデルでは、差し込んだリアルタイム情報と自動想起を、送った時点でペルソナのデータに残し、次のターン以降も同じ位置に同じ文面で送る。** 送る中身は毎ターン後ろに足されるだけになり、前回の送信が今回の送信の先頭とそのまま一致する。

## 2. なぜ必要か (実測)

2026-10-14、Gemini 4 Argon の暗黙キャッシュを、SAIVerse を通さない直接の呼び出しで測った。

- Argon の暗黙キャッシュで保持されていたのは二か所だけだった。前回の送信の「末尾から 2,049 トークン手前まで」と「システムプロンプトの終わりまで」。同じ中身を送り直すと、三つの実験すべてで「全体 − 2,049」だけが当たった。
- 2,017 トークンの差し込みを最後の発言の前に置いた場合、次のターンはほぼ全部当たった。3,217 トークンにすると、前に置いても後ろに置いても、システムプロンプトの分しか当たらなかった。
- キャッシュの保持時間は、8 分あけた送り直しでは当たり、11 分半では当たらなかった (各一回の測定)。

アイフィとの実際の会話でも同じ形が出た。画像付きの発言 (画像だけで 1,151 トークン) の次のターンは、9 万トークン中、システムプロンプトの 26,349 トークンしか当たらなかった。当たった回と外れた回で、1 回あたりの費用は約 $0.017 と約 $0.14 で、8 倍違う。

「2,049」は公式の数字ではなく実測の値なので、Google が変えれば変わる。この設計はその数字に依存しない (毎ターン後ろに足すだけなら、キャッシュの範囲がどこで切れても、前回の送信は今回の送信の先頭と一致する)。

## 3. 設定

モデル定義の `cache` に `persist_realtime_and_recall` (真偽値、省略時 false) を置く。

```json
"cache": { "type": "implicit", "explicit_supported": false, "persist_realtime_and_recall": true }
```

- ON にするのは、境目を指定できないキャッシュで、かつキャッシュに乗った分の割引が大きいモデル。2026-10 時点の組み込みでは Gemini 4 Argon だけ。
- 境目を指定できるモデル (Claude、明示キャッシュの Gemini) では OFF のままにする。保存したメッセージの分だけ Metabolism (古い会話をあらすじに置き換えて送る量を減らす処理) が早く実行されるのに、得るものが無い。
- llama.cpp は、境目の目印をこちらから渡せるようにするフォークが本来の対応 ([issue](../issues/llama_prompt_cache_full_reprocess_swa_checkpoint.md))。それができるまでのつなぎとして、この設定を ON にすることもできる。

設定値は `saiverse/model_configs.py` の `get_cache_config` で読み、未指定なら false になる。ON かどうかは、送る列を組むときのモデル (`prepare_context` に渡る `model_key`) で決める。組んだ後で別のモデルへ切り替わる経路 (tell の `select_llm_client` など) は、組んだときのモデルの判定に従う。

## 4. ON のモデルで何が変わるか

### 4.1 送る並び

ON のモデルへ送るとき、そのターンのリアルタイム情報と自動想起は、一つのまとまりとして**送る列の一番後ろ** (最新の発言と、そのターンの知覚のまとめの後ろ) に置く。OFF のモデルは今までどおり (最新の発言の直前)。リアルタイム情報のメッセージが無いターンにリアルタイムスペルが自前でメッセージを作る経路も、ON では一番後ろに置く。

一番後ろに置くのは、次のターンにこのまとまりが出る位置 (= 残した時点で最後にあった発言とそのターンの知覚の直後) と、今回送る位置を一致させるため。同じパルスの中で LLM 呼び出しが二回目以降 (スペルの繰り返し) になっても、このまとまりは最初の位置に据え置き、ツールの往復はその後ろに積む。

### 4.2 保存する

そのまとまりを、送った文面のまま、ペルソナの `memory.db` に一行のメッセージとして保存する (以下「保存したメッセージ」)。保存先は知覚のまとめと同じ表 (`perception_batches`) で、種類の欄で知覚と区別する。保存先を揃える理由は、送る列から外す規則 (Chronicle の付記で外れる)・Metabolism の量の勘定・位置を決める既存の列 (`boundary_created_at` / `boundary_rowid` = 残した時点で最後に保存済みだった発言) に、前例の仕組みのまま乗れるから。

- **残す時刻**: そのターンの最初の LLM 呼び出しが成功した後。リアルタイムスペルの結果は最初の LLM 呼び出しの直前に足されるので、それより前には文面が確定しない。呼び出しが失敗したターンは残さない (返事の無いターンに、差し込みだけが残ることを防ぐ)。
- **残すパルス**: state の `_pulse_type` が user / auto / schedule のパルスだけ。それ以外 — キャッシュを保つための定期の送信 (keepalive)、Metabolism の前に覚えておくことを採取する処理 (`sea/sluice.py`)、作業セッション (`work_session`)、tell、判断のパルス (meta_judgment) — では差し込みを残さない。作業セッションや tell の実行時にもペルソナの発話は生まれるが、これらは会話の流れとは別に組んだ列で一回ずつ呼ぶ処理で、その列の続きが次のターンに来るわけではないので、残しても前方一致の役に立たない。これらの処理でも、すでに残してある差し込みは送る列に含める (4.3)。その処理自身が組んだ差し込みは、今までどおり次のターンには消える。
- **一ターン一回**: スペルの繰り返しで LLM 呼び出しが何度あっても、残すのは一回。
- **出すものが無いターン**: 時刻の項目が両方 OFF でスペルの結果も無く、新しく浮かんだ記憶も無いターンは、まとまり自体を作らず、何も残さない (realtime_info.md 不変条件 3 と同じ)。
- **画像**: リアルタイムスペルが画像を返したときは、その画像も一緒に残す。保存したメッセージの画像は、送る画像の枚数の上限 (既定 4 枚、新しい順) の数に**入れない** (head の視覚メッセージと同じ扱い)。数に入れると、残した画像が増えるたびに一番古い画像が文字に置き換わり、そこから後ろが毎ターン一致しなくなる。

### 4.3 次のターン以降の送り方

- 保存したメッセージは、**残した時点で最後に保存済みだった発言 (とそのターンの知覚) の直後**に置く。位置は既存の境界の列 (`boundary_created_at` / `boundary_rowid`) で決め、時刻の秒では決めない。知覚のまとめは秒単位の時刻の順に並ぶため、同じ秒の前後が区別できない。保存したメッセージは最新の発言と返事のすき間という狭い位置に入るので、秒の丸めで前後が入れ替わる余地がある。同じ発言の直後に並ぶもの同士は、表の id の順に並べる。
- **位置を決める発言が送る列に無いとき** (別のスレッドにいる、Chronicle を無効にしたペルソナの窓の外、など) は、その差し込みを送らない。自動想起の台帳を thread ごとに分けた理由 (前のスレッドで浮かんだ記憶を新しいスレッドの冒頭へ出さない — memory_architecture_v2.md §4.3 の 2026-07-12 実装ノート) を、保存したメッセージでも守るため。
- 保存したメッセージを送るのは、送り先のモデルが ON のときだけ。OFF のモデルへ送るときは保存したメッセージを含めず、今までどおりそのターンの差し込みを最新の発言の直前に置く。
  - 例: アイフィが Argon (ON) で 10 ターン話したあと 3.8 Flash (OFF) に切り替えると、3.8 Flash へは保存したメッセージが送られず、毎ターンの差し込みが今までどおり出る。Argon に戻すと、保存したメッセージは元の位置に戻ってくる。
- 保存したメッセージは、Chronicle の付記で送る列から外れる (知覚のまとめと同じ)。
- **あらすじの材料には入れる** (arasuji_levels.md §7-1 のまはー裁定「本人の提示に立った行は、すべて編纂の材料と被覆に入る。意味・種類による仕分けはしない」。編纂 = あらすじ作成、被覆 = あらすじが元の発言のどこまでを要約済みとして受け持つかの範囲)。材料では、想起を含む差し込みに【想起 (過去の再提示)】のラベルを付け、生成プロンプトの既存の注記 (過去の出来事の再提示であり、この期間の新しい出来事として語らない) に乗せる。想起を含まない差し込み (時刻とスペルの結果だけ) は【通知】のラベルにする。長さは機構名義の行と同じ規則 (閾値を超えたら、LLM を使わず本文と metadata から機械的に作る一行に縮めて材料に渡す) に従う。
- 知覚のキーワード検索 (記憶検索 API の `search_perceptions`) には入れない。

### 4.4 自動想起の出し方

ON のモデルでは、想起は「新しく浮かんだ分だけ」を出して残す。

- 今の自動想起の仕様では、一度浮かんだ記憶を「粘着」させ、話題から外れて 3 ターン経つまで毎ターン全件を出し直す。ON のモデルでそのまま残すと、同じ記憶が毎ターン積み重なる。
- ON のモデルでは、**いま送る列にある保存したメッセージに入っている記憶を、候補を集める段階で除外する** (採用した後で捨てると、候補の枠が既出の記憶で埋まったまま件数だけ減る — auto_recall_jev_rerank.md の詰まり 1 と同じ理由)。そのために、保存したメッセージには、出した記憶の識別子 (種類と id) を構造化して持たせる。
- 「新しく浮かんだ」の基準は、粘着の台帳ではなく保存したメッセージにする。台帳の記録は keepalive や作業セッションの呼び出しでも更新されるので、台帳を基準にすると、それらの呼び出しで最初に浮かんだ記憶が二度と残らなくなる。
- 一度出た記憶は、Metabolism で送る列から外れるまで、ペルソナの目に入り続ける (粘着の「しばらくしたら引っ込める」は、ON のモデルでは働かない — 2026-10-14 まはー了承)。
- 画面に出す想起 (UI の表示と、返事に付ける想起の記録) も、残したのと同じ「新しく浮かんだ分」にする。
- 新しく浮かんだ記憶が一つも無いターンは、想起を出さない (リアルタイム情報があればそれだけを残す)。

### 4.5 自動想起のきっかけにしない

保存したメッセージは、知覚のまとめとは別の印を付け、自動想起のきっかけ (検索に使う文。このターンに新しく目に入った物) と Jev に渡す観察 (`_trailing_perception_blocks` / `_is_conversational_message` / `_latest_user_message` が集める物) から明示的に外す。同じ印にすると、ユーザーの発言の無いターン (自律の思考) で、保存したメッセージが想起のきっかけになり、思い出したことをまた思い出す循環が起きる。

### 4.6 リアルタイム情報

ON のモデルでは、毎ターンの「現在時刻」の行が残っていく。ペルソナには会話の各ターンの時刻が残ることになる。「前回発言」の行は、OFF と同じくペルソナ設定のトグルに従う。

## 5. 守ること (不変条件)

1. **前回の送信は、今回の送信の先頭そのもの** — ON のモデルで、あるターンに送った列は、返事を挟んだ次のターンの列の先頭と、保存したメッセージまで含めて一字一句同じになる。例外は、Metabolism・head の作り直しが起きたターンと、ユーザーの画像が増えて枚数の上限で古い画像が文字に置き換わったターン (既存の issue `image_attachment_limit_breaks_cache_prefix.md`。この設計の範囲外)。これがこの設計の存在理由で、検収で最も重く見る点。
2. **OFF のモデルは何も変わらない** — 送る並びも、残すかどうかも、自動想起の出し方も、今までと同じ。
3. **保存したメッセージは機構の名義** — `<system>` タグ付きの user ロールで残し、ペルソナの発言としては残さない。想起のきっかけにも、知覚のキーワード検索の対象にもならない。あらすじの材料には §7-1 どおり入り、ラベルで機構の物と分かるようにする。
4. **一ターン一行** — `_pulse_type` が user / auto / schedule のパルスの、最初の LLM 呼び出しの成功につき一行。失敗したターン・keepalive・Metabolism の前の採取・作業セッション・tell・判断のパルスでは残さない。

## 6. 全体の流れ (時間順)

```
パルスの頭: 知覚を消費してバッチにする (今まで通り)
  ↓
prepare_context: head + 履歴 + 知覚のまとめ
                 + [ON なら 保存したメッセージを、位置を決める発言の直後へ (発言が無ければ送らない)]
                 + そのターンのリアルタイム情報・自動想起
                   [ON なら 既出の記憶を候補から外し、送る列の一番後ろ / OFF なら 最新の発言の直前]
  ↓
最初の LLM ノード: リアルタイムスペルの結果を足す → LLM 呼び出し
  ↓ 成功
[ON かつ user/auto/schedule なら そのターンの差し込みを、送った文面のまま一行残す]
  ↓
返事を保存 (今まで通り)
  ↓ 次のターン
prepare_context: 保存したメッセージは「残した時点で最後の発言」の直後に出る → 前回の送信と一致
```

## 7. 置き場所の理由

- **なぜ残すのか (境目の指定でなく)**: Argon は境目を指定できず、キャッシュの範囲も Google が決める。直せるのは「末尾に消える物を置かない」ことだけ。
- **なぜモデルごとか**: 境目を指定できるモデルには得が無く、保存したメッセージの分だけ Metabolism が早まる損だけが残る。
- **なぜ知覚のまとめと同じ保存先か**: 送る列から外す規則・Metabolism の量の勘定・位置を決める境界の列・あらすじの材料への引き渡しを、新しく作らずに済む (別の表にすると、付記で外す仕組みと勘定への参加を自前で作ることになり、作り漏れで保存したメッセージが送られ続けるか、勘定から漏れる)。前例と違うところ (想起のきっかけから外す・キーワード検索から外す・モデルで送り分ける・材料のラベル) は、種類の欄で分岐させる。

## 8. 残る結果

- ON のモデルでは、保存したメッセージの分だけ会話が速く伸び、Metabolism が早い段階で実行されるようになる。Metabolism を実行したターンはキャッシュが一度外れる。Argon のようにキャッシュに乗った分が 1/20 のモデルでは、保存したメッセージを送り続ける費用より、毎ターン外れる費用の方がずっと大きいので、差し引きで得になる。
- キャッシュの保持時間 (実測で 8〜11 分) を超えて間があいたターンは、この設計でも外れる。明示キャッシュの無いモデルでは手の打ちようがない。
- 自動想起の「粘着」が ON のモデルでは働かなくなる (4.4)。
- ON から OFF に切り替えると、ON のときの返事が引用した想起の原本が、OFF のモデルには見えなくなる (粘着が防いでいた「引用した次のターンに原本が消える」形が、切り替えの瞬間にだけ起きる)。
- 送る列の最後が `<system>` の差し込みになる (返事を求める最新の発言の後ろに機構の文が来る)。返事が想起の方へ引っ張られないか、またペルソナが `<system>` の形を真似て偽の通知を書かないか (memory `feedback_no_assistant_impersonation_in_memory` の逆方向の事故) は、まはーの実機で確かめる。
- ユーザーの画像が 5 枚目に達するたびに一番古い画像が文字に置き換わって先頭の一致が崩れる問題は、この設計では直らない (既存の issue)。Argon では ON にしたことで、この崩れ方が目立つようになる。

## 9. 検証

- **一字一句の一致 (不変条件 1)**: 隔離環境で、ON のモデル設定・合成ペルソナ・偽の LLM を使い、二ターン続けて送る列を取り出して、一ターン目の列が二ターン目の先頭と完全に一致することを確かめる。リアルタイムスペル付き (画像あり)・自動想起の新規採用あり/なし・同じ秒に発言と残す時刻が並ぶ場合・スペルの繰り返しがある場合を含める。
- **OFF の不変 (不変条件 2)**: 同じ手順を OFF のモデルで行い、送る列が変更前と同じであることを確かめる。
- **切り替え**: ON → OFF → ON で、保存したメッセージが送られなくなり、また戻ること。
- **残さない処理**: keepalive・Metabolism の前の採取・作業セッション・tell・判断のパルスで行が増えないこと。失敗したターンで行が増えないこと。
- **想起**: 既出の記憶が候補の段階で外れ、新しい記憶が枠に入ること。保存したメッセージが自動想起のきっかけと Jev の観察に入らないこと。
- **あらすじ**: 付記で送る列から外れ、材料には【想起 (過去の再提示)】/【通知】のラベル付きで入ること。
- **実機**: まはーが Argon のペルソナと続けて話し、画像付きの発言の次のターンもキャッシュが当たることをログで見る (`[DEBUG] Usage recorded: ... cached=`)。
