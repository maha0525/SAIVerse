## 一言で

ペルソナが話す標準モデルは、「チャット画面のモデル一時上書き → ペルソナ個別の標準モデル → グローバル設定の標準モデル」の順に見て、空でない最初のものになる。どれも空なら、組み込みの既定モデルになる。

どの画面で設定を変えても (モデルやプロバイダの設定そのものを含む)、その場でこの順番に沿って全員のモデルを決め直す。再起動は要らない。書いている途中の返事は前の設定で最後まで書き、次の返事から新しい設定になる。

選ばれたモデルが SAIVerse に無いとき、または繋げないときは、代わりのモデルでは動かさない。そのかわり、どこで選び直せば話せるかを、ユーザーに見える場所で伝える。設定ファイルの無いモデルの名前は、そもそも保存しない。

## 全体像 — 誰に何を約束するか

- **ユーザー**: 画面で選んだモデルと、ペルソナが実際に話すモデルが食い違わない。食い違う状態が起きるなら、黙っていないで、その操作をしたその場の画面で伝える。とくに、安いモデルに変えたつもりのまま、知らされずに高いモデルで話し続ける、という費用の損害を起こさない。設定を変えたら、再起動しなくても効く (まはー「ユーザーにとってはすぐ反映されないものっていう発想自体が無いし」)。
- **ペルソナ**: ユーザーが選んでいないモデルで、勝手に話させない。話せないときに、SAIVerse がペルソナの名義で「話せません」と言うこともしない。話せなかったことの知らせは画面にだけ出し、建物の会話の記録やペルソナの記憶には書かない (建物の記録に書くと、同じ部屋のペルソナの記憶にまで写る)。
- **保守**: 話すモデルを決める順番を、コードの一か所にだけ書く。2026-09-11 の時点では六か所に、少しずつ違う形で書かれていた (下の「経緯」)。

## 決まったこと

1. **設定を変えたら、その場で反映する。話すモデルを決める順番は、コード上の同じ処理一つにまとめる。** 対象は、グローバル設定の標準モデルの保存 (「モデルロール」画面・チュートリアルでの選び直し・環境タブ・プリセット)、ペルソナ設定の保存、チャット画面の一時上書きの設定と解除、ペルソナの作成 (ワールドエディタからの作成と、設計図 (Blueprint) からの生成)、起動時の読み込み、それとモデルやプロバイダの設定の変更 (決まったこと 11)。
   - ペルソナを作るときは、一時上書きのモデルを個別の標準モデルとして保存しない。2026-09-11 の時点では、設計図からペルソナを生成する処理で、一時上書き中なら上書きのモデル名が個別の標準モデルとして保存され、一時上書きが無いとモデル名が空のまま定義を引いて例外になる (コードで確認、実行はしていない)。
   - 根拠: まはーの依頼 (原文)「「保存した標準モデルを、動いているペルソナへ安全に反映する」作りの選択肢を示す」。順番を一か所にまとめる案はメティスが推した。まはーはこの案そのものに一言では答えず、その上で「一人ずつ切り替える」に「それでいい」と決め、以後の議論もこの案の上で進み、2026-09-11 の最後の提示に「ほかはいいと思う」と返した。
2. **一人ずつ切り替える。一人が切り替えられなくても、ほかの人は切り替える。** 切り替えられなかったペルソナは前のモデルのまま話し、そのことを保存したその場の画面と、ページを開いたときの警告で、名前つきで伝える。切り替えられなかった原因が解けたあとは、もう一度保存し直すか、再起動すれば切り替わる。
   - 根拠: メティスが最初に出した「確かめが通らなければ誰も切り替えない」案に、まはー「一人だけ壊れてんのに他二人もClaudeに変えられないのはおかしいだろ。その変更は誰の何を守ってんの？」。守りたかったのは「切り替わっていない人がいるのに、全員に反映されたように見える」を防ぐことで、それは名前つきで伝えれば守れる、と直した案に、まはー「それでいい」。
3. **一時上書き中は、上書きのモデルのまま話す。** 上書きを解除した時点で、新しい標準モデルになる。
   - 根拠: メティスの提案。まはーは 2026-09-11 の最後の提示に「ほかはいいと思う」と返した。
   - メティスの具体化: 選んだモデルが無くて止まっているペルソナも、一時上書き中は上書きのモデルで話せる。そのあいだの警告は「止まっています」ではなく、「上書きを解除すると止まる」ことを伝える。
4. **グローバル設定の標準モデルを空に戻したら、その場で組み込みの既定モデルになる。**
   - 根拠: 理由 (「空に戻すのはユーザーが自分で選んだ操作だから」) はメティスの説明。まはーは「空って何を？」と意味を確かめたあと、異論を出していない。
5. **設定の保存と一時上書きの変更は、一件ずつ順番に処理する (ロック)。** ほぼ同時に二つの保存が来ても、保存された値と実際に話すモデルが逆にならない。別々の設定を同時に保存して、片方が .env から消えることもなくなる。
   - この約束が成り立つように、ロックは .env を書き換える処理そのものに掛ける。モデル以外の設定の画面 (画像の既定品質、「添付したメディアの内容を自動想起に使う」、Gemini の自動キャッシュ) から .env を書き換えるときも、同じロックを掛ける。
   - チャット画面の一時上書きにすでにある仕組み (同じ画面から遅れて届いた古い選択を弾く) は残し、その内側でこのロックを取る。
   - 根拠: 2026-09-11 のレビューが出した穴 (保存と反映を一件ずつにしていない) を受けて、メティスが出した案。まはーは同日の最後の提示に「ほかはいいと思う」と返した。モデル以外の設定の画面にも広げるところはメティスの判断 (まはー未確認)。
6. **設定ファイルの無いモデルの名前は、どの役割でも保存しない。** 同じときに保存したほかの設定は保存する。保存しなかったことと、ペルソナがいま話しているモデルを、保存したその場で画面に出す。対象は、グローバル設定の標準・軽量・Memory Weave (記憶の整理に使うモデル)・画像/音声/動画の要約モデルと、ペルソナ設定の標準・軽量・Memory Weave モデル。
   - 根拠: メティスは最初「組み込みの既定モデルに切り替える」、次に「元のモデルのまま話し、ページを開いたときに警告する」を出した。後者に、まはー「ユーザーにしてみたらClaudeからGPTに変えたと思い込んでるでしょ？それが費用削減のためだったらどうする？安価なGPTだと思い込んでClaudeで話し続けてた時の損害は計り知れない。勝手にそんなことやるのは絶対にダメ」。保存を断ってその場で伝える形は、この発言を受けてメティスが出した。標準モデル以外の役割とペルソナ設定へ広げることに、まはー「うん、拡げていいと思う」(2026-09-12)。
   - 「無い」かどうかは、その役割の値を実際に使う側と同じ引き方で判定する (`role_model_is_defined`)。標準モデルと軽量モデルは設定ファイル名の完全一致、Memory Weave モデルと要約モデルは名前の一部一致も含む引き方になっているのは、使う側がそう引いているから。
   - ペルソナ設定の画像/音声/動画の要約モデルは対象に入れない。保存されるだけで、どこからも読まれないため (`saiverse/model_defaults.py` の `MODEL_ROLES` の注記)。
   - いま効いている値と同じ名前を保存し直したときは、確かめ直さずに受ける。新しい保存ではないからで、ここで断ると「保存しませんでした」と伝えながら、その値は残ったままになる。その値のモデルが無いことは、ページを開いたときの警告が伝えている (メティスの判断、まはー未確認)。
7. **選んだモデルが SAIVerse に無いとき、また繋げないとき、代わりのモデルで動かさない。起動したときも、動いている間も同じ。** 2026-09-11 の時点では次のように代わりのモデルで動いていて、知らせはページを開いたときの警告だけだった。
   - グローバル設定の標準モデルが無い → 組み込みの既定モデルで話していた。
   - ペルソナ個別の標準モデルが無い → グローバル設定の標準モデルで話していた。
   - 軽量モデルが無い、または設定ファイルはあるのに繋げない (API キーが無い、など) → そのペルソナの標準モデルで代わりに動いていた (`sea/runtime.py` の `select_llm_client` の二か所。軽量モデルは安いモデルを当てる役割なので、高くつきやすい)。
   - 画像・音声・動画の要約モデルが無い → 組み込みの既定モデルで要約していた。
   - Memory Weave モデルが無い → すでに、選び直すまで記憶の整理が止まる形になっていた。ほかの役割をこれに揃える。
   - 標準モデルが構造化出力に対応していないときに軽量モデルへ回す既存の使い分けは、失敗の代わりではなく、モデルの能力に合わせた使い分けなので残す。
   - 根拠: 無いときについて、まはー「確かにそうすべきだね。その方が確実で安全だと思う」(2026-09-11)。繋げないときについて、まはー「うん、動かさなくていいと思う。不慮のトラブルで使えないって状態なのだから、それはもう使えないで良いよねって感じ。SAIVerseが要らんおせっかいをするリスクの方が重い」(2026-09-12)。その結果、v0.3.12 で削除したモデルを選んでいた人は、この変更を載せた版に更新したあと選び直すまで、そのペルソナと話せない。
   - 「止まっている」の意味 (メティスの具体化): そのモデルを使う仕事 (返事を書く、自分から動く判断、記憶の整理、画像・音声・動画の要約、会話の要約) をしない。LLM を使わない処理 (部屋の様子の記録など) は今までどおり続く。自分から動く判断は、そのモデルを使う段で失敗する。LLM は呼ばれないので費用は出ない。
   - 将来の構想との関係: [model_provider_management.md](model_provider_management.md) にある「モデル単位で、障害時に切り替える別のモデルを順序付きで指定できるようにする」(まはー構想、未実装) を入れるときは、この決まりを決め直す必要がある。ユーザーが自分で指定した切り替え先は「勝手な代わり」ではないが、この決まりは無条件の文なので、そのままでは両立しない。
   - 外部カタログとの関係: この決まりの下では、カタログから取った定義が消えると、それを選んだペルソナが止まる。カタログの intent が守ると決めていること (1: カタログが無くても機能は落ちない / 4: 更新が止まっても異常として扱わない) と両立させるため、カタログの段階 3 以降では、カタログが取れなくなっても取得済みの定義を消さない (メティスの追記、まはー未確認。段階 3 は未実装)。
8. **話せないときに「どこで選び直せば話せるか」の文面が、確実にユーザーに届くようにする。** まはー「ちゃんとそのモデル切り替えれば話せるっていう文面がユーザーに届くことだけ確実にしてね。見えないと詰むから」。届け先は二つある。
   - Web のチャット画面で話しかけたとき: 返事が出るはずの場所に、エラーとして出す。軽量モデルが無くて返事の途中の仕事が失敗したときも同じ。
   - ページを開いたとき: 画面の上の警告に出す。ペルソナは ID ではなく名前で呼ぶ。グローバル設定の標準モデルが無いときは、個別の標準モデルを持たないペルソナの名前を並べる。ペルソナが自分から動こうとして止まったときは、見ている人がいないので、この警告で伝える。
   - モデルが無いときの文面では、チャット画面でモデルを選び直す (一時上書き) 案内ではなく、ペルソナ設定かグローバル設定の「モデルロール」を案内する。
   - スタックチャンに声で話しかけたときは、今の作りでは届かない。まはー「スタックチャン側については何かドキュメント残しておいて。今触ることではない」→ [issue](../issues/stackchan_voice_errors_not_shown.md)。
9. **手を入れないもの。** Discord Gateway (レガシーで、現在は動作しない見込み — `docs/features/discord-gateway.md`) と、Unity との連携 (普通の発言も受け付けられない作りのままという見立て。裏は取っていない)。
   - 根拠: 外すことを提案したのはメティス。まはーは 2026-09-11 の最後の提示に「ほかはいいと思う」と返した。声で話しかけたときに知らせが届かないスタックチャンは、まはーの言葉つきで別の issue に切り出してある (決まったこと 8)。
10. **書いている途中の返事は、その返事を始めたときのモデル・接続・パラメータで最後まで書く。次の返事から新しい設定になる。** 標準モデルの保存、一時上書きの変更、モデルやプロバイダの設定の変更、どれで変わったときも同じ。
    - 材料: SAIVerse はすでに、「その返事で使うモデルは返事の始まりに決め、ペルソナに送る内容もそのモデルに合わせて組み立てる」と決めている ([beat_execution_context.md](beat_execution_context.md))。途中から新しいモデルに書かせると、前のモデルに合わせて組み立てた内容を新しいモデルに送ることになる。
    - 根拠: まはー「(b)で。理由はメティスの言う通り、(a)やろうとすると色々ごちゃごちゃする。(b)は挙動として特に不思議でもないと思う」(2026-09-12)。2026-09-11 の時点では、チャット画面の一時上書きを変えると、書いている途中の返事の続きから新しいモデルで書かれていた。
    - **受け入れた限界** (四つを挙げたのはメティス。まはーが「実用上は実害出ないと思う」と受け入れた、2026-09-12): 返事を書いている途中に設定を変えると、次の四つはその一回の返事にも入り込む。入り込むのは設定ごとに見て「前の設定」か「新しく選んだ設定」のどちらかで、代わりのモデルにはならない。次の返事からは全部新しい設定になる。
      1. API キーを書き換えたとき、その返事がまだ接続を作っていなければ、新しいキーで繋ぐ。
      2. 画像・音声・動画の要約モデルを変えたとき、その返事の中で行う要約は新しいモデルで行う。
      3. モデル管理でそのモデルの設定 (構造化出力に対応するか、llama.cpp の起動設定など) を書き換えたとき、その返事の残りの部分は、書き換えたあとの設定で動く。
      4. 保存とほぼ同じ瞬間に始まった返事は、古い設定と新しい設定が混ざった状態で始まることがある (ペルソナの値は保存の前、モデルの定義は保存の後、のような混ざり方)。
    - 隙間なく守る形 (返事の始まりに API キー・要約モデル・モデルの能力の設定までコピーしておき、返事の中はそのコピーだけを見る) は採らなかった。LLM に繋ぐ処理の全部が「コピーを読む」決まりを守り続けることになり、新しい処理を足すたびに読み忘れの穴ができる。把握できる複雑さに収めることを優先した ([CLAUDE.md](../../CLAUDE.md) の把握可能性)。
11. **モデル管理やプロバイダの設定を変えたときも、その場で反映する。** モデル管理の画面でモデルを追加・削除・編集したとき、プロバイダの接続先や API キーの環境変数名を変えたときは、全員を決め直し、次の返事から新しい設定で動く。削除したモデルを選んでいたペルソナはその場で止まり、話しかけると文面が出る。モデルを追加し直せば、再起動しなくても話せる。[provider_change_does_not_reach_live_personas.md](../issues/provider_change_does_not_reach_live_personas.md) (すでに話したペルソナは、プロバイダの設定を変えても再起動まで前の接続を使い続ける) もここで直る。
    - 根拠: まはー「(a)で。反映したい。ユーザーにとってはすぐ反映されないものっていう発想自体が無いし」(2026-09-12)。
    - この決まりで、[model_provider_management.md](model_provider_management.md) の「反映の範囲を約束しすぎない」の段落 (すでに動いているペルソナは作成済みの LLM クライアントを持ち続ける) は置き換わった。その段落と、[providers.md](../reference/providers.md)・[environment-vars.md](../reference/environment-vars.md) の同じ記述は、実装と同じ変更で書き直してある (まはーの実機確認はこれから)。

## 文面の例

実装で言い回しを整えてよい。話せない・止まっていることを伝える文面には、「誰が」「どのモデルが無いか (または繋げないか)」「どこで選び直すか」「再起動は要らないこと」の四つを必ず入れる。保存を断った知らせには「どの設定を保存しなかったか」「ペルソナがいま話しているモデル」を、切り替えられなかった知らせには「誰が」「いま話しているモデル」「どうすれば切り替わるか」を入れる。

- チャット画面 (ペルソナ個別の標準モデルが無い): 「アイが選んでいた標準モデル 'example-model' は SAIVerse にありません。ペルソナ設定で標準モデルを選び直すと、再起動しなくても話せるようになります。」
- チャット画面 (グローバル設定の標準モデルが無い): 「アイが使うグローバル設定の標準モデル 'example-model' は SAIVerse にありません。グローバル設定の「モデルロール」で標準モデルを選び直すと、再起動しなくても話せるようになります。」
- チャット画面 (軽量モデルが無い): 「アイの軽量モデル 'example-lite' は SAIVerse にないため、返事の途中の作業ができませんでした。ペルソナ設定 (個別に選んでいない場合はグローバル設定の「モデルロール」) で軽量モデルを選び直すと、再起動しなくても続けられます。」
- チャット画面 (軽量モデルに繋げない): 「アイの軽量モデル 'example-lite' に繋げなかったため、返事の途中の作業ができませんでした。API キーなどの接続の設定を確かめるか、軽量モデルを選び直してください。再起動は要りません。」
- ページを開いたときの警告: 「アイの標準モデル 'example-model' は SAIVerse にないため、アイは止まっています。ペルソナ設定で選び直すと、再起動しなくても話せるようになります。」
- 保存を断ったとき: 「'example-modle' というモデルは SAIVerse にないため、標準モデルは保存しませんでした。個別の標準モデルを持たないペルソナは、いまも 'model-before' で話しています。」
- 一人だけ切り替えられなかったとき: 「アイは新しい標準モデルに切り替えられなかったため、いまも 'model-before' で話しています。もう一度保存し直すか、再起動すると切り替わります。」

## 実装が守ること

- 話す標準モデルを決める処理は、コードの一か所にだけ置く。決まったことの 1 に並べた操作は、全部その処理を使う。
- 決め直すときは、先に必要なもの (各ペルソナの個別の設定、使うモデルの設定ファイル) を読み、それから一人ずつ当てはめる。一人ずつ当てはめるときは、値を書き換えるだけにする。新しいモデルへの接続は、そのペルソナが次の返事を始めるときに作られる。
- 書いている途中の返事には、始めたときに決めたモデルと接続を最後まで使う。途中で設定が変わっても、その返事の LLM 呼び出しと、送る内容の準備が、別々のモデルや接続先を見ることがないようにする。一時上書きのパラメータ (温度など) を変えたときも、作ってあった接続を設定し直さずに捨て、次の返事から新しいパラメータで接続を作る。決まったこと 10 の「受け入れた限界」に挙げた四つは、この規則の外。
- Stelis のスレッド (ペルソナが作業のために開く、本筋と切り離した会話) を閉じるときの要約と、ユーザーと最後に話してからの要約は、返事の中なら返事の始まりに決めた軽量モデルの接続を使い、返事の外なら返事の始まりと同じ決め方 (個別 → グローバル → 組み込み) で軽量モデルを決める。使えなければ代わりのモデルで要約しない。Stelis の要約は作らず、ユーザーと最後に話してからの要約は、LLM を使わない件数だけの要約になる (LLM の呼び出しが失敗したときと同じ)。Stelis の要約を作らないときも、スレッドは要約なしで閉じる (終了の状態は completed のまま)。件数だけの要約は、これまでどおりペルソナの記憶に残る — これは話せなかったことの知らせではなく、LLM を使わずに書ける事実だから。
- 一人の失敗で、ほかの人の切り替えを止めない。
- ロックは .env を書き換える処理そのものに掛け、そのあとの決め直しと一時上書きの変更 (一時上書きのパラメータの変更を含む) も同じロックの中で行う。モデルやプロバイダの設定の読み直しも、定義を差し替えるところから決め直しが終わるところまで、同じロックの中で行う。ロックを取る順番は、このロックがいちばん外、ペルソナの接続のロックが次、記憶の整理の見張りの記録のロック (`sea/session_lifecycle.py`) がいちばん内側。ロックの中で行うのは、設定の読み書き、ペルソナの値の書き換え、作ってあった接続の破棄と作り直し、記憶の整理の見張りの記録を捨てることまで。ペルソナが返事の一区切りを終えるのを待つ処理 (`sea/beat_gate.py` のロック) は、ロックの中に入れない。
- モデルやプロバイダの設定を読み直したら (読み直しの入口は `saiverse/model_configs.py` と `saiverse/provider_configs.py` の `reload_configs` に集まっている)、上のロックの中で全員を決め直し、作ってあった接続を捨てる (ペルソナの接続と、要約に使う接続の両方。要約の接続は、ペルソナの決め直しが途中で失敗しても捨てる)。切り替えられなかったペルソナの名前は、読み直しを起こした画面の応答に載せる。書いている途中の返事が持っている接続は、その返事が終わるまで使う。
- 設定ファイルの無いモデル、または繋げないモデルを指す設定は、どの役割でも代わりのモデルで動かさない。
- 決まったこと 6 の「いま効いている値と同じ名前は確かめ直さない」は、環境変数の保存 (`split_undefined_model_updates`) とペルソナ設定の保存 (`manager/admin.py` の `_checked`) の両方で同じに動く。比べる相手は、環境変数ならいまプロセスに読み込まれている値、ペルソナ設定ならそのペルソナの DB 行の値。
- 会話が止まっている間に記憶の整理を前もって行う処理は、前回試したときから状態が変わっていないペルソナを飛ばすための記録を持っている (`invalidate_cold_sweep_fingerprints` で捨てられる)。ペルソナのモデルの設定を変えたとき (ペルソナ設定の保存を含む) は、この記録も捨てる。捨てないと、Memory Weave モデルを選び直しても、会話が動くまで整理が再試行されず、「再起動しなくても」が偽になる。
- 話せなかったことの知らせを、建物の会話の記録やペルソナの記憶に書かない。
- モデル設定の警告は、v0.3.12 と同じく、画面を開いたり読み込み直したりするたびに、いまの設定と各ペルソナの状態から作る。「再起動するまで反映されません」の代わりに、切り替えられなかったペルソナがいるときだけ、そのペルソナの名前つきで出す。

## リリースノートに書くこと

版が決まったら、release_history の「次の版の範囲」に写す。

- 選んだモデルが SAIVerse に無いとき、または繋げないとき、代わりのモデルでは動かず止まる。選び直せば、再起動しなくても話せる。v0.3.12 で削除したモデルを選んでいた場合は、ペルソナ設定とグローバル設定の「モデルロール」で選び直す。
- v0.3.12 のリリースノートでは「画像・音声・動画の要約モデルが無いときは、組み込みの既定モデルで要約を続ける」と伝えていたが、この版からは要約も止まる。
- 設定を変えたら、再起動しなくても効く (標準モデル、ペルソナ設定、モデル管理、プロバイダの設定)。書いている途中の返事は、始めたときのモデルで最後まで書き、次の返事から新しいモデルになる。API キーと、画像・音声・動画の要約モデルを変えたときは、書いている途中の返事にも効く。
- 設定ファイルの無いモデルの名前は保存されず、保存したその場で知らせが出る。

## 検証

隔離環境 (本番とは別のフォルダに作ったテスト用の SAIVerse。SAIVERSE_HOME を本番から切り離し、テスト用のペルソナだけを置く) で、実際の画面と API を通して確かめ、出てきた文面を読む。モデルを切り替えた時点では新しいモデルへの接続を作らないので、LLM は呼ばれない。

- グローバル設定で標準モデルを保存すると、個別の標準モデルを持たないペルソナが切り替わり、警告が出ない。
- 設定ファイルの無いモデルの名前を保存しようとすると断られ、その場で画面に文面が出る。ほかの設定は保存される。標準モデル以外の役割とペルソナ設定でも同じ。
- 一時上書き中に保存しても、ペルソナは上書きのまま。解除すると新しい標準モデルになる。
- 空に戻すと、組み込みの既定モデルになる。
- ペルソナ設定で個別の標準モデルを空に戻すと、そのペルソナがグローバル設定の標準モデルになる。
- 一時上書き中に作ったペルソナ (ワールドエディタと設計図の両方) が、上書きのモデルで話し、個別の標準モデルとしては保存されない。
- 無いモデルを選んだペルソナは、起動しても代わりのモデルで動かず、話しかけるとチャットに文面が出て、ページを開くと警告が出る。軽量モデルと要約モデルでも、代わりのモデルで動かない。
- モデル管理の画面で、ペルソナが選んでいるモデルを削除すると、そのペルソナが止まる。追加し直すと、再起動しなくても話せる。
- プロバイダの接続先を変えると、次の返事から新しい接続先の設定で接続が作られる (接続の設定を読むところまでで確かめ、LLM は呼ばない)。
- Memory Weave モデルをペルソナ設定で選び直すと、再起動しなくても記憶の整理が再試行される。
- 書いている途中の返事で設定が変わっても、その返事は前のモデルで最後まで書かれる。これは動いているサーバーでタイミングを合わせるのが難しいので、自動テストで確かめる。
- データベースを読めずに切り替えられない場面は、動いているサーバーでは作れないので、自動テストで確かめる。
- この検証で確かめないもの: スタックチャンに声で話しかけたとき (issue に切り出し済み)、Discord、Unity。

## 経緯

- v0.3.12 の組み込みモデルの棚卸しで、Codex による 2 回目のレビューで「グローバル設定の標準モデルを変えても、動いているペルソナには反映されないのに、警告だけ消える」という指摘が出た。環境変数の保存から `update_default_model` を呼んでその場で切り替える形をいったん入れたが、3 回目のレビューで穴が出たため取り下げ、「再起動するまで反映されない」を警告で知らせる形にしてリリースした。
- 3 回目のレビューで出た穴は四つ。定義の検査より先に標準モデルの値を書き換え、途中の失敗を握り潰して成功として返す。チャット画面の一時上書きを見ずに切り替える。空に戻しても切り替わらない。保存と反映をロックなしで行うので、同時に保存すると保存された値と実行中の値が逆になりうる。
- 2026-09-11 にコードを読み直し、四つとも確かめた。同じ理由の穴が隣に二つあった。ペルソナ設定で個別の標準モデルを空に戻しても、再起動するまで前のモデルで話し続け、警告も出ない (`update_ai` では、個別の標準モデルが空のとき何も切り替わらない)。一時上書き中にワールドエディタでペルソナを作ると、上書きのモデルではなく標準モデルになる (ペルソナを作る処理では、起動時に写しておいた一時上書きの値が使われる)。
- 同日の文書の整合性の検査で、設計図からの生成が六か所目の書き方だったこと、.env を書き換える画面がモデル以外にも三つあること、返事の途中の切り替えが beat_execution_context の決定と食い違うこと、Memory Weave モデルを選び直しても記憶の整理を前もって行う処理が再試行しない可能性があること、外部カタログの intent が守ると決めていることとの関係が分かり、この文書に反映した。そのうち、まはーに決めてもらう 5 件を 2026-09-12 に提示し、全件の答えを得た (決まったこと 6・7・10・11 と「載せる版」)。
- 話す標準モデルを決める順番は、起動時の読み込み (`_load_single_persona`)、一時上書きの解除 (`set_model` の空の分岐)、ペルソナ設定の保存 (`update_ai`)、プリセット (`update_default_model`)、ワールドエディタからの作成 (`_create_persona`)、設計図からの生成 (`manager/blueprints.py`) の六か所に書かれていて、並び方も「設定ファイルが無いときに次へ進むか」も少しずつ違っていた。
