# 自律 Pulse の器統合 + tell スペル

**ステータス: 実装中** (2026-08-08 設計裁定 → 同日実装着手。経緯の親 = [issue](../issues/slot_light_pulse_runs_on_conversation_vehicle.md))

## 何を守るための設計か (全体像)

自律行動 v2 の一日は「判断点 (専用 Playbook)」「作業コマ (セッション運転)」「暮らしコマ (出かける/自室/自由時間)」でできている。前二者は専用の器を持つが、**暮らしコマだけ器が無く、会話 Track の Playbook (`track_user_conversation`) を既定値経由で借りて走っていた**。帰結: 暮らしの一手が独白でなく発話 (UI + TTS) になる / 文体が不在のユーザー宛になる / 会話 aspect で走るためスペル権限も会話並みに開く (track_activate が唱えられ、会話 Pulse の自己起動・会話状態の自己捏造・コマ実行との衝突 = 2026-08-08 実機で全部発生)。

守るべき不変条件:

1. **暮らしの一手は独白** — Building 履歴に発話として載らない。生産義務を課さない (充填独白 v1 の再発防止)
2. **ユーザーに届く声は標準モデル** (「会話は標準」の鉄則) — 禁止ルールでなく構造で保証する
3. **世界の状態 (会話中かどうか) はペルソナの一存で変わらない** — 「喋る」と「会話が始まる」は別の出来事
4. **自律系 Pulse が既定値経由で会話の器に落ちない** — 落ちたら観測できる

## 決定 (2026-08-08 まはー裁定)

### A. 暮らしコマはセッション運転へ統合する

`run_work_session` を唯一の運転機構とし、暮らしコマは**暮らしプロファイル**で乗る:

| パラメータ | 作業コマ | 暮らしコマ |
|---|---|---|
| budget_rounds | コマの予算 | **1** (将来の膨らみは数字を変えるだけ) |
| instruction | カタログの指示書テンプレ | 状況文 + 許可形の一文 (義務形禁止) |
| close_hook (帰属+経験値ノート) | あり | **なし** |
| post_session 判断 | あり | **なし** |
| episode | kind='work_session' を開く | **開かない** (コマ発火が開く kind='presence' が既にある) |
| 記録 | 内部ログ (発話しない) | 同じ (これで不変条件 1 が成立) |
| aspect / モデル | WORKER / 軽量 | 同じ |

- 会話の器を借りていた `_dispatch_slot_pulse` (schedule 型 Pulse 経由) は撤去する。
- ライフ予算 (活動 N/M 回) の計上は従来どおり 1 コマ 1 消費を維持する (モデルが軽量になっても「その日の自発活動の回数」という利用者向け意味を優先。life.md §5.3 の「標準 LLM の呼び出しを数える」という記述とはここでズレるため、life.md 側をこの意味論に追従させる)。
- 副次効果: WORKER aspect になることで**既存のモード別スペル権限ゲート (mode_spell_permissions) が track_activate 等の Track 操作を自動で遮断**する。②の剥がしの第一段はこれで成立し、追加の禁止コードは書かない。

### B. tell スペル (宛先明示の発声、1 Beat・標準モデル)

①統合後、自律行動中にユーザーへ届く発話の経路はこのスペルだけになる。

- **形**: `tell target=<相手> gist=<伝えたいことの要旨 (任意)>`。target = 同室のペルソナ / user / all。
- **speak でなく tell である理由** (まはー裁定): ペルソナから見て「ユーザーに見えて損なこと」はほぼ無く、見せる/見せないの判断軸では全部見せる側に倒れる。「誰に伝える価値があるか」を毎回問わせる含意が乱発を構造的に防ぐ。宛先の記録は将来の通知・未読バッジ・ペルソナ間会話 (相手の知覚バッファへの投入) の器になる。
- **1 Beat の分業** (裁定 B 案): 唱える側 (軽量でありうる) は「いま・誰に・何を」の判断だけを担う。**実際の言葉は、スペルが起動する 1 Beat — CONVERSATION aspect の実行文脈 = 標準モデルの 1 呼び出し — が書く**。モデル階層は aspect 導出の既存規則で決まるため、「届く声は標準」が禁止ルールなしで構造的に成立する (不変条件 2)。実装は Playbook JSON でなく `run_work_session` と同じコード駆動 (aspect・投函・記録を正確に制御するため)。
- **投函**: 生成文を `runtime._emit_say` で Building 履歴へ (UI・TTS・Unity は既存経路がそのまま効く)。SAIMemory へは本人の発話として保存し、metadata に宛先 (`tell_target`) と gist を残す。
- **会話エピソードは開かない・Track に触らない・タイムアウトを装填しない** (不変条件 3)。返事はユーザーの通常入力が既存機構で会話を開く。
- **会話中の分岐**: 今まさに会話中の相手への tell は実行せず「その相手とは会話中です。返答に書けばそのまま届きます」を返す (返答との二重発話の防止)。別の相手への tell は許す。
- **カタログの出し分けはしない** (head は persona×model 固定)。実行時分岐で捌く。

### D. 席違いフォールバックの機械検査

「auto 系 Pulse は必ず meta_playbook 指定」という不変条件は `_choose_playbook` の docstring にしか無く、破られても無音だった。ExecutionRequest の `type` を使い、**user 系以外の type で meta_playbook 未指定のまま既定の会話 Playbook に落ちるとき WARNING を出す** (不変条件 4)。禁止はしない — リマインド等、会話の器を意図して使う schedule があり得るため、まず観測可能にする。

### C. 会話 Track の特殊機構の剥がし (段階)

第一段は A の副次効果 (WORKER ゲートで Track 操作遮断) で成立。`on_track_activated` の Pulse 自己起動・エピソード開きの本体撤去は、tell の実機実績を見てから次段で判断する (ユーザー起点の会話開始は現行機構が正当に使っているため、一括撤去はしない)。

## 責任分界

| 何を決める | 誰が |
|---|---|
| いつ・誰に・何を伝えたいか | 唱える側の認知 (軽量可) |
| 実際の言葉 | tell の 1 Beat (標準モデル = 会話の声) |
| 発話が届く範囲 | 世界の物理 (同室 + UI 越しのユーザー) |
| 会話が始まったか | ユーザーの実際の応答 (既存機構) |
| 暮らしコマの独白の器 | セッション運転 (WORKER) |

## 検証の旅程

- 単体: 暮らしプロファイルの配線 (会話 Playbook 不使用・発話ゼロ・予算 1・presence 記録の維持) / tell の宛先検証・会話中分岐・投函経路 / フォールバック WARN の発火条件
- 実機 (統合検証手順に相乗り): 出かけるコマで独白が内部記録に残り Building 履歴に発話が**出ない**こと / tell でソフィーの声が UI + TTS に届くこと / 会話 Track の自己起動が再発しないこと
