# 組み込みツールのログの責任境界

**ステータス**: 検証待ち — [既存 issue の対応方針](../issues/import_time_log_handlers_escape_isolation.md)に沿う撤去・隔離回帰済みで、develop に取り込み済み。実機のログでの確認待ち

## 全体像と約束

ツールは起動時の自動検出でも読み込まれる。使っていないツールの import が利用者のログを開いたり、隔離検証が引き継いだ環境変数を通して別環境へ書いたりしてはいけない。運用者が指定した本体のログ出力先とレベルに、ツールの実行記録も集まる必要がある。

ログの経路は「ツールの `logging.getLogger(__name__)` → root logger → 起動時に `saiverse.logging_config.configure_logging` が設定した handler → session の `backend.log`」。保存先・handler・レベルの所有者は起動側であり、calculator / read_url_content / send_email_to_user は記録の発生元だけを担う。隔離側で古い変数を上書きして症状を隠すのでなく、この 3 本が独自の保存先を開く原因を除く。

## 不変条件と変更範囲

- 3 本の import は `SAIVERSE_LOG_PATH` と作業ディレクトリの `saiverse_log.txt` を作成・touch・追記しない。モジュール専用 handler、レベル固定、伝播停止、初期化の一行も置かない。
- ツール実行時のログは root へ伝播し、本体のレベル設定に従う。URL は userinfo・query・fragment を除いた宛先だけを記録する。計算結果、URL の取得・整形、メールの宛先・本文・送信結果は変えない。
- 既存ログの削除や移動はしない。本番の起動済みプロセスの handler を書き換える仕組みも追加しない。反映は新しいプロセスから。
- この修正だけであらゆる環境変数やアドオンの隔離を保証したとは扱わない。隔離検証の環境確認は引き続き必要。

## 検証の境界

新規 subprocess で個別 import と実際の `tools` 自動検出を通し、引き継いだ旧ログ先 / 未設定時の既定名、既存 / 未作成の各場合で内容と更新時刻が変わらないことを確認する。そのまま本体のログ設定に DEBUG / INFO が一度ずつ届くことまで検査する。計算は既存テスト、URL / メールは通信と DB を fake にして実処理を検査する。本番ペルソナ、実 HTTP、SMTP 配送は検証対象外。


## 追加レビュー (2026-10-03)

URL ログの root 伝播を戻したことで、共有されやすい backend.log に資格情報や署名 query が混ざる経路が生じた。技術原因は URL 全体の INFO 記録、判断の誤りは保存先の責任だけを見て内容の秘匿境界を見落としたこと、検出漏れの条件は通常 URL だけを使うテストだった。開始・完了の両記録で userinfo / query / fragment を除去し、不正 URL は入力を記録しない。取得 URL・ツールの返却内容は変更しない。

秘匿情報を含む境界値で「届く記録」と「届いてはいけない値」を併せて検査する型は、ログ経路の変更だけでなくエラー通知と設定診断にも必要。この変更では URL ログ 4 件を修正前に再現し、関連 28 件を通した。全システムの秘匿化を保証するものではない。
