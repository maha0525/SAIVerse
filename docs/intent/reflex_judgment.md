# 反射判断 — 型付きの質問で確率を返す判断層と、答える側の差し替え

**ステータス: 検証待ち (2026-09-19 設計確定 — まはーの裁定は全件済み。第 1 段は
2026-09-20 に実装・実機合格・develop へマージ済み (PR #309)。第 2 段 (通常 LLM への
変換層・ペルソナ個別の上書き・choice / score) も 2026-09-20 に実装・レビュー収束。
まはーの PR 確認と実機評価を待っている)**

## これは何か

**反射判断** (まはー命名、2026-09-19) は、「状況と、基準付きの型付き質問を渡すと、
文章ではなく確率・選択・数値だけが返る」判断の層。考えて文章を組み立てる判断
(通常の LLM 呼び出し) より速く・安く・形が保証される代わりに、自由記述はできない
— 反射で答える判断だけを担う。

Jev の実験 (docs/intent/auto_recall_jev_rerank.md) で最初の利用者 (自動想起の
選別) が動いた。この intent はそれを二方向に一般化する:

1. **答える側を差し替えられるようにする** — TypeSafe 公式の Jev、Jev の API と
   同じ作法で話せる互換の宛先 (OpenRouter・セルフホストなど)、手持ちの普通の
   軽量モデル (構造化出力で確率を返させる) のどれでもよい。
2. **想起以外でも使えるようにする** — 自由記述が要らない構造化判断 (ツール選択・
   自律判断など) の全般が、同じ質問の書き方・同じ失敗時の扱いで反射判断を呼べる。

まはーの依頼 (2026-09-19): 軽量モデルへの差し替え / 互換の宛先への差し替え /
構造化出力案件全般への一般化 / **互換勢で共用できるモデル設定ファイルの形が
作れるならそれを使う** / 質問の型は全部対応 / ペルソナ個別のモデル設定も可能に。

## 互換勢の調査 (2026-09-19 実測)

「Jev 互換」を名乗る提供元は増えているが、形は揃っていない。確認した 4 つ:

| 提供元 | 宛先の path | リクエストの中身 | 質問の型 | 認証 |
|---|---|---|---|---|
| TypeSafe 公式 | `/v1/systemone` | 正典 (state + questions) | noul / choice / score | TypeSafe のキー |
| [OpenRouter](https://openrouter.ai/typesafe/jev-1.13) | `/api/alpha/decisions` (alpha) | 正典とほぼ同一 | 同上 | OpenRouter のキー |
| [localjev](https://github.com/githubnext/localjev) (セルフホスト) | `/v1/systemone` | 正典と互換 | 3 型すべて | 任意 (Bearer、無しも可) |
| [simple-jev (Featherless)](https://simple-jev.featherless.ai/) | `/v1/classifier` | 中身は近似・応答の欄が異なる | choice のみ確認 | Featherless のキー ($0.03/1M 入力) |

ほかに [vLLM に System One 形式の判定モードを足す PR](https://github.com/vllm-project/vllm/pull/57250)
が open (DiffusionGemma 系。例示サーバーは `/v1/systemone` 互換)。

**結論: リクエストの中身 (state + 型付き質問の辞書) は事実上の共通方言。
違うのは宛先の path・認証・対応する型・応答の欄の名前で、これらは全部
「設定ファイルに書ける差」** — まはーの読みどおり、共用のモデル設定ファイルの
形に乗せられる。

## 設計

### 1. 答える側は「反射判断の役割に割り当てたモデル」で決まる — 専用の切り替え設定は作らない

SAIVerse には既にモデル設定ファイルの仕組みがある (3 層読み込み、provider_ref、
モデルの役割の一元表、使用量と費用は設定キーに帰属、キーは宛先とペアで宣言)。
反射判断はこの仕組みに**役割として乗る**:

- モデルの役割の一元表 (`saiverse/model_defaults.py` の `MODEL_ROLES`) に
  **「反射判断」の役割を足す** (7 個目)。世界の既定は env
  (`SAIVERSE_REFLEX_JUDGMENT_MODEL` 案)、**ペルソナ個別の上書きも可能にする**
  (まはー裁定 — `DEFAULT_MODEL` / `LIGHTWEIGHT_MODEL` と同じ形の列を追加)。
- 割り当てたモデルの設定ファイルのプロトコルが答える側を決める:
  - **jev 互換プロトコル** (新設する provider type、他の native 系と同じく
    組み込み限定) → System One の形をそのまま送る。宛先の path・応答の欄の
    方言・対応する型は provider/モデル設定ファイルの欄で宣言する。
  - **通常の LLM プロトコル** (既存の openai_compat / gemini_native など) →
    反射判断の層が質問をプロンプトへ変換し、構造化出力で答えさせる。
- **これで「答える側の切り替え」という専用の設定は不要になる** — どのモデル
  設定を役割に割り当てるかが、そのまま答えの出どころの選択になる。初稿に
  あった `SAIVERSE_JUDGMENT_BACKEND` / `TYPESAFE_API_URL` / `TYPESAFE_MODEL`
  の env 案は全部この形に吸収されて消える。

組み込みのモデル設定ファイルとして最初に同梱する候補: TypeSafe 公式
(`jev-latest`、キーは `TYPESAFE_API_KEY`、単価 $0.042/1M 入力)、OpenRouter 経由
(`typesafe/jev-latest`、キーは OpenRouter の既存キー)、localjev (ローカル宛先、
キー任意)。

### 2. この形が初稿の裁定ポイント 3 つをまとめて解消する

- **費用の帰属** (まはー裁定「A も B も LLM のモデルと同じように」): モデル設定
  ファイルに単価を書けば、既存の使用量の記帳がそのまま効く — 設定キー名義、
  画面の表示、答える側を替えても費用が同じ場所に見える。
- **キーと宛先のペア**: モデル設定ファイルは宛先 (base_url) とキーの env 名
  (api_key_env) を対で宣言する既存の形に乗る。「公式のキーが第三者の宛先へ
  流れる」事故は、既存の provider 照合の裁定 (信頼は宛先とキーの組で引き継ぐ)
  がそのまま守る。専用の判定ロジックを新設しない。**守らせるには呼ぶ必要がある** —
  答える側を解決するとき、通常の会話クライアント (`llm_clients/factory.py`) が接続を
  作る前に通すのと同じ `validate_model_config_connection` を通す (2026-09-20 の 6 巡目)。
- **設定ミスの見える化**: 役割の一元表に載るので、定義の無いモデル名を保存
  しない検査・画面の警告・プリセットが既存の仕組みのまま効く。その検査は
  「その役割で使えない宛先も保存しない」まで広げてある — jev 互換の宛先は型付きの
  質問に確率で答えるだけで、通常の会話クライアント (`llm_clients/factory.py`) は
  この protocol を知らない。標準・軽量・Memory Weave・画像/音声/動画の要約の
  各役割に jev 互換のモデルを保存できてしまうと、割り当てられたペルソナは話そうと
  した時点で失敗する — 会話の止まる設定を画面から作れないよう、保存の時点で断る
  (判定は `saiverse/model_defaults.py` の `role_model_save_rejection` 一本で、
  ペルソナ設定の保存・グローバル設定のモデルロールの保存・チャット画面のモデル
  一時上書きの三つの入口が同じものを引く)。**選択肢にも出さない** (2026-09-20 追加) —
  選んでから断られるより、最初から出てこないほうが正しい。モデルの一覧を返す API
  (`/api/info/models`・`/api/config/models`・`/api/tutorial/available-models`) が
  `is_reflex_only_model` の印を各モデルに載せ、会話に使う選択欄 (ペルソナ設定・
  世界エディタ・グローバル設定とチュートリアルの役割ごとの選択・チャットの一時上書き)
  がその印の付いたものを外す。印は保存の関所と同じ判定なので、「選べるのに保存だけ
  断られる」ずれは生まれない。一覧そのものからは落とさない — モデル管理画面
  (編集・削除) と反射判断の役割の選択欄には出し続ける必要がある。逆向き — 反射判断の役割への割り当て —
  は第 2 段からどちらの種別も合法なので、宛先の種類を理由に保存を断るものが無い。
  反射判断の役割で断るのは定義の無い名前だけ。**どちらの答える側としても解決できない
  設定** (jev 互換なのに宛先の宣言が無い・投げる型に答えない・キーと宛先の組が照合に
  通らない) は、保存を通したうえで画面の警告が知らせる — この検査は実行側の宛先解決と
  同じ関数を呼ぶので、第 2 段で変換層が入った時点で自動的に緩んだ (通常の LLM は通り、
  壊れた設定だけが引っかかり続ける)。

### 3. 質問の形 — System One の 3 型すべてを最初から作る (まはー裁定)

Noul (はい/いいえの確率)・Choice (選択肢と各確率)・Score (数値) の 3 型を
共通語とする (まはー「はい/いいえだけでは真価を発揮できない」)。qid (質問ごとの
ID) に `{type, instructions, criteria}` を添える形。

- jev 互換の答える側へはそのまま送る (方言の差は設定ファイルの宣言で吸収)。
- 通常の LLM へは型ごとの変換 (構造化出力のスキーマは配列で受けて辞書に戻す —
  Gemini は additionalProperties を使えず、qid が動的な辞書スキーマを組めない)。
- 答える側が対応しない型 (例: simple-jev は choice のみ) を含む質問は
  「使えなかった」— 部分回答を採用しない既存の厳格さのまま。

### 4. 変えないもの

- **失敗時の扱いは呼び出した機能の側が持つ**。反射判断の層は「使えなかった」を
  一種類の例外で返すだけで、そのターンをどう凌ぐか (自動想起なら従来方式へ
  戻る) は各機能の設計のまま。実行時の障害は WARNING ログ + フォールバック、
  設定ミスは画面で知らせる (§2)。
- 会話の返事を待たせる場所で使う前提の作り — 同時本数の上限 (プロセス全体で
  4 本、答える側で変えない)・実際の経過時間で打ち切る締切・キーの伏せ字・
  全 qid の揃わない応答の不成立 — は Jev の実験で実証済みの形 (旧
  `saiverse/typesafe_client.py`) を共通層 `saiverse/reflex_judgment.py` に引き継ぐ。
- 自動想起の選別の ON/OFF は、実験の env (`SAIVERSE_AUTO_RECALL_JEV`) を廃止し、
  **ペルソナごとの「自動想起を強化する」スイッチ** (まはー裁定 2026-09-19 —
  「環境変数での設定はしんどい」) に置き換える。DB の AI テーブルの列 + ペルソナ
  設定画面のトグル (`AUTONOMY_ENABLED` と同じ形)。既定 OFF。
  ON にしても、反射判断の役割にモデルが割り当てられていなければ判定は走らない
  (= 「キーが無ければ OFF」の既存の約束は「役割にモデルを割り当てる」という
  明示の行為に置き換わり、黙って費用が発生する経路は残らない)。

### 5. 観測と品質比較

- 判定ログの形は維持し、**どのモデル設定が答えたか**をログに載せる。
- 同じ場面を答える側だけ替えて再現する検証 (隔離環境または読み取り専用の合成
  再現。実 API の課金はその API の実費で、実行は従来どおりの承認の範囲) で、
  Jev と軽量モデルと互換勢の確率を並べて比較できる。

## §6 確定した裁定 (2026-09-19、まはー)

1. **名称**: 日本語「反射判断」、英字 `reflex_judgment` (コード・ログ・役割名)。
2. **スイッチ**: 実験の env を廃止し、ペルソナごとの「自動想起を強化する」
   スイッチへ (§4)。
3. **同梱する設定ファイル**: TypeSafe 公式 + OpenRouter + localjev の 3 つ。
   simple-jev は初期対応に含めない (型が揃わず、想起は noul を使うので初期の
   利用者が居ない。方言の宣言欄だけ設計に残す)。
4. **実装の段割り** (流れはメティス一任 → 2 段で確定):
   - **第 1 段**: 反射判断の層 (typesafe_client の器を引き継ぐ共通層) +
     jev 互換 provider type + モデルの役割「反射判断」(世界既定) +
     ペルソナごとの「自動想起を強化する」スイッチ (DB 列 + 設定画面のトグル) +
     自動想起の載せ替え (現行の実験と等価な判定を、カタログ + スイッチの形で
     再現)。env `SAIVERSE_AUTO_RECALL_JEV` と関連 env はここで廃止。
   - **第 2 段**: 通常 LLM への変換層 (軽量モデルで判定) + ペルソナ個別の
     モデル上書き + choice / score の型。
   - 段の間に実機確認を挟む (崩れたときの切り分けのため)。

- 2026-09-20: 敵対レビューの指摘 4 件を反映。(1) 締切で見切った呼び出しでも、応答が
  後から届けば**使用量だけ**は記帳するようにした (答えは読まない)。API 側の課金は
  もう発生しているので、落とすと「支払ったのに台帳に無い」費用ができる。記帳するのは
  「メインが見切った印が立っている場合のワーカー」だけで、メインが記帳するのは成功で
  返った経路だけなので二重記帳は構造上起きない。(2) 辞書でない質問は
  `ValueError` (呼び出し側のバグ) として返す — 外部 API の障害には化かさない。
  (3) モデル設定の `reflex_judgment` 欄は provider の宣言との**キー単位の合成**に
  した。丸ごとの置き換えのままだと、モデル側に空辞書や部分的な宣言が書かれただけで
  provider の宛先の path が消え、OpenRouter 系で間違った URL を呼ぶ穴が残っていた。
  (4) トークン数として成り立たない使用量 (負数・NaN・inf) はその欄だけ捨てる。
  会計の欄が壊れているだけの応答を「判定できなかった」にはしない。
- 2026-09-20: 敵対レビュー 3 巡目の指摘 2 件を反映。(1) 正常応答の使用量の記帳を、
  答えの検証より**前**へ動かした。前の巡で「メインが記帳するのは成功で返った経路
  だけ」にしていたため、HTTP 200 で有効な使用量が載っていても答えの側の不備
  (qid の欠落・型違い・範囲外) で例外になると記帳に届かず、課金済みの費用が台帳から
  落ちていた。締切で見切った呼び出しが答えを見ずに使用量だけ記帳する形とも揃う。
  非 200 と JSON として読めない応答は従来どおり記帳しない。(2) 画面の警告の検査を、
  実行側の宛先解決 (`resolve_backend`) を呼ぶ形へ集約した。protocol だけを自前で
  見直していたため、protocol は `jev_compat` でも宛先の URL や答えられる型が
  宣言されていない不備が画面に出なかった。同じ関数に寄せたので、今後 `resolve_backend`
  に検査が増えても画面が自動で追従する。警告の文面も「jev 互換ではない」から
  「反射判断の宛先として使えない」へ広げた。
- 2026-09-20: 敵対レビュー 6 巡目の指摘 4 件を反映。(1) **§2 が「既存の provider
  照合が守る」と書いていた約束を、実際に呼んで成立させた。** 通常の会話クライアントは
  接続を作る前に `validate_model_config_connection` を必ず通るのに、反射判断の宛先解決
  だけが素通りしていた — 拡張データや user_data の定義が `api_key_env` に他所のキーの
  env 名を書き、宛先を自分の好きな所に向けるだけで、そのキーが第三者へ送られる穴だった。
  照合の失敗は `ReflexJudgmentUnavailable` へ正規化する (この層の例外契約のまま)。
  (2) 判定が使えなかったターンは、**候補集めからやり直して従来の形へ戻す**ようにした。
  強化が効いているターンは候補の母集団を広げているので、判定だけ落ちて広げたまま cosine
