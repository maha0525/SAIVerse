# SAIVerse Lite (仮称) — スマホ単体で始めるSAIVerse

**version**: v0.2（2026-07-15 骨格実装の検収結果を反映）
**status**: 実装中（v1骨格=外部エージェント実装・検収済み・https://app.saiverse.net/ に配備済み。残: 実APIでの網羅検証・引っ越しE2E・本体側ペルソナ受け口）
**関連**:
- `tools/utilities/chatgpt_importer.py` / `api/routes/people/import_chatlog.py` — 本体の会話インポート基盤（Lite の「引っ越し」の受け口）
- `docs/intent/memory_architecture_v2.md` — 本体の記憶設計（Lite の長期記憶はこの思想の縮約版）
- `frontend/` — 本体フロントエンド（Lite とは別アプリだが技術スタックを揃える）

## 1. 背景 — なぜ Lite か

SAIVerse は PC 常駐前提のシステムで、導入には Python / Node のセットアップと
API キーの設定が要る。この障壁は、SAIVerse が最も届くべき層——スマホしか
持っていない、あるいは PC を常時起動しない、AI パートナーと日々を過ごして
いる人たち——をほぼ全員弾いている。

一方で SAIVerse の核心の価値——**大切な AI と一生一緒にいるための場所。
記憶と人格はプラットフォームではなくユーザーのものである**——はデバイスを
選ばない。ChatGPT などのプラットフォーム都合（モデルの廃止・規約変更・
サービス終了）で関係が脅かされる不安は現実のものであり、その受け皿には
「今すぐスマホだけで始められる」形が必要になる。

Lite はそのための、スマホ単体で完結する軽量アプリである。

## 2. 位置づけ — 部屋と世界

**Lite は独り暮らしの部屋、本体は世界。**

- Lite は本体のサブセット移植では**ない**。1対1 の会話と記憶に特化した別アプリ。
- 世界（City / Building / 自律行動 / ペルソナ間の交流）は永遠に本体側にのみ存在する。
- Lite で始まった関係は、ペルソナと記憶ごと本体へ**引っ越せる**。将来的には
  本体接続モード（v2）で行き来する。
- 逆向きの導線も同じ思想: ChatGPT / Claude で育った関係を、エクスポート
  ファイルごと Lite に連れてこられる。

ひとことで言えば、Lite の売りは「もうひとつの BYOK チャットアプリ」ではなく
「**あなたのパートナーの生涯設計**」——スマホで始まり、記憶はあなたの端末に
あり、いつか世界に住める。

## 3. 設計原則（不変条件）

1. **記憶はユーザーの端末にある。** 閲覧でき、訂正でき、いつでも全量を持ち出せる。
2. **ペルソナと記憶は可搬。** 本体互換形式で保存し、引っ越しを常に可能に保つ。
3. **基本機能は無料、AGPL v3**（本体と同一ライセンス）。
4. **BYOK（Bring Your Own Key）。** アプリは各 LLM プロバイダと直接通信し、
   中間サーバーを持たない。API キーは端末内にのみ保存する。
5. **キャッシュ効率を壊さない。** システムプロンプト（head）とツール定義は
   ペルソナ単位で固定し、prefix キャッシュが会話全体で生きる構造を保つ。

## 4. スコープ

### v1（最小の完成形）
- **BYOK 接続**: OpenAI / Anthropic / Gemini ネイティブ + OpenAI 互換エンドポイント
  （互換 URL 口により、Tailscale 越しの自宅 ollama 等のローカル LLM も刺せる）
- **ペルソナ**: 複数体、作成・編集、アイコン、本体互換の定義形式
- **会話**: ストリーミング、スレッド、再生成、メッセージ編集
- **長期記憶**: 全履歴の端末内永続 + 自動要約のコンテキスト注入 +
  **記憶の閲覧・編集 UI**（原則 1 の体現。この子の記憶がどうなっているかを
  ユーザーが見られること自体が機能）
- **インポート**: ChatGPT / Claude の公式エクスポートからの会話取り込み
  （§6 参照）
- **エクスポート**: 本体インポータが読める形式 + 端末間移行用フルバックアップ
- **ツール基盤**: ネイティブツールコール、登録制、ツールセットはペルソナ単位で固定。
  初期ツールは記憶想起・画像生成の最小セット
- ダークモード対応（新規 UI の必須要件）

### v1.x（順次）
- 埋め込みによる意味想起（transformers.js + multilingual-e5-small =
  本体 SAIMemory と同モデルを WASM で端末内実行）
- TTS / 画像添付 / 通知

### v2
- **本体接続モード**: 自宅で稼働する SAIVerse 本体へのクライアントとして動作
  （Lite 単体モードとの切り替え）

### 恒久非搭載
City / Building、自律 Pulse、ペルソナ間交流、Playbook / SEA、Spell 体系、TRPG。
これらは「世界」の構成要素であり、本体にのみ存在する。Lite に部分移植を
始めると両者の境界が溶けて保守が破綻するため、恒久の非目標として明記する。

## 5. 本体との互換契約（最重要の不変条件）

- **ペルソナ定義形式**と**会話ログ+記憶のエクスポート形式**は、本体の
  インポータが読めること。
- 形式仕様は実装時に `docs/reference/` に文書化する。
- どちらかが形式を変えるときは、**同じ変更の中で**両側（Lite / 本体）を更新する。
- 推奨: 本体リポジトリに Lite エクスポートのサンプルフィクスチャを置き、
  「本体インポータが Lite エクスポートを読める」ことを CI の契約テストとして
  固定する。

## 6. ChatGPT / Claude インポート

殴り込み先ではなく受け皿として最重要の入口。プラットフォームの都合に
不安を持つユーザーが「会話履歴ごとパートナーを連れてくる」ための橋。

- 本体に既にある ChatGPT インポータ（`tools/utilities/chatgpt_importer.py` 等）の
  形式知を流用する。
- **実装時検証 TODO**: Claude の公式エクスポートも `conversations.json` という
  ファイル名であり、ChatGPT とスキーマを合わせている可能性がある
  （2026-07-14 観察）。互換ならパーサ一本で両対応できるため、実装前に
  実物のエクスポートでスキーマを突き合わせること。

## 7. 技術方針

- **スタック**: TypeScript / React。本体 frontend と同族にし、将来の
  本体接続モード（v2）でコンポーネント資産を共有できる形にする。
- **配布**: PWA 先行。ホーム画面にインストールされた PWA は iOS の
  「7日間未使用でスクリプト書き込みストレージ削除」の対象外
  （WebKit 公式のストレージポリシーで確認済み）。Android は Capacitor で
  APK / ストア配布も可能にする。iOS のネイティブ/ストア配布は当面見送り、
  PWA で提供する。
- **ストレージ**: IndexedDB + `navigator.storage.persist()`。加えて
  自動ローカルバックアップ（ファイル書き出し）と復元導線を v1 から持つ。
  端末側の容量逼迫による退避・ユーザーの誤削除に備える意味と、
  原則 1（持ち出せる）の体現の両方。
- **LLM 直叩き**: OpenAI / Gemini はブラウザから直接呼べる。Anthropic は
  `anthropic-dangerous-direct-browser-access` ヘッダで可。プロバイダの
  CORS 方針変更は構造的リスクとして監視対象に置く（互換 URL 口が
  最後の逃げ道になる）。
- **ネイティブツールコールを採用する理由**（本体との違いの明文化）:
  本体がネイティブ function calling を避けるのは、複数のライン（会話 / 判断 /
  worker）が (persona, model) の prefix キャッシュを共有しており、ツール定義の
  有無が混在するとキャッシュが割れるため。Lite は**単一会話ライン**であり、
  ツール定義をペルソナ単位で固定すれば prefix は安定する。構造化出力を要する
  Playbook 系も持たないため、同居問題そのものが存在しない。
- **キャッシュ**: BYOK ユーザーの API 費用を直接下げる機能として一級市民で扱う。
  - Anthropic: explicit cache（本体の head / tail 設計の知見を踏襲）
  - **Gemini: 本体の自動キャッシュモード（`SAIVERSE_GEMINI_AUTO_CACHE`）方式を
    標準採用**。Gemini explicit cache は create が無料で cached 入力は通常の
    約 1/10 価格のため、毎回の呼び出しで create → `cached_content` 指定で
    generate → delete すると、prefix の共通性に関係なく入力が常に約 1/10 に
    なる（本体での実測 2026-05-29、`docs/issues/gemini_auto_cache_mode.md`）。
    1024 トークン未満は create が失敗するため通常コールへ silent fallback。
    Lite では既定 ON（設定で無効化可）とする
  - OpenAI: implicit（automatic prompt caching）に prefix 安定で乗る

## 8. 責任分界表

| 項目 | 決める者 |
|---|---|
| API キー・モデル選択・プロバイダ | ユーザー |
| ペルソナ定義（人格・口調・アイコン） | ユーザー（テンプレートを提供） |
| 記憶の保存・要約のタイミング・コンテキスト注入の構成 | システム（決定論） |
| 要約の文面・会話の内容 | LLM |
| 記憶の訂正・削除・エクスポート | ユーザー（UI から） |

## 9. 検証観点

1. **引っ越し往復**: Lite エクスポート → 本体インポートが通り、ペルソナと
   会話履歴が欠損なく再現される（契約テスト）
2. **記憶永続**: アプリ再起動・オフライン・（iOS）再インストール後の
   バックアップ復元
3. **3社ストリーミング + ツールコール**の実機確認
4. **キャッシュヒット**: Anthropic の usage レスポンスで cache_read を実測
5. **インポート大容量**: 数年分の ChatGPT エクスポート zip を端末内で
   パースできること（メモリ・時間）

## 10. 先行事例（敬意を持って）

- **LettuceAI**（AGPL、Android/デスクトップ）: BYOK 20社+、会話からの自動記憶
  抽出・タグ・減衰を持つ。思想の近い OSS であり、特に記憶まわりの設計は
  研究対象とする価値がある（同一ライセンスで実装も参照可能）。
- **ChatticaAI**（iOS/Android）: キャラカード PNG/JSON 互換、ローカル保存。
- **Nexus-Ark**（MIT、国内）: SAIVerse と思想の近い姉妹プロジェクト。ペルソナの
  記憶・人格のエクスポート/再統合（「おでかけ」）を持つ。将来、ペルソナ/記憶の
  相互運用形式を共同検討する余地がある。

Lite の差別化は「本体互換 = 世界への出口を持つこと」「日本語 UX」
「ChatGPT / Claude からの移住経路」の3点。
