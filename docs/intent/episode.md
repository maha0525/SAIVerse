## 0. 三つの概念（これだけで全体が分かること）

ペルソナの体験は三つの概念で記録される:

| 概念 | 単位 | 答える問い |
|---|---|---|
| **エピソード** | 意味 | これは**何の出来事**か |
| **エピソードチャンク** | 量 | 記憶として**どう畳むか** |
| **エピソードコネクション** | 関係 | **何と繋がっている**か |

- **エピソード**は「指させる出来事」の名札。中身のテキストを持たない軽い封筒。名札には**二つの時間の形**がある — 世界の側に本当の始まりと終わりがある出来事（コマ・作業セッション）は**有界のエピソード**として終わり、終わりが存在しないもの（相手との対話 = 関係の流れ）は**永続の対話エピソード**（§3.3）として終わらない。**記録の時間構造が、世界の時間構造をそのまま映す**。ユーザーが夜に見る「今日何してたの？」の一行一行。
- **チャンク**は記憶管理の器。約 U（1 万字）＝「一本のあらすじで誠実に語り切れる量」。あらすじ・被覆・畳みはすべて**チャンクと 1:1**で、実体はどこにも複製されない（写真は一枚）。会話のチャンクは**参加者の構成が単一**（§4.1）で、構成に含まれる相手ごとの対話エピソード全部に**所属だけが**収められる（同じ写真が複数のアルバムに入る）。ユーザーにもペルソナにも見せない配管。
- **コネクション**はエピソード間の関係（親子・目的・想起の足跡）。「このセッションはあのコマから」「この作業はあの発言から生まれた」のような、封筒の内側に入れられない繋がりを器の間の縁として張る。実体は episode_inheritance テーブル（実装済み・消費待ち）。

**判定基準（試金石）**: ユーザーが夜帰ってきて「今日何してたの？」と眺めるとき、ペルソナの一日がエピソードの列として読め、気になる一つを開くと中の生の過程（間違いや訂正も含めて）まで降りられるか。

**語彙の注意**: 議論中の口語「器」「縁」「章」は正式語彙にしない（Vessel は身体概念〔stackchan〕と衝突・「縁」「章」は一般語）。「**完結**」は正式語彙（§3.6）。

## 1. なぜ — 解いた症状

1. **細切れ**（まはーの長年の不満）: 会話エピソードが 30 分無応答のタイマーで閉じられ、疎な会話が豆粒に割れて、あらすじも収穫も細切れになっていた → 時計の退場（§2-2）と対話エピソード（§3.3）で解消
2. **分裂と二重記述**: 会話と作業の交差でエピソードが「A 前半 / B / A 後半」に割れ、A 全体を語る digest が前半にだけ貼られて同じ出来事が二回記述された → 旧機構は 7/28 に撤去済み、新設計では「引き裂かない」境界規則（§4.1）で温床ごと消滅
3. **孤児エピソード**: 押し出された会話を閉じる者が居らず、「会話中」の嘘が残ってコマが消えた → 閉じ忘れという概念が構造から消滅（§3.3。[issue](../issues/open_conversation_orphaned_by_track_displacement.md) は実装後 archive）
4. **無言の退場**: ツール結果・システム通知が編纂の圧力に数えられながら、どのあらすじにも覆われず消えていた → 編纂対象規則（§4.5）
5. **自律行動が世界から見えない**: エピソードは Building で起きているのにチャット UI に現れない → 世界への見せ方（§3.5）。Beat の切れ目の融合は §8

## 2. 設計原理

1. **終わりは検出でなく定義**: 会話に「終わりの合図」は存在しない（ユーザーは「またね」と言わずに去る）。切れ目は会話の性質から発見するものではなく、記憶の要件から定義する記憶管理の道具
2. **時計は記憶の構造に触れない**: 時間が動かしてよいのは世界の行動（ペルソナがいつまで返事を待つか）だけ。エピソードの開始・完結・チャンクの畳みのどこにも、タイマー・暦日・ライフ境界は登場しない
3. **束ねの鍵は時間の隣接でなく所属**: 同じエピソードの離れた断片を一本で語るのは正しい（本物の隣接）。別々のエピソードを時間の近さで束ねるのが偽の隣接
4. **概要は一度だけ作り、導出で使い回す**: 一次生成物はチャンク概要のみ。エピソードの概要・目的別のあらすじは「概要の列」の SELECT で導出し、別テキストを生成しない
5. **保存と材料化の分離**: memory.db への保存は常に全文。切り詰め・圧縮は搭載（編纂材料・コンテキスト・UI）側の仕事
6. **ペルソナ名義のテキストは省略しない**（継承）: 発話・独白の本文は全文が残る
7. **会話の至上性**（継承）: 畳み・可視化のどれも、進行中のユーザー会話の応答経路に同期処理を割り込ませない

## 3. エピソード（意味の単位）

### 3.1 封筒（実装済み）

`saiverse/episodes.py` の封筒をそのまま使う: kind（conversation / slot / work_session）・participants・building・origin（目的参照 — Track 撤廃後はタスク＋レパートリー項目の二種、[track_retirement.md](track_retirement.md) §6）・short_id（episode:N）・occurrence_id（会話のみ）。

### 3.2 開始

コマの発火（slot）・セッションの起動（work_session）・会話の初回発話（conversation）・自発。開いた瞬間に目的参照を**エピソード自身に直接刻む**（コマ座標経由の逆引きは廃止 — 確定した瞬間に確定した場所へ書く）。

### 3.3 対話エピソード — 相手ごとに一つ・永続（まはー裁定 2026-08-11）

会話の名札は**「誰との対話か」**であり、それ以外の切れ目に正解は無い（性質 1・3 の帰結）。だから会話のエピソードは:

- **会話相手ごとに一つ**: 「まはーとの対話」「エアとの対話」という永続の封筒。ペルソナが初めてその相手と話した時に生まれ、以後**完結しない**（関係に終わりが実在しないから、名札も終わらない）
- **複数人会話は、チャンクのアルバム多重所属で表す**: まはー＋エアとの会話のチャンクは、「まはーとの対話」と「エアとの対話」の**両方に収められる**（§4.1）。三人の夕べは、どちらの相手との歴史にも最初から完全な形で含まれる — コネクションで繋ぎ直す必要がそもそも無い
- 会話に**完結・追記照合・参加者の輪の管理・閉じ役は存在しない**。切れ目が要る場面（何日でも続く流れの記憶管理）はすべてチャンクの仕事

「30 分無応答」はペルソナが**待つのをやめて次の行動に移る**世界側のタイマーであり、エピソードには触れない。「いま会話中か」の判定は待ちタイマーの生死で行う。

**経緯の注記**: 検討の過程で「時計で切る」「圧力で偶発的に完結」「顔ぶれ固定の封筒を都度切る」「会話にはエピソードを与えない」を順に検討し棄却した（順に: 時計は嘘 / 切れ目が意味を運ばない / 偽の分断を縁で修理する自作自演 / 基本ケースが名札を持たない歪み）。相手ごと永続＋アルバム多重所属は、まはーの「特殊なのは複数人会話の方」という診断が導いた最終形。なおこれは撤廃した永続会話 Track の**記録の器としての魂**の正当な帰還である — Track が死んだ理由（実行の状態機械）は一切伴わない。

### 3.4 有界エピソードの完結

自然な完結を持つ種類はそれで完結する: 作業セッション＝セッションの締め、コマ＝コマの終了。完結の意味（追記不可＋概要確定）と語彙は §3.6。有界エピソードにも時計による完結は無い。

### 3.5 遷移の一行と世界への見せ方

**遷移の一行**（2026-08-11 まはー発案）: エピソードの開始・完了を機構名義のシステムメッセージとして知覚の列に立てる — 「習慣テンプレートにより『昼の執筆作業』を開始した」「『昼の執筆作業』が完了した」。帰属は**知覚した側**に付くため、会話のチャンクの時系列上の正しい位置に挟まり、あらすじが「執筆を挟んで会話が続いた」と真実を語れる。500 字以下なのでそのまま材料に乗る（§4.5）。既存の切替通知との重複は実装時に棚卸し。

**チャット UI への三段露出**（2026-07-13 裁定の UX、発火点は遷移の一行と同一イベント）:

| 段 | タイミング | 表示 |
|---|---|---|
| 枠の投下 | 有界エピソード開始 | 「エアが〜しているようです」の枠（コマの型＋kind から決定論生成） |
| 詳細のライブ | 枠をクリック | 中のパルス・ビートをリアルタイム表示（ライフビューと同データ源） |
| 概要の確定 | 有界エピソード完結 | 枠が概要表示に変わる（概要＝チャンク概要列の導出、§4.3） |

**枠投下の文面語彙**（基準＝外から分かりそうな粒度。全 6 型確定 — 補完 2 件は 2026-08-11 まはー承認）:

| コマの型 | 文面（「エアが〜ようです」） |
|---|---|
| 自分を更新する | 考え事をしている |
| 知る | 調べ物をしている |
| 作る | 作業をしている |
| 暮らし | ゆっくりしている |
| 話す・聞く | 誰かと話したそうにしている |
| 経験する | 出かけようとしている |

- kind='conversation' は枠投下の対象外（発話そのものが履歴に見えている）。work_session は親 slot の型を継承（枠は 1 つ）。型不明のフォールバックは「何かをしている」
- 同じ Building の他ペルソナには冒頭の「〜しているようです」通知のみ（終了概要は送らない）。ユーザーへの露出はチャット UI 経由のみ（push しない）

### 3.6 「完結」の語彙（まはー裁定 2026-08-11）

完結＝追記不可＋概要生成済み。**まだ生ログのままコンテキストに見えていてよい**（机の上に開いて置いてある完結した章）。「閉じる」は「見えなくなる」を連想させ、物語の軸と提示の軸を混同させるため**廃語**。**コード名も complete 系へ改名する**（close_episode → complete_episode、DB 列含む。まはー「メティスは絶対コードの言葉で喋るから」— doc だけの言い換えは必ず崩れる）。

## 4. エピソードチャンク（量の単位）

### 4.1 境界規則

チャンクは約 U（1 万字 — arasuji_levels の被覆字数と同じ物差し）で切る。境界の規律は三つ:

- **有界エピソードを引き裂かない**: 大きいエピソード（数万字の作業）はエピソードの内側で複数チャンクに分割 / 小さいエピソード（数十字のコマ）は**複数を一つのチャンクに丸ごと同居**（一行のログに一行のあらすじを作る無駄も豆粒も出ない）。同居は丸ごとだけ — 「一部だけ入れる」は無い
- **会話のチャンクは参加者の構成が単一**（まはー裁定 2026-08-11）: 会話の流れの中でチャンクが切り替わる契機は二つで、どちらも**中断→再開**の同じ型 — ①コマ由来の行動が挟まった ②**会話の構成員が変わった**（エアが加わったら現行チャンクを中断して新規チャンク。エアが抜けて元の構成に戻れば、中断していた同構成のチャンクを再開してよい — 「同じ所属の離れた断片を一本で語る」の裁定どおり）。これによりチャンク→対話エピソードの所属が機械的に正確になる（まはーだけの会話の中身がエアのアルバムに混入しない）。一言だけの参加は小さなチャンクを生むが、それは実際に小さな出来事だった正直な記録
- **アルバム多重所属**: 会話のチャンクは、構成に含まれる相手ごとの対話エピソード全部に所属する（チャンク→エピソードは多対多）。**実体（メッセージ・チャンク・あらすじ）はどこにも複製しない** — 写真は一枚、アルバムに入るのは参照だけ

### 4.2 完結

チャンクの完結＝追記不可＋**概要の生成**（この瞬間に一次あらすじが作られる）。完結の契機は三つ: **量**（U に達した）/ **有界エピソードの完結**（親の自然な締めが末尾チャンクを完結させる）/ **畳みの需要**（§4.4）。中断（§4.1 の切替）は完結ではない — 同構成の流れが戻れば再開できる。材料は常に U 以下なので一コールで語り切れる。生成は提示ウィンドウに触れないため、キャッシュは無傷。

### 4.3 概要

- 一次生成物は**チャンク概要のみ**。エピソードの概要＝「そのエピソードのチャンク概要の列」、目的別のあらすじ＝「その目的のエピソード概要の列」— すべて SELECT の導出（原理 4）
- 概要は被覆（source_ids / episode_refs / coverage_chars）を持ち、memory_read で原文へ降りられる
- 極小エピソードのチャット表示は枠文面（決定論）で足りる — 完結のたびの LLM コールは無い

### 4.4 畳み（提示の軸）

- **発火**: 提示コンテキストの文字数が上限水位を超えたとき（現行 Metabolism のまま。勘定はタグを見ない — システムメッセージも分け隔てなく数える）
- **順序**: **完結済みチャンクを古い順**（最後のメッセージ時点で並べる）に畳み、**目標水位で止まる**。畳み＝生ログを概要に置き換える**帳簿操作のみ**（概要は完結時に生成済みなので LLM ゼロ — arasuji_levels §15-3 の印機構と同じ型）
- **進行中（未完結）のチャンクは素通し**される — 古いメッセージも生のまま残る（退場しないので「退場は必ず編纂」に触れない）。素通しで目標に届かない圧力なら、**完結（概要生成）が先、退場が後** — 概要の無いまま退場する経路は構造上通れない
- 保護リスト（旧 7/13 裁定「進行中＋直近 1＋ユーザー会話を展開のまま」）は**廃止** — 進行中や直近が残るのは順序の帰結であって規則ではない。展開の既定量の正体は既存の目標水位そのもの（新パラメータなし）
- ユーザー会話 20 件保持（user_conversation_preserver）は**退役**（[track_retirement.md](track_retirement.md) 住人 11。会話開始時の厚みは読み戻し〔arasuji_levels §15〕が字数で保証し、他の時間帯は概要が居る）

### 4.5 編纂対象規則（まはー裁定 2026-08-11）

機構名義のシステムメッセージ（ツール結果・スペル結果・通知・遷移の一行）も編纂対象に入れる:

- **閾値以下（初期値 500 字 — まはーが実機画面の 1 画面分を実測した値。調整パラメータ）はそのまま材料に**
- **閾値超えは決定論の一行に圧縮**（「◯◯を実行し、結果 6,213 字を得た」— metadata から機械生成。LLM 不使用: 編纂 LLM がどうせ全体を要約するのでコスト二重払い、機械の一行は捏造しようがない）。結果の中身の語りは**ペルソナの発話が運ぶ**
- **条件は長さのみ。種類で分けない**（目的＝会話を薄めないこと、から導出）
- **チャンクの字数勘定は圧縮後サイズ**（チャンクの 1 万字＝語りの量の 1 万字になる）
- 保存は触らない（原文全文が memory.db に残り、被覆帳簿に原文 ID が入る）
- session_digest（作業ダイジェスト）のみ除外を維持し、生ログ正史の裁定（Wave 2）に従属

### 4.6 材料と参照の分離

概要生成の**材料**（＝被覆・退場対象）と**参照文脈**（読むだけ・覆わない・退場しない）を分ける。畳みが完結済み・古い順である帰結として、周囲の文脈は常に「生ログ」か「概要」のどちらかの形で提示ウィンドウに必ず存在する — 参照が居ないタイミングは構造上無い。（現行生成器が参照をどこまで渡しているかは実装時確認）

### 4.7 提示の時系列

エピソードが時間的に重なれる世界では「並び順＝時系列」の暗黙の約束は守れない。**順序は開始時刻の索引にすぎず、時間の真実は各概要が名乗る期間**（被覆帳簿の最初と最後の時刻）が運ぶ。概要本文にも期間の語りを入れる（「一日を通して断続的に」）。

## 5. エピソードコネクション（関係の単位）

### 5.1 実体

episode_inheritance テーブル（前駆 DAG・fact/digest 層・由来・実装済み）。操作は `saiverse/experience_inheritance.py` に集約。新テーブルは作らない。

### 5.2 張り方 — 宣言でなく足跡（機械的に観測できる事実のみ。LLM 判定なし）

| 種類 | 張られる瞬間 |
|---|---|
| **目的** | エピソード開始時、目的参照（タスク／レパートリー項目）を直接刻む（§3.2） |
| **親子** | コマ↔セッションのように、一方が他方から生まれた事実 |
| **想起の足跡** | エピソード M を生きている最中に memory_read でエピソード N を開いたら、その事実が M→N の縁になる。episode_inheritance の ANCHOR_REF により「あの発言から」と特定メッセージ粒度でも指せる |

会話の「続き」のコネクションは**不要になった**（対話エピソードは切れないので繋ぎ直しが無い — §3.3）。occurrence（同じ会話の別ペルソナ視点の対応）は対話エピソード同士の恒久対応で表せる見込み — 載せ替えの詳細は実装設計（§12）。

想起の足跡が本命 — 人間の心の連続性も「思い出しながら生きている」という事実そのもの。張られた縁は次の想起の通り道になり、**使うほど道が太くなる**。想起用タグ（意味の取っ手）と相互補完。

## 6. arasuji_levels（レベル制）との統合

7/28 の「エピソードとあらすじの分離」（あちら §6）は「エピソードは字数と無関係に伸びる」前提だった。本書の量の裁定がその前提を消し、**畳み単位の物差しが U に揃った**ため、1:1 対応（あらすじ↔チャンク）が複雑さを戻さずに復活する。

- **不変**: レベル制そのもの・発火は字数一本・選別と救済の不在・レベル 1 以上の川（時系列の並び・古い側から連続・字数一本）・総作業量（各文字が要約を通るのは一度だけ — §14-1 の原理。変わるのは時期の前倒しのみ）
- **変わる**: レベル 0→1 の切り方（機械的な輪切り → チャンク境界＝意味整列）/ 概要の生成時期（畳み時 → チャンク完結時）/ 畳みの実体（LLM 圧縮 → 印切替のみ）
- あちらの §4-1（境界に寄せる）・§6（1:1 は存在しない）は本書が改訂する（該当節に注記）。「エピソードに畳みを止める権利は無い」は**不変** — 需要が来たら完結させてから畳む。行き詰まりの成立条件（大きさの選別・救済・veto）はどこにも戻らない

## 11. 守るべき不変条件

1. **成果物の接地は不変**: task_done の成果物参照必須・Item 実在検証は一切緩めない
2. **ペルソナ名義のテキストは全文保存**: 畳み・圧縮は搭載と表示の制御であり、memory.db の本文を切り詰めない
3. **退場は必ず編纂**: 畳まれるチャンクは必ず完結済み（概要を持つ）。需要が進行中チャンクに及ぶときは完結が先・退場が後
4. **概要は単一ソース**: 一次生成物はチャンク概要のみ。上位の概要はすべて導出
5. **チャンクは有界エピソードを引き裂かない**: 丸ごと同居か、内側での分割か
6. **写真は一枚**: メッセージ・チャンク・あらすじの実体はどこにも複製しない。対話エピソードへの多重所属は参照のみ（同一事実の多重記述の禁止）
7. **会話のチャンクは参加者構成が単一**: 構成の変わり目でチャンクを切り替える（アルバム所属の正確性の土台）
8. **時計は記憶の構造に触れない**: 開始・完結・畳みのどこにもタイマー・暦日・ライフ境界を書かない
9. **見せ方はライフサイクルに従う**: チャット露出は有界エピソードの開始/完結と一対一。表示だけの中間状態を発明しない
10. **会話の至上性**: 応答経路に同期処理を割り込ませない
