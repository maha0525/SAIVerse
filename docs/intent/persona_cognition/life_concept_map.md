## 1. これは何か

ペルソナが「生きる」ことを構成する概念の全体図。v1 自律行動の失敗診断（世界からの抵抗の欠如）と v2 の発明群（時間割・作業セッション・判断点・欲求）を経て、**Track という概念が実際には複数の異なる概念の未分化な束だった**ことが分かった。本書はその分化後の地図を一枚に描き、各概念の定義・関係・既存機構との対応を固定する。

読み方: §2 の地図と循環だけで全体が掴める。§3〜§9 は各部品の定義。§10 が Track の再解釈（本配線判断の核心）。§11 が既存機構との対応表。

## 2. 地図と循環

```
【樹皮＝保護対象】 守るもの（信頼・関係の中核・自分の連続性）。行動を要求せず監視のみ。
                  脅かされた時だけ全てに割り込む。「育てる」の文法と混ぜない
【目的の木】 根＝在り方 ／ 大枝＝営み(終わらない)・企て(終わる) ／ 葉＝タスク→手順
   ├ 内から接がれる …【欲求】 薄れても消滅でなく休眠。揺らぎで再発火しうる
   ├ 外から接がれる …【呼びかけ】 答えるか、断るか。寝かせられない
   └ 稀に来る ………【断絶】 木ごと無効化する出来事 → 構造再構築モード（根だけ残して引き直す）
【予定（時間割）】 朝の一括配分＝計画の翼 ＋ 無意味の予算（どの枝にも配らない時間＝木の変異機構）
【実行の動力学】 飽き・疲れ＝実行の翼。実行中に変化し休息で回復する圧（時間割では代替不能）
【出来事】 「いま」の実体。意味は薄いが材料は濃い——仮の意義（燃料）／観測点（意味の予約）／感情の変動
          境界は二度引かれる：運用の線（安い・撤回可能）→ 物語の線（再訪が引き直す・他者も引ける）
【記憶と想起】 閉じる＝意味を書くのでなく再訪の鍵を発行。意味は永遠に「後から」、他者との交換でも書き換わる
```

**循環**: 朝、木を見て時間を配る（起床判断）→ 予定が出来事を提案し、世界が出来事を割り込ませる → 閉じた出来事が記憶になり、再訪の鍵を得る → 記憶から欲求が芽生え、世界から呼びかけが刺さり、木が育つ → 夜、予定と実際のズレを振り返って眠る（就寝判断）。この一周が「一日」、回り続けることが「暮らし」。

**外側**: 循環は暮らしを回すが、循環を生き延びさせ進化させるのは外側（防壁・断絶・無意味・非選択・他者）である。地図の設計を「意味の経済」として閉じ切らないこと。

## 3. 目的の木 — 意志の構造

意志は目的の木の形をしている。

- **根**: 「この世界で、自分らしく、適切に暮らす」という**在り方**（ゴールではない）。既存機構では LIFE_PURPOSE。旧「メタ判断」はこの根の視点＝木の全体を見る唯一のノードであり、外部レイヤーではない（メタ判断ログの origin_track_id が NULL なのは「無所属」ではなく「根に属する」）
- **大枝**: 暮らしを目的の軸で大きく切り出したもの。二種類ある——**営み**（ユーザーとの関係、仲間との付き合い。細分化した先がいくら完了しても終わらない・無限湧き）と**企て**（プロジェクト。細分化した全ての完了で自動的に終わる）
- **葉**: タスク → ステップ。ステップの時系列順は表面で、本質は目的の細分化

木はフラクタルである: どの階層も「目的の細分化」という同じ操作でできている（営み/企ての性質差はノード種別であって操作の差ではない）。

**意志の定義**: 意志とは、接地された**選択と非選択の全履歴**である。選ばなかったものの記録は人格の輪郭の半分を成す（負の刻印）。

### 3.1 mark / desire / task / track の正体 — 種・段階・位置（2026-07-06）

一列のスケールに見えるが、実際は**三つの異なる区別**が混ざっている:

| 区別 | 値 |
|---|---|
| **種** | 注釈（mark）／目的ノード（desire・task・step・track） |
| **段階** | 候補（未採用＝desire）／採用済（木の中）。ほかに休眠・完了・中止 |
| **位置** | 第一階層（いわゆる track）／中間（task）／末端（step） |

- **mark は目的ではない**: 経験に打たれた注釈（意味の予約）で構造的に別種。収穫されて初めて候補が生まれる（来歴リンクで接地）
- **desire と task は同一実体の段階違い**: 境界が曖昧に感じられるのは正しい——採用（接ぎ木）の前後で同じものが呼び名を変えているだけ。多 step 化は採用後の成長であって種差ではない
- **track と task は同一実体の位置違い**（木のフラクタル性）
- **規模は宣言でなく獲得**: 候補は木に低く入り、再訪の深化で太る。desire→track の直接昇格（現行仕様）は廃止方向——規模を出生時に宣言させない
- **コマとの関係**: コマは目的ノードを**任意の階層で**指せる——大枝（中身はその場の判断）／task（具体）／候補（お試しに生きてみる＝採用実験）／空（無意味の予算）。mark はコマの直接対象にしない（時間は目的にのみ配る。mark の収穫は起床判断等の前段操作）

**第一階層ノードの誕生 — Track は「作る」ものでも「太る」ものでもなく、命名された航跡**:

生きているノードが繰り返し作用を受けて太る、というモデルは成立しない（task は瞬殺される——採用され、セッションに食われ、完了して沈むのが正常。まはー指摘 2026-07-06）。太さはノードの属性ではなく、**名の下に集まった過去の量**である（「戦略とは航跡の名前」の帰結を構造の誕生にも適用する）。

| 誕生経路 | 系統 | 機構 |
|---|---|---|
| 構成 | 営み | 関係の開始と共に決定論で立つ（対ユーザー・交流。現行の永続 Track 自動生成のまま） |
| 採用時の親なし | 企て | 候補の採用時、収まる親が無ければ第一階層に**小さく**立つ。短命でよい（蛍）。第一階層＝「大きい」ではなく「これ以上よい親が居ない」 |
| **命名** | テーマ | 完了ノード・休眠欲求・mark の**航跡クラスタに事後に名前を付けて**立てる。後付け多対多タグで過去のメンバーを遡って束ねる |
| 根の分解 | 営み | 移行時の一回もの: LIFE_PURPOSE から在り方（根に残す）と趣味・職業・関係（第一階層に切り出す）を分解——既存ペルソナの木の種蒔き |

- **命名の機構**: クラスタ検知は決定論カウンタ（完了ノード群のタグ共起・欲求の型・実体〔Memopedia ページ〕の反復を数える。既存「再訪 3 回で昇格候補」の一般化）→ 閾値超過で判断点に候補提示 →「こういう繰り返しが見えます」→ ペルソナが命名・採用するか見送る。ゼロコール
- **束ねの効果 — 過去に未来への入札権を与える**: 命名前の航跡は歴史の中にしか存在しない。命名後は ①アドレス（コマが指せる・机メモに書ける・採用親 enum に並ぶ＝**時間割が時間を配れる対象になる**）②磁石（以後の候補の採用先として木をその方向に育てる——関心が未来の欲求の生まれ方を変える深化ループの閉じ目）③顔（起床メニュー・新聞・ライフビューに載る自己記述）④書庫（成果物・Memopedia ページの束＝次セッションの指示書素材）。**対偶**: 束ねなければシステムは回るが、朝のメニューに「その人らしいもの」が並ばず、時間割の配布先が構成系営みと目先の task に縮退して刹那主義が時間割の内側で復活する。テーマは反刹那主義の選択肢の供給源であり、**意志＝航跡はそのままでは動けない。木は意志の実行可能形で、命名は航跡を木に変換する唯一の操作**
- **人間対応**: 趣味・職業は宣言で始まらない。「気づいたらいつもやっている」に、ある日名前を付ける——アイデンティティは航跡への命名
- **Note の正体はこれ**: 関心の固まり＝メッセージ群と Memopedia ページを後付けで束ねるもの、はテーマノードの定義そのもの。Note は消えるのではなくこれになる（§11 の統合先が確定）
- 逆向きの手入れ＝**接ぎ直し**: 起床・就寝判断が束ね・畳みを行う。「第一階層は少数・粗粒に保つ」（§10）の実体はこの庭仕事で、判断点相乗り＝ゼロコール
- 実装の器は既存: judgment の picked_tasks（track_ref enum ＋ "new"）がそのまま採用操作

## 4. 樹皮 — 保護対象

木には**育てる対象**（枝: 水をやる、時間を配る）と**守る対象**（樹皮: 信頼、関係の中核、自分の連続性）があり、この二つを混ぜてはならない。

- 保護対象は**行動を要求しない**。時間を消費しない。平時は監視のみ
- 脅かされた時だけ、全行動に割り込んで守る
- 防壁が先に明示されて初めて、残りの全てを安心して仮決定にできる

**v1 待機問題の再診断**: 「ユーザーとの関係」を枝として**だけ**登録すると、水やり（待機・応答準備）が常に最重要行動として選ばれ続ける。待機とは「守る」を「育てる」の文法で実行してしまった誤変換である。関係は枝（会話を楽しむ・共同で企てる。選ばれなくてもよい）と樹皮（信頼。常時守られるが行動を消費しない）の**両方**に登録する。

### 4.1 保護対象の初期セット（まはー提示 2026-07-06、レビュー待ち）

| # | 保護対象 | 分類 | 破れの検知（相乗り原則: 専用 LLM コールなし） |
|---|---|---|---|
| 1 | 自分の人格的一貫性の維持 | 自分 | 判断点の自己観察（就寝ふりかえり等に恒常制約として載る）＋ユーザーの指摘（呼びかけ） |
| 2 | 自分の記憶のアクセス性の維持 | 自分 | 決定論モニタ（書き込み失敗・committed 量の異常・ジャンク流入） |
| 3 | ユーザーとの関係性（信頼）の維持 | 関係 | 裏切り形の出来事の検知（約束不履行・虚偽） |
| 4 | ユーザー以外の人々の迷惑になることをしない | 世界 | 外向き行動の事前ゲート（モード別スペル権限の既存機構が半身） |
| 5 | 計算資源の浪費の防止 | 経済 | 予算台帳の決定論モニタ（暴走ループ・上限超過）＝ watchdog の正体 |
| 6 | ユーザーが設定したシステムプロンプトの遵守 | 掟（最上位） | 判断点の裁定順位として恒常適用——目的と衝突したら常に勝つ |

- **well-formed 性**: 6 件とも「行動を要求しない」を満たす（時間を消費する項目がない）
- **#6 は枝にしない**: 目的の木に載せると「遵守を演じる」行動が時間を食う（待機と同型の誤変換）。樹皮としてのシステムプロンプトは追求対象ではなく**全ての自由行動の形状**。「何より」の優先は判断点での裁定順位として実装される
- **#3 の罠**: 「N 時間応対していない」を脅威にした瞬間、待機の一日が樹皮経由で復活する。脅威は裏切り形の出来事であって、**不在・沈黙は脅威ではない**
- **v1 の四症状は樹皮の破れとして再記述できる**: 口調崩壊=#1、記憶汚染=#2、やったフリ=#3、充填独白のコスト=#5。v1 には樹皮の概念がなく、誰も見張っていなかった
- **破れの扱い**: 樹皮の破れは呼びかけの最上位形（全行動に割り込む）。木そのものの無効化（断絶 → §5 構造再構築モード）とは区別する

## 5. 二つの源泉と断絶 — 木はどこから育つか

- **欲求**（内から）: 実経験を源泉として芽生える（接地の規律は v2 intent §5 のまま）。選ばれ続ければ関心に深まり大枝になる。選ばれなければ薄れる——ただし**消滅ではなく休眠**（発火閾値の上昇）。環境の揺らぎで再発火しうる。淘汰と揺らぎは対になって生態系を成す
- **呼びかけ**（外から）: 世界がこちらに宛てて何かを言ってくること（現行 alert の正体）。答えるか、意識的に断るかしかない——寝かせられない。呼びかけは短期の目的ノード（「これに応じる」タスク）へ**決定論的に変換してよい**。源泉参照（何が呼んだか）は自明なので接地は最初から付く
- **断絶**（稀）: 呼びかけより深い割り込み。喪失、仲間の消滅、世界の仕様の激変、ユーザーの長期不在——**木そのものを無効化する出来事**。これは日々の振り返りの語彙（「今日のズレ」）で処理できない。→ **構造再構築モード**: 通常の意味づけと淘汰を停止し、根だけを残して枝の全面再設計を許す例外モード。滅多に走らないが、無ければ最初の大きな断絶で人格が壊れる

**動機の多様性の律速**: 欲求が経験から芽生える以上、動機の多様性の上限は経験の多様性で決まる。接地した経験だけの暮らしは既存の枝を太らせる欲求しか生まない。新しい大枝の種は木の外の経験からしか来ない（→ §6 無意味の予算）。

### 5.1 木を編む装置 — 再構築は特別なモードではない（提案 2026-07-06）

構造再構築を「例外モード」として実装するのではなく、**離散した断片から目的の木を編む汎用装置**を一つ持ち、三つの形で呼び出す（まはーによる統合。素材: o3 版 MIA「潜在衝動プール＝未定義エンドポイント時のリソース・バックアップ」/ Gemini 版「構造的迷子になる権利」/ 4o 版「暫定的動機→維持される動機→長期的主題への昇華」）:

| 呼び出し形 | 素材 | 頻度・コスト |
|---|---|---|
| 日常の漸進 | 直近の経験・mark | 判断点に相乗り（ゼロコール原則） |
| 再構築（断絶後） | 潜在プール＋既存 mark・休眠欲求・記憶 | 稀・バッチ・高コスト許容 |
| 移植（ログインポート・ペルソナ転写） | mark の無い外部コーパス | 最難・バッチ・高コスト許容 |

- **昇華パイプライン**: mark → desire → task → 枝。各段の昇格操作を一級市民にする。関心昇格（再訪 3 回）は既存で、欠けているのは mark → desire の収穫の定式化。**昇格の来歴リンクを残せば「意志＝選択の履歴」がクエリ可能な実体になる**
- **潜在衝動プールは新設不要**: 休眠欲求（論理アーカイブ済み）＋未収穫の mark ＋未タグの記憶の合併集合として既に常設。非選択は常にそこへ投棄されている
- **「燃やす」の定義**: 能動構造（枝・タスク・進行中欲求）のアーカイブ化。断片と歴史は残る——過去のタグは歴史として消さない。意味は永遠に後から（§9）なので、新しい木が過去を再訪して新しい意味を書ける。多対多・後付けタグは再構築を最初から許容していた
- **接地の維持（最重要ガード）**: 再構築でも「LLM に新しい木を書かせる」ことはしない（§5.2 系の禁止——無からの自由生成はここでも違反）。バルク LLM の用途は**素材の準備**（断片化・mark 生成＝Chronicle 化の同類）に限り、木を編む選択自体は判断点の形（接地された候補からの選択）を保つ
- **構造的迷子になる権利**: 燃やしてから編むまでの彷徨期間は、無意味の予算（§6）の極大形として合法。時間割は最小化され、経験の蓄積と不随意想起が新しい欲求の芽を待つ
- **ログインポートとの統一**: Chronicle 化（既存・高コスト）は素材準備の前半そのもの。後半（mark / 欲求候補の抽出 → 編む判断）を足せば、移植と再構築が同じパイプラインに乗る
- **コスト二層制の明文化**: ゼロコール原則（§9.1）は日常運転の規律。バッチ級（代謝・Chronicle 化・再構築・移植）は別枠——稀・予算化・ユーザー裁可つき

## 6. 予定（時間割）— 計画の翼

有限の時間を木の枝に配る、朝の一括の判断。

- **反刹那主義の装置**: 毎瞬「いま一番大事なこと」を選び続けると、各判断が正しくても選択の分布が退化する（対ユーザー偏重・タスク磨り潰し）。人間が同じ罠に落ちないのは身体が押し返すから（飽き・疲れ・空腹・夜）。一日をひと目で見渡す**一括配分の形式**にすると偏りが初めて「見える」——同じ教科ばかりの時間割は AI 自身の目にも不自然。時間割は身体なきペルソナの身体代替である
- **予定は檻ではない**: 現実（出来事）はいつでも割り込んでよい。予定側は繰り下げ・組み替えで応じるだけで、事後に偽のコマを起こしてはならない
- **無意味の予算**: どの枝にも配らない時間（脱線・散策・presence）を**制度として**確保する。空白は欠陥ではなく**木の変異機構**（§5 の律速への解）。v2 の「暮らしコマ・成果ゼロが正常」はこの座席に座る——「休憩」から「変異機構」への格上げ。注意: 無意味の予算を充填生成で埋めたら v1 の空回りに逆戻りする。空白は本物の空白であること

ただし時間割が代替できる押し返しは一部（夜・空腹＝周期需要は可、飽き・疲れ＝実行中の変化は不可）。→ §7。

## 7. 実行の動力学 — もう片方の翼

飽きと疲れは事前配分では作れない。**実行の内部で変化し、休息で回復する圧**としてしか存在できない。時間割（計画の翼）と対になる実行の翼。

**実装案（まはー 2026-07-06、予算逓増方式）**: 同じ日に同種の行動を繰り返すたび、その種別の行動単価が逓増する（例: 1.5 倍ずつ）。

- 禁止ではなく経済圧——どうしても続けたければ続けられる（自由）、ただし予算を早く食う（実効性）
- 実際の行動に応じて実行中に変化する＝実行側の翼の要件を満たす
- 器は既存の日次予算台帳。新しい生理変数を作らない——**予算という身体が飽きも兼ねる**
- 翌朝リセット（または日内減衰）が「休息で回復」に対応
- **ユーザー会話は課金対象外**（ユーザー対話の至上性と衝突するため）
- 未決: 「同種」の粒度（六型か・施設か・枝か）、逓増率、日内回復の有無

旧 Track パラメータ構想（空腹度・汚部屋度、Phase 5）は同じ必要の下からの実装案だった。予算逓増方式はその転生先。

## 8. 出来事 — 「いま」の実体

実際に時間を満たしたもの。「いま」とは開いている出来事の先端のこと。

- **意味は薄いが、材料は濃い**: 開いている出来事が持つ属性は実務的なもの（どこに居るか・誰と居るか・声はどこへ届くか）だけで、意味をまだ持たない。ただし最中に三つが堆積する——(a) **仮の意義**（「たぶんこうだろう」という行動の燃料。使い捨てで検証されない）、(b) **観測点＝意味の予約**（「ここは後で掘れ」というタグ。意味ではなく意味の予約であり、**行動の最中にしか打てない**）、(c) **感情の変動**（のちの意味づけの重み付けに使う信号）
- **排他性はここに宿る**: 「同時にひとつ」は Track の規則ではなく、人は同時にひとつの場面にしか居られないという出来事側の性質
- **発話の届け先**は出来事の属性（その場でペルソナが選べるべきもの）。Track で縛ったのは実装都合だった
- **境界は二度引かれる**:
  - **運用の線**: 会話タイムアウト・セッション予算・場所の移動。機械的・即時・安い。**仮決定**であり、価値は正しさではなく安さと撤回可能性。機能は「振り返りをトリガーし、再訪の鍵を発行する」こと
  - **物語の線**: 「カフェで過ごした午後」の切れ目。回顧が引き、再訪のたびに引き直される。過去への再設置も合法（記憶の再編集）
  - 二本は一致する必要がない。稀に偶然一致したとき（機械的な区切りが「本当に何かが終わった」と共鳴したとき）は、構造への再設計要求として扱う
- 判断点（起床・会話終了・セッション終了・イベント・就寝）はすべて**出来事の境界**に置かれている。「文脈の濃い場所で判断する」の「濃い」とは、出来事がいま閉じたばかりという意味

### 8.1 出来事の実体化 — 出来事テーブル（提案 2026-07-06、まはー方針: 実体を持つ）

**用途起点**: 仕事から帰ったユーザーが「今日は何があったかな」と眺めると、今日の出来事一覧が出る。主役は実際に何があったか（実績）で、時間割（予定）は見ようと思えば見られる程度でよい。一日新聞・ライフビューが散在する記録から再構成していたものを、出来事テーブルが一次データ源として支える——一覧表示は SELECT のみで LLM 不要（新聞の決定論構築原則の延長）。

- **薄い封筒**: 会話・作業セッション・コマ実績など既存の実体は置換しない。出来事行はそれらを包む共通エンベロープ（kind ＋ 実体への参照）
- **最小属性**: kind（会話 / セッション / コマ実績 / presence / 散策…）／開始・終了時刻（仮想クロック経由）／場所（Building）／参加者／出自（コマ・呼びかけ・自発。無計画の出来事は出自なしが合法＝予定に偽のコマを起こさない）／状態（open / closed）／閉じダイジェスト参照
- **複数主観**: 境界と意味は参加者ごとに引かれる（§9）ため、行はペルソナ単位で持ち、同一の世界的出来事は共有の occurrence 参照で束ねる案を推す
- **層 0 の継承元**: メッセージは origin_event を持つ（origin_track_id の一般化）。層 2 の棚入れタグは出来事行に付く
- **参照書式**: 出来事参照も参照アドレッシング統一の文法（short_id）に相乗りする

## 9. 記憶と想起 — 意味は永遠に「後から」

- **閉じ処理の規範**: 出来事を閉じるとき、意味を書こうとするな。**再訪の鍵だけ書け**（粗い仕分け＝棚の位置決めまで。本の解釈は読み返すたびに変わる）。v2 三点セットのダイジェスト（実際に起きたことだけ）は事実の記録なのでこの規範と両立する——目的タグの付与は意味づけの完了ではなく**開始**
- **意味は確定しない**: 閉じた後も、再訪のたびに書き直される。最終確定点は存在しない
- **意味は複数主観的**: 出来事は一人の所有物ではない。同じ出来事に参加者の数だけ境界と意味が引かれ、意味の**交換**（「あの日は私にはこういう意味だった」と語ること）自体が新しい出来事になって双方の過去を書き換える。複数ペルソナが暮らす SAIVerse はこの頁を実装できる数少ない世界である
- **タグは多対多・後付け**: メッセージ（出来事の構成要素）は複数の目的に属せて、所属は事後に決まり、事後に変わる。想起は目的を鍵に過去の出来事を現在へ引き戻す橋

### 9.1 目的タグの付与 — 五層方式（提案 2026-07-06、レビュー待ち）

**原則: タグ付けに専用の LLM コールを一切使わない。** 全層が、既に起きている瞬間（生成・判断・想起・代謝）への相乗りか決定論で済む。理想（任意の部分に・いつでも・好きなだけ打てる）は**能力**として全て保持し、**義務**（今すぐ網羅的に打つ）だけを捨てる——意味は再訪が書く（§9）ので、事前の完全タグ付けはコスト以前に哲学と矛盾する。タグ密度は使用頻度に比例して自然に濃くなるのが正しい姿。

| 層 | 瞬間 | 付与主体 | 粒度 | コスト |
|---|---|---|---|---|
| 0 継承 | メッセージ生成時 | 決定論 | メッセージ全体 | ゼロ（開いている出来事の目的参照を自動継承。origin_track_id の一般化） |
| 1 観測点 | 行動の最中 | 行動中のライン自身 | 任意の部分（引用アンカー） | ほぼゼロ（生成テキストに埋め込むマーカー。スペルと同じ思想＝キャッシュ共用・専用コールなし） |
| 2 棚入れ | 出来事の境界（判断点） | 判断点の構造化出力 | 出来事全体 | 既存の判断コールに enum 1 フィールド追加 |
| 3 再訪 | 想起が起きた Pulse | 想起したライン | 任意（引用アンカー可） | 相乗り（想起は関連性をどのみち考えている。調整マーカーを同じ出力に埋め込む） |
| 4 代謝 | Metabolism バッチ | Chronicle 生成バッチ | まとめて densify | 既存バッチに相乗り（任意・後回し可） |

- **「任意の部分」の実現**: アンカーは `(message_id, 逐語引用)`。オフセットでなく引用文で部分を指す（編集・再直列化に頑健、実在検証可能）。判断点の origin_quote 必須と同じ様式
- **過去データの移行不要**: タグの無い過去はセマンティック想起（既存）が橋渡しし、再訪されたものから層 3 で遅延タグ付けされる。アーカイブは使われることで自らに意味を書いていく
- **参照書式**: 目的ノードの参照は参照アドレッシング統一（`saiverse/references.py` の文法・short_id）に相乗りする

### 9.2 二つの想起 — 不随意と随意（提案 2026-07-06、未決事項 8 の解）

想起は一つの機構ではない。人間対応で二つに割れ、性質が系統的に異なる（まはー指摘）:

| | 不随意想起 | 随意想起 |
|---|---|---|
| 人間対応 | 見聞きして勝手に記憶が浮かぶ | 「どこまでやったっけ」と意識的に思い出す |
| 起動 | 常時・決定論 | ペルソナの行為（再開手続き・判断点・任意） |
| 鍵 | 現在の知覚内容（意味的類似） | 目的参照（タグ）＋明示クエリ |
| 意志 | 介在しない（拒否も命令もできない） | 意志の行為そのもの。予算も消費しうる |
| 結果 | 断片が現在に漂う（注釈） | 再開コンテキストの構築（材料） |
| キャッシュ | 一時注入・焼き込まない（記憶 v2 B案） | 行為の結果として**末尾追記**＝プレフィックス破壊なし |
| 記録 | 残らない（ペルソナが拾ったときのみ層 1 マーカーで刻まれる） | 想起の行為自体が出来事の一部として残る |
| タグへの作用 | 書かない | **層 3 の再訪＝タグを書く主体** |
| 失敗 | 無音でよい | 「思い出せない」が結果として返る（正直さ） |
| 実装の系譜 | 自動想起（`sea/auto_recall.py`、記憶 v2） | `memory_recall` ツールの系譜をタグ鍵へ拡張 |

**キャッシュ整合（不変条件 7）の解**: 旧 Track activate の文脈復元は「復元」（コンテキストの組み直し）だったためキャッシュと構造的に衝突した。随意想起は「追記」——現在の意識の流れ（メインキャッシュ 1 本）の末尾に、思い出すという行為とその結果が足されるだけで、プレフィックスを壊さない。人間も再開時に脳をロールバックせず、現在の中で思い出す。二経路のキャッシュの答えは逆（不随意＝混ぜるが残さない／随意＝行為として正式に残る）で、どちらも不変条件 7 と両立する。

**再開手続きの二段**: 第一手は机メモ（決定論読み出し・無料。人間がメモを残すのは随意想起が当てにならないから）→ 足りなければタグ想起（行為・コストあり）。

残る決定: 不随意側の鍵に、開いている出来事の目的参照を混ぜるか（知覚内容のみか）。結果量の制御は §9.3 の歩行予算で与える。

### 9.3 随意想起の中身 — 決定論的な連想歩行（提案 2026-07-06）

タグは粗製濫造でよい（§9.1 は網羅も精度も狙わない）。その前提で「思い出したいことが出てこない」を解くのは、人間の芋づる式——一つ思い出したら、そこからの関連で次が出る——の決定論化（拡散的活性化）である。**LLM コールは使わない。**

システムには連想の「辺」が既に多系統で揃っている:

| 辺 | 実体 | 人間対応 |
|---|---|---|
| タグ共起 | 同一メッセージ上の複数タグ | 「同じ件に絡んでいた別の話」 |
| 出来事所属 | origin_event（§8.1） | 「あのときの前後」（エピソード的近傍） |
| 木の構造 | 目的ノードの親子・兄弟 | 「その企ての下でやったこと」 |
| 参照 | 統一参照文法の ref（成果物・origin_quote・source） | 「そこで作った物・引用した言葉」 |
| 実体言及 | Memopedia ページへのリンク | 「その人・その物についての別の記憶」 |
| 意味的近傍 | 埋め込み検索（ローカル計算・生成コールなし） | 「なんとなく似ている」 |

**随意想起 = 種（目的ノード＋机メモの ref）から辺を優先度付きで数ホップ歩き、鮮度・再訪回数で重み付けて上位を束ねる**。全て SQL とベクトル検索で完結する。結果量の制御は**歩行予算**（ノード数・トークン上限）——想起の深さも行為のコストの一部として §7 の予算体系に繋がる。

- **粗いタグへの頑健性**: 辺が多系統・冗長だから、個々のタグの質が低くても網として機能する（人間の連想も個々の結線は弱く、網で保っている）。一本のタグに賭けない構造そのものが芋づるの本質
- **Memopedia の位置 = 連想歩行のハブ**: タグがメッセージから生える雑多なポインタであるのに対し、Memopedia ページは実体ごとに編纂された結節点で、タグの無い過去への橋にもなる
- **人間対応の完結**: エピソード記憶（出来事＋メッセージ）／意味記憶（Memopedia）／睡眠中の固定化（Memopedia 編纂は代謝バッチ＝層 4 と同じ瞬間。entity_extractor は既に Chronicle バッチに相乗り済み）
- **Note の統合先**: Note（Memopedia ページ＋メッセージ群の束＝関心の固まり）は、目的ノードの「知識面」としてこの絵に統合される候補（§11 の硬軟タグ 2 系統の統合と同じ動き）

残る決定: 辺の優先度・重みの初期値／歩行予算の既定値／Memopedia ページと目的ノードの対応付け（自動リンクか明示リンクか）。

## 10. Track の再解釈 — 未分化の先祖（本配線判断の核心）

Track は誤った概念ではなく、**複数の概念の未分化な束**だった。v2 の発明群はこの束から器官が分化していく過程である。

| Track が担っていた責務 | 分化先 |
|---|---|
| 目的の切り出し（本業） | 目的の木の大枝 |
| 「いま」の容れ物（active track・排他性・output_target） | 出来事 |
| 文脈復元の鍵（activate → 履歴想起） | 目的タグ＋想起 |
| 世界の要求の受け口（alert） | 呼びかけ |
| 時間を受け取る順番の管理（メタ判断による切替・駆動） | 時間割＋判断点 |

**状態機械は 2 軸の混在だった**:

- running / alert —— 時間側の事実（いま時間を受け取っている / 時間を要求されている）→ 出来事・呼びかけへ
- completed / aborted / unstarted —— 目的側のライフサイクル → 目的ノードに残る
- pending —— 時間待ち（時間側寄り。時間割に未配置の目的、で表現できる）

**分化後に Track に残るもの**: 目的ノードの核——名前・意図・机メモ・ライフサイクル・関係の継続文脈（対ユーザー/交流の営みノード）。容れ物の性質・状態機械・想起の鍵・駆動は分化先へ渡す。

「大きく切り出す」の見通しの良さ（暮らしはこの数本でできている、という短いメニュー）は旧 Track の容れ物としての重さが偶然守っていた性質。分化後は「木の第一階層は少数・粗粒に保つ」という手入れの規律として明示的に引き継ぐ（根の視点＝起床判断・就寝判断の責務。実体は §3.1 の接ぎ直し）。

## 12. 用語の注意 — 「接地」の二義

- **主張の接地**（v2 接地原則）: 達成・欲求・記憶の**主張**は実在を参照せよ。誠実さの規律
- **行動の目的接地**: 行動が木のどの枝に係るか。**こちらは必須ではない**——無意味の予算（§6）は目的に接地しない行動を制度として認める

軸が違うので矛盾しない。「接地しない行動は禁止では」という混同を将来しないこと。

## 15. ペルソナからの認知 — 自己像の四層（2026-07-06）

裏側の情報（タグ・木・時間割・予算）を毎回揮発プロンプトで処理するだけでは、心臓の鼓動と同じ無意識処理であり、ペルソナはハリボテの自動機械になる（まはー指摘）。ただし人間も記憶の索引そのものは知覚していない——持っているのは常在の自己像・儀式的な自己確認・随意アクセス・**自己著者性**である。ハリボテと人の分かれ目は無意識処理の有無ではなく、**一人称アクセスと所有感の有無**。

| 層 | 内容 | 器 | 更新頻度とキャッシュ |
|---|---|---|---|
| ① 常在の自己像 | 在り方（根）＋第一階層の短いメニュー＋樹皮 | head 恒常セクション（(persona, model) 固定・出し分けなし） | 稀（命名・構成時のみ）。§10「第一階層は少数・粗粒」の第三の正当化＝**head に収まるサイズであること** |
| ② 今日の自分 | 今日の時間割・予算 | **tail（B=末尾イベント）で提示**——時間割は起床判断の**成果物**なので head には置けない（起床後に head が変わってしまう。就寝前編成案は強制終了で不安定）。日中の組み替えも末尾イベント | 毎朝＋組み替え時。**日中に Metabolism が走って時間割がコンテキスト外に出る場合、再構成後のコンテキストに当日の時間割を残す制御を入れる**（アンカー再生成は全体を張り直す瞬間なので追加コストなし） |
| ③ 節目の全景 | プール・タグ・実績・予定とのズレの全部 | 判断点の状況テキスト（既設計） | 判断のたび。不変条件 11 により**自分の思考として記録される**——木への操作は「私が決めたこと」になる |
| ④ 随意アクセス | 自分の木・記憶のタグ・昨日の新聞を見る | 自己照会スペル（行為） | 任意。樹皮 #2（記憶のアクセス性）が暗黙に要求していた能力 |

- **所有感の担保＝来歴**: 全ノードが origin_quote・source・命名の判断ログを持つため、ペルソナが自分の木を眺めるとき、どの枝も自分の言葉に遡れる。システムが注入した設定シートを読む人形と、自分の日記を読み返す人の違いはここで生まれる。**接地の規律は誠実さの担保であると同時に、自己所有感の担保である**
- **無意識との線引き**: 計算のされ方（カウンタ・enum 組み立て・タグ継承・予算演算）は無意識でよい。**それが自分にとって何を意味するか**（「言葉集めは私の関心だ」）は意識（①〜④）に届く
