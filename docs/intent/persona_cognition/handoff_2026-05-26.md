## #8 paired_action_text の context 復元 (認知モデルの本質修正)

**発見した破綻**: 各 LLM ノードの action (指示テキスト) は `paired_action_text` カラムに応答とペアで記録されていた (Phase 1 P0-6) が、**context 構築の SELECT に含まれず、次 Pulse で読まれていなかった**。= ペルソナが「過去に何を指示されたか」を Pulse 跨ぎで思い出せない文脈喪失。#2 の Pulse で「サブラインとしての最初のパルス」と誤認したのはこれが原因 (#1 の起動 action が context に無く、毎回「最初」だと思っていた)。

**重要な切り分け**: Pulse 内 (spell loop / run_playbook の子ライン) では action は messages 変数で持ち回されるので揮発しない (ログで確認: track_autonomous の action が web_research 子ラインの全ラウンドに残っていた)。**揮発は Pulse 跨ぎのみ**。

**修正**: scope に連動させた。
- `_LINE_METADATA_COLUMNS` に `paired_action_text` 追加 (SELECT に含める) — `storage.py`
- `_payload_from_message_locked` で **scope=committed の応答のみ** payload に乗せる (volatile は揮発) — `adapter.py`
- `_expand_paired_action_payloads` で「action → 応答」順に展開 (committed の action を `<system>` 付き user メッセージとして応答の直前に挿入) — `adapter.py`、`recent_persona_messages` 系で適用

**綺麗にする案 (見送り)**: action を生成時に独立 user メッセージで記録すれば時系列で自然に並ぶが、SAIMemory (記憶本体) に指示が混ざって汚れる + レコード倍。paired_action_text は記憶の純度を守る設計なので、保存=ぶら下げ/復元=前置展開の非対称は受け入れる。

**当初の遠回り**: 最初 `_dump_llm_io` で送信 messages 全体を pulse_logs に二重記録しようとしたが、(a) paired_action_text に既にあった (b) messages 配列丸ごとは system prompt + 全履歴で重複過剰、と判明して revert した。

### 設計整理: 自律 Pulse とサブラインの概念

まはーとの議論で、ライン・scope・モデル選択が絡み合って「全部ぐちゃぐちゃ」になっていた設計を整理した。

**4 パターンに集約される**:

| パターン | ライン | scope | モデル |
|---------|--------|-------|--------|
| ① 通常会話 | main | committed | 標準 |
| ② Playbook 内部処理 (run_playbook spell) | sub | volatile | 軽量 |
| ③ 自律行動 | main | committed | 軽量 |
| ④ メタ判断 | main | committed/discardable | 標準 |

**核心的な理解**:
- サブライン (②) = run_playbook spell でのみ発生する「サブエージェント的分身」。ユーザー目線では「Playbook 起動は分身に作業を任せるもの」
- ①③④ はすべて main_line。ライン概念を意識する必要がない
- 自律行動 (③) は通常会話 (①) と同格の「ペルソナの体験」であり、同じ記憶空間に入る。コスト抑制はモデル選択 (pulse_type=auto → 軽量) で行い、line_role では分離しない
- ユーザーが知るべきことは 2 文: 「通常会話は標準モデル」「自律行動は軽量モデルが頻繁に動作し、定期的に標準モデルによる方針決定が行われる」

**旧設計の問題**:
- 自律 Track が `default_entry_line_role = "sub_line"` だったため、自律行動の記憶が main_line フィルタで全除外されていた (Pulse 間でも、通常会話からも参照不可)
- `_force_lightweight_model` は `line="sub"` にバインドされていたが、自律 Pulse は `line="main"` で実行されるため軽量モデルにならなかった
- 結果: 標準モデルで 38 回の自律 Pulse が走り、1000 円以上の課金 + 記憶は全部消失

### track_pause 失敗の根本原因

Pulse #3 で `track_pause` が発火されたが、ペルソナ (Gemini) が Track の UUID を正確に引用できず、直前に作成した memopedia ページ ID の後半部分と混同した。`track not found` で pause 失敗 → Track は running のまま → SubLineScheduler が 38 回 Pulse をトリガーし続けた。→ `docs/issues/track_short_id_for_spell_args.md` で issue 化済み。

### ユーザー会話保持機構の確認

`saiverse/user_conversation_preserver.py` がオーナーユーザーとの会話を最低 20 件 (`SAIVERSE_USER_CONV_PRESERVE_COUNT`) 確保する仕組み。`origin_track_id` で区別するため、自律行動が main_line に入っても通常会話が押し流されない。今回の修正と整合することを確認済み。
