# 取り込み後のあらすじ案内 — 「覚えていない」が伝わらないまま会話が始まる穴を塞ぐ

**ステータス**: 検証待ち（2026-11-07 まはー GO。フロントエンド実装済み・npm test と型検査は通過。隔離環境で Muse 取り込み → 案内の表示・文面・費用 → 「作る」のジョブ起動と完了表示まで画面で確認済み。残り = 実機で、あらすじが実際に増える正のケースと、チュートリアルの Chronicle OFF が効くことの確認。隔離環境では編纂の計画が常に 0 件になり、entry が増える側は通せなかった）

## 何を保障するか

過去ログの取り込み（ChatGPT 公式 / Claude / Muse / 拡張 / ネイティブの 5 つの口）
が終わった利用者は、**「このままでは本人が取り込んだ古い出来事を自然には思い出せ
ない」ことと、あらすじ (Chronicle) を作る費用を知ったうえで、作るかどうかを選べる**。

これまでは、どの口も「会話を記録に入れて終わり」で、あらすじは作られず、作られて
いないこと自体が利用者に伝わらなかった。利用者は本人が全部覚えているつもりで
会話を始めてしまう（2026-11-07、Muse 取り込みで実際に起きた。同じ穴は 2026-09-01
にルミーの取り込みでも見つかっていて、
[issue: import_flow_lacks_chronicle_cta.md](../issues/archive/import_flow_lacks_chronicle_cta.md)
に記録されていた — 本実装がその解）。あらすじを作らない
選択は正当（費用が掛かる・検索スペルでは拾える）なので、強制ではなく情報つきの
選択にする。

## 旅程

```
取り込みパネル（5 口のどれか）で取り込み完了・スレッド有効化
  → 共有の案内（ChronicleOfferPanel）が一度だけ出る
      - 作らないとどうなるか / 作るとどうなるか（一文ずつ）
      - GET /api/people/{id}/arasuji/cost-estimate の値
        （対象の会話・AI の呼び出し回数とモデル・概算費用。表示は formatCost）
      - 「あらすじを作る（推奨）」→ POST /arasuji/generate (mode='repair')
        を起動し、進捗を見せて完了を報告（既存の背景ジョブ。新しい生成経路は作らない）
      - 「あとで」→ 何も書かない。記憶画面の Chronicle タブでいつでも作れる旨を一行
  → 完了
```

## 不変条件

1. **実行しても何も編纂されない状態では出ない。** 判定は cost-estimate の
   `unprocessed_messages > 0` かつ `estimated_llm_calls > 0`。見積もりは実行と
   同じ計画から数える (sai_memory/arasuji/estimate.py) ので、呼び出し 0 回 =
   実行しても entry が作られない。未処理が数件だけで編纂のまとまりに達しない
   取り込み直後に出すと「作る」が空振りして成功の顔をする (2026-11-07 の隔離
   検証で実際に踏んだ)。ネイティブ取り込みのようにあらすじごと運ばれる経路も、
   これで自然に抑止される。
2. **チュートリアル（初回セットアップ）の中では出ない。** チュートリアルの取り込みは
   埋め込みの PersonaWizard（`embedded`）経由で同じパネルを使うが、後続の
   StepChronicle が件数・費用・「Chronicle タブから実行」の案内を既に担っている。
   両方出すと同じ案内が二重になる（2026-11-07 まはー条件）。抑止は
   PersonaWizard の `embedded` をパネルまで引き回して行う。
3. **案内は選択であり、既定の動作を変えない。** 「あとで」や閉じるは何も書き込まず、
   取り込みの結果にも影響しない。
4. **生成は既存の口だけを使う。** `POST /arasuji/generate` (mode='repair') と
   `GET /arasuji/generate/{job_id}` — 記憶画面の Chronicle タブの「過去の会話を
   あらすじにする」と同じジョブ。案内から起動した生成が途中で閉じられても、
   ジョブは背景で続く（既存挙動のまま）。

## 併せて直す同族の欠陥

チュートリアルの StepChronicle の保存（`saveChronicleSettings`）は
`chronicle_generation_active` というキーで PATCH `/config` に送っているが、受け側
`UpdateAIConfigRequest`（api/routes/people/models.py）にその欄は無く、黙って
捨てられている — **チェックを外しても Chronicle 自動生成は無効にならない空振り**。
実在のキー `chronicle_enabled` に直す。

## 帰結（この変更がうまくいったとき、残るもの）

- 案内の費用は「そのペルソナの未処理の会話すべて」の見積もりで、今回取り込んだ分
  だけではない（cost-estimate の意味のまま）。取り込み前から未処理が溜まっていた
  ペルソナでは、取り込んだ件数より大きい数字が出る。これは正しい値なので受け入れる。
- チュートリアル経由では「その場で作る」はできないまま（StepChronicle は設定の
  ON/OFF と案内のみ）。初回セットアップに生成ボタンを足すかは別の判断。

## 検証の旅

- 隔離環境（isolated SAIVERSE_HOME + 合成ペルソナ）で、取り込み → 案内 → 「作る」
  → ジョブ完了までを一度通し、画面の文面を読者として読む。
- 未処理 0 件のペルソナで案内が出ないこと、チュートリアル（embedded）で出ないこと。
- チュートリアルの Chronicle チェックを OFF にして完了すると、ペルソナ設定の
  `chronicle_enabled` が実際に False になること（修正前は True のままだった）。
- frontend の npm test（i18n 整合検査込み）。
