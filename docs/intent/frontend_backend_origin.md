# Intent: フロントエンドのバックエンド接続先を一つにする

**ステータス**: 検証待ち

## 全体として守ること

画面の利用者・運用者は、バックエンドの接続先を一度設定すれば、通常 API、アドオンの設定変更・音声・イベント、MCP のすべてが同じ環境へ向くと期待する。画面の操作は Next.js の rewrite または Route Handler を経由して FastAPI へ届き、書き込みならその環境の設定・履歴などを変える。経路ごとに環境変数が違うと、隔離テストの一部だけが本番へ漏れる。

接続先の選択はフロントエンドのサーバー側で一元管理する。起動ファイルで二つの変数を設定する回避では、別の起動方法の利用者に同じ落とし穴が残る。

## 決定と不変条件

2026-10-02 のまはー承認: 正式名 `SAIVERSE_BACKEND_ORIGIN` を優先し、旧名 `SAIVERSE_BACKEND_URL` も互換用に受け付ける。両方が違えば警告する。

- 前後の空白を除いた非空の `SAIVERSE_BACKEND_ORIGIN` → 同様の `SAIVERSE_BACKEND_URL` → 既定 `http://127.0.0.1:8000` の順で選ぶ。
- 両方が非空で、空白除去後の文字列が異なるときはサーバーに警告する。接続先や資格情報をログへ漏らさないよう、警告には変数名だけを出す。
- `frontend/backend-origin.cjs` を選択規則の唯一の実装とし、`next.config.ts` と三つの Route Handler が同じ関数を使う。ブラウザ側へ設定を公開しない。
- SSE の逐次転送、音声の既存バッファ処理、Range/206、書き込み body、クエリ、応答ステータス・ヘッダの中継は変更しない。
- URL の結合方法も変更しない。設定値は `http://host:port` のように末尾 `/`・パス・クエリ・フラグメントを含めない origin を使う。従来から、rewrite は文字列連結、Route Handler はルート相対 URL の結合であり、パス付きの base URL を共通の接頭辞として扱う機能はない。末尾 `/` の除去や URL 正規化は今回の範囲外。

## 運用・移行と残る境界

旧名だけを設定している環境も全経路でその値を使う。新しい設定は正式名に寄せる。二つを併記する必要はなく、食い違いは正式名を採用する。

この変更は接続先の分裂を解消するが、両方を未設定にした隔離テストを安全にするものではない。既定値は従来どおり通常環境の 8000。隔離テストでは正式名で 18000 を明示する。Next.js の環境はシェルまたは `frontend/.env.local` に設定し、build と start に同じ値を渡す（rewrite は build 時に保存される）。リポジトリルートの `.env` は Next.js が自動で読む場所ではない。

## 検証の経路

同じ env の組み合わせを共通関数、実際の Next.js 設定、実際の Route Handler へ渡し、通常 API とアドオン・MCP の GET/書き込みが同じ fake バックエンドの 18000 を向くことを確認する。未設定・空・空白・旧名のみ・同値・不一致も検査する。単体回帰では fetch を fake に限定する。追加の HTTP 検証では、18000 にテスト自身の fake サーバー、18010 に実 Next.js production server を起動して読み書きを通す。ポートが使用中なら中止し、既存サーバーは使わない。本番 8000 への通信も実 LLM 呼び出しも行わない。SSE の初回チャンク、Range とメディア例外、応答の中継を回帰で押さえる。

実ブラウザでの音声再生、本番データ、実 LLM は検証範囲外。実機確認まで issue を archive へ移さない。
