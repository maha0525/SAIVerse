# 過去ログ取り込みの一本道化 — 流せない選択と、迷わない画面遷移

**ステータス**: 検証待ち（初版は PR #460 で develop にマージ済み。2026-11-08 のまはーの実機確認で「取り込みを 1 回終えるとペルソナ作成の完了へ直行し、複数回取り込めない」「Muse のファイル取り込みが流れの中に無い」の二つの抜けが出て、同日 GO で複数取り込み対応を実装 — ブランチ feature/import-flow-multi、隔離環境での画面確認まで済み。残り = まはーの PR 確認と実機確認）

## なぜ作り直すか

2026-11-07、Muse の 606 メッセージの取り込みをペルソナ作成ウィザードで通した
まはーの観察: あらすじを作るかの案内 (ChronicleOfferPanel、PR #458) が
**滅茶苦茶スルーされやすい** — 画面の中央に出ない、下に「ファイルからの引っ越し」
「ペルソナまるごとパック」などの表示が続いてごちゃつく、そして案内を無視して
「スキップ」も「完了」も押せてしまう。エンベディングの選択も同じ構造。

この案内は「本人が古い出来事を覚えていないことが、利用者に伝わらないまま会話が
始まる」のを防ぐためのもの (docs/intent/import_chronicle_offer.md)。流せる位置と
形に置いたままでは目的の半分しか達成していない。最初のペルソナ作成でこの
ごちゃつきを見ると混乱する、という初見の利用者の観点も同じ指摘に含まれる。

## 画面遷移 (まはー案 2026-11-07)

チャットログの取り込みを、途中で終了させない一本道にする:

```
① どこから取り込むか選ぶ (ChatGPT 公式 / Claude / Muse / 拡張 / ネイティブ /
   取り込まない)
   — ここだけが既存の場所に残る: ペルソナ作成ウィザードの step2、
     メモリー画面の引っ越しタブ
② ZIP (またはファイル) を入れ、取り込む会話を選ぶ
③ 取り込み中 (進捗)
④ エンベディングを作るか — 二択必須 (作る / あとで)
⑤ あらすじ (Chronicle) を作るか — 費用つき二択必須 (作る / あとで)
⑥ 完了
```

②〜⑥は①から開く**専用のウィンドウ**で、ペルソナ作成ウィザードと
メモリー画面の両方から同じものを使う (共用)。

- **④⑤は選択ボタンを押す以外に先へ進む方法が無い。** スキップボタンも完了
  ボタンも置かない。「あとで」は選択肢の一つとして明示的に押させる。
- **閉じられるのは②（取り込み開始前）と⑥だけ。** ②で閉じれば丸ごと
  キャンセルで①に戻る（何も取り込まれていない）。③が始まったら閉じる手段は
  無い — 取り込みは進みながら書き込むので、途中で閉じても巻き戻せないため。
  ③が失敗したときは②へ戻り、また閉じられる。閉じる手段が無い間は Tab キーの
  フォーカスもウィンドウの中に閉じ込める — 背後に残るペルソナ作成ウィザードの
  カードへキーボードで抜けて、進行中の流れを壊せないように (2026-11-08、
  Codex レビュー P2 への対処)。
- **③の追跡が切れたとき** (状態の問い合わせが 8 回連続で失敗): 「次へ」ボタンを
  出すが、押された瞬間に終了状態をもう一度確かめる。まだ走っていれば進捗表示へ
  戻り、失敗していれば②へ戻す。走行中に④へ進んで「作成する」を押すと、その後に
  取り込まれた分がエンベディングから漏れるため (reembed は開始時点の対象だけを
  埋める)。再確認も届かないときだけ、閉じ込めないことを優先して④へ進む — 漏れは
  メモリー画面の「未処理を埋める」で後から補完できる (2026-11-08、同レビューへの対処)。
- **③の完了後は閉じられない** (④⑤の二択で進むだけ)。取り込み済みの会話を
  巻き戻す = ペルソナから記憶を消すコードは作らない (2026-11-07 まはー了承。
  ④⑤はデータに触らない選択なので、必ず答えられる)。
- **④の実現**: 取り込みではエンベディングを作らず (skip_embedding=true)、
  ④で「作成する」を選んだら既存の `POST /reembed` (force=false) を呼ぶ。
  これで作られるのはまだエンベディングの無いメッセージの分だけなので、普段は
  今回取り込んだ分しか計算しない (エンベディングのモデルの記録が違うときだけ
  全件の再計算に自動で切り替わる)。取り込み API のエンベディング選択は開始時に
  しか渡せず、③のあとに④を置くにはこの形しかない。作成はバックグラウンドで
  続き、進み具合の行が⑤⑥にも出る。
- 複数スレッドが見つかった取り込みでは、③と④の間に「どのスレッドから会話を
  続けるか」の選択が入る (従来からある選択を一本道の中へ移した)。
- ⑤で「作る」を選んだときの生成の進捗・完了・追跡不能の表示は
  ChronicleOfferPanel の実装 (PR #458) をこのウィンドウに移植する。出す条件
  (見積もりの呼び出しが 0 回なら⑤を飛ばして⑥へ) も同じ。
- 「ペルソナまるごとパック」はチャットログの一本道とは別物なので、
  メモリー画面の別の節として残し、ペルソナ作成の step2 には出さない
  (初見の画面を細くする)。Muse の SOUL/IDENTITY/MEMORY/AGENTS のファイル取り込みも
  当初は同じ扱いにしたが、Muse の人には正規手順の一部なので、一本道の中へ入れ直した
  (下の「Muse のファイル取り込み」)。メモリー画面の「ファイルからの引っ越し」の節は、
  あとから取り込む口としてそのまま残す。
- チュートリアル (初回セットアップ) 内のペルソナ作成も、画面に組み込まれた
  PersonaWizard 経由で同じ一本道を通る。⑤が出るので、チュートリアルの
  StepChronicle からは件数・費用の案内を外して「自動生成の ON/OFF」だけに
  絞る (二重案内の解消 — import_chronicle_offer.md 不変条件 2 の置き換え)。

## 複数の取り込み (2026-11-08 まはーの実機確認から)

初版は⑥で閉じると、ペルソナ作成ウィザードでは作成完了の画面へ直行させていた。
「1 ペルソナの作成 = 1 回の取り込み」を暗黙の前提にした作りで、ChatGPT と Claude を
併用していた人や、Muse のようにチャットログとファイルの二段構えが正規手順の
取り込み元が、2 つ目を入れられなかった。直す:

- **⑥の「閉じる」は①の入口へ戻す** (メモリー画面では最初からこの挙動。ウィザードも
  同じにする)。ウィザードの入口には「ここまでに取り込んだもの」(取り込み元・会話数・
  メッセージ数) の一覧が積まれる。
- **ウィザードで先へ進むのは、入口の「取り込みを終える」ボタンだけ。** まだ何も
  取り込んでいないときは従来どおり「取り込まない」カードを出し、1 件でも取り込んだら
  「取り込まない」は「取り込みを終える」ボタンに置き換わる。
- ④⑤の二択は取り込みのたびに出る。その回に入れた分への選択だから、繰り返し出るのが
  正しい (2 回目の取り込みで④「作成する」を選べば、1 回目で「あとで」にした分も
  まとめて作られる — reembed はエンベディングの無い分を全部埋めるため)。

## Muse のファイル取り込み (SOUL / IDENTITY / MEMORY / AGENTS) を一本道に入れる

Muse のエクスポート ZIP にはこれらのファイルが入っていない (muse_export_import.md)
ので、チャットログとは別にファイルを入手して取り込む工程が Muse の正規手順に
含まれる。初版はこれをメモリー画面の節だけに置き、ウィザードから見えなかった。直す:

- **Muse を選んだ取り込みでは、スレッド選択の後・④の前に「ファイルも取り込むか」の
  必須二択 (ファイルを取り込む / あとで) を入れる。** ④⑤と同格で、押す以外に先へ
  進む方法は無い。ファイルの入手の手順案内 (Muse 側からのコピー) をこのステップに出す。
- 「取り込む」はメモリー画面の「ファイルからの引っ越し」と同じ経路
  (`muse/files/preview` → `muse/files`) をウィンドウの中で通す: ファイルを選ぶ →
  どこへ何件入るかのプレビュー → 実行 → 結果を見て④へ。
- 「あとで」は、メモリー画面の「ファイルからの引っ越し」の節からいつでもできる、と
  添えて④へ進む。
- **④より前に置く理由**: AGENTS.md から作られる Memopedia のページはエンベディング
  作成 (reembed) の対象に含まれるため、ファイルを先に入れてから④で「作成する」を
  選べば一緒に拾える。

## 不変条件

1. チャットログの取り込みで、エンベディングとあらすじの選択を**見ずに**完了に
   到達する経路が存在しない。
2. 取り込みが完了した会話は、この流れの操作では消えない (キャンセルで巻き戻る
   のは取り込み開始前まで)。
3. ②〜⑥の中身の処理 (プレビュー・取り込み・進捗・エンベディング・費用見積もり・
   あらすじのバックグラウンド生成) は既存の API をそのまま使う。バックエンドは
   変えない。
4. 取り込み元ごとの固有画面 (Claude のカテゴリ別ドロップ枠、Muse の手順案内と
   ワークスペースファイルの注意) は②の中に残す — 一本道にするのは画面遷移で、
   取り込み元ごとの案内を削ることではない。
5. ペルソナ作成ウィザードは、取り込みを何回でも繰り返してから完了に進める。
   取り込みが 1 回終わった時点で作成完了へ直行する経路は存在しない (2026-11-08)。
6. Muse のチャットログ取り込みで、ファイル取り込みの選択を見ずに④へ到達する経路が
   存在しない (2026-11-08)。

## 帰結

- 既存の MemoryImportForm / useMemoryImport / ClaudeImportPanel / MuseImportPanel
  の画面遷移は専用ウィンドウへ再構成される。PR #458 で各取り込みパネルの中に
  個別に出していた案内 (ChronicleOfferPanel) は、この専用ウィンドウの⑤に
  集約される。
- メモリー画面の引っ越しタブは「①の入口 + ファイルからの引っ越し + ペルソナ
  まるごとパック + エクスポート」の静かな一覧になる。
- ペルソナ作成ウィザードの step2 は「取り込みの実績一覧 + 入口 + 終えるボタン」の
  ハブになり、取り込みの回数と順番は利用者が決める (2026-11-08)。

## 検証の旅

- 隔離環境で、ペルソナ作成とメモリー画面の両方から: 取り込み → ④⑤が必ず出て
  二択以外で進めない → ⑥完了、を画面で通す。
- ③完了前のキャンセルで①に戻り、会話が増えていないこと。③完了後に閉じる手段が
  無いこと。
- チュートリアル経由で二重案内が出ないこと (StepChronicle の表示の変更含む)。
- frontend npm test (i18n 整合込み)・tsc。
- (2026-11-08 の複数取り込み対応) ウィザードで: 1 回目の取り込み後に入口へ戻り、
  実績一覧が出て、2 回目の取り込みができ、「取り込みを終える」で完了へ進むこと。
  Muse の取り込みでファイルの二択が④の前に必ず出て、「取り込む」で SOUL/MEMORY が
  入り、「あとで」で④へ進むこと。メモリー画面の Muse 取り込みでも同じ二択が出ること。
